# 居民的一天与城市人气

**案子身份：实现当前案 · 2026-10-15 接管。** 用户授权开发并真实游玩测试 0.3，本案接管居民职责链，负责居民的落脚位置、日常作息、可见的生活动作，以及城市的人气。既有身份、人口规则、交互与同伴能力沿用 [01 居民与同伴](01_NPC居民生活与冒险同伴.md)能力参考；生活设施与作息冲突处以本案为准。总纲见[异世界冒险体验](../../../10_product/异世界冒险体验/README.md)。

```mermaid
flowchart LR
  A[清晨：从自己的床起来] --> B[从入口出门]
  B --> C[上午：在自己的工位干活]
  C --> D[午间：吃饭、小聚]
  D --> E[下午：继续工作]
  E --> F[傍晚：公共活动、串门]
  F --> G[夜里：回家睡觉]
  G --> A
```

群体同时行动、城市日历与居民关系见下一案[城市节奏：群体日程与城市日历](11_城市节奏_群体日程与城市日历.md)（设计中案）。

## 现在的居民为什么怪

<small>原话：“NPC目前也没什么生活其实，甚至生成位置、生活的动作都怪怪的（好像只会乱走吧目前）”</small>

<small>原话：“前面那俩我感觉你说的都挺对的”（指 AI 对居民位置与行为问题的分析）</small>

**AI 总结：** 现在居民的落脚点是在建筑占地里随便找的空地，常挤在角落、屋檐下或院子里；同一栋楼的工人共用一个工作点；生活只是在家与工作点之间来回，到了就站着，巡逻职业随机乱走，休息也不睡觉。本案的目标是让居民像真正住在城里的人。

## 导出时自动整理生活设施

<small>原话（2026-10-15）：“这种实际床位、工位，我个人觉得是应该读tag之类的？就像村民能够找到工作方块一样，我们导出的时候就已经知道各个建筑里有什么建筑了，有几个床（甚至最新版本的坐垫、mod里面的椅子），我觉得是不是都能统计出来？”</small>

<small>确认（2026-10-15）：“就先这样呗，咱写进案子里”（确认自动识别为主、作者补充用途与特殊位置的方案）。</small>

**AI 总结：** 建筑导出时读取实际方块，依据目标整合包的标签与设施适配规则，自动整理床、工作设施、椅子、坐垫等生活设施。原版与 Mod 设施按规则识别；整合包作者配置一次，同类设施在各建筑中共用，不逐栋、逐个手填，也不让 AI 为每个居民单独挑坐标。作者标注用于补充房间用途、特殊活动位置与自动识别不足的信息。

清单保留每处设施的位置、朝向、使用站位及可供使用的人数，并据此汇总数量。一张床按完整床统计，床头与床尾不能算成两张；识别出座位后，还要有适用于该设施的坐下动作，才能作为居民可用的座位。

```mermaid
flowchart LR
  A[建筑导出：读取实际方块] --> B[生活设施清单：位置、用途与容量]
  B --> C[建筑落地：设施位置与朝向一同对应到世界]
  C --> D[居民认领床位与岗位，按作息使用设施]
```

## 内置生活行为与作者扩展

<small>原话（2026-10-16）：“其实我之前说的可坐下是可配置项，也就是这种动作是走配置的，目前是走配置的吗，比如睡觉啊这种，完全可以根据Mod的增加由作者增加的”</small>

<small>确认（2026-10-16）：“是的，加入睡觉这个动作也是能够适配其他的mod的，那感觉可玩性会高很多”</small>

<small>确认（2026-10-16）：“对的，我感觉你给出的这套比较合理的，感觉应该是原版行为+可拓展行为？因为我的mod是面向整合包的，我觉得应该提供给作者更多的配置甚至开发空间”</small>

**AI 总结：** Realmfolk 面向整合包，生活行为由内置能力、作者配置和开发扩展共同组成：

- **内置基础行为**：提供原版兼容的生活能力，以及坐下、躺卧、走到设施、面向目标、持物等居民动作。坐下本身就是一种可复用行为，不绑定某一个家具 Mod。
- **作者通过配置接入和组合**：将新增 Mod 的椅子、坐垫、床、睡袋或吊床关联到已有行为，设置使用位置、朝向、高度、容量等适配内容；可组合已有动作形成生活行为，同类设施共用配置。
- **开发者扩展新能力**：已有行为不能表达的玩法或 Mod 专用交互，通过开放的扩展接口增加实现。加入后，整合包作者继续用配置选择和复用，无需每增加一种家具就修改 Realmfolk 核心。

适配后的睡眠与座位设施进入同一套发现、占用、认领及作息流程。AI 根据城市与文明选择已提供的行为和内容，程序执行；AI 不临时编写未知 Mod 的交互逻辑。群体日程和节日复用这些生活能力，见 [11 城市节奏](11_城市节奏_群体日程与城市日历.md)。

## 设施用途由建筑与房间决定

<small>原话（2026-10-15）：“就先这样呗，咱写进案子里”（确认设施识别结合房间用途，以及特殊岗位使用作者活动点）。</small>

**AI 总结：** 标签识别设施种类，建筑与房间用途决定它供谁使用：居民卧床、旅馆客床和医院病床分别安排，不能把所有床都算成常住人口名额。工作设施按其支持的职业安排岗位；护理、接待、巡守等不对应独立工作方块的工作，使用作者补充的活动点或区域。现有房间和点位标注与自动识别结果共同组成清单。

## 住自己的床，在自己的岗位工作

<small>原话（2026-10-15）：“明确床位、工位和通路依赖”</small>

**AI 总结：** 居民依据生活设施清单和房间用途安排生活：从入口进出，在适合的房间里活动，在自己的岗位干活，睡在房间里实际的床上。每位常住居民有自己的床，并按职业分配工位或工作区域；公共座位按活动临时使用，避免同时占用同一位置。床位、岗位和通路是日常作息成立的前提：设施与活动位置要实际可用，居民能从街道经入口进入房间，并在住所、工作地点和公共活动场所之间正常往返。

住房与岗位容量以用途匹配、实际可用且可达的床位和岗位为依据，不能只凭建筑里有空地可站立就认定能住人、能工作。作者未逐个标注的普通设施可由自动识别提供；无法确认用途或通路不通时如实报告缺口，不把屋檐、阳台、墙缝和院子当作家，也不让居民超过设施容量挤占位置。居民真正使用前检查设施仍然存在、通路可达且可供自己使用；玩家拆除设施或改变通路后，原清单不能继续充当可用证明。城市快速配置据此把居民安排到实际可用的空间，见 [07](07_城市内容快速配置.md)。

### 工位有类型，职业找对口的工位

<small>原话（2026-10-18）：“还有工作方块，这个我感觉是最要命的，有很多mod就比如我们的新生魔艺，他里面自带有抄写台方块的，我感觉如果我们把这个塞进去会很帅。”</small>

**AI 总结：** 2026-10-18 新增，待开发。现在分配工位时，先按建筑用途找到建筑，再随便取一个空着的工位，不看工位是什么方块；一栋楼里同时有抄写台和熔炉时，抄写员可能被分到熔炉前。今后工位带类型（如抄写、锻造、烹饪、炼药、研究），职业写明优先使用哪类工位，分配时先匹配类型，没有对口工位再退而求其次并报告。Mod 工作方块通过设施规则被认成工位（Create 座椅、Comforts 睡袋已是这样接入），配上“面向 + 手持物品 + 做工”的组合动作，例如抄写员站在抄写台前拿着书和羽毛笔。模板里怎样放进 Mod 工作方块，见 [08 Mod 工作方块](08_整合包Mod适配与拜师学艺.md#mod-工作方块功能位替换)。

## 有作息的一天

<small>原话：“另一个问题也就是NPC的一天我感觉可以先做”</small>

**AI 总结：** 居民按职业作息度过一天：清晨起床出门，白天在工位干活，午间吃饭，傍晚参加公共活动或串门，夜里回家上床睡觉；下雨时回到室内。工作时面向工作台，偶尔换到同一房间的另一个工位；守卫沿街道和城门巡逻，而不是随机乱走。不同职业的作息有差别，同一职业的人也略有先后，不会整齐划一。

## 看得见的生活

**AI 总结：** 居民的生活要让玩家看得见：走路自然、不抽搐不绕屋顶，干活有动作，相遇的熟人会停下聊几句，坐在长椅、台阶上休息，睡觉真的躺在床上。远离玩家的居民不必逐步模拟，玩家走近时，他们已经在这个时刻应在的地方。

## 城里要有人气

<small>原话：“就是声望、法律、警卫这里，我现在想了想，感觉体感怪很多时候可能是因为城里没啥居民吧，没啥人所以很多时候感觉怪怪的”</small>

**AI 总结：** 玩家走在城里，应该时常能看到人：街上有行人，店里有店员，广场上有人聚着，城门有守卫。人口仍跟着住宅走（见 01）；别的城市来的旅人和商人也会让城里热闹，但他们都是有家的真人，见下文“世界上每个人都有家”。居民在一天中按时段出现在不同的公共场所，避免满城的人都待在屋里。目击、报案与警卫追捕的体验依赖足够的人气，见 [02 法律声誉与警卫追捕](02_法律声誉与警卫追捕.md)。

## 人气看“看得到的人”，不看总人口

<small>原话（2026-10-17）：“对于人口这块我还是有点小意见，就是就算加满到82张床都有人，是不是其实也不够人数呢？我感觉这个人口密度还是太低了 我感觉建筑的模板有锅，当然当前系统生成的规则也有锅，现在的表现就是经常能看到没有人的建筑的，而且也没看到NPC之间的交互。现在的密度感觉，甚至不如原版村庄”</small>

**AI 总结：** 用同一存档里的数据对比：城外较大的原版村庄每 1 万格有约 17～50 个村民；学院城现在约 1.3 人，82 张床全部住满也只有约 3.1 人。光加人加不上去，要同时从四处入手：

- **城市更紧凑**：按功能区定人口、再定楼，楼的数量由需要决定（见[按功能区设计城市](../../../systems/city/10_product/案子/具体流程的案子/30_D4蓝图编译/按功能区设计城市/README.md)）。
- **模板床位和工位要够**：学院宿舍应有十几到二十多张床；有用途的建筑必须有对应的工位。工作台导出素材时，对“用途需要床位或工位、模板里却没有”给出提示。
- **把人放到街上**：通勤、吃饭、集会、赶集让居民有理由出门，见 [11 城市节奏](11_城市节奏_群体日程与城市日历.md)。
- **人与人之间有交互**：同见 11 号案。

**验收标准按玩家看到的来定。** 白天站在城中心任意位置，64 格内能看到约 10 个人，其中约一半在户外；每栋有用途的建筑在它的营业时段有人。总人口只是达成这个标准的手段。

## 世界上每个人都有家

<small>原话（2026-10-17）：“话说需要流动人口嘛，我感觉这个设计是不是有点旧时代的取舍，因为我们现在这个系统是国度、世界级别的，我感觉这样会不会有点掉价，如果是担心优化的话感觉可以交给后人的智慧（？）”；随后确认：“对的，有家这个是的”</small>

**AI 总结：** 不做凭空刷出来的路人。世界里的每个人都有家、有床、有来处：

- **本城居民住自己的床，在自己的岗位工作。** 下班不会消失，晚上真的回家睡觉。这是本系统相比传统 NPC 的优势，保持不变。
- **外来的人是别处的真人。** 邻城的商队沿城际道路走来，晚上住客栈的床，第二天再上路；冒险者在城市之间往来。他们在世界里各有自己的家，只是暂时在这座城，见 [10 商队与传闻](10_城际商队与传闻网络.md)。
- **现在的访客要改。** 当前的访客不睡觉、没有来处，属于旧做法；改为有来处的旅人，过夜时住进客栈或驿站的床位。

**性能不左右设计。** 同时活动的实体数量交给工程层解决：远处的居民不逐 tick 运行，只按日程推算此刻应在的位置，玩家走近时再成为真实实体，并已经在这个时刻该在的地方。现在“远处原地停住、走近再归位”是这个思路的初版，后续升级它，而不是为此减少世界里的人。
