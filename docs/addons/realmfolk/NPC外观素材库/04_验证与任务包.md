## 扩大量产前的门槛

Gate 0（本轮离线）：学院标准完整组合、三身体兼容与三风格对照，文件可复现、规则无悬空引用、代理家具检查通过。允许针对源文件做小幅美术修整，不能因此宣布新NPC功能上线。

Gate 1（编辑器）：用Blockbench实开学院标准工程，查骨组、UV与PNG；保存、重新打开、导出后复核。将任何编辑器改动回写canonical源；如工具不支持往返，明确人工回写记录和差异。未通过时不要批量复制问题工程。

Gate 2（最小游戏闭环）：先实现一套学院standard加载→服务器解析→持久化→同步→渲染；实际运行站、走、坐、睡、持、食、工。通过后再扩三体型和另两风格。加载失败或无资源客户端有安全fallback，重进不变脸。此门槛未完成，当前不安排全库精制。

Gate 3（适配与规模）：使用真实原版床、Create座椅、Comforts睡袋/吊床及实际工作台；四个朝向、主副手，至少书/食物/工具；低背/高背、带扶手与靠墙家具；裸体型与实际宽服。碰撞箱、视点、导航、站起位置单独记录。先以现有学院人口实测帧时/纹理缓存/内存，再增加样本。身高0.95/1.05在此另开矩阵，本轮未测试。

每次验收保留seed、原始resolved快照、模型/纹理哈希、实际游戏版本/依赖与截图/录屏。发现穿插应记录骨名、动作相位、家具表面参数和所用variant，避免只写“坐姿有问题”。

## 可分给其他 agent 的任务包

以下是可复制的任务边界，**本轮没有启动其他agent或批量生产**。每个任务先遵循项目入口；只读相关规范，交付组件源JSON、PNG、对应工程、预览、来源许可、验证记录。模型id使用既定名字；新增ID先在个人候选清单提出，由集成人统一写catalog/pools，避免多人改同一文件。

### A · 程序最小闭环（先行依赖）

输入：02规范、03接口、`draft/resolved/academy_standard.json`、学院源组件、当前ClientViews/LivingCitizenModel/CitizenEntity与人口/生活契约。

任务：实现RFH1加载与学院standard渲染，独立双臂与真物品挂点，保存/同步实际快照，复用现有生活动作状态；提供缺资源fallback与只读诊断。第一步只接一套完整组合，不直接全量重写人口系统。

输出：实现仓Java/API/有意义的回归、开发记录、独立测试世界证据，正式支持后再单独升级契约。验收：Gate2全部七姿态、两客户端/重连/重进一致、换池不变脸、旧人物身份与物品不变。未经游戏证据不能标成“已支持RFH1”。

### B · 三体型与基础服装

输入：body三组件、base_tunic、rig/UV和学院standard对照。独占范围：身体/基础服几何候选与自己的纹理文件；不改骨架版本、挂点语义或全局池。

任务：精修standard/slender/sturdy的肩肘膝接缝、裤裆腿缝、袖口和手部，保持30u等高及既定骨链；先完成tunic三变体，再提出工作内搭候选。须证明皮肤/脸UV仍共享，不以放大整个人体解决衣物。

验收：裸身/内搭/学院外衣三组、7姿态×3身体；无地面负厚度，肘膝弯曲不露大片缝；配饰挂点不飘。Gate1后制作，Gate2前限于现有三体型修整。

### C · 脸、眼、头发、耳与胡须

输入：head UV、face/eyes/hair/ears/beard组件。独占范围：头部组件及其图像；不得将肤色/发/耳与species、presentation硬绑定。

任务：先实开并修整cropped/bob/tied，确认低帽配合；补胡须进食案例、narrow眼形案例；Gate2后按01目标扩展轮廓。长发提交可见性策略或明确的折叠几何，不能只在站姿拉长一块。

验收：低帽+短发/波波/束发、尖耳+眼镜、短须+进食；后视和转头检查；包+长垂尾被规则拒绝；每个新增轮廓有独立ID与许可记录。已有两种脸/眼不要用换色冒充新轮廓。

### D-AA / D-SR / D-FS · 服饰（三个独立包，游戏门槛后扩量）

输入：各自outer组件三身体变体、相应palette、base_tunic。每包只修改自己的风格衣物及候选图案，不能改其他风格或人物种族池。

AA：修整分片袍与双襟，保证坐姿四片按腿弯折，新增日常短上衣候选。SR：修整开襟/短袖与包带，新增劳动围裙候选。FS：修整斜向叶形衣襟/短摆，新增园林劳动短衣候选。样板衣服均须三体型专用几何；不得让FS只剩绿色调色，或让AA只剩紫色上衣。

验收：风格靠轮廓和构造可读；居民/劳动/专业三身份在装饰预算内可区分；站/走/坐/睡/持/食/工矩阵，至少两个基础肤色与圆/尖耳交叉，不能靠标签宣称适配。不得新增环裙/长披风，除非另提交其动态方案。

### E · 配饰兼容

输入：cap/goggles/scarf/belt/pouch/backpack/badge七组件与excludes/hideRules。独占范围：配饰候选及每体型位置，不改现有装备、库存或动作配置。

任务：先完善眼镜镜腿、腰带扣与包带接缝；补帽压发候选（如确需），保持背包与长垂尾/披风互斥。为高背椅或需要包常显的情形提出侧挂专用版本，不悄悄删除隐藏策略。

验收：三体型前/侧/后；坐睡隐藏后恢复；饰物没有真实物品属性；与头发、领口、腋下、椅背、墙面的约束有证据；新增ID须填fallback和来源。

### F · 集成验收与目录维护

输入：其他包候选、基准verification.json、对应编辑器/游戏证据。独占catalog/pools/发行manifest与全库预览，由此单点集成；不代替其他包修改资产语义。

任务：校验ID唯一、模型/材质/骨架支持、互斥/fallback环、保存实际ID与颜色、预算；合并后重建预览并核对哈希。负例至少包括帽+高发、包+披风、包+垂尾、重复腰槽、缺身体、缺可选饰物、资源恢复、旧人物重进、关键人物冲突。

验收：每项结果标静态/离线动画/编辑器/游戏层级，完整记录剩余穿插；通过Gate3后才建议按01数量批量制作。不能把未做的真实碰撞、寻路或性能测试写成“自动通过”。
