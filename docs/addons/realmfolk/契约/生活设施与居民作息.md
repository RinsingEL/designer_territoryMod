# 生活设施与居民作息

对应09《居民的一天与城市人气》实现；需求仍以需求案为准。2026-10-16基础生活及可配置行为首版已通过自动与AI实机验证，等待用户试玩；当前首版配置/API与截图见实现仓addons/realmfolk/docs/可配置生活行为.md。学院局部通路问题另列于总路线图，不因此宣布09整体完成。

## 素材导出

Studio 每次从最终 NBT 导出 `living_facilities.json`，schema 为 `realmfolk_facilities.v1`。内容包括 `size`、源 NBT 的 `sourceSha256`、`facilities` 与识别警告。原版床按完整床头/床尾配对计数；配置睡眠设施按真实锚点与必需部分核对，作者声明不能生成不存在的设施。

设施保存 `id`、`kind`（bed/work/seat/entrance/meeting）、局部 `pos`、可选 `approach`、`block`、`facing`、`use`、`room`、`name`、`adapter`、`seatHeight`。每个使用站位提供一个名额，多人岗位由不同工作站位表达。`use` 支持 building/resident/guest/care/public/staff；building 继承已批准建筑用途，guest/care 不计入常住住房。

作者 `points` 可用 `use` 覆盖该设施用途，房间可用 `living_use` 提供默认。work/meeting 等作者活动点可位于可站立空气格；睡眠设施必须对应完整、可用的真实方块。座位需要明确的行为适配，普通台阶不会仅因外形自动成为座椅。

Studio 测试素材包同时输出 `realmfolk_facilities.json`（`realmfolk_facility_catalog.v1`），按 `templateRef + templateHash` 绑定 Minecraft 实际模板编解码后的哈希，保留逐项设施清单及可选behavior/sourceRule/slot、surfaceHeight/useOffset、requiredState/requiredParts。运行时读取 `config/realmfolk/facilities.json`、素材目录 `config/structureTemplate/terrasense/*/realmfolk_facilities.json`，以及明确配置的主模组素材来源目录中的同名文件。同一模板和哈希出现不一致清单时拒绝该作者清单并记录告警。局部坐标使用主模组的同一旋转、镜像和原点转换，随建筑保存为世界坐标。

## 整合包设施规则

运行时有两层作者配置：

- `config/realmfolk/behaviors.json`：schema=1，behaviors按命名空间ID定义kinds和1～16个顺序steps，每步引用action及parameters。内置原版床、普通座位和工作行为保持可用；自定义定义不覆盖内置ID。已完成步骤的效果保持到整体停止，之后逆序清理；最后一步可持续运行。
- `config/realmfolk/facility_rules.json`：facilities按方块ID或`#标签`匹配，支持id、requiresMod、state、kind（bed/seat/work/meeting）、behavior、use、facing、height、slots及requires。每处物理slot独立占用；未提供slots时为一个default名额，显式slots为1～8个稳定ID，含可选approach整数站位偏移与offset小数使用偏移。偏移以朝北为基准随设施朝向旋转。requires核对多格家具的相对位置、同方块/选择器与状态，`$属性名`引用锚点状态。第一条匹配同类同slot的规则生效。

原有adapter=stand/bed/marker_seat及seatHeight继续兼容，映射到相应内置行为。原版床仍做床头/床尾完整性检查；自定义睡眠设施可使用sleep_surface，按配置表面高度真正睡眠、保存锚点并参与住房认领。缺失部分、不可达或未知行为不提供新增人口容量；不把任意空气格作为睡眠设施。

内置动作包括face、hold_item、wait、sit、sleep_bed、sleep_surface、work，均使用realmfolk命名空间。sleep_surface可配目标方块的布尔occupiedProperty；执行期间保持锚点及重力状态，退出还原。该适配处理居民睡眠，不触发第三方Mod的玩家跳时或重生点逻辑。临时持物只用于动作，停止时恢复原装备。

开发扩展入口为`com.rinsing.realmfolk.api.life.RegisterLivingActionsEvent`（Forge总线），开发者注册命名空间LivingAction，验证参数并创建每次独立Execution，提供tick和stop。内置行为使用同一接口；所有执行在服务器线程，框架负责设施互斥、异常退出和逆序清理，开发者负责释放自己创建的第三方资源。未知动作、参数及重复ID拒绝加载。

管理员`/realmfolk behaviors reload`先完整验证新行为及设施规则，成功才结束旧执行、替换配置并令设施重扫；失败保持旧配置与动作。未安装requiresMod对应模组时跳过该设施规则。具体字段边界、示例与扩展约定单处维护于实现仓说明；当前上学放学等群体日程仍由11后续接管。

新增睡眠朝向使用实体同步数据，Realmfolk网络协议升为3，客户端与服务端须使用对应新版JAR；模组里程碑版本号本轮不变。

离线导出可用 `build_studio_test_bundle.py --living-rules <文件>` 提供同一规则及目标整合包的 `tags` 成员快照。NBT 不携带全部标签定义；离线标签快照仅用于提取，运行时按当前注册表和真实方块复核。

旧素材或后加家具可在已加载、已有正式落地证据的建筑范围内识别。读取设施不加载整座城、不创建建筑。作者用途和活动点作为补充，不能覆盖实际方块缺失。每200tick刷新最多重新扫描1栋到期的已加载建筑，距上次扫描1200tick后排队；玩家放置/破坏使相关建筑立即到期，命令或其他Mod变化由周期扫描发现。仍保留每轮最多4栋的轻量有效性检查。重扫保留作者用途、房间、活动点、设施身份与导出来源；大量建筑轮转可能长于60秒。Create座椅样例位于实现仓addons/realmfolk/examples/create_facility_rules.json，已实测marker_seat。

## 分配与运行

实际可用的住宅床位乘入住率决定常住人口目标；工作岗位同时受实际独立工位与职业配额限制。未检查的建筑不提供新人口名额。每个居民保存 bedSite/workSite，保护原 UUID、姓名、好感、同伴和任务关系；设施减少报告缺口或改认领空位，不删除人物。访客单独标记，不占常住住房目标。

入口到使用站位先做建筑内通路检查，使用时仍检查实际方块、站位和游戏寻路。跨建筑日常行走按当前建筑入口、目的建筑入口、实际设施分段；同楼目标直接寻路，已完成入口在部分路径重试间保留。单段路径搜索最多160格、节点预算为原版4倍，只读取已加载区块，不扩大战斗追踪范围。有碰撞的BushBlock（如杜鹃）按阻挡处理，无碰撞花草保持原版通行。路径受阻不会把居民传送到眼前或屋顶。门、方块与设施变化后重新核对；睡眠使用真实床，公共座位临时占用，工作、用餐与闲聊具有对应动作。

作息依据世界时刻与职业休息时间，同职业按身份错开。战斗、执法、交谈与同行优先；离开这些状态后恢复生活。远处居民不持续寻路，重新接近时仅在玩家近距离视野之外补齐日程位置。下雨时停止露天活动并寻找既有室内位置。

## 诊断与验收

`realmfolk_life_status` 为只读 MCP，报告世界时间、已发现建筑设施、居民位置/认领与实际睡眠、坐姿等状态。另含livingBehavior（当前行为、设施、步骤、占用或错误），以及spawned以区分尚未生成与暂未加载，已加载实体提供entityTicks、nearestPlayerDistance、导航目标/末端、可达性和路径节点进度。本地测试桥 `/life {}` 提供同一只读报告，`/state` 另含实际实体 sleeping/sitting/usingItem。

管理员 `/realmfolk life_demo` 创建独立生活功能场景，使用真实床、工作方块与公共空间，由正式快速配置发布居民。该场景用于功能验收，不作为自然城市生成通过的证明。真实测试调用与截图必须另行保存。

## 临时阻路与旧存档

设施物理存在（`present`）与当前可达、可使用（`available`）分别记录。未加载的旧数据不据此取消认领；已认领的床或岗位暂时被挡住时仍保留归属，只暂停使用。实际拆除或用途不再允许认领时，才寻找同建筑空位。新增人口和新认领只能使用当前可达的设施。

前往已认领的远处设施时，目标区块未加载属于尚未核对，不直接报告通路受阻；保留最近的可用性结论并允许在已加载区域尝试部分路径，接近后重新核对真实方块与站位。此行为不强制加载目标区块，也不替代已加载位置的占用和可达性检查。

建筑内房门不能单独证明街道可达；运行时从建筑外围地基附近核对进屋通路，并按已加载建筑轮转刷新。旧居民缺少新增字段时采用兼容缺省值，旧实体使用新版寻路范围。旧城市原有超额居民不删除，报告实际缺床情况。
