# 生活设施与居民作息

对应 09《居民的一天与城市人气》实现；需求仍以需求案为准。2026-10-15 开发中，真实游玩结果见实现仓本轮任务记录。

## 素材导出

Studio 每次从最终 NBT 导出 `living_facilities.json`，schema 为 `realmfolk_facilities.v1`。内容包括 `size`、源 NBT 的 `sourceSha256`、`facilities` 与识别警告。床按完整床头/床尾配对计数；作者单独声明床位不能生成不存在的床。

设施保存 `id`、`kind`（bed/work/seat/entrance/meeting）、局部 `pos`、可选 `approach`、`block`、`facing`、`use`、`room`、`name`、`adapter`、`seatHeight`。每个使用站位提供一个名额，多人岗位由不同工作站位表达。`use` 支持 building/resident/guest/care/public/staff；building 继承已批准建筑用途，guest/care 不计入常住住房。

作者 `points` 可用 `use` 覆盖该设施用途，房间可用 `living_use` 提供默认。work/meeting 等作者活动点可位于可站立空气格；床必须对应物理床。座位需要明确的行为适配，普通台阶不会仅因外形自动成为座椅。

Studio 测试素材包同时输出 `realmfolk_facilities.json`（`realmfolk_facility_catalog.v1`），按 `templateRef + templateHash` 绑定 Minecraft 实际模板编解码后的哈希，保留逐项设施清单。运行时读取 `config/realmfolk/facilities.json`、素材目录 `config/structureTemplate/terrasense/*/realmfolk_facilities.json`，以及明确配置的主模组素材来源目录中的同名文件。同一模板和哈希出现不一致清单时拒绝该作者清单并记录告警。局部坐标使用主模组的同一旋转、镜像和原点转换，随建筑保存为世界坐标。

## 整合包设施规则

运行时 `config/realmfolk/facility_rules.json` 的 `facilities` 数组按 `blocks` 匹配方块 ID 或 `#方块标签`。每条可声明 kind=work/seat、use、adapter 和 seatHeight（0～2）。目前支持 stand（站位）、bed（物理床）和 marker_seat（独立座位实体承载坐姿）；不执行任意脚本或 Mod 内部机器逻辑。座椅如需调用特定 Mod 的交互功能，应另做固定适配。

离线导出可用 `build_studio_test_bundle.py --living-rules <文件>` 提供同一规则及目标整合包的 `tags` 成员快照。NBT 不携带全部标签定义；离线标签快照仅用于提取，运行时按当前注册表和真实方块复核。

旧素材或后加家具可在已加载、已有正式落地证据的建筑范围内识别。读取设施不加载整座城、不创建建筑。作者用途和活动点作为补充，不能覆盖实际方块缺失。

## 分配与运行

实际可用的住宅床位乘入住率决定常住人口目标；工作岗位同时受实际独立工位与职业配额限制。未检查的建筑不提供新人口名额。每个居民保存 bedSite/workSite，保护原 UUID、姓名、好感、同伴和任务关系；设施减少报告缺口或改认领空位，不删除人物。访客单独标记，不占常住住房目标。

入口到使用站位先做建筑内通路检查，使用时仍检查实际方块、站位和游戏寻路。路径受阻不会把居民传送到眼前或屋顶。门、方块与设施变化后重新核对；睡眠使用真实床，公共座位临时占用，工作、用餐与闲聊具有对应动作。

作息依据世界时刻与职业休息时间，同职业按身份错开。战斗、执法、交谈与同行优先；离开这些状态后恢复生活。远处居民不持续寻路，重新接近时仅在玩家近距离视野之外补齐日程位置。下雨时停止露天活动并寻找既有室内位置。

## 诊断与验收

`realmfolk_life_status` 为只读 MCP，报告世界时间、已发现建筑设施、居民位置/认领与实际睡眠、坐姿等状态。本地测试桥 `/life {}` 提供同一只读报告，`/state` 另含实际实体 sleeping/sitting/usingItem。

管理员 `/realmfolk life_demo` 创建独立生活功能场景，使用真实床、工作方块与公共空间，由正式快速配置发布居民。该场景用于功能验收，不作为自然城市生成通过的证明。真实测试调用与截图必须另行保存。

## 临时阻路与旧存档

设施物理存在（`present`）与当前可达、可使用（`available`）分别记录。未加载的旧数据不据此取消认领；已认领的床或岗位暂时被挡住时仍保留归属，只暂停使用。实际拆除或用途不再允许认领时，才寻找同建筑空位。新增人口和新认领只能使用当前可达的设施。

前往已认领的远处设施时，目标区块未加载属于尚未核对，不直接报告通路受阻；保留最近的可用性结论并允许在已加载区域尝试部分路径，接近后重新核对真实方块与站位。此行为不强制加载目标区块，也不替代已加载位置的占用和可达性检查。

建筑内房门不能单独证明街道可达；运行时从建筑外围地基附近核对进屋通路，并按已加载建筑轮转刷新。旧居民缺少新增字段时采用兼容缺省值，旧实体使用新版寻路范围。旧城市原有超额居民不删除，报告实际缺床情况。
