# TerraSense 代码导览

## 仓库

当前 Windows 工作区：`E:\Mod_Dev\TerraSense`。TerraSense 是独立 Forge 1.20.1 + Node/React 工程；改动前先检查该仓库自己的 `git status --short`。

## Forge 扫描

| 入口 | 当前代码 | 职责 |
| --- | --- | --- |
| 客户端命令/UI | `src/main/java/com/rin/terrasense/event/ClientForgeEvents.java` | 注册扫描、assembly、UI 和停止入口。 |
| 固定模板发现 | `StructureDiscovery.java`、`SingleRootTemplateDiscovery.java` | 发现 NBT 与 single-template 根。 |
| configured structure 发现 | `StructureAssemblyDiscovery.java` | 枚举 structure registry，供 `structure_assembly` 扫描。 |
| Jigsaw pool 发现 | `JigsawPoolDiscovery.java` | 枚举 template pool，供 `jigsaw_assembly` 调试。 |
| 扫描队列 | `client/scanner/ScanQueueManager.java` | 批量调度放置、等待、摄影和写出。 |
| 放置/硬事实 | `server/StructurePlacer.java` | 执行模板或命令放置，记录 palette、connector、footprint 和差分事实。 |
| 自动扫描 | `client/scanner/AutoScanController.java` | 相机、截图、data 输出和 AI 调用。 |
| Workspace 写入 | `client/autotest/ScanWorkspaceWriter.java` | 写 manifest、单结构文件和索引。 |

C3.5 pipeline 与 assembly 扫描代码仍存在于 TerraSense，用于该工具自身的扫描/研究能力；它们不是当前 StructureBinder City runtime 路径。

## 当前导出实现

`exportCityProfiles` 支持 `official|debug|both|binder`。official/debug 读取 `structure_assembly`；binder 只读取 `single_template + approved review`。具体字段和已知跨仓库不兼容见 `../20_contracts/StructureCurationExport.md`。

StructureBinder 消费端位于实现仓库 `CityStructureProfileCatalog`。当前 importer 支持 v0.2 binder source 的 descriptor 形态，但字段层要求 `terrainModes`；TerraSense exporter 当前输出 `terrainTerms`。这是真实待修复断点，不应在代码导览里写成已打通。

## 修改路由

- 扫描样本或硬事实变化：先改 Forge model/writer，再更新 `ScanWorkspace` 与 Java 测试。
- Studio API 或 review 变化：同步 server、frontend、API tests。
- exporter/source 字段变化：同步 exporter test、`StructureCurationExport` 和 StructureBinder importer fixture。
- City NBT 几何、worldgen 或 D4 算法变化不应回写 TerraSense scanner；两者通过冻结静态语义产物交接。
