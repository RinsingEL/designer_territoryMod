## 完成后对接关注点

TerraSense 本体完成后，后续不再优先补工具功能，而是确认导出产物是否被 StructureBinder 稳定消费：

- `ScanWorkspace` 中三类样本的 manifest、截图、硬事实、AI 建议和人工审核结果是否完整。
- `C3_5_StructureCatalog.preprocessed.json` 与 `C3_5_FunctionEnumTable.json` 是否能覆盖当前 StructureBinder 兼容消费。
- `StructureProfile` 或等价画像快照是否能支撑 C 大重构的权重召回。
- runtime jigsaw 原始字段是否随导出进入 C8 可读的结构详情。
- Windows 本地克隆当前存在 `C35Pipeline.java` 未提交改动，涉及按 jigsaw/pool 引用扩展选中模板集合；提交或同步前不要把它误当作无关变更回退。

## 完成能力清单

| 能力 | 形态 | 说明 |
| --- | --- | --- |
| `autotest_scan` | Forge 客户端命令或自动测试入口 | 固定扫描三类样本并输出 `ScanWorkspace` |
| `scan_workspace_writer` | 文件写入服务 | 写出 `scan_manifest.json`、`data.json`、`scan_config.json` 和截图路径 |
| `scan_index` | JSON 状态索引 | 记录 pending/scanned/ai_done/reviewed/failed |
| `review.json` | Studio 侧文件 | 人工审核真值 |
| `TerraSense Studio` | 本地 Web 工具 | 读取 workspace、浏览截图、修改标签、写备注、审核 |
| `studio_file_api` | 本地文件 API | 限制在 workspace 根目录内读写 `ai_suggestion.json` 与 `review.json` |
| `ai_batch_labeler` | Studio 侧批处理 | 支持 mock 与真实 vision API，批量初标，失败可重试 |
| `catalog_exporter` | Studio/脚本 | 输出 StructureBinder 可消费 catalog 和下一代 `StructureProfile` |

## 与 StructureBinder 对接

当前 StructureBinder 从 `template_output/C3_5_StructureCatalog.preprocessed.json` 读取结构 catalog。

消费入口包括：

- `CityC35CatalogIO`
- `StructureTemplateQueryService`
- C7 工头计划
- C8 节点会话与 jigsaw 求解
- C9 执行层

TerraSense 第一阶段导出必须优先满足当前 C3.5 catalog，再逐步扩展到 `StructureProfile`。
