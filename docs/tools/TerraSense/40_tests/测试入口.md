# TerraSense 测试入口

## 仓库

当前实现位于 `E:\Mod_Dev\TerraSense`。该仓库存在独立工作区改动，验收时必须先看其 `git status --short`，不得用 StructureBinder 文档覆盖正在开发的 exporter 行为。

## 自动测试

```powershell
.\gradlew.bat test
Set-Location studio
npm run test:api
npm run build
node --test test/export-city-profiles.test.mjs
```

按本轮修改范围可缩小测试，但 exporter 字段、source descriptor 或准入规则变化时，`export-city-profiles.test.mjs` 必须执行。

## 能力矩阵

| 范围 | 验收 |
| --- | --- |
| ScanWorkspace | manifest、data、scan config、截图和 review 路径可重放。 |
| Forge 扫描 | `single/template/single_template`、structure assembly 和 jigsaw assembly 按入口生成对应样本，不混淆语义。 |
| Studio | 可浏览 workspace、保存人工 review、维护 vocabulary；AI 结果只作建议。 |
| exporter | official/debug/both/binder mode 的准入、skip reason、schema 和产物集合与脚本一致。 |
| 路径安全 | Studio API 和导出器不得逃逸 workspace/output 根。 |

## StructureBinder 集成闸门

当前不能把 binder 导出视为集成通过：TerraSense 输出 `terrainTerms`，StructureBinder 要求 `terrainModes` 并拒绝前者。完成修复前，只能分别验收“导出器按自身代码产出”和“消费端按自身代码拒绝不兼容字段”。

真正闭环必须增加一条跨仓库 fixture：TerraSense 生成 binder source 与 JSONL，StructureBinder `CityStructureProfileCatalog` 直接读取，同步验证 approved、function、单一 planning role、地形字段、style、run identity 和 vocabulary path。没有这条测试，不得在验收说明中写“已接入 City”。

MC 截图、结构放置和真实 vision API 仍需单独人工/环境验收；Node mock、Java 单测或已有文件不能替代客户端现场结果。
