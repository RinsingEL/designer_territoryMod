# 作者资产与验收证据

本契约属于离线工具的作者工作区，**不扩展国度 Mod 的运行时模板契约**。`planning_role.*` 记录作者意图；导入现有目录需要单独映射与验证。

`planning_role` 只接受 `planning_role.key`、`planning_role.anchor`、`planning_role.fill`、`planning_role.structure`、`planning_role.self_contained`。核心按用途使用 key/anchor，重复填充使用 fill，专项明确选用使用 structure；self_contained 需要实际完整组合证据。校验器拒绝缺失或自行翻译的 special、landmark、filler 等值。合法取值本身不证明角色选择合理，仍须结合清单与实际模型审查。

## 资产目录

`asset_catalogs/original_civilizations/<文明>/models/<变体编号>/`：

| 文件 | 含义 |
| --- | --- |
| `structure.nbt` | Minecraft Java 1.20.1 单 palette 结构，DataVersion=3465，gzip 压缩时间戳固定为 0。 |
| `author.json` | `structure-studio.author.v1`：稳定编号、结构族、文明、角色、尺寸、环境、房间、使用点、楼层和设计差异。 |
| `validation.json` | `structure-studio.validation.v1`：重新读取 NBT 后产生的数据与离线通路检查报告；包含对应 NBT SHA-256。 |
| `previews/` | 导出后在真实浏览器拍摄的查看证据。 |
| `review.json` | 作者实际看图后的结论，必须与当前 NBT、author.json 的 SHA-256 同时一致。自动截图不等于审美批准。 |

建模源码使用 Git 管理，样板源为 `tools/structure_studio/studio/samples.py`。文件路径相对实现仓。NBT 中明确写入的 air 清除内部空间；未写入坐标不产生方块操作。旋转、镜像或单纯换材质不能自动算成独立填充变体。

## 坐标与标记

局部整数坐标 `[x,y,z]`，X 东、Y 上、Z 南；样板正面朝 -Z。`size` 包含实际方块边界。房间 `min/max` 使用闭区间；`points[].pos` 为所标对象所在格，`approach` 为玩家使用站位的脚底格。入口点为步行站位；物件点不必自身可以站立。碰撞检查将站位 X/Z 加 0.5，Y 保持脚底高度。

`rooms` 保存房间用途，`points` 保存入口、工作、床位与交通点；`connections` 保存接驳位置与净空的作者说明。`terrain` 是环境适用说明，不是已证实的实际世界生成能力。楼层 `y/max_y` 与 `roof_min_y` 控制展示切片，不修改 NBT。

`preview_context` 是可选作者展示记录，`kind` 为 `flat`、`shore`、`slope` 或 `canal`。`land_surface_y` 为陆面上边界；水岸另给 `shore_z`、`water_surface_y` 和 `bed_y`；微坡另给 `run`、`rise`、`slope_origin_z`。`padding` 控制展示周边宽度。可选 `surface` 为 `grass`（默认）、`sand`、`red_sand`、`snow` 或 `podzol`，选择展示表层与基底，不改变选址条件。它创建独立查看网格，不增加、清除或修改模板方块；不代表真实地形测试。`agriculture` 记录作者的作物与布局说明，验证器另从最终 NBT 核对支撑、水源，不以该声明为已灌溉证据。

`canal` 另给整数 `canal_x0/canal_x1`（模型内航道 X 闭区间）、`upper_end_z`（模型内上游最后一格 Z）、`upstream_surface_y/downstream_surface_y`（水面上边界）与 `bed_y`。航道向模型前后展示边缘延伸，Z≤`upper_end_z` 使用上游水面，其余使用下游水面；两个水面均须高于河床。两岸使用陆面条件。示意只填充模板未写入的坐标，显式 air 也不被覆盖。闸室当前状态由 NBT 表达；这种两级示意不模拟开闸、蓄泄水、船舶通行或水动力。

实际看图后可使用 `studio.publish` 归档。输入审查记录必须包含 `id`、`reviewer`、`checks`、`reviewed_views`，可另给修订和边界说明。工具核对截图双哈希与实际图片，重跑数据和通路检查；存在错误、警告或不可达点时拒绝归档。它不会产生视觉结论，结论由实际查看图片的作者填写。

`ventilation` 是可选作者几何记录，数组中的 `roof_y` 指要穿过的屋顶方块层，`min/max` 是通风孔局部整数闭区间，`note` 说明用途。它用于核对塔内空腔与室内是否连通，不表示已实现气流、温度或运行时气候机制。

## 查看与验收范围

本地只读服务：`GET /api/catalog`、`GET /api/model?id=<编号>`、`/resources/` 资源缓存与编译后的前端。监听 127.0.0.1，无写入接口；目录解析限制在允许根目录。

预览使用本机 MC 原始模型与纹理，动画取首帧；方块颜色和光照是查看设置。截图记录 `capture.json`，含 NBT、作者记录哈希、视角文件名、缺失纹理与渲染错误。模型或标记变更导致旧验收过期。

2026-09-22 的文明名称迁移只替换作者记录顶层 `civilization` 文本。确认作者文件除此字段外字节不变、NBT 与视口截图字节不变，且旧证据双哈希匹配后，允许同步证据中的作者哈希，并附 `metadata_migrations`：保存字段、旧名、新名、前后作者哈希、NBT 哈希、日期与迁移范围。这是保留既有图审的名称迁移，不是重新截图或重新验收；原 reviewer、checks、status 保留。原本过期或缺失的证据不得迁移为有效。截图脚本的未归档整页 workbench 图可能保留历史名称，正式证据 shots 为不含文明标题的视口截图。此例外不适用于房间、站位、地形条件、切片、结构名称或其他标记改动。

步行检查使用 Minecraft 1.20.1 碰撞盒、0.6×1.8 玩家体积、半格水平采样、0.6 格跨阶；木门按可打开处理，铁门保持原状态。不模拟跳跃、游泳、爬梯或实体。报告将未覆盖或不可达列为待复核，不能据此宣称游戏内寻路、流体、机器或世界生成已经验收。
