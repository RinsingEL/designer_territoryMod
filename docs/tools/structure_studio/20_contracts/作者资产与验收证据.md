# 作者资产与验收证据

本契约属于离线工具的作者工作区，**不扩展国度 Mod 的运行时模板契约**。`planning_role.*` 记录作者意图；导入现有目录需要单独映射与验证。

`planning_role` 只接受 `planning_role.key`、`planning_role.anchor`、`planning_role.fill`、`planning_role.structure`、`planning_role.self_contained`。核心按用途使用 key/anchor，重复填充使用 fill，专项明确选用使用 structure；self_contained 需要实际完整组合证据。校验器拒绝缺失或自行翻译的 special、landmark、filler 等值。合法取值本身不证明角色选择合理，仍须结合清单与实际模型审查。

## 资产目录

`asset_catalogs/original_civilizations/<文明>/models/<变体编号>/`：

| 文件 | 含义 |
| --- | --- |
| `structure.nbt` | Minecraft Java 1.20.1 单 palette 结构，DataVersion=3465，gzip 压缩时间戳固定为 0。 |
| `author.json` | `structure-studio.author.v1`：稳定编号、结构族、文明、角色、尺寸、环境、房间、使用点、楼层和设计差异。 |
| `validation.json` | `structure-studio.validation.v1`：重新读取 NBT 后产生的数据与离线通路检查报告；包含对应 NBT SHA-256。 |
| `previews/` | 导出后在真实浏览器拍摄的查看证据。 |
| `review.json` | 作者实际看图后的结论，必须与当前 NBT、author.json 的 SHA-256 同时一致。自动截图不等于审美批准。 |

建模源码使用 Git 管理，样板源为 `tools/structure_studio/studio/samples.py`。文件路径相对实现仓。NBT 中明确写入的 air 清除内部空间；未写入坐标不产生方块操作。旋转、镜像或单纯换材质不能自动算成独立填充变体。

## 坐标与标记

局部整数坐标 `[x,y,z]`，X 东、Y 上、Z 南；样板正面朝 -Z。`size` 包含实际方块边界。房间 `min/max` 使用闭区间；`points[].pos` 为所标对象所在格，`approach` 为玩家使用站位的脚底格。入口点为步行站位；物件点不必自身可以站立。碰撞检查将站位 X/Z 加 0.5，Y 保持脚底高度。

`rooms` 保存房间用途，`points` 保存入口、工作、床位与交通点；`connections` 保存接驳位置与净空的作者说明。`terrain` 是环境适用说明，不是已证实的实际世界生成能力。楼层 `y/max_y` 与 `roof_min_y` 控制展示切片，不修改 NBT。

### 功能词与选址说明（2026-09-24）

功能层级、独立用途与内部配套、组合检索及选址分类的需求见[建筑功能层级与选址](../10_product/建筑功能层级与选址.md)。`function_terms` 仍为平面字符串数组；Studio 在浏览器端依据明确词义映射建立功能层级，支持父类包含下级及多个用途的全部／任一匹配。界面派生的层级不回写作者文件，不从名称、风格或附属物件自动推断用途。未知词保留原始标签检索入口；用途条件的自动关联尚未实现。

筛选之间取交集：风格、规划角色、文字、原始功能词和选址文字分别收窄结果，用途条件内部选择全部或任一匹配。角色直接读取 `planning_role`：key/anchor 合并为核心（`core`），fill 为填充，structure 为明确选用，self_contained 为完整组合，缺失或非法值归未标注／未识别（`unknown`）。列表与模型标题显示相同角色；不根据体量、风格或用途推断角色。文字搜索按空白分词，所有词均需出现在编号、名称、风格、原始功能词或归类路径中；原始标签按完整词精确匹配。选址文字只检索 `terrain` 中除 `推荐情境` 外的说明，不代表实际地形准入判定。详情分开展示原始功能词、派生路径、作者条件和推荐情境。

页面 URL 保存筛选：`asset` 为当前预览编号，`q` 为搜索文本，`style` 为风格，`role` 为角色分组，`functions` 为逗号分隔的界面分类 ID，`mode=any` 表示任一匹配（默认全部），`tag` 为原始功能词，`site` 为选址文字。未知分类 ID 或角色分组忽略；界面分类和角色分组不扩展运行时枚举。改变筛选不自动切换当前预览；预览不在结果中时给出提示。

- `function_terms` 为可选的非空、不重复字符串数组，记录作者确认的主体用途与可独立选用的兼用用途。当前原创库在导出前由明确的结构族／单体表补齐，不从名字或外观自动推断；附属员工床位不自动把工厂标成住宅。
- 功能词描述已建空间及作者用途，不证明传送、供能、生产或交通机制已运行；旧设施用遗址、封存等用途区别现役能力。`civilization` 仍表达建筑风格，不是居民种族限制。
- `terrain.选址`、地基／高程／岸线／支撑／净空等说明记录单体实际条件。`terrain.推荐情境` 为字符串数组，只记录可选背景，不作为准入条件，不要求配齐整套设施。适用环境与硬条件冲突时，实际条件优先。
- 供给按具体用途确认：有人驻留才需要对应生活补给，畜群需要饮水饲料，种植需要耕土、水和生长条件。普通生活建筑不因学院风格要求魔力、不因北欧风格要求海湾；船屋等专用设施仍要求真实水岸。
- Studio 列表返回 `function_terms` 与完整 `terrain`，搜索可匹配功能词。它仍是作者工具接口，不自动导入 City；正式规划须另映射并审核既有 `functionTerms/styleTerms/terrainModes` 等契约。
- 通过 `studio.refine_annotations` 迁移已有作者记录时仅修改已列出的非几何内容，NBT、点位、空间坐标和旧证据保持不变，记录前后作者哈希及逐字段差异。**旧 review/capture 不改哈希、不自动延续为当前标记验收**；重新图审仍走原流程。本轮标签校核记录与视觉验收分别保留。

`preview_context` 是可选作者展示记录，`kind` 为 `flat`、`shore`、`slope` 或 `canal`。`land_surface_y` 为陆面上边界；水岸另给 `shore_z`、`water_surface_y` 和 `bed_y`；微坡另给 `run`、`rise`、`slope_origin_z`。`padding` 控制展示周边宽度。可选 `surface` 为 `grass`（默认）、`sand`、`red_sand`、`snow` 或 `podzol`，选择展示表层与基底，不改变选址条件。它创建独立查看网格，不增加、清除或修改模板方块；不代表真实地形测试。`agriculture` 记录作者的作物与布局说明，验证器另从最终 NBT 核对支撑、水源，不以该声明为已灌溉证据。

`canal` 另给整数 `canal_x0/canal_x1`（模型内航道 X 闭区间）、`upper_end_z`（模型内上游最后一格 Z）、`upstream_surface_y/downstream_surface_y`（水面上边界）与 `bed_y`。航道向模型前后展示边缘延伸，Z≤`upper_end_z` 使用上游水面，其余使用下游水面；两个水面均须高于河床。两岸使用陆面条件。示意只填充模板未写入的坐标，显式 air 也不被覆盖。闸室当前状态由 NBT 表达；这种两级示意不模拟开闸、蓄泄水、船舶通行或水动力。

实际看图后可使用 `studio.publish` 归档。输入审查记录必须包含 `id`、`reviewer`、`checks`、`reviewed_views`，可另给修订和边界说明。工具核对截图双哈希与实际图片，重跑数据和通路检查；存在错误、警告或不可达点时拒绝归档。它不会产生视觉结论，结论由实际查看图片的作者填写。

`ventilation` 是可选作者几何记录，数组中的 `roof_y` 指要穿过的屋顶方块层，`min/max` 是通风孔局部整数闭区间，`note` 说明用途。它用于核对塔内空腔与室内是否连通，不表示已实现气流、温度或运行时气候机制。

## 查看与验收范围

本地服务：`GET /api/catalog`、`GET /api/model?id=<编号>`、`/resources/` 资源缓存与编译后的前端。监听 127.0.0.1；目录解析限制在允许根目录。2026-09-26 用户授权手动标注主入口，新增唯一写接口 `POST /api/frontage`，只允许修改已登记资产的 `author.json.frontage`。请求必须同源 JSON、携带 `X-Studio-Write: frontage` 与模型编号、当前作者/NBT SHA-256；过期返回 409，不覆盖已有改动。

### 主入口标注与运行时导出

2026-09-26 后续用户原话“如果是就选第一个，因为我想尽快把流程跑起来”覆盖下文早期未标多入口拒绝策略：未手工标注且没有唯一明确 front 时，按 `points` 中 kind=entrance 的数组原顺序取第一项作为固定主入口，不随机、不回写为人工确认。已有人工配置、唯一入口和明确 front 保留优先级；非法或过期的人工配置仍拒绝，不擅自覆盖。

可选 `frontage` 对象包含 `policy`（`FIXED_FRONT` 或 `ANY_AUTHORED_ENTRANCE`）、`entrance_id`（固定正面必填且指向现有入口，任一入口模式必须为空）、`nbt_sha256`、`entrances_sha256`。后者为所有入口的 id/pos/facing 按固定 JSON 序列化后的 SHA-256；绑定人工确认时的 NBT 与入口几何。保存不移动入口，也不批准通路或视觉验收。旧 capture/review 不改哈希。

模型源码重新导出时保留已有人工 `frontage` 及其原始绑定哈希；几何变化后标记失效，不能自动刷新绑定为“已确认”。Studio 显示入口坐标、朝向、待标/失效状态，并支持按状态筛选、定位入口、保存和跳到当前筛选的下一个待标项。URL 的 `frontage=pending|ready` 保存筛选。

素材包导出映射规则：固定正面将已选入口 ID 映射为 City 既有 `front`，其他几何与入口保留；原有其他名为 front 的入口改用唯一 authored_ 前缀避免歧义。任一入口模式映射为 `ANY_AUTHORED_ENTRANCE`，同时移除入口 ID 隐含的 front 优先权。原始作者点位与编号仍保存在导出溯源中。缺省仅兼容唯一入口或唯一明确命名 front 的已有主入口；其余多入口不猜测，导出前集中列出待标素材并拒绝生成包。目录哈希随新目录重新生成；新包后须通过正式流程重建受影响 Context，不改旧冻结产物。

预览使用本机 MC 原始模型与纹理，动画取首帧；方块颜色和光照是查看设置。截图记录 `capture.json`，含 NBT、作者记录哈希、视角文件名、缺失纹理与渲染错误。模型或标记变更导致旧验收过期。

2026-09-22 的文明名称迁移只替换作者记录顶层 `civilization` 文本。确认作者文件除此字段外字节不变、NBT 与视口截图字节不变，且旧证据双哈希匹配后，允许同步证据中的作者哈希，并附 `metadata_migrations`：保存字段、旧名、新名、前后作者哈希、NBT 哈希、日期与迁移范围。这是保留既有图审的名称迁移，不是重新截图或重新验收；原 reviewer、checks、status 保留。原本过期或缺失的证据不得迁移为有效。截图脚本的未归档整页 workbench 图可能保留历史名称，正式证据 shots 为不含文明标题的视口截图。此例外不适用于房间、站位、地形条件、切片、结构名称或其他标记改动。

步行检查使用 Minecraft 1.20.1 碰撞盒、0.6×1.8 玩家体积、半格水平采样、0.6 格跨阶；木门按可打开处理，铁门保持原状态。不模拟跳跃、游泳、爬梯或实体。报告将未覆盖或不可达列为待复核，不能据此宣称游戏内寻路、流体、机器或世界生成已经验收。

## 共享浏览分类

浏览器 `web/functions.js` 与主 Mod 的 `CityMaterialCatalogBrowser` 共用实现仓 `src/main/resources/geomantia/catalog/structure_functions.json` 中的功能树、术语映射、角色和精确资产规则。此共享只统一浏览语义，不改变本契约的作者／运行时边界；Studio 原创目录不会自动进入主 Mod。旧运行时宽泛术语只映射到确定的父层级，未映射术语继续通过原始标签检索。当前浏览器的风格字段使用作者 civilization，主 Mod 使用已批准的 styleTerms，素材发布时仍需显式映射。
