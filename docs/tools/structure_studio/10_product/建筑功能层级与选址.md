## AI 需求总结

### 功能层级与风格

功能从大类逐层细化，让 AI 先确定需要解决什么需求，再寻找适合的建筑。**功能分类可以是树，一栋建筑可以同时具备多个分支的用途。** 不要求所有建筑标到同样深度；只标作者能够确认的用途。

功能与风格分别表达。同一种功能可以由中式、中世纪、北欧等不同风格的建筑承担，风格不限定居民种族。具体建筑内容、形体和空间仍在各风格文档内设计，不要求每种风格配齐功能树，也不按固定的功能与布局组合批量换皮。材料换皮仍只替换材料。

**核心、填充等规划角色作为独立筛选条件**，可以与风格和功能组合使用。列表显示模型已有的角色标记，选择角色只影响候选范围，不改变模型的用途或角色。

功能记录实际可以做什么。温室、棚架等实现形式以及遗址、封存等状态需与用途区分；不能把历史上承担过的用途认作当前可用能力。

### 店铺功能的细分

功能层采用“商品零售”，兼容实体店和货摊。“面包店”“渔具店”等常用名称可以帮助理解，但不绑定某种建筑外形。

```text
商业
└─ 商品零售
   ├─ 食品
   │  ├─ 粮油
   │  ├─ 果蔬
   │  ├─ 肉类与水产
   │  ├─ 面包与糕点
   │  └─ 香料
   ├─ 衣物
   │  ├─ 布料
   │  ├─ 成衣
   │  └─ 鞋靴
   ├─ 器具
   │  ├─ 生产工具
   │  ├─ 厨具与容器
   │  ├─ 渔具
   │  └─ 灯具
   ├─ 文化用品
   │  ├─ 书籍
   │  ├─ 文具
   │  └─ 地图
   ├─ 农牧用品
   │  ├─ 种子与苗木
   │  └─ 饲料
   ├─ 药材
   ├─ 材料与零件
   ├─ 礼仪用品
   └─ 综合杂货
```

**只有确实影响建筑选择的区别才继续细分。** 面包与糕点先归在同一分支；铁剑、铜剑、精灵剑不必各建一个功能类别，具体商品由世界观和经营内容说明。综合杂货是一种经营用途，不表示能满足所有商品需求。

### 独立用途与内部配套

作者确认的主体用途、可独立选用的兼用用途可以共同参与建筑检索。商住面包铺可同时具有：

```text
商业 → 商品零售 → 食品 → 面包与糕点
生产加工 → 食品加工 → 烘焙
居住与住宿 → 家庭居住
```

**内部配套不能自动提升为面向聚落的独立功能。** 面包铺的小储物间记录为内部配套，不因此进入“给聚落找一座仓库”的候选池；工厂值班床不让工厂成为住宅候选。是否存在独立用途，要依据模型实际空间和作者确认，不能只凭出现某个物件推断。

### 层级匹配与组合选择

- 查询父类可以找到其下级用途：需要食品零售时，面包铺和果蔬铺都可参与选择。
- **上级标记不能反向证明具备下级用途。** 只标食品零售的模型，在寻找面包零售时属于信息不足；售卖面包也不自动证明能够现场烘焙。
- 同时要求多种用途时，候选必须同时满足。例如“现场制作并销售面包”需要烘焙和售卖两种用途。
- 找不到细分类时，可以提供上级候选供核对，并明确缺少什么信息；不能把待核对候选直接当作已满足需求。
- 尚未收录的新用途先落在能够确认的上级，并补充具体说明；检查模型确实支持后，再增加更具体的功能标记。不为满足一次查询虚构建筑能力。

### 选址、使用条件与推荐情境

选址信息分为三类。功能父类不自动附带某种地形或整套设施要求，条件按具体模型与实际使用的用途确认。

| 信息 | 面包铺示例 | 对选择的影响 |
| --- | --- | --- |
| 模型落地条件 | 基础承载、入口高程、通路、占地 | 按实际模型检查；不能被推荐情境覆盖 |
| 用途成立条件 | 现场烘焙需要原料、水及适用的烘烤条件 | 按实际启用的用途核对；可经供给网络满足的资源，不强制要求紧邻产地 |
| 推荐情境 | 商业街、旅店附近、车站周边 | 用于比较候选，不作为准入门槛 |

**需要某种资源，不等于必须紧挨资源产地。** 面包铺可以接收运来的粮食和水；但水岸设施自身的岸线、水深、接驳等真实条件仍要满足。有人驻留需要生活补给，畜群需要饮水饲料，种植需要适合的耕作与生长条件；这些要求不因风格而增加或消失。

矿区可以选用北欧风格的面包铺，由商队运来粮食，同时承担烘焙、销售和店主居住。它不需要靠海，也不需要旁边先建麦田。AI 的创造空间来自用途组合、供给关系和风格选择，功能标记负责准确表达可用能力。
