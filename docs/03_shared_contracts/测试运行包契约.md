# 测试运行包契约

## 目的

一次端到端测试必须以“测试运行”而不是“阶段”作为最小保存、恢复和移交单位。D3、Blueprint、D4-D7、LandUse 和城墙只是同一次测试中的阶段，不得继续在 `<runId>/` 下各自创建互不归属的同级目录。

本契约首个落地对象是 City 全链路；其他系统需要可恢复的多阶段测试时复用同一原则，但不得直接假定 City 的阶段名。

## 身份与目录

City 测试运行身份由 `runId + citySeedId` 唯一确定。当前目录固定为：

```text
run/realm_debug/<runId>/
  city_test_runs/
    <safeCitySeedId>/
      test_run_manifest.json
      steps/
        d3/
        blueprint/
        d4/
        d5/
        d6/
        land_use/
        d7/
        walls/
        workflow/
```

- `<runId>/` 仍承载世界调查、城市种子注册表等国度级共享输入。
- `<safeCitySeedId>/` 是一次 City 测试的完整运行包根；复制或归档时以它为单位。
- 阶段可以拥有包内子目录，但不得再以 `city_d3_<id>`、`city_d4_<id>` 等形式散落在 `<runId>/` 根目录。
- 同一 `runId + citySeedId` 的 workflow 续跑更新同一运行包，不创建新的阶段散件。

## 清单

包根必须包含 `test_run_manifest.json`，当前 schema 为 `city_test_run_manifest.v0.1`。至少记录：

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 固定 `city_test_run_manifest.v0.1`。 |
| `testRunId` | 由 `runId + citySeedId` 稳定派生，不使用随机临时 ID。 |
| `runId` / `citySeedId` | 完整上游身份。 |
| `workflowMode` | 当前执行的正式或显式 debug 工作流。 |
| `worldIdentity` | dimension、world seed 或指向冻结 world manifest 的 artifact ref。 |
| `citySeedSnapshot` | 本次测试使用的城市种子快照，至少能恢复中心、候选范围和目标区块。 |
| `createdAt` / `updatedAt` | 包首次创建和最后一次写入时间；续跑不得重置 `createdAt`。 |
| `status` / `nextAction` | 当前总状态和唯一推荐继续动作。 |
| `latestRequest` | 最近一次 workflow 请求的去敏完整快照，用于原样续跑。 |
| `attempts[]` | 每次调用 workflow 的起止时间、状态、耗时和 `steps[]`；续跑追加，不覆盖历史。 |
| `artifacts` | 包根、清单和当前关键阶段产物的相对引用。 |

每个 step 至少记录 `name`、`status`、`startedAt`、`endedAt`、`durationMs`、`reasonCode`；阶段响应包含 artifacts 时应原样复制其引用摘要。`status=waiting_for_worldgen|waiting_for_confirmation|awaiting_city_blueprint|awaiting_site_review` 是可恢复停止点，不是失败。

## 写入与恢复

- 新测试第一次产生 City 阶段产物时即锁定为运行包布局；之后所有阶段只写包内路径。
- 清单必须原子写入，避免进程中断留下半个 JSON。
- 恢复时先读取清单，再核对 `runId/citySeedId/worldIdentity`，最后按 `status/nextAction/latestRequest` 继续；不得依赖操作者回忆上一步命令。
- 预览、计划、ledger 引用和 observation 仍各自承担事实语义；清单只负责把它们组织成一次测试，不能把 planned 冒充 applied。
- 敏感值不得写入 `latestRequest`。当前 City MCP 参数不应承载密钥；未来若出现敏感字段，写清单前必须显式过滤。

## 旧布局兼容

已有 `<runId>/city_d3_<id>` 等目录视为 legacy run：允许继续读取和续跑，但不自动移动、删除或伪装成完整运行包。只要新包根已经存在，该身份就必须始终使用新布局，不得在新旧目录间混写。

旧 run 若需要长期恢复，应通过显式迁移工具复制并校验依赖后生成清单；首版不做隐式迁移。

## 验收

- 新 `runId + citySeedId` 执行 D3 后，`<runId>/` 根不得出现新的 `city_d3_<id>`。
- 从 Blueprint 续跑到 D7，全部新产物位于同一包根。
- workflow 暂停后重跑，`attempts[]` 增加且旧 attempt 保留。
- 单独复制运行包后，可从清单识别世界、城市、当前停止点、下一动作和关键 artifact。
- 旧 run 不因新布局失去可读性，也不得与新包混写。
