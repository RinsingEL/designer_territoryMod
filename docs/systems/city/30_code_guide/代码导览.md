# City 系统代码导览

## 当前状态

City D3-D6 active path 已破坏性切换为结构落地驱动：

- D3 仍由 `CityLandformReviewBuilder` 产出地形 patch 真值。
- D4 由 `CityStructureAnchorPlanner` 校验 AI/Codex 提交的 `StructureAnchorPlan`。
- D5 由 `CityReservationMaskPlanner` 生成 reservation mask、road access 和 `BuildOperationPlan`。
- `city_execute_d5` 通过 `CityReservationMaskRegistry` 激活生成期 mask 和 planned structure registry，不主动执行会触发 chunk 生成的 WorldEdit 操作。
- D6 由 `CityStructureMaterializationPlanner` 输出 `plannedWorldgenStructures[]`，不要求目标 chunk loaded。
- `city_execute_d7` 保留入口名，但正式路径只查询 worldgen ledger / chunk 状态；旧 `placeInChunk` 仅在 `debugLateMaterialize=true` 时用于诊断。

旧 `CityFunctionZoneBuilder`、`CityRoadBoundaryPlanner`、`BuildableAreaMapBuilder`、`CityStructureD6Planner`、`CityStructureD7Executor` 和 bounded jigsaw solver 仍在实现仓库中作为历史 / 后续参考代码，但不再是 active endpoint 默认路径。

## 类职责

| 类 | 职责 |
| --- | --- |
| `CityStructureProfileCatalog` | 导入 TerraSense `StructureProfile.jsonl` / debug catalog；拒绝 compat catalog、`functionTags`、`function_candidates` 等旧字段；保留 TerraSense terms 原样。 |
| `CityStructureAnchorPlanner` | D4 主服务；校验 anchor 在 D3 grid / patch 内、结构来自 TerraSense catalog、footprint 可用、reservedEnvelope 不重叠；输出 `structure_anchor_map.json`。 |
| `CityReservationMaskPlanner` | D5 主服务；从 D4 anchor map 生成 `noVegetationMask`、`vegetationLimitedMask`、`noVanillaStructureMask`、`road_access_plan` 和 `build_operation_plan`。 |
| `CityReservationMaskRegistry` | server-root active mask / planned structure registry；为 mixin hook 提供 vegetation / vanilla structure 抑制、planned anchor 查询和 worldgen ledger 记录。 |
| `ConfiguredFeatureMaskMixin` | 注入 `ConfiguredFeature.place`，在 mask 内抑制树、草、花、藤蔓、灌木、竹子、蘑菇等植被 feature。 |
| `ChunkGeneratorStructureMaskMixin` | 注入 `ChunkGenerator.tryGenerateStructure` 抑制自然结构抢占，并在 `ChunkGenerator.createStructures` 尾部触发 planned structure 注入。 |
| `MinecraftCityWorldgenStructurePlacer` | 在 worldgen structure 阶段生成 configured `StructureStart`，校验 D4 envelope 后写入 `ChunkAccess.setStartForStructure(...)` 并记录 ledger。 |
| `MinecraftCityWorldgenStatusInspector` | 判断 planned anchor chunk 是未生成、已过 features，还是可等待 worldgen。 |
| `CityStructureMaterializationPlanner` | D6/D7 计划与 ledger 查询编排；正式路径不写世界；统一 trace / waiting / failure summary。 |
| `MinecraftCityStructureMaterializationBackend` | 旧诊断 backend；只在 `debugLateMaterialize=true` 时允许使用 `StructureStart.placeInChunk`。 |
| `CityStructureLandingPreviewRenderer` | 新主链预览：D4 anchor envelope、D5 mask、D6 planned worldgen structures、D7 ledger。 |

## HTTP / MCP 入口

| 入口 | 实现方法 | 当前语义 |
| --- | --- | --- |
| `city_plan_d2` | `handlePlanD2` | 构建 `CitySiteContext`。 |
| `city_plan_d3` | `handlePlanD3` | 局部 GIS 刷新并写 D3 package / preview。 |
| `city_plan_d4` | `handlePlanD4` | required `terrasenseProfileSource` + `structureAnchorPlan`；输出 `structure_anchor_map.json`。 |
| `city_plan_d5` | `handlePlanD5` | 读取 D4 anchor map；输出 reservation mask / road access / operation plan。 |
| `city_execute_d5` | `handleExecuteD5` | required `confirmWorldMutation=true`；激活 mask / planned structure registry，WorldEdit operations 标记为 deferred。 |
| `city_plan_d6` | `handlePlanD6` | 读取 D4/D5；输出 planned_worldgen 状态，不改世界。 |
| `city_execute_d7` | `handleExecuteD7` | 正式路径查询 worldgen ledger / chunk 状态；`debugLateMaterialize=true` 才允许旧 true-run materialize。 |

## 旧主链硬失败

`CityPlanningEndpointHandler.rejectLegacyArtifacts(...)` 与 `RealmPlanningHttpController.rejectLegacyCityFields(...)` 会阻断旧字段 / artifact：

- `patchGroupPlan`
- `functionType`
- `functionTag`
- `function_candidates`
- `terrasenseProfileSource` 进入 D6
- `structureChoicePlan`
- `fixedPlacementSelectionPlan`
- `function_zone_map.json`
- `buildable_area_map.json`
- `planned_fixed_placement_map.json`
- `structure_pool_map.json`
- `start_candidate_set.json`

错误前缀必须是 `LEGACY_CITY_FUNCTION_ZONE_FLOW_REMOVED`。

## 真实游玩注意

真实游玩需使用 vanilla-like 新存档，禁用 RTF，启用结构包：

```bash
.\gradlew.bat runClient -PgeomantiaDevUseReTerraForged=false -PgeomantiaDevUseStructurePacks=true
```

未生成 chunk 时 D6/D7 应返回 `WAITING_FOR_WORLDGEN`，由玩家从目标 chunk 外侧触发首次生成后重复查询 ledger，不算失败。已生成且无 ledger 时返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，正式路径不得 late paste。
