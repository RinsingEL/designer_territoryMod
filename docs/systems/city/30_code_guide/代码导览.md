# City 系统代码导览

## 当前状态

City D3-D6 active path 已破坏性切换为结构落地驱动：

- D3 仍由 `CityLandformReviewBuilder` 产出地形 patch 真值；`LandUseTerrainFieldCompiler` 同步编译高度、坡度、水体、群系等 LandUse 粗格事实。`handlePlanD3` 按 city grid + `patchScanPaddingBlocks` 覆盖多个 GIS region，不主动加载未生成 chunk。
- `city_profile_structure_envelopes` 由 `CityStructureEnvelopeProfiler` 对顶层 configured structure 做 cache-backed dry-run bbox profiling；cache miss / stale 时现场构造 `StructureStart` / pieces 采样，不写世界。
- D4 推荐由 `city_run_workflow d4CandidateMode=key_then_array` 分阶段编排：关键结构 slot 先走 `CityStructureAnchorCandidatePlanner` 顺序 session，逐个选择并冻结 `collisionEnvelope` / body occupied；随后每个 `array_fill` slot 走 `CityStructureArrayCandidatePlanner` 阵列候选，读取上一阶段 `StructureAnchorMap` 避让已放结构，并合并回标准 `StructureAnchorPlan`。结构群整组候选保留为显式调试 / 整城构图实验路径；`array_layout_loop_v0_3` 作为显式新路径支持 `composite_array` 父 zone / subZones / child arrays。
- D4 由 `CityStructureAnchorPlanner` 校验 AI/Codex 提交的 `StructureAnchorPlan`。
- D5 由 `CityWallReservationPlanner` 生成 wall reservation，再由 `CityReservationMaskPlanner` 合入结构 mask 和墙带 mask；默认 v2 仍是 D3 patch 贴边墙带，显式 `wallVersion=v3` 使用结构种子 patch region hull；road/build 仍只保留占位，不提前决定道路路线。
- D6 由 `CityStructureMaterializationPlanner` 做 non-mutating probe-and-lock，锁定真实 bbox / group / signature，并做最终防撞。
- `city_plan_land_use` 在 D6 后由 LandUse source resolver / planner 读取 D4 group provenance、D6 locked footprint、规则 profile 和可选严格 intent，生成 block spans、boundary loops、gate slots、claim trace 与 preview；workflow 默认关闭该层。
- `city_plan_city_dressing` 由 `CityDecorationProgramPlanner` 校验 v0.3 判别联合；`CityDecorationContentCatalog` / loader 从 server config 读取内容姿态和无实体 prefab，冻结 `catalogHash`；v0.2 只读兼容。v0.1 业务 planner 与内置测试模板库已从源码删除。
- `city_probe_decoration_terrain` 由 `CityDecorationTerrainProbe` 读取 compiled plan + slot projection；`CityPlanningEndpointHandler.LoadedChunkDecorationTerrainView` 只从当前已加载 FULL chunk 的 `MOTION_BLOCKING_NO_LEAVES` heightmap 采样，未加载 slot 只报告 unavailable。该入口不生成 chunk、不写世界、artifact、active registry 或 ledger。
- `city_execute_d5` 通过 `CityReservationMaskRegistry` 激活 D6 locked mask 和 planned structure registry，通过 `CityLandUseWorldgenRegistry` 激活可选 LandUse plan，并通过 `CityRoadWeaverBridge` 可选注册 RoadWeaver 道路端点；v0.3 decoration compiled plan 与 planning completion 成对存在时先冻结完整 terrain run / foundation，再激活 DecorationProgram。worldgen owner 内顺序为 LandUse -> Decoration -> RoadWeaver 后写。
- `city_execute_d7` 保留入口名，但正式路径只查询 worldgen ledger / chunk 状态；ledger 完整后仅显式 `roadProvider=worldedit_debug` 才运行旧 WorldEdit debug road，RoadWeaver 已注册或 `auto` 缺 RoadWeaver 时均跳过并输出诊断。旧 `placeInChunk` 仅在 `debugLateMaterialize=true` 时用于诊断。
- `city_plan_city_walls` / `city_execute_city_walls` 在 D7 ledger 完整后扫描 actual road mask，按 RoadWeaver 道路裁门，并沿 D5 wall reservation 放置石墙 / 塔楼 / foundation；显式 v3 会分类内部/外部道路、聚类城门并输出地形/mask/gap debug report；`wallDesignPolicy=v3.2` 在 v3 外环上增加天然边界、道路趋势开门、独立 gatehouse 和可用塔节点；v1 矩形墙仅保留为 `wallVersion=v1_debug`。

旧 `CityFunctionZoneBuilder`、`CityRoadBoundaryPlanner`、`BuildableAreaMapBuilder`、`CityStructureD6Planner`、`CityStructureD7Executor`、bounded jigsaw solver 及其专用模型 / preview / Minecraft backend 已从实现仓库删除。历史产品案仍保留原始设计记录，但不得再作为可调用能力或后续开发基座；需要类似能力时必须基于当前结构落地主链重新设计。

## 类职责

| 类 | 职责 |
| --- | --- |
| `CityStructureProfileCatalog` | 导入 TerraSense `StructureProfile.jsonl` / debug catalog；拒绝 compat catalog、`functionTags`、`function_candidates` 等旧字段；保留 TerraSense terms 原样。 |
| `CityStructureCatalogQueryService` | 只读检索已导入的 TerraSense 画像。`allOfTerms` / `anyOfTerms` / `excludeTerms` 均在原始 canonical terms 上过滤；若 source 显式给出 `vocabularySnapshotPath`，才加载冻结词表的 `term_id`、中文 `label` 与 `aliases[]` 做解析，未知或歧义 term 明确失败，不回退旧 C3.5 或 City 自建标签。 |
| `CityStructureEnvelopeProfiler` / `CityStructureEnvelopeFacts` | D2 / D4 前置结构大小区间画像；默认读取本地 profile cache，cache miss / stale 时调用 sampler 重算；输出/读取 validSamples、bboxGroups、generationConfigHash、profileCache、cacheKey / cacheStatus；`placementRecommendation.collisionEnvelopeSource` 是 D4 几何真值：dominant group、stable max 或 P95。 |
| `MinecraftCityStructureEnvelopeSampler` | 基于 configured structure registry 生成 `StructureStart` dry sample，提取 bbox / piece count，不写世界；同时提供 runtime registry / generation context cache identity。 |
| `CityD4DesignLoopStatePlanner` | D4 多轮城市设计 loop 的 state / artifact 基础设施；create/read/append/write-back 只读写 `city_d4_design_loop_<citySeedId>` JSON 产物，保存 `cityId`、`planningMode`、`roundIndex`、已放结构 / anchors、occupied field、function zones、array zones、patch availability、next AI summary 和 trace；occupied field 只从 `collisionEnvelope` / `bodyEnvelope` 派生，不触发 D5/D6/dressing/roads/worldgen。 |
| `CityD4StagedPlanCompiler` | D4 `key_then_array` 的纯 application 编译器；校验 key slot 必须先于 array slot，生成 key-stage / array candidate / 空 layout 计划并合并标准 `StructureAnchorPlan`。不读写文件、不依赖 HTTP 或 Minecraft。 |
| `CityStructureAnchorCandidatePlanner` | D4 候选前置服务；读取 `DesignSlotPlan`，按 D3 patch 代表点、TerraSense profile、envelope facts 和已选/暂选 `collisionEnvelope` occupied 生成少量 anchor 候选；选择后转换为标准 `StructureAnchorPlan`。 |

| `CityStructureArrayCandidatePlanner` | D4 阵列候选前置服务；读取 `ArrayCandidatePlan`，默认按 `loose_cluster` / `patch_axis_band` / `scattered` 从 D3 patch member cells 生成批量结构候选组；显式支持 `compound_cluster`、`grid`、`courtyard`、`l_shape`、`u_shape`、`organic_compact` 与 `rows/columns/spacingBlocks`；未显式给 spacing 时按 D2 推荐 collision 包络计算，组内只用 collision 防撞，mask overlap 不撑开 anchors。 |
| `CityStructureArrayLayoutLoopPlanner` | D4 v0.2/v0.3 显式阵列 loop；create/execute/finalize 三段式，每轮只执行一个 item。`compound_cluster` 支持 `grid/courtyard/l_shape/u_shape/organic_compact` 与 `rows/columns/spacingBlocks`；未显式给 spacing 时按 D2 推荐 collision 包络计算，v0.3 `composite_array` 在同轮生成 parent zone、subZones 和 child zones。v0.5 在常规 outward 未传 `targetPatchRef` 时读取已 Plan focus 的 D2 body / collision bbox，以 `expansionPolicy` 按 near / middle / far 连续前沿生成候选，再后置按 D3 patch 筛选 / 评分；前沿参考使用整组 D2 body 并集，`actualBodyGapBlocks` 取整组最小方向 body gap，连续 `guide_line_dual_side` 先锁内侧首排、再向外展开另一侧；候选集写 `frontierSearchTrace[]`，不写 state 直到 select。 |
| `CityTemplateOrientationSolver` | 纯几何门面朝向排序器；在模板 `allowedRotations[]` 内计算变换后入口方向与 array center、最近 D3 WATER cell 或 cardinal 目标的对齐分数。阵列 planner 仍负责逐旋转执行 grid / collision 检查；显式 rotation 不进入自动排序。 |

## 真实游玩注意

真实游玩需使用 vanilla-like 新存档，标准启动为不加载 RTF、启用结构包、启用 RoadWeaver：

```bash
.\gradlew.bat runClient -PgeomantiaDevUseStructurePacks=true -PgeomantiaDevUseRoadWeaver=true
```

`gradle.properties` 应保持 `geomantiaDevUseStructurePacks=true`、`geomantiaDevUseRoadWeaver=true`，且不再配置 RTF / ReTerraForged 启动参数。旧 WorldEdit debug 道路只允许在诊断时显式传 `roadProvider=worldedit_debug`，不得作为 `auto` 的缺省 fallback。

未生成 chunk 时 D6/D7 应返回 `WAITING_FOR_WORLDGEN`，由玩家从目标 chunk 外侧触发首次生成后重复查询 ledger，不算失败。已生成且无 ledger 时返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，正式路径不得 late paste。

## 模板建筑 active 路径补充

模板建筑 active 路径以 `CityTemplateCatalog` / `CityTemplateCatalogLoader` 读取模板目录，以 `MinecraftCityTemplateReader` 通过 `StructureTemplateManager` 读取 NBT 尺寸和内容 hash，再由 `CityTemplatePlacementGeometry` 按 anchor、rotation、mirror 派生 transformed footprint 与 transformed `roadEntrances[]`。D4 / D6 / D7 传递并校验同一 `templateRef`、`templateHash`、`variant`、`rotation`、`mirror`、`terrainPosePolicy`、`footprint`；D5 可把锁定结果写入 City 自己的 active template placement registry，再由 worldgen NBT placement 消费，并由 `CityRoadWeaverBridge` 通过 mod API 注册 transformed entrances。

普通模板路径不查询 `Registries.STRUCTURE`，不使用 Jigsaw pool。`CityTemplateTerrainPosePolicy` 在目录模型和 D6 规划期把 `geomantia:` 身份强制冻结为 `structure_start_beard_thin`，并派生 `generator_base_height_motion_blocking_no_leaves` datum；非 `geomantia:` 模板仍按显式目录值选择 terrain start 或 direct template。`CityTemplateTerrainStartPolicy` 只从 D5 frozen plan 消费该值，`MinecraftCityWorldgenStructurePlacer` 再创建 City 注册的单-piece start。configured structure / `StructureStart` sampler 只服务非模板的结构画像与落地主线；bounded jigsaw solver 和旧 D7 materializer 已从实现仓库删除。active template endpoint 不得为模板建筑回填 configured structure bbox、入口或落地结果。
