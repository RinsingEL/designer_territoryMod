# City 系统代码导览

## 当前状态

City D3-D7 active path 已破坏性切换为固定 NBT 唯一主线：

- D3 仍由 `CityLandformReviewBuilder` 产出地形 patch 真值；`LandUseTerrainFieldCompiler` 同步编译高度、坡度、水体、群系等 LandUse 粗格事实，但完整 D3 handler 运行在 API worker，不再占用服务器 tick。`CityPlanningEndpointHandler.handleReviewD3Site` 为 T4 AI 候选首都写入绑定 D3 / CitySeed identity 的选址决策，所有 D4 入口通过 `loadCitySeedForD4` 统一阻断未审查、要求重选或 stale 决策。
- 新 D4 AI 边界由 `CityBlueprintService` 编排：prepare 冻结无版本 `city_blueprint_context`、`city_blueprint_catalog_snapshot`、`city_blueprint_reference_catalog`、完整 LandUse rule/foundation/surface recipe/landscape/relay fill profile 与 D3 terrain field，submit 通过严格 codec/reference/validator 接受一次 `city_blueprint`。多功能区中允许关系扩张的 Group 必须在提交前至少声明一条 relation，避免 accepted 后才因 `FUNCTION_AREA_RELATION_UNSPECIFIED` 失败。`groups[]`、`arrayCompositions[]` 与显式 `Landscape[]` 由 `CityBlueprintCompilerService` 编译；Group 可按 Patch/边界/其他 Group 定位，并选择简短的建筑附属绿化策略。父阵列以完整 Group extent 编排子阵列。required 建筑先按城市构图落位，required Landscape 再以 owner 为种子做地形驱动容量搜索；`owner` 只有 `groupId` 时由整个功能区所有，带 `requiredStructureRef` 时为建筑所有或兼容建筑种子。景观不得反向迫使建筑换位，缩水或零格写 warning。根级 `outdoorPlan` 保持冻结到 D6，全程不再调用 AI。
- D2 由 `CityTemplateCatalog` 与 `MinecraftCityTemplateReader` 读取显式 `city_template_catalog` 和当前世界 NBT，确认 hash、rawSize、入口、允许变换，并把所有 City catalog 模板冻结为 `structure_start_beard_thin`。
- 离线素材接入由 `tools/city_templates/jigsaw_template_sanitizer.py` 先审计跨 Mod NBT；只有 manifest 人工确认的独栋模板才按各自 `final_state` 清除 connector。它不执行 pool，入口候选不直接进入 catalog。Trek 专用导入器复用同一替换原语，但继续保留 `trek:mobs/` marker 白名单、processor 烘焙和实体清理等来源规则。
- `city_run_workflow` 只走 CityBlueprint；`d4CandidateMode` 已删除，自动队列与外部调用都不得提交该字段。缺 Context/Blueprint 时返回 `awaiting_city_blueprint`，有效蓝图自动编译并继续 D5/D6。array loop、cluster groups、sequential session 仅作各自独立的显式 legacy/debug 工具。
- D4 由 `CityStructureAnchorPlanner` 校验 fixed-template `StructureAnchorPlan`，并按 transformed exact footprint 派生 collision 和 mask；`CityInternalStreetPlanner` 在 required/core 后、fill 前按 GRID/COURTYARD/LINEAR/COMPACT 与可选 CENTER 预留区内街道骨架，fill 避让街带落位，最终再按真实入口使用裁撤、生成同功能区绕障共享扩展或短巷并冻结 `streetBands[]`；`CityResidentialOverflowPlanner` 把至少三栋 outward fill 冻结为带路、有矩形边界的住宅子区；`CityMainRoadPlanner` 只消费显式交通 `CONNECTION`，后续需求以低成本优先复用既有主路网络，路径避水、避崖、避建筑且只含 90° 转弯。空间/HIERARCHY/父阵列关系不自动造路；`CityArrayVisualQualityGate` 最后检查六阵列形态及全部道路连路缘对 actual footprint 零重叠。
- D5 由 `CityWallReservationPlanner` 生成 wall reservation，再由 `CityReservationMaskPlanner` 合入结构 mask 和墙带 mask；默认 v2 仍是 D3 patch 贴边墙带，显式 `wallVersion=v3` 使用结构种子 patch region hull；road/build 仍只保留占位，不提前决定道路路线。
- D6 由 `CityStructureMaterializationPlanner` 通过当前世界 NBT inspector 做 non-mutating identity-and-geometry lock，重新校验 hash、rawSize、变换、exact footprint、collision、mask 和 owner chunks；不创建 `StructureStart`，不输出 piece/signature/bbox group。
- D4 在建筑候选提交前把 Foundation 建筑边距计入模板阵列 pitch，最终 anchor 冻结 `buildingParcelPlan`：NBT 与必要保留范围是硬碰撞，完整矩形建筑地块是可压缩空间，花坛不足只降级。正式 workflow 在 D6 后由 `CityOutdoorBlueprintCompiler` 读取同一 Blueprint、locked footprint、D3 terrain field 和 Reference Catalog v0.9：全部结构 footprint 与道路 `platformBounds` 进入 Foundation；只有 D4 已选中的建筑绿化才以 `buildingParcelPlan.resolvedBounds`、locked collision 排除和城市 style plant palette 编译为绿化 spec；住宅外溢边界、道路 bands 与绿化 spec 一并交给 `LandUsePlanningService`，冻结到 SurfacePrintPlan v0.7 `featureCells[]`。农田/林场仍只走既有独立 Landscape Parcel 逐格扩张，不读取建筑绿化或道路逻辑。
- `city_plan_city_dressing` 由 `CityDecorationProgramPlanner` 校验 v0.4 判别联合；`CityDecorationContentCatalog` / loader 从 server config 读取 v0.4 分层内容、姿态和无实体 prefab，冻结 `catalogHash`。旧 schema 不进入当前规划器。
- `city_plan_decoration_anchor_candidates` 在最终 dressing 规划前，由 `CityDecorationAnchorCandidatePlanner` 对 required 单点 prefab 生成完整 footprint + clearance 安全候选；同 plan 已固定单点 Decoration 作为障碍。候选入口只读规划 artifact，不采样真实地形、不加载 chunk、不自动选择。
- `city_probe_decoration_terrain` 由 `CityDecorationTerrainProbe` 读取 compiled plan + slot projection；`CityPlanningEndpointHandler.LoadedChunkDecorationTerrainView` 只从当前已加载 FULL chunk 的 `MOTION_BLOCKING_NO_LEAVES` heightmap 采样，未加载 slot 只报告 unavailable。该入口不生成 chunk、不写世界、artifact、active registry 或 ledger。
- `city_execute_d5` 通过 `CityReservationMaskRegistry` 激活 D6 locked mask 和 planned structure registry，并把 D5/D6/LandUse/Decoration hash 冻结为 activation provenance；workflow 仅在全部身份一致时跳过。`CityLandUseWorldgenRegistry` 校验并激活 area + SurfacePrintPlan v0.7；owner chunk 裁切 Area spans 与精确 feature cells，在同一事务中执行 base/overlay、道路 bottom slab + outward bottom stair、绿化 ground/path/plant、住宅边界、crop/boundary。
- `city_execute_d7` 复核固定模板 worldgen ledger / chunk 状态与完整 identity；显式执行世界修改时让 `CityLandUseWorldgenRegistry` 按当前 plan identity 对计划 owner 做 ledger 差集，并进入每 tick 最多一个动作的异步 FULL chunk 队列。竞态漏过首次 FEATURES 的缺失 owner 仍执行幂等 `CONTROLLED_D7_BACKFILL`，写 v0.2 `land_use_owner_completion.json`；队列中返回 waiting，失败或最终仍缺失才 hard fail。它不是建筑 late paste，也不执行任何 WorldEdit 道路后处理。`debugLateMaterialize` 与建筑 late paste 已删除。
- `city_plan_city_walls` / `city_execute_city_walls` 在 D7 ledger 完整后扫描 actual City road mask，按实际道路裁门，并沿 D5 wall reservation 放置石墙 / 塔楼 / foundation；显式 v3 会分类内部/外部道路、聚类城门并输出地形/mask/gap debug report；`wallDesignPolicy=v3.2` 在 v3 外环上增加天然边界、道路趋势开门、独立 gatehouse 和可用塔节点；v1 矩形墙仅保留为 `wallVersion=v1_debug`。

旧 `CityFunctionZoneBuilder`、`CityRoadBoundaryPlanner`、`BuildableAreaMapBuilder`、`CityStructureD6Planner`、`CityStructureD7Executor`、bounded jigsaw solver 及其专用模型 / preview / Minecraft backend 已从实现仓库删除。历史方案只从 Git 追溯，不得再作为可调用能力或后续开发基座；需要类似能力时必须基于当前结构落地主链重新设计。

## 类职责

| 类 | 职责 |
| --- | --- |
| `CityTestRunLayout` | 以 `runId + citySeedId` 统一解析 City 测试包和包内阶段目录；新 run 写入 `city_test_runs/<city>/steps/`，已有旧 run 保持 legacy 布局读取，禁止新旧混写。 |
| `CityWorkflowStepRunner` | 把一次 `city_run_workflow` 记录为运行包 manifest 的一个 attempt；阶段进度实时原子写入，续跑追加 attempt 并保留旧历史。 |
| `CityStructureProfileCatalog` | 导入 TerraSense `StructureProfile.jsonl` / debug catalog；拒绝 compat catalog、`functionTags`、`function_candidates`、`terrainTerms` 等退役字段。`city_semantic_profile_catalog.v0.4` 输出 identity/source/review/catalog mode、三组可配置词表 `functionTerms/planningRoleTerms/styleTerms` 与 City 固定枚举数组 `terrainModes`；正式目录仅 `reviewState=approved` 准入，debug 缺状态归一为 `unreviewed`，不暴露 configured identity 或 profile 几何。`styleTerms` 仅为 AI-facing 字段。 |
| `CityStructureCatalogQueryService` | 只读检索已导入的 TerraSense 画像，响应为 `city_structure_catalog_query.v0.5`。`allOfTerms` / `anyOfTerms` / `excludeTerms` 只在功能、规划角色、风格三组 canonical terms 上过滤；`terrainModes` 直接展示但不进入动态词表解析。若 source 显式给出 `vocabularySnapshotPath`，才加载冻结词表的 `term_id`、中文 `label` 与 `aliases[]` 做解析，未知或歧义 term 明确失败，不回退旧 C3.5 或 City 自建标签。 |
| `CityStructureTerrainMode` | City 固定 placement topology 枚举：`SURFACE/EMBEDDED/FLOATING`。画像可声明多值，按 OR 解释；未知或归一后重复值在导入期拒绝。 |
| `CityStructureTerrainGate` | 用冻结 `city_land_use_terrain_field.v0.1` 对 transformed collision footprint 覆盖的全部格执行 topology gate，输出 `city_structure_terrain_gate_trace.v0.2`；不扫描世界、不加载 chunk。当前只实现 `SURFACE`：全部格必须存在、已采样、非水并满足 Group `terrainPolicy` 的坡度、起伏和完整占地高程范围；仅声明 `EMBEDDED/FLOATING` 时明确返回不支持。 |
| `CityTemplateCatalog` / `MinecraftCityTemplateReader` | 严格加载 `city_template_catalog`，从当前 `StructureTemplateManager` 读取 NBT 并校验 hash、rawSize、道路入口和允许变换；不查询 configured structure registry。 |
| `CityD4DesignLoopStatePlanner` | D4 多轮城市设计 loop 的 state / artifact 基础设施；create/read/append/write-back 只读写 `city_d4_design_loop_<citySeedId>` JSON 产物，保存 `cityId`、`planningMode`、`roundIndex`、已放结构 / anchors、occupied field、function zones、array zones、patch availability、next AI summary 和 trace；occupied field 只从 `collisionEnvelope` / `bodyEnvelope` 派生，不触发 D5/D6/dressing/roads/worldgen。 |
| `CityD4StagedPlanCompiler` | D4 `key_then_array` 的纯 application 编译器；校验 key slot 必须先于 array slot，生成 key-stage / array candidate / 空 layout 计划并合并标准 `StructureAnchorPlan`。不读写文件、不依赖 HTTP 或 Minecraft。 |
| `CityStructureAnchorCandidatePlanner` | D4 候选前置服务；读取 `DesignSlotPlan`、显式 template catalog、D3 patch 与 TerraSense 语义标签，按 fixed-template collision occupied 生成候选；选择后转换为标准 `StructureAnchorPlan`。 |
| `CityStructureClusterGroupCandidatePlanner` | D4 结构群整组候选服务；复用顺序候选 session 的 `planNext/selectSession/finalizeSession` 规则做 beam search，输出多组完整 slot 落脚方案和 `expandedStructureAnchorPlan`；组内使用 selection 同口径的 collision/body occupied 防撞，结构大小只读取固定 NBT template catalog；不再是 workflow 默认推荐路径。 |
| `CityStructureArrayCandidatePlanner` | D4 阵列候选前置服务；读取 `ArrayCandidatePlan`，默认按 `loose_cluster` / `patch_axis_band` / `scattered` 从 D3 patch member cells 生成批量结构候选组；程序化 Blueprint 编译器可注入内部 `candidateOrigins[]` 精确槽位，member-cell 只做合法 mask，不再把这些 guides 吸附回 cell center。显式支持 `compound_cluster`、`grid`、`courtyard`、`l_shape`、`u_shape`、`organic_compact` 与 `rows/columns/spacingBlocks`；未显式给 spacing 时按 D2 推荐 collision 包络计算，组内只用 collision 防撞，mask overlap 不撑开 anchors。 |
| `CityBlueprintGroupLayoutPlanner` | 正式 Blueprint compiler 阵列语法；规则阵列及父规则阵列使用全组最大模板跨度、世界轴和精确槽位，非法槽留空。GRID 生成固定 row/column，并在同一逻辑地块提供最大 1 block 微调；COURTYARD 生成空心五槽基础环，LINEAR 锁入口轴；COMPACT 逐圈八方向布置，并在同一半径提供有界切向微调，首圈没有跟随建筑时禁止扫描断裂外圈；ORGANIC 只保留 1–3 block 随机连通缝隙。 |
| `CityGridStreetReservation` / `CityInternalStreetPlanner` / `CityArrayVisualQualityGate` | required/core 后先按计划数量、formation span 与阵列语法冻结虚拟街道骨架并加入 occupied，fill/connectivity/percentage 建筑围绕该骨架落位。最终使用审查按真实入口、门脸、路口和主路交汇裁撤无用段；近端用最多 32 格短巷，无法合法接入的远端在同 Group 内以确定性 block BFS 生成可复用 `SHARED_NETWORK_EXTENSION`。短巷先退出完整路面+双侧路缘净空，全部路线避 actual body；ORGANIC_COMPACT 和无本区正式网络的 Group 不隐式生路。产物附 `streetFirstNetworkTrace`，质量门检查最终连通与 road/body 零重叠。 |
| `CityMainRoadPlanner` | 只消费 Blueprint 显式交通 `CONNECTION`；required/core 后、fill 前生成共享主路骨架。后续连接对已有主路 cell 使用更低代价，优先让一张网络服务多项交通需求，再冻结窄街过渡、D3 避水避崖和 block 级全宽避建筑路线；空间关系、HIERARCHY 与父阵列成员不自动造路。 |
| `CityResidentialOverflowPlanner` | 识别同 Group 至少三栋 `fill + outwardGuided` 建筑，冻结 `city_residential_overflow_plan.v0.1`、成员、相交区内道路、矩形边界和道路门洞。 |
| `CityBlueprintCompilerService` | 编译 v0.12 Blueprint；Foundation 建筑边距进入模板空间需求和规则阵列 pitch，最终 anchor 冻结完整、可压缩的 `buildingParcelPlan` 与稳定逐栋绿化选择，花坛不足不参与硬失败。父子规则阵列统一 pitch、禁内部 outward 改轴，required/fill 使用精确 guide 与门脸旋转，区内道路和 `arrayVisualQuality` 同时进入 plan/map/trace。首个核心只在显式 preferred Patch 起步，域内无合法位置时留空且不换起点；成功起步后的 required/fill 阵列可连续跨越相邻 Patch 标签，并由实际 claim 形成范围。terrain/surface 原因逐级提升到 selection、Group 与 acceptance。验收逐项核对 `requiredStructureRefs[]`，fill/connectivity 不得抵扣缺失 required。跨组连接仍在内部成形完成后独立生长。 |
| `CityBlueprintService` / `CityBlueprintCodec` / `CityBlueprintReferenceCatalog` / `CityBlueprintValidator` | 准备 v0.10 Context、v0.10 snapshot 与 v0.9 Reference Catalog，完整冻结结构目录、LandUse rule、FoundationProfile、SurfaceRecipe、LandscapeProfile、LandscapeFillProfile 和 D3 terrain field；只接受一次严格 v0.12 Blueprint。Group 必填 `buildingGreeneryPolicy`，只包含覆盖、构图和疏密枚举。Validator 另校验关系位置端点、父阵列引用、唯一归属与中心对称成员配对；旧 Blueprint/context/snapshot 不迁移。 |
| `CityLandscapeCapacityReservationPlanner` | D4 景观地形容量搜索器。每个 required 实例同时枚举 owner 边缘与远端好地、稳定方向和父子拓扑；只保留未采样/水体/陡坡/断崖地形门禁与结构/景观真实占用避让，Patch 仅作软偏好。方案优先保留非零实例和实际面积，再按 owner 距离、长宽比、树深、方向覆盖、分叉和包络择优；普通后续 Parcel 从父 Parcel 四邻接接力，功能景观含 `GROUND_PATH + CORRIDOR` 时改从父边界外第二格接力并冻结中间一格。目标数量/面积可按地形缩减，零格写 warning 而非让 D4 失败。产物为 `city_landscape_capacity_reservation_plan.v0.2`。 |

Patch Explorer 的共享实现位于 `systems.realm_planning.PatchExplorerService`，City 侧不复制一套 patch 排名器。`RealmPlanningHttpController` 在 `city_plan_d4_candidates`、`city_plan_d4_array_candidates`、`city_create_d4_array_layout_loop`、两段 array expansion、`city_plan_d4_structure_cluster_groups` 和 `city_create_d4_candidate_session` 进入现有 `CityPlanningEndpointHandler` 前解析 `patchSelectionRef`。

解析过程先拒绝外部手写的保留字段 `candidateLegalRegion`，再深拷贝请求，验证同 run / 同 city D3 scope、source identity、scope snapshot 与选择组件内容。City D4 的 source identity 由 D3 文件 hash 与规范化 committed occupied 几何构成，不 hash 可变候选会话全文；候选会话只读取顶层 `occupiedEnvelopes[]`，不会递归把未选择候选的 `estimatedCollisionEnvelope` 当作占用。随后把 `sourcePatchRefs[]` 注入既有 `candidatePatchRefs[]` 作为搜索依据，并把选择组件注入 `candidateLegalRegion`。`CityStructureCandidateEnvelope` 统一要求实际 collision 完全落在 member-cell union 内；anchor session 与 cluster 通过原 plan 深拷贝继承，array layout expansion 由 resolver 合法传播到 nested item。无 `patchSelectionRef` 且无保留字段的旧请求不发生字段或行为变化。

共享 MCP 定义仍位于 `country_designer_mcp/src/realm/tools.ts` 与 `handlers.ts`，工具名为 `patch_explorer_open`、`patch_explorer_show_candidates`、`patch_explorer_select_candidate`。

## 真实游玩注意

真实游玩需使用未生成目标区块并启用结构包。ReTerraForged 保持配置化、可选但强烈推荐；当前标准测试启用它：

```bash
.\gradlew.bat runClient -PgeomantiaDevUseStructurePacks=true -PgeomantiaDevUseReTerraForged=true
```

`gradle.properties` 当前保持 `geomantiaDevUseStructurePacks=true`、`geomantiaDevUseReTerraForged=true`；需要验证无 RTF 环境时可显式关闭后单独运行。外部道路 Mod、旧沙砾道路和其他道路 provider 均不属于正式或调试链路。

未生成 chunk 时 D6/D7 应返回 `WAITING_FOR_WORLDGEN`，由玩家从目标 chunk 外侧触发首次生成后重复查询 ledger，不算失败。已生成且无 ledger 时返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，正式路径不得 late paste。

## 模板建筑 active 路径补充

模板建筑 active 路径以 `CityTemplateCatalog` / `CityTemplateCatalogLoader` 读取模板目录，以 `MinecraftCityTemplateReader` 通过 `StructureTemplateManager` 读取 NBT 尺寸和内容 hash，再由 `CityTemplatePlacementGeometry` 按 anchor、rotation、mirror 派生 transformed footprint 与 transformed `roadEntrances[]`。D4 / D6 / D7 传递并校验同一 `templateRef`、`templateHash`、`variant`、`rotation`、`mirror`、`terrainPosePolicy`、`footprint`；D5 可把锁定结果写入 City 自己的 active template placement registry，再由 worldgen NBT placement 消费。transformed entrances 只供 City 自有路网选择真实接入点。

普通模板路径不查询 `Registries.STRUCTURE`，不使用 Jigsaw pool。`CityTemplateTerrainPosePolicy` 在目录模型和 D6 规划期把 `geomantia:` 身份强制冻结为 `structure_start_beard_thin`，并派生 `generator_base_height_motion_blocking_no_leaves` datum；非 `geomantia:` 模板仍按显式目录值选择 terrain start 或 direct template。`CityTemplateTerrainStartPolicy` 只从 D5 frozen plan 消费该值，`MinecraftCityWorldgenStructurePlacer` 再创建 City 注册的单-piece start。configured structure / `StructureStart` sampler 只服务非模板的结构画像与落地主线；bounded jigsaw solver 和旧 D7 materializer 已从实现仓库删除。active template endpoint 不得为模板建筑回填 configured structure bbox、入口或落地结果。
