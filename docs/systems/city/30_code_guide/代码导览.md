# City 系统代码导览

## 当前状态

City D3-D6 active path 已破坏性切换为结构落地驱动：

- D3 仍由 `CityLandformReviewBuilder` 产出地形 patch 真值；`handlePlanD3` 会按 city grid + `patchScanPaddingBlocks` 覆盖多个 GIS region，避免结构 / v4 城墙靠近 region 边界时缺 patch 背景，并从 GIS cell `biomeId` 聚合 patch 级 `biomeSummary`。
- `city_profile_structure_envelopes` 由 `CityStructureEnvelopeProfiler` 对顶层 configured structure 做 cache-backed dry-run bbox profiling；cache miss / stale 时现场构造 `StructureStart` / pieces 采样，不写世界。
- D4 推荐由 `city_run_workflow d4CandidateMode=key_then_array` 分阶段编排：关键结构 slot 先走 `CityStructureAnchorCandidatePlanner` 顺序 session，逐个选择并冻结 occupied；随后每个 `array_fill` slot 走 `CityStructureArrayCandidatePlanner` 阵列候选，读取上一阶段 `StructureAnchorMap` 避让已放结构，并合并回标准 `StructureAnchorPlan`。结构群整组候选保留为显式调试 / 整城构图实验路径。
- D4 由 `CityStructureAnchorPlanner` 校验 AI/Codex 提交的 `StructureAnchorPlan`。
- D5 由 `CityWallReservationPlanner` 生成 wall reservation，再由 `CityReservationMaskPlanner` 合入结构 mask 和墙带 mask；默认 v2 仍是 D3 patch 贴边墙带，显式 `wallVersion=v3` 使用结构种子 patch region hull；road/build 仍只保留占位，不提前决定道路路线。
- D6 由 `CityStructureMaterializationPlanner` 做 non-mutating probe-and-lock，锁定真实 bbox / group / signature，并做最终防撞。
- `city_execute_d5` 通过 `CityReservationMaskRegistry` 激活 D6 locked mask 和 planned structure registry，并通过 `CityRoadWeaverBridge` 可选注册 RoadWeaver 道路端点。
- `city_execute_d7` 保留入口名，但正式路径只查询 worldgen ledger / chunk 状态；ledger 完整后仅显式 `roadProvider=worldedit_debug` 才运行旧 WorldEdit debug road，RoadWeaver 已注册或 `auto` 缺 RoadWeaver 时均跳过并输出诊断。旧 `placeInChunk` 仅在 `debugLateMaterialize=true` 时用于诊断。
- `city_plan_city_walls` / `city_execute_city_walls` 在 D7 ledger 完整后扫描 actual road mask，按 RoadWeaver 道路裁门，并沿 D5 wall reservation 放置石墙 / 塔楼 / foundation；显式 v3 会分类内部/外部道路、聚类城门并输出地形/mask/gap debug report；`wallDesignPolicy=v3.2` 在 v3 外环上增加天然边界、道路趋势开门、独立 gatehouse 和可用塔节点；v1 矩形墙仅保留为 `wallVersion=v1_debug`。

旧 `CityFunctionZoneBuilder`、`CityRoadBoundaryPlanner`、`BuildableAreaMapBuilder`、`CityStructureD6Planner`、`CityStructureD7Executor` 和 bounded jigsaw solver 仍在实现仓库中作为历史 / 后续参考代码，但不再是 active endpoint 默认路径。

## 类职责

| 类 | 职责 |
| --- | --- |
| `CityStructureProfileCatalog` | 导入 TerraSense `StructureProfile.jsonl` / debug catalog；拒绝 compat catalog、`functionTags`、`function_candidates` 等旧字段；保留 TerraSense terms 原样。 |
| `CityStructureEnvelopeProfiler` / `CityStructureEnvelopeFacts` | D2 / D4 前置结构大小区间画像；默认读取本地 profile cache，cache miss / stale 时调用 sampler 重算；输出/读取 validSamples、bboxGroups、generationConfigHash、profileCache、cacheKey / cacheStatus；输出稳定性分类、dominantBBoxGroup、stableMaxEnvelope、bboxVarianceSummary、profileConfidence 和 placementRecommendation；固定 / 近固定结构供 D4 选择 bbox group，非固定结构供 D4 使用 P95/P99/maxObserved。 |
| `CityD4DesignLoopStatePlanner` | D4 多轮城市设计 loop 的 state / artifact 基础设施；create/read/append/write-back 只读写 `city_d4_design_loop_<citySeedId>` JSON 产物，保存 `cityId`、`planningMode`、`roundIndex`、已放结构 / anchors、occupied field、function zones、array zones、patch availability、next AI summary 和 trace；occupied field 只从 `collisionEnvelope` / `bodyEnvelope` 派生，不触发 D5/D6/dressing/roads/worldgen。 |
| `MinecraftCityStructureEnvelopeSampler` | 基于 configured structure registry 生成 `StructureStart` dry sample，提取 bbox / piece count，不写世界；同时提供 runtime registry / generation context cache identity。 |
| `CityStructureAnchorCandidatePlanner` | D4 候选前置服务；读取 `DesignSlotPlan`，按 D3 patch 代表点、TerraSense profile、envelope facts 和已选/暂选 occupied envelope 生成少量 anchor 候选；选择后转换为标准 `StructureAnchorPlan`。 |
| `CityStructureClusterGroupCandidatePlanner` | D4 结构群整组候选服务；复用顺序候选 session 的 `planNext/selectSession/finalizeSession` 规则做 beam search，输出多组完整 slot 落脚方案和 `expandedStructureAnchorPlan`；组内使用 selection 同口径的 safety/collision occupied 防撞；不再是 workflow 默认推荐路径。 |
| `CityStructureArrayCandidatePlanner` | D4 阵列候选前置服务；读取 `ArrayCandidatePlan`，按 `loose_cluster` / `patch_axis_band` / `scattered` 从 D3 patch 生成批量结构候选组，组内用估算 collision envelope 防撞，并输出可直接交给标准 D4 的 `expandedStructureAnchorPlan`；支持 `round_robin`、`seeded_random`、`weighted_random` 变体分配。 |
| `CityStructureCandidateEnvelope` | D4 候选层共用 envelope helper；统一单点候选和阵列候选的 fixed bbox / P95-P99 / fallback jigsaw envelope 估算。 |
| `CityStructureAnchorPlanner` | D4 主服务；校验 anchor 在 D3 grid / patch 内、结构来自 TerraSense catalog、footprint 可用；固定 / 近固定结构使用 `fixed_bbox_group + smallClearanceBlocks`，非固定结构使用 `fixed_depth_statistics`；输出 `structure_anchor_map.json`。 |
| `CityWallReservationPlanner` | D5 城墙预留服务；v2 读取 D3 patch、D4 source patches 抽取 patch union 外缘；v3 从结构 sourcePatch / planned footprint 出发扩张 city domain、填凹陷并生成 `outerWallRing` / `wallCorridorMask`。 |
| `CityReservationMaskPlanner` | D5 主服务；从 D4 anchor map 的 `maskEnvelope` 与 D5 `wallCorridorMask` 生成 reservation mask 预案；`road_access_plan` / `build_operation_plan` 只保留占位，标记 `roadPlanningStage=d7_after_worldgen_ledger`。 |
| `CityReservationMaskRegistry` | server-root active mask / planned structure registry；为 mixin hook 提供 vegetation / vanilla structure 抑制、planned anchor 查询和 worldgen ledger 记录；active registry 使用 D6 locked footprint / collision envelope / signature。 |
| `CityRoadWeaverBridge` | RoadWeaver optional adapter；通过 `ModList` + 反射调用 `RoadNetworkApi`，生成 endpoint / connection plan；`auto` 缺 mod 时返回 `ROADWEAVER_UNAVAILABLE` skip state，只有显式 `worldedit_debug` 进入旧 debug fallback state。 |
| `CityRoadMaskScanner` | CityWalls v2 实际道路扫描器；在 wall corridor 附近按 RoadWeaver 常见道路方块白名单生成 `actual_road_mask.json`，供墙线裁门和执行保护使用。 |
| `ConfiguredFeatureMaskMixin` | 注入 `ConfiguredFeature.place`，在 mask 内抑制树、草、花、藤蔓、灌木、竹子、蘑菇等植被 feature。 |
| `ChunkGeneratorStructureMaskMixin` | 注入 `ChunkGenerator.tryGenerateStructure` 抑制自然结构抢占，并在 `ChunkGenerator.createStructures` 尾部触发 planned structure 注入。 |
| `MinecraftCityWorldgenStructurePlacer` | 在 worldgen structure 阶段生成 configured `StructureStart`，校验 D6 locked signature / collision envelope / ledger overlap 后写入 `ChunkAccess.setStartForStructure(...)` 并记录 ledger。 |
| `MinecraftCityWorldgenStatusInspector` | 判断 planned anchor chunk 是未生成、已过 features，还是可等待 worldgen。 |
| `CityStructureMaterializationPlanner` | D6/D7 计划与 ledger 查询编排；D6 non-mutating preflight 生成并锁定 actual bbox / actual bbox group key / piece boxes / expected signature / locked collision envelope；D7 正式路径只查 ledger 并可在 ledger 完整后触发真实 footprint 道路后处理。 |
| `MinecraftCityStructureMaterializationBackend` | 旧诊断 backend；只在 `debugLateMaterialize=true` 时允许使用 `StructureStart.placeInChunk`。 |
| `CityStructureLandingPreviewRenderer` | 新主链预览：D4 anchor envelope、D4 候选 / 结构群整组候选 / 阵列候选、D5 mask、D6 planned worldgen structures、D7 ledger；`structure_cluster_group_candidates.png` 中颜色代表整组候选，主图不绘制 bbox。 |
| `CityWallPlanner` | 默认读取 `wall_reservation_plan.json`、D7 placed ledger 和 `actual_road_mask.json`，生成 `city_wall_plan.v0.2`；显式 v3 会合并 road component、忽略 inside road、聚类 external gate；`wallDesignPolicy=v3.2` 额外做 road trend 过滤、gate spacing 合并、天然水体 / 峭壁 boundary 和 gatehouse segment；`wallDesignPolicy=v3.3` 继续对近墙外部道路做 projection gate；`wallVersion=v4` 以 D7 `actualFootprint` 为硬约束生成墙图，并用 D5 `cityDomainMask` cell 外缘做 `terrain_adaptive_domain_guided_land_ring` 小幅贴形，输出 `terrainContourEvents[]`；`wallVersion=v5` 保留 D5 `wallLine` 不改线，声明分段统一墙顶高度 / 阶梯段过渡 / 高差天然屏障断墙阈值，并从邻近墙段推断节点 `wallAxis`；`v1_debug` 保留旧矩形墙。 |
| `CityWallTemplateLibrary` | 按临时石墙方案导出 vanilla structure-template NBT 与 template library JSON；当前包含 `wall_straight_15`、`wall_tower_small`、`wall_gap_gate_7`、`watchtower_5x5`、`beacon_5x5`、`gatehouse_9`、`gatehouse_13` 和天然边界空模板。 |
| `CityWallPlacementBackend` | 不依赖 WorldEdit，使用 vanilla `setBlock` 后端按 `MOTION_BLOCKING_NO_LEAVES` 高度放置墙段；v1/v2 硬保护 road mask / structure footprint / gate gap，低洼处补 foundation，陡坡段报告 `WALL_TERRAIN_TOO_STEEP`；v3 按 unit 放置并可输出 step=1 terrain、mask、gap debug report；v3.2 会跳过 `natural_boundary` 连续墙并放置独立 `gatehouse`；v5 使用原始 1-block surface sample 生成 `v5HeightSegmentation`，段内统一墙顶，8..16 高差标记阶梯过渡，>=17 高差写 `NATURAL_CLIFF_BOUNDARY_NO_WALL`，并填实坑底台基、按 bounds 自适应门楼 `栅栏-空气-栅栏` 石砖顶开口、按 `wallAxis` 贯通烽火台墙顶通道。 |
| `CityWallPreviewRenderer` | 渲染 wall reservation 与城墙 plan 预览，显示 D3 patch、wall corridor、actual road mask、source footprint、wall segment、tower、gate gap / gatehouse / natural boundary；v4 会单独用 olive 图层标出 terrain contour 调整和 `terrain_contour_link`。 |

## 旧主链硬失败

`CityPlanningEndpointHandler.rejectLegacyArtifacts(...)` 与 `RealmPlanningHttpController.rejectLegacyCityFields(...)` 会阻断旧字段 / artifact：

- `patchGroupPlan`
- `functionType`
- `functionTag`
- `function_candidates`
- `terrasenseProfileSource` 进入 D6
- `structureChoicePlan`
- `fixedPlacementSelectionPlan`
- `function_zone_map.json`
- `buildable_area_map.json`
- `planned_fixed_placement_map.json`
- `structure_pool_map.json`
- `start_candidate_set.json`

错误前缀必须是 `LEGACY_CITY_FUNCTION_ZONE_FLOW_REMOVED`。

## 真实游玩注意

真实游玩需使用 vanilla-like 新存档，标准启动为不加载 RTF、启用结构包、启用 RoadWeaver：

```bash
.\gradlew.bat runClient -PgeomantiaDevUseStructurePacks=true -PgeomantiaDevUseRoadWeaver=true
```

`gradle.properties` 应保持 `geomantiaDevUseStructurePacks=true`、`geomantiaDevUseRoadWeaver=true`，且不再配置 RTF / ReTerraForged 启动参数。旧 WorldEdit debug 道路只允许在诊断时显式传 `roadProvider=worldedit_debug`，不得作为 `auto` 的缺省 fallback。

未生成 chunk 时 D6/D7 应返回 `WAITING_FOR_WORLDGEN`，由玩家从目标 chunk 外侧触发首次生成后重复查询 ledger，不算失败。已生成且无 ledger 时返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，正式路径不得 late paste。
