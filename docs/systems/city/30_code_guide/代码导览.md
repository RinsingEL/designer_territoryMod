# City 系统代码导览

## 当前状态

City D3-D7 active path 已破坏性切换为固定 NBT 唯一主线：

- D3 仍由 `CityLandformReviewBuilder` 产出地形 patch 真值；`LandUseTerrainFieldCompiler` 同步编译高度、坡度、水体、群系等 LandUse 粗格事实。`CityPlanningEndpointHandler.handleReviewD3Site` 为 T4 AI 候选首都写入绑定 D3 / CitySeed identity 的选址决策，所有 D4 入口通过 `loadCitySeedForD4` 统一阻断未审查、要求重选或 stale 决策。
- 新 D4 AI 边界由 `CityBlueprintService` 编排：prepare 冻结 v0.6 Context、v0.7 snapshot、完整 LandUse rule/foundation/surface recipe/landscape profile 与 D3 terrain field，submit 通过严格 codec/reference/validator 接受一次 CityBlueprint v0.7。`groups[]` 仍由 `CityBlueprintCompilerService` 编译为结构，根级 `outdoorPlan` 保持冻结到 D6；结构连接继续复用 near frontier 完整批次、稳定选择与原子提交，全程不再调用 AI。
- D2 由 `CityTemplateCatalog` 与 `MinecraftCityTemplateReader` 读取显式 `city_template_catalog.v0.1` 和当前世界 NBT，确认 hash、rawSize、入口、允许变换，并把所有 City catalog 模板冻结为 `structure_start_beard_thin`。
- 离线素材接入由 `tools/city_templates/jigsaw_template_sanitizer.py` 先审计跨 Mod NBT；只有 manifest 人工确认的独栋模板才按各自 `final_state` 清除 connector。它不执行 pool，入口候选不直接进入 catalog。Trek 专用导入器复用同一替换原语，但继续保留 `trek:mobs/` marker 白名单、processor 烘焙和实体清理等来源规则。
- `city_run_workflow` 默认 `d4CandidateMode=blueprint`；缺 Context/Blueprint 时返回 `awaiting_city_blueprint`，有效蓝图自动编译并继续 D5/D6。`key_then_array`、array loop、cluster groups、sequential session 仅作显式 legacy/debug。
- D4 由 `CityStructureAnchorPlanner` 校验 fixed-template `StructureAnchorPlan`，并按 transformed exact footprint 派生 collision 和 mask。
- D5 由 `CityWallReservationPlanner` 生成 wall reservation，再由 `CityReservationMaskPlanner` 合入结构 mask 和墙带 mask；默认 v2 仍是 D3 patch 贴边墙带，显式 `wallVersion=v3` 使用结构种子 patch region hull；road/build 仍只保留占位，不提前决定道路路线。
- D6 由 `CityStructureMaterializationPlanner` 通过当前世界 NBT inspector 做 non-mutating identity-and-geometry lock，重新校验 hash、rawSize、变换、exact footprint、collision、mask 和 owner chunks；不创建 `StructureStart`，不输出 piece/signature/bbox group。
- 正式 workflow 在 D6 后由 `CityOutdoorBlueprintCompiler` 读取同一 Blueprint、locked footprint、D3 terrain field 和冻结 reference catalog：`CityFoundationPlanner` 先把全部结构 footprint 编译成一块连续且有最小颈宽的 Foundation domain，再按 D6 `blueprintPlacementPhase` 为景观生成独立 Parcel。`LandUsePlanningService` 按 Foundation 底层、Landscape 覆盖层执行；正式路径不读取入口、组内连接树、跨组关系线、D5 corridor 或 urban residual，也不启用 LandUse 自动连接。RoadWeaver 是唯一道路权威；SurfacePrint、crop、boundary 和 owner worldgen 仍是纯执行层。
- `city_plan_city_dressing` 由 `CityDecorationProgramPlanner` 校验 v0.3 判别联合；`CityDecorationContentCatalog` / loader 从 server config 读取内容姿态和无实体 prefab，冻结 `catalogHash`；v0.2 只读兼容。v0.1 业务 planner 与内置测试模板库已从源码删除。
- `city_plan_decoration_anchor_candidates` 在最终 dressing 规划前，由 `CityDecorationAnchorCandidatePlanner` 对 required 单点 prefab 生成完整 footprint + clearance 安全候选；同 plan 已固定单点 Decoration 作为障碍。候选入口只读规划 artifact，不采样真实地形、不加载 chunk、不自动选择。
- `city_probe_decoration_terrain` 由 `CityDecorationTerrainProbe` 读取 compiled plan + slot projection；`CityPlanningEndpointHandler.LoadedChunkDecorationTerrainView` 只从当前已加载 FULL chunk 的 `MOTION_BLOCKING_NO_LEAVES` heightmap 采样，未加载 slot 只报告 unavailable。该入口不生成 chunk、不写世界、artifact、active registry 或 ledger。
- `city_execute_d5` 通过 `CityReservationMaskRegistry` 激活 D6 locked mask 和 planned structure registry，通过 `CityLandUseWorldgenRegistry` 校验并激活 area + SurfacePrintPlan v0.3，并通过 `CityRoadWeaverBridge` 可选注册道路端点；v0.3 decoration compiled plan 与 completion 成对存在时先冻结完整 terrain run / foundation。worldgen owner 内先裁切并直接刷入 Foundation / Landscape 的全局 FIELD / CHANNEL role spans，再执行 FIELD-only CROP、recipe-owned BOUNDARY、稀疏 Decoration和 RoadWeaver 后写。
- `city_execute_d7` 保留入口名，但只查询固定模板 worldgen ledger / chunk 状态并复核完整 identity 和三层几何；ledger 完整后仅显式 `roadProvider=worldedit_debug` 才运行旧 WorldEdit debug road。`debugLateMaterialize` 与建筑 late paste 已删除。
- `city_plan_city_walls` / `city_execute_city_walls` 在 D7 ledger 完整后扫描 actual road mask，按 RoadWeaver 道路裁门，并沿 D5 wall reservation 放置石墙 / 塔楼 / foundation；显式 v3 会分类内部/外部道路、聚类城门并输出地形/mask/gap debug report；`wallDesignPolicy=v3.2` 在 v3 外环上增加天然边界、道路趋势开门、独立 gatehouse 和可用塔节点；v1 矩形墙仅保留为 `wallVersion=v1_debug`。

旧 `CityFunctionZoneBuilder`、`CityRoadBoundaryPlanner`、`BuildableAreaMapBuilder`、`CityStructureD6Planner`、`CityStructureD7Executor`、bounded jigsaw solver 及其专用模型 / preview / Minecraft backend 已从实现仓库删除。历史产品案仍保留原始设计记录，但不得再作为可调用能力或后续开发基座；需要类似能力时必须基于当前结构落地主链重新设计。

## 类职责

| 类 | 职责 |
| --- | --- |
| `CityStructureProfileCatalog` | 导入 TerraSense `StructureProfile.jsonl` / debug catalog；拒绝 compat catalog、`functionTags`、`function_candidates`、`terrainTerms` 等退役字段。`city_semantic_profile_catalog.v0.4` 输出 identity/source/review/catalog mode、三组可配置词表 `functionTerms/planningRoleTerms/styleTerms` 与 City 固定枚举数组 `terrainModes`；正式目录仅 `reviewState=approved` 准入，debug 缺状态归一为 `unreviewed`，不暴露 configured identity 或 profile 几何。`styleTerms` 仅为 AI-facing 字段。 |
| `CityStructureCatalogQueryService` | 只读检索已导入的 TerraSense 画像，响应为 `city_structure_catalog_query.v0.5`。`allOfTerms` / `anyOfTerms` / `excludeTerms` 只在功能、规划角色、风格三组 canonical terms 上过滤；`terrainModes` 直接展示但不进入动态词表解析。若 source 显式给出 `vocabularySnapshotPath`，才加载冻结词表的 `term_id`、中文 `label` 与 `aliases[]` 做解析，未知或歧义 term 明确失败，不回退旧 C3.5 或 City 自建标签。 |
| `CityStructureTerrainMode` | City 固定 placement topology 枚举：`SURFACE/EMBEDDED/FLOATING`。画像可声明多值，按 OR 解释；未知或归一后重复值在导入期拒绝。 |
| `CityStructureTerrainGate` | 用冻结 `city_land_use_terrain_field.v0.1` 对 transformed collision footprint 覆盖的全部格执行 topology gate，输出 `city_structure_terrain_gate_trace.v0.2`；不扫描世界、不加载 chunk。当前只实现 `SURFACE`：全部格必须存在、已采样且非水；仅声明 `EMBEDDED/FLOATING` 时明确返回不支持。 |
| `CityTemplateCatalog` / `MinecraftCityTemplateReader` | 严格加载 `city_template_catalog.v0.1`，从当前 `StructureTemplateManager` 读取 NBT 并校验 hash、rawSize、道路入口和允许变换；不查询 configured structure registry。 |
| `CityD4DesignLoopStatePlanner` | D4 多轮城市设计 loop 的 state / artifact 基础设施；create/read/append/write-back 只读写 `city_d4_design_loop_<citySeedId>` JSON 产物，保存 `cityId`、`planningMode`、`roundIndex`、已放结构 / anchors、occupied field、function zones、array zones、patch availability、next AI summary 和 trace；occupied field 只从 `collisionEnvelope` / `bodyEnvelope` 派生，不触发 D5/D6/dressing/roads/worldgen。 |
| `CityD4StagedPlanCompiler` | D4 `key_then_array` 的纯 application 编译器；校验 key slot 必须先于 array slot，生成 key-stage / array candidate / 空 layout 计划并合并标准 `StructureAnchorPlan`。不读写文件、不依赖 HTTP 或 Minecraft。 |
| `CityStructureAnchorCandidatePlanner` | D4 候选前置服务；读取 `DesignSlotPlan`、显式 template catalog、D3 patch 与 TerraSense 语义标签，按 fixed-template collision occupied 生成候选；选择后转换为标准 `StructureAnchorPlan`。 |
| `CityStructureClusterGroupCandidatePlanner` | D4 结构群整组候选服务；复用顺序候选 session 的 `planNext/selectSession/finalizeSession` 规则做 beam search，输出多组完整 slot 落脚方案和 `expandedStructureAnchorPlan`；组内使用 selection 同口径的 collision/body occupied 防撞，结构大小只读取固定 NBT template catalog；不再是 workflow 默认推荐路径。 |
| `CityStructureArrayCandidatePlanner` | D4 阵列候选前置服务；读取 `ArrayCandidatePlan`，默认按 `loose_cluster` / `patch_axis_band` / `scattered` 从 D3 patch member cells 生成批量结构候选组；程序化 Blueprint 编译器可注入内部 `candidateOrigins[]` 精确槽位，member-cell 只做合法 mask，不再把这些 guides 吸附回 cell center。显式支持 `compound_cluster`、`grid`、`courtyard`、`l_shape`、`u_shape`、`organic_compact` 与 `rows/columns/spacingBlocks`；未显式给 spacing 时按 D2 推荐 collision 包络计算，组内只用 collision 防撞，mask overlap 不撑开 anchors。 |
| `CityBlueprintGroupLayoutPlanner` | 正式 Blueprint compiler 的 Group 级持续阵列语法；把 `densityClass` 编译为算法专属 gap/jitter/claim/handoff 参数，为连续 slot 生成二维 COMPACT、GRID、LINEAR、COURTYARD、ORGANIC_COMPACT guides。连接阶段从当前结构前沿向指定 Group 推进并保留算法特有横向节奏，不生成直线桥；它不做模板/collision 合法性判断。 |
| `CityBlueprintService` / `CityBlueprintCodec` / `CityBlueprintReferenceCatalog` / `CityBlueprintValidator` | 准备 v0.6 Context 与 v0.7 snapshot，完整冻结结构目录、LandUse rule、FoundationProfile、SurfaceRecipe、LandscapeProfile 和 D3 terrain field；只接受一次严格 v0.7 Blueprint。`groups[]/relations[]` 与根级 `outdoorPlan` 同属一次 AI 决策，旧 Blueprint/context/snapshot 不迁移。 |
| `CityFoundationPlanner` | 以 D6 locked structure footprint 为无条件结构域，在 D3 可用地形上执行可配置 margin 与递增 closing；要求结果恰好一个连通分量，并以侵蚀复核最小颈宽。无法在 `maxJoinDistanceBlocks` 内形成宽连接时明确失败，不退回细桥或多个岛。 |
| `CityOutdoorBlueprintCompiler` / `CityOutdoorIntentPlan` | D6 后的纯程序投影器。`foundationProfileRef` 编译唯一 Foundation seed group；景观 profile 的 `ParcelStyle` 按 required 核心建筑与 fill 建筑分别确定次数、单块面积、间距和从既有 Parcel 分支概率，每个 Parcel 单独成组且禁止同类自动合并。输出可哈希 `city_outdoor_intent_plan.v0.3`，不读取文件、不调用 AI。 |
| `LandUsePlanningService` | 识别正式分层 seed groups，先生成 Foundation claims，再让 Landscape claims 覆盖；正式路径固定无 corridor、无自动连接、无 residual resolver。legacy/debug 的 STANDARD groups 仍保留旧扩张入口，但不得混入分层正式计划。 |
| `CityUrbanResidualResolver` / `CityUrbanSpacePlan` | 仅保留 legacy/debug LandUse 的残余空间能力；正式 Blueprint v0.7 由单一 Foundation domain 给出覆盖证明，不再调用本 resolver。 |
| `CityStructureArrayLayoutLoopPlanner` | D4 v0.2/v0.3 显式阵列 loop 的几何与原子 state 能力；`compound_cluster` 支持 `grid/courtyard/l_shape/u_shape/organic_compact` 与 `rows/columns/spacingBlocks`。v0.5 outward 读取已 Plan focus 的 D2 body / collision bbox，以 `expansionPolicy` 按 near / middle / far 连续前沿生成候选，再后置按 D3 patch 筛选 / 评分；前沿参考使用整组 D2 body 并集，`actualBodyGapBlocks` 取整组最小方向 body gap，连续 `guide_line_dual_side` 先锁内侧首排、再向外展开另一侧。16 格锚点优先落在合法 gap 区间内，构建后用真实 `plannedFootprint` 复算并校正漂移。候选集可返回一组或多组完整候选；`minCandidateCount` 已删除并明确拒绝。生成候选不写 state，程序 select 才原子提交。 |
| `CityTemplateOrientationSolver` | 纯几何门面朝向排序器；在模板 `allowedRotations[]` 内计算变换后入口方向与 array center、最近 D3 WATER cell 或 cardinal 目标的对齐分数。阵列 planner 仍负责逐旋转执行 grid / collision 检查；显式 rotation 不进入自动排序。 |
| `CityD4CandidateLegalRegion` / `CityStructureCandidateEnvelope` | 前者解析 resolver 内部注入的 Patch Explorer member-cell union，并判断完整 collision 是否被包含；后者是 D4 候选层共用 envelope helper，在既有 D2 collision 几何估算后统一执行该硬约束。anchor、array、layout 与模板路径不得复制 bbox 特判。无 `candidateLegalRegion` 时保持原估算和点序。 |
| `CityDecorationProgramPlanner` | v0.3 规划 facade；继承 v0.2 Shape / Pattern 判别联合与世界坐标投影，并严格读写新增连续落差 / foundation terrain policy。v0.2 只读兼容，新规划输出 v0.3。 |
| `CityDecorationAnchorCandidatePlanner` | `infrastructure/dressing` 下的 required 单点装饰候选器；只接受局部 `(0,0)` rectangle + active `grid_repeat`，每个 anchor 复用 runtime 确定性 palette 选择，并以 prefab rotation 0 计算 footprint。按 resolved target mask、comfort/conflict clearance 和硬障碍生成稳定的 1-8 个候选；已固定单点 Decoration 进入 `fixedDecorationObstacles`，空候选保留 rejectionCounts。 |
| `CityDecorationTerrainProbe` / `DecorationSlot` | activation 前纯读取探针；只消费 compiled plan 和 slot projection，按 program / palette 汇总已加载高度、邻接高差和 coverage。`cross_section_repeat` / `parallel_rows` 的每个 palette slot 都生成 `continuousBandProfiles[]`，槽位内容语义由调用方解释。`LoadedChunkDecorationTerrainView` 只查询已加载 FULL chunk 的高度图，缺块记 unavailable；不触发 chunk 生成，不写世界、artifact、active registry 或 ledger。 |
| `CityDecorationContentCatalog` / `CityDecorationContentCatalogLoader` | 严格加载 `city_decoration_content_index.v0.3`，冻结 `groundPlaneLocalY/embedDepthBlocks/clearanceMode` 与 pose hash；支持 above / replace / embed 三种姿态。v0.2 以 0/0/preserve 只读兼容且保留旧 hash 算法，不改文件；query 显式报告 upgrade required。 |
| `CityDecorationStyleProfileCatalogLoader` / `CityDecorationStyleProfileResolver` | 从 `config/geomantia/city_decoration/styles/<styleProfileId>.json` 读取 `semanticRef -> variants[{contentRef,weight}]`，验证文件名、schema、语义键和 concrete content。resolver 将 AI palette 的语义键与权重解析成 concrete prefab 与合成权重，写 `city_decoration_style_resolution.v0.1`；profile hash 漂移或未映射语义键 hard fail。 |
| `CityDecorationTerrainRunCompiler` / `CityDecorationFrozenTerrainPlanCodec` | activation 前对 cross-section / parallel rows 的完整 projection 编译全局 run，冻结 water / cliff / cumulative drop、END_CAP / TERMINATE / DEFER、targetY 和 foundation segments；runId / ordinal 不按 chunk 重启。codec 拒绝未知字段、重复 run / slot、child runId 错配，以及顶层 segments 与各 run 派生段不一致。 |
| `MinecraftCityDecorationTerrainSampler` | 仅在 `city_execute_d5` activation 使用 `ChunkGenerator.getBaseHeight/getBaseColumn`；不请求或加载 chunk。连续 run 需要 sampler 而 ServerLevel 缺失时 hard fail。 |
| `CityDecorationChunkCompiler` | v0.3 chunk-local 编译器；消费 active frozen slot outcome，校验确定性 content，END_CAP 使用冻结 fallback，TERMINATE / DEFER 保留原因。fill-only 仅接受已达到 frozen target ±1 的运行地表，未成形以 `CITY_DECORATION_FOUNDATION_NOT_MATERIALIZED` skipped，不强抬 datum、不 deferred。只对非连续旧路径保留单槽下坡 fallback；不写世界。 |
| `CityStructureAnchorPlanner` | D4 主服务；校验 anchor 在 D3 grid / patch 内且模板命中显式 catalog，冻结 template identity、exact body、collision、mask 与 transformed road entrances。TerraSense 只参与语义标签，不提供 geometry 或 configured identity。 |
| `CityWorkflowCandidateSelector` | `city_run_workflow` 的纯候选选择策略；按 `scoreBreakdown.total` 选择 anchor、structure cluster group 和 array 候选，保持原 reasonCode，不读取文件或 HTTP 请求。 |
| `CityWorkflowStepRunner` | `city_run_workflow` 的通用步骤执行器；负责 existing artifact 跳过、步骤耗时与摘要、暂停 / 失败 reasonCode、报告写入回调和最终 workflow 状态，不依赖 `platform.http`。 |

## HTTP / MCP 入口

Patch Explorer 的共享实现位于 `systems.realm_planning.PatchExplorerService`，City 侧不复制一套 patch 排名器。`RealmPlanningHttpController` 在 `city_plan_d4_candidates`、`city_plan_d4_array_candidates`、`city_create_d4_array_layout_loop`、两段 array expansion、`city_plan_d4_structure_cluster_groups` 和 `city_create_d4_candidate_session` 进入现有 `CityPlanningEndpointHandler` 前解析 `patchSelectionRef`。

解析过程先拒绝外部手写的保留字段 `candidateLegalRegion`，再深拷贝请求，验证同 run / 同 city D3 scope、source identity、scope snapshot 与选择组件内容。City D4 的 source identity 由 D3 文件 hash 与规范化 committed occupied 几何构成，不 hash 可变候选会话全文；候选会话只读取顶层 `occupiedEnvelopes[]`，不会递归把未选择候选的 `estimatedCollisionEnvelope` 当作占用。随后把 `sourcePatchRefs[]` 注入既有 `candidatePatchRefs[]` 作为搜索依据，并把选择组件注入 `candidateLegalRegion`。`CityStructureCandidateEnvelope` 统一要求实际 collision 完全落在 member-cell union 内；anchor session 与 cluster 通过原 plan 深拷贝继承，array layout expansion 由 resolver 合法传播到 nested item。无 `patchSelectionRef` 且无保留字段的旧请求不发生字段或行为变化。

共享 MCP 定义仍位于 `country_designer_mcp/src/realm/tools.ts` 与 `handlers.ts`，工具名为 `patch_explorer_open`、`patch_explorer_show_candidates`、`patch_explorer_select_candidate`。

## 真实游玩注意

```bash

```

`gradle.properties` 应保持 `geomantiaDevUseStructurePacks=true`、`geomantiaDevUseRoadWeaver=true`，且不再配置 RTF / ReTerraForged 启动参数。旧 WorldEdit debug 道路只允许在诊断时显式传 `roadProvider=worldedit_debug`，不得作为 `auto` 的缺省 fallback。

## 模板建筑 active 路径补充

模板建筑 active 路径以 `CityTemplateCatalog` / `CityTemplateCatalogLoader` 读取模板目录，以 `MinecraftCityTemplateReader` 通过 `StructureTemplateManager` 读取 NBT 尺寸和内容 hash，再由 `CityTemplatePlacementGeometry` 按 anchor、rotation、mirror 派生 transformed footprint 与 transformed `roadEntrances[]`。D4 / D6 / D7 传递并校验同一 `templateRef`、`templateHash`、`variant`、`rotation`、`mirror`、`terrainPosePolicy`、`footprint`；D5 可把锁定结果写入 City 自己的 active template placement registry，再由 worldgen NBT placement 消费，并由 `CityRoadWeaverBridge` 通过 mod API 注册 transformed entrances。

普通模板路径不查询 `Registries.STRUCTURE`，不使用 Jigsaw pool。`CityTemplateTerrainPosePolicy` 在目录模型和 D6 规划期把 `geomantia:` 身份强制冻结为 `structure_start_beard_thin`，并派生 `generator_base_height_motion_blocking_no_leaves` datum；非 `geomantia:` 模板仍按显式目录值选择 terrain start 或 direct template。`CityTemplateTerrainStartPolicy` 只从 D5 frozen plan 消费该值，`MinecraftCityWorldgenStructurePlacer` 再创建 City 注册的单-piece start。configured structure / `StructureStart` sampler 只服务非模板的结构画像与落地主线；bounded jigsaw solver 和旧 D7 materializer 已从实现仓库删除。active template endpoint 不得为模板建筑回填 configured structure bbox、入口或落地结果。
