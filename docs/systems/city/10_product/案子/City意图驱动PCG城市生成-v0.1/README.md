## AI 需求总结

*城市设计只围绕三个结果*：城市生成的核心是**美观和工整**，判断必须来自城市设计效果，并集中在三个结果：**功能明确、界限分明、有主有次**。现有约束只有直接服务这三个结果时才应保留；不得继续用大量局部硬限制、重复条件和层层兜底代替最终城市效果，也不得因为内部规划条件没有全部满足，就否定一座实际已经清楚、美观、可用的城市。

*AI只决定城市意图*：AI只负责决定城市的**意图**，包括这座城市有哪些功能、各部分是什么关系、哪里是主要部分、哪里是次要部分，以及希望形成怎样的整体城市形态。AI不负责逐栋建筑选址，不在 Agent Loop 中反复调整建筑数量、精确位置和各种落地参数，也不通过一次次试错替程序求解施工细节。禁止重新走向效果差、耗时长的“AI全程设计”。

*建筑由PCG全程生成*：AI给出意图后，剩余城市建筑由 **PCG生成器全程完成**。具体放多少栋、选择哪些可用建筑、落在哪里、如何朝向、怎样组成街区以及如何适应现场，都由生成器根据城市意图自动决定。这是一套半自动城市生成系统，不要求 AI 先提交一张每个细节都正确的施工图，再由程序逐条审核。

*普通地形不能让城市失效*：真实城市不会因为普通坑洼和起伏就无法建设，城市生成也不能如此脆弱。遇到坑洼时，PCG可以根据实际效果选择用**台基跨过或消化地形**；不适合建设时，也可以让当前建筑**不落地**，继续完成其余城市。普通地形问题是生成器需要消化的现场条件，不应直接升级为整个建筑群或整座城市失败。

*Agent Loop退出建筑求解过程*：Agent Loop不再承担逐栋摸索和反复试参数的职责。生成器应自行完成建筑落位、地形处理和必要取舍；AI只在城市意图需要改变时参与。一次生成未放下某栋建筑时，应由PCG选择台基或不落地，而不是堆叠新的限制和兜底，再要求 Agent 从头猜测失败原因。

*最新需求覆盖旧的失败规则*：本案是对当前 D4 架构的**严重缺陷修订**。既有案子中凡是把普通坑洼、局部起伏或单栋建筑无法落地直接升级为整城失败的内容，均由本案最新需求覆盖；凡是要求 AI 承担具体建筑编排和持续落地求解的内容，也不再作为当前产品目标。台基和不落地是 PCG 的正常生成选择，不是为维持旧硬约束而继续增加的 fallback。
