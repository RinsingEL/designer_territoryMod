# 案子 02：D4 程序化城市编译器

## 实现状态（2026-08-02）

v0.6 已接通正式主链。`city_compile_d4_blueprint` 继续只读取案子 01 已接受的 CityBlueprint v0.4、同一 catalog snapshot 和 D3 member-cell 真值；程序以 Group 级持续阵列状态完成方位播种、关系图连接生长、算法化疏密、空间预算、评分、occupied 提交和标准 anchor 冻结。连接阶段把 Blueprint 语义桥接到既有连续外扩阵列引擎，由程序自动选完整批次。`city_run_workflow` 默认值已从旧 `key_then_array` 改为 `blueprint`：缺 Context/Blueprint 时返回 `awaiting_city_blueprint + nextAction`，存在有效 Blueprint 时自动编译并继续 D5/D6。

旧 `key_then_array`、`array_layout_loop_v0_2/v0_3`、`structure_cluster_groups`、`sequential_session` 仅在显式传入 `d4CandidateMode` 时可用，统一属于 legacy/debug。v0.4 仍不支持 `LANDSCAPE`，不实现道路、城墙、Foundation、地表细节或装饰退役。

## 目的

把 D4 中已经具备的模板校验、候选生成、阵列扩张、碰撞检查、occupied 冻结和锚点输出能力，收束成一个完全程序化的城市编译器。

编译器消费案子 01 的 `CityBlueprint`，自动完成结构 Group 的实际落点选择。正式主链不再等待 AI 或人工选择候选。

## 输入与输出边界

输入：

- 已校验的 `city_blueprint.json`。
- D3 地形与 patch 真值。
- TerraSense 结构画像与 tag 真值。
- structure envelope facts。
- 模板池、算法和组成策略目录。
- 已有结构 ledger 或 occupied 上下文。

输出：

- `city_generation_compile_trace.json`
- `group_extent_map.json`
- 标准 `structure_anchor_plan.json`
- 标准 `structure_anchor_map.json`
- 结构锚点与 Group 范围预览。

标准锚点产物继续交给现有 D5/D6，不为新编译器建立下游特殊分支。

## 编译过程

### 1. 蓝图装载

- 重新校验 D3 hash、目录 hash 和 schemaVersion。
- 解析结构 Group、关系、硬约束和软目标。
- 为所有 Group 建立稳定的执行顺序。

### 2. 核心种子落地

- 按优先级先处理所有 `requiredStructureRefs`。
- 从 `preferredPatchRefs[]` 的精确 member-cell 并集生成候选。
- 按 `preferredPatchZone=CENTER|NORTH|EAST|SOUTH|WEST` 在成员格并集的内部 50%/25%/75% 目标附近选首核种子；北=-Z、南=+Z、西=-X、东=+X。非规则 patch 仍只选择真实成员格。
- required 首核与核心阵列不读取其他 Group 位置；跨 Group 朝向只允许从专用 connectivity growth 开始。
- 每个 Group 都先在自己的偏好 patch 播种；首栋不因与既有 Group 超过固定距离而拒绝。
- 过滤越界、碰撞、核心 Group 范围和地形策略不允许的候选。
- 所有核心结构成功后进入专用连接阶段，连接完成后才允许自由扩张。

### 3. Group 连接生长

- 优先读取 `CONNECTION / ADJACENCY / HIERARCHY` 关系构建连接图；若显式关系不足以覆盖全部 Group，按初始结构前沿距离与稳定 seed 确定性补齐最短组件边。
- 对每条连接边，双方交替从“离对端最近的本组最后提交阵列”继续外扩；程序自动计算 focus、八方向朝向与疏密换算的实体 gap，调用既有 `CityStructureArrayLayoutLoopPlanner.planExpansionCandidates` 生成近圈多组完整阵列候选，再确定性选择并原子提交整个批次。
- `connectionPlan` 的结构池、算法和疏密均可独立覆写；缺省逐项继承 Group fill 配置。非 LINEAR 算法桥接为 `compound_cluster`，LINEAR 桥接为 `guide_line_dual_side`；连接结构是本轮放置角色，不是新的结构永久分类。
- required 核心只认 `preferredPatchRefs[]`；连接槽位可使用 D3 `review.grid` 内符合该 Group terrain policy 的 member cells。`review.grid`、collision、地形与组内连续最大 gap 始终是硬约束。
- Group 间没有统一最大距离。距离只增加连接结构、迭代和空间需求；双方前沿达到各自 handoff gap 的严格最小值后，结构连接阶段完成，实体 block-span 连通继续等待 LandUse。
- `extentClass` 的目标面积与最大跨度是核心/fill 的软规模口径；连接阶段可以超出，但必须输出连接结构数、连接空间需求、扩张距离和是否因连接越过范围档位。
- 若在 D3 规划网格内不存在合法连续槽位，明确返回 `CITY_BLUEPRINT_CONNECTIVITY_NO_LEGAL_PATH`，不得伪造 LandUse 成功或静默删除 Group。

### 4. 程序化扩张

- 每个 Group 建立一次持续布局 frame；每栋结构必须消费该 frame 的下一个阵列槽位，禁止把 Group 拆成互不相关的单元素阵列后按最近格放置。
- 从 Group 已冻结边界连续生长候选，组内候选不得超过当前阵列算法按疏密档位派生的最大 gap。
- 只使用 `algorithmProfileRef` 指向的算法配置。
- 从 `fillPoolRef` 指向的模板池选择结构。
- 使用 `compositionProfileRef` 控制模板组成顺序，不设置产品层建筑数量上限。
- `extentClass` 冻结核心/fill 空间预算和最大跨度；`densityClass` 由当前阵列算法编译为目标 edge gap、最大 gap、错位幅度、空间 claim 和 LandUse handoff gap。建筑数由模板 collision footprint、阵列占用和空间预算自然产生。
- 专用连接阶段结束后恢复自由阵列生长，不切换算法，也不为追求目标面积撤销已完成的连接。
- 每次提交后原子更新实际使用 patch、Group extent 与 occupied field。

### 5. 自动评分与选择

候选评分至少考虑：

```text
符合 Group 关系
+ 符合扩张算法
+ 保持 Group 紧凑
+ 合理使用可认领空间
+ 地形兼容程度
- 碰撞风险
- 越界代价
- 过度地形改造代价
```

评分相同或接近时，使用稳定排序键与 `generationSeed` 做可复现选择。禁止依赖系统时间、集合遍历顺序或未记录随机源。

### 6. 锚点冻结

- 冻结结构 anchor、旋转、collision envelope 和入口端点。
- 冻结 Group 实际范围、空间需求、建筑数和接入既有城市的连接边。
- 输出现有 D5/D6 能直接消费的标准锚点产物。

## 硬约束与软目标

硬约束：

- `requiredStructureRefs` 必须全部落地。
- 所有 STRUCTURE Group 必须形成一张连通城市图；自动连接不是可选 relation。
- 多个 Group 可以共享同一 patch，但 collision envelope 不得重叠。
- collision envelope 不得与已冻结结构重叠。
- 程序不得自行删除 Group 或替换城市主题。

软目标：

- `extentClass` 对应的核心/fill 空间预算；为完成全城连接时允许有 trace 的扩张。
- `densityClass` 经阵列算法解释后的间距、错位、claim 与 LandUse handoff 参数。
- 在多个合法方向之间的偏好。

软目标可以因真实容量缩小，但必须记录实际空间需求、建筑数和停止原因。

## 失败规则

- 蓝图或目录失效：立即停止，返回蓝图校验错误。
- 必要结构无合法落点：编译失败，不进入自由扩张。
- 连通合法空间不足：允许以 `CONNECTED_SPACE_EXHAUSTED` 软停，不允许省略必要结构。
- 所有候选都被过滤：记录每类过滤原因和最终停止原因。
- 不得在失败后重新请求 AI 逐候选处理。
- 不得通过放宽 collision、伪造 member-cell/claimed patch 事实或跳过 D6 来制造成功。

## 现有 D4 能力处理

保留并内部化：

- 关键结构先于阵列的顺序约束。
- candidate generation。
- array layout algorithms。
- collision / occupied 校验。
- anchor freeze 与标准 finalize。
- 候选与最终锚点预览。

降级为显式调试入口：

- 顺序候选 session。
- AI/Codex 候选选择。
- 结构群整组比较。
- 手工 `candidateId` 提交。

## 不做事项

- 不实现 `LANDSCAPE` Group。
- 不生成道路、城墙或道路附属物。
- 不实现 Foundation Program。
- 不实现最终地表细节填充。
- 不改变 D5/D6/D7 的 artifact 与 worldgen 准入边界。
- 不负责删除旧装饰系统。

## 验收口径

- 输入合法蓝图后，无需 AI 或人工即可生成最终结构锚点产物。
- 所有必要结构先于自由扩张落地。
- 每次选择都有候选、过滤、评分和提交 trace。
- 同一输入和随机种子产生相同结果。
- 同一范围下，小 footprint 模板自然产生更多建筑；同一模板下 `DENSE` 自然多于 `SPARSE`。
- 所有 Group 在 `group_extent_map` 中形成单一连通图；每条连接边的最终 gap 不超过双方算法 handoff gap 的严格最小值。
- 输出可直接进入现有 D5/D6。
- 容量不足、碰撞和地形失败均有明确 reason code，不出现静默降级。

## v0.6 冻结实现口径

- Group 先按 `HIERARCHY` 的 `fromGroupId -> toGroupId` 做稳定拓扑排序；同一批可执行 Group 再按 `CORE -> STANDARD -> PERIPHERAL -> groupId` 排序。层级环在候选生成前以 `CITY_BLUEPRINT_HIERARCHY_CYCLE` hard fail；所有 Group 的 `requiredStructureRefs` 全部成功后才开始 fill。
- required/fill 每个结构继续复用既有 `CityStructureArrayCandidatePlanner` 的 template geometry、member-cell legal region、collision 与 occupied 过滤；连接阶段改为复用旧连续外扩阵列候选器并整批原子提交，任一成员不合法时整批拒绝。
- `COMPACT / GRID / LINEAR / COURTYARD / ORGANIC_COMPACT` 分别映射到既有 `loose_cluster / grid / patch_axis_band / courtyard / organic_compact` 候选算法，不建立第二套几何实现。
- `extentClass` 的目标空间预算为 `SMALL=4096 / MEDIUM=16384 / LARGE=36864 blocks²`，核心/fill 最大 collision union 跨度为 `96 / 160 / 240 blocks`。这些值约束功能区规模，不约束建筑数；连接阶段可越过目标与跨度，但必须记录扩张事实。
- 疏密基础参数按 `DENSE / BALANCED / SPARSE` 分别为：目标 edge gap `4 / 8 / 16`、最大 edge gap `12 / 20 / 32`、LandUse handoff gap `16 / 24 / 40 blocks`。算法再叠加自身修正：`GRID +2/+4` 且无错位，`LINEAR +1/+2`，`COURTYARD +4/+4` 并保留院心，`ORGANIC_COMPACT +2/+3` 并增加确定性错位，`COMPACT` 使用基础值。
- 每栋结构的空间 claim 为 `(collisionWidth + targetGap) * (collisionDepth + targetGap) * algorithmMultiplier`；`GRID/LINEAR/COURTYARD/ORGANIC_COMPACT/COMPACT` multiplier 分别为 `1.08/1.04/1.20/1.06/1.00`。统一覆盖率只作为实际结果 `estimatedCoverageRatio`，不再控制建筑数。
- fill pool 按冻结 `ROUND_ROBIN` 组成策略选择；候选按基础分、关系适配分、自动连通分和稳定 seed tie key 排序。内部 `256 anchors/group` 只作为异常安全护栏，命中时 hard fail，不是产品规模含义。
- v0.2 按候选实际来源 D3 patch 的 `meanSlope` 执行 terrain policy hard gate：`CONFORM<=6`、`BALANCED<=12`、`ASSERTIVE<=18`；合法范围内的坡度继续进入既有 terrainFit 评分。
- HARD 关系在已有对端范围时参与候选过滤，所有必要结构落地后再次复验；v0.2 阈值为 ADJACENCY/CONNECTION `<=256`、BUFFER `>=64`、DISTANCE NEAR `<=256`、FAR `>=128`，DIRECTION 按中心相对方位判断。
- `city_generation_compile_trace.v0.6` 的 required/fill 选择和标准 anchor 继续冻结 `blueprintLayout`；连接 selection 另冻结 `arrayId/plannerType/focusArrayId/direction/resolvedConnectionPlan/semanticParameters/frontierSearchTrace/committedAnchorIds`，根级连接边增加批次数。
- `group_extent_map.v0.6` 冻结原有连接与 LandUse 分层语义；每个 Group 回写继承解析后的 `resolvedConnectionPlan` 和连接结构/批次数，调用方必须明确读取结构拓扑或 LandUse 状态。
- Blueprint 自动连接只请求 near frontier；near 不可用即把该侧本轮判为无合法候选，再尝试连接边另一侧，不自动扩到中远圈。候选按目标 gap、engine score 和 candidateId 稳定排序，AI 不再参与选择。
- 连接边施工完成后的 HARD 关系复验必须继续使用双方解析后的 `resolvedConnectionPlan.derivedLayoutParameters.landUseHandoffGapBlocks` 严格最小值；不得退回 Group 内部 required/fill 的 `layoutParameters`。同一条边不得先输出 `HANDOFF_READY`，再因另一套阈值误报 `CITY_BLUEPRINT_HARD_RELATION_UNSATISFIED`。
- 所有 Group 先在偏好 patch 播种，再按关系图进入专用 connectivity growth；显式关系不足时输出 `FALLBACK / DETERMINISTIC_SHORTEST_COMPONENT_EDGE`。D4 不再输出或读取 `maxInterGroupGapBlocks`，初始距离不参与可行性拒绝；最终实体连通仍必须由 LandUse block spans 验收。
- D3 patch 的 `memberCells[]` 可能包含扫描 padding；编译器只允许 `review.grid` 正式规划范围内的成员格参与前沿种子与 legal region，不能把 padding 当作可建设空间。
- 编译器把选定的精确前沿格作为内部 `candidateOrigin` 传给复用的阵列候选器，使候选排序从连续生长前沿开始，而不是重新退回 patch center。该字段由程序生成，不进入 CityBlueprint，也不允许 AI 提交坐标。
- connectivity 的阵列推进原点必须是离目标最近的本组既有结构中心；D3 前沿 cell 只负责生成 legal region。不得把 cell center 当作既有结构中心后再前进一个完整 spacing，否则首槽会被双重外推并违反组内最大 gap。
- 编译入口重算 context identity，复核 accepted validation/submission trace、Blueprint hash、D3/catalog ArtifactRef 和 schema；任何 stale 输入在候选生成前停止。
