# 案子 01：D4 单次城市决策

## 目的

删除 D4 正式主链中的逐 slot、逐候选和逐轮 AI 决策。

D3 完成地形审查后，D4 开头只调用一次 AI。AI 读取完整设计上下文，一次性输出 `CityBlueprint`，随后退出城市生成主链。

本案只定义 AI 决策边界和蓝图契约，不实现后续程序化城市编译。

## 输入

AI 只读取程序准备好的结构化上下文：

- D3 地形图、patch、member cells、指标、邻接关系和审查预览。
- 城市种子、城市身份、国度风格和规模约束。
- 可引用的结构目录与模板池配置。
- 可引用的阵列算法、地形策略和风格配置目录。
- 每份输入 artifact 与配置目录的版本和 hash。

AI 不自行扫描世界，不查询隐藏目录，也不在输出后继续请求候选。

## AI 负责的决策

- 城市主题、身份和主要功能组成。
- 城市包含哪些 Group。
- 每个 Group 偏好的一个或多个 patch；这些是核心种子的精确候选域，不是排他所有权，也不是连接生长的永久边界。
- Group 之间的主次、邻接、连接、缓冲、远近和方向关系。
- Group 的空间范围档位、疏密档位与地形态度；AI 不决定建筑数量。
- 从白名单中选择模板池、算法和风格配置。
- 可选指定连接结构池、连接算法、连接疏密，以及 cluster shape 或双侧带状阵列的 side/stagger/width 语义；不填时继承 Group 的 fill 设置。
- 城市级道路风格、景观风格和地表细节倾向。

AI 不负责：

- 单栋结构的 block 坐标和旋转。
- 每轮 focus、扩张方向、block 间距、候选圈层和候选选择。
- 候选过滤、评分和平局选择。
- 碰撞修复和 patch 原子认领。
- D5/D6/D7 执行与 worldgen 状态处理。

## CityBlueprint 公共外壳

首版公共字段：

| 字段 | 含义 |
|---|---|
| `schemaVersion` | 蓝图契约版本。 |
| `cityId` | 目标城市 ID，必须与 D3 审查包一致。 |
| `sourceD3Ref` | D3 artifact 路径、版本与内容 hash。 |
| `catalogSnapshotRef` | 本次读取的配置目录版本与 hash。 |
| `generationSeed` | 后续程序使用的可复现随机种子。 |
| `designIntent` | 城市身份、主题和功能定位。 |
| `styleProfile` | 结构、地表、景观和道路的统一风格。 |
| `groups[]` | 城市 Group 清单。 |
| `relations[]` | Group 之间的显式关系。 |
| `roadProfile` | 道路等级和风格，不包含具体路径。 |
| `surfaceDetailProfile` | 地表细节倾向，不产生独立装饰计划。 |

Group 公共字段：

| 字段 | 含义 |
|---|---|
| `groupId` | 蓝图内唯一 ID。 |
| `groupKind` | 首版实现 `STRUCTURE`；`LANDSCAPE` 扩展由案子 04 定义。 |
| `preferredPatchRefs[]` | 一个或多个偏好 patch；不同 Group 可以共享。 |
| `preferredPatchZone` | `CENTER / NORTH / EAST / SOUTH / WEST`；指定核心在偏好 patch 精确成员格并集中的内部起步方位，不提交坐标。 |
| `role` | Group 在城市中的功能。 |
| `priority` | 核心、普通或外围优先级。 |
| `extentClass` | `SMALL / MEDIUM / LARGE` 核心空间范围档位，不表示建筑数量；为完成全城连接，程序可以超出该软目标并记录扩张事实。 |
| `densityClass` | `SPARSE / BALANCED / DENSE` 疏密档位。 |
| `algorithmProfileRef` | 程序白名单中的算法配置。 |
| `terrainPolicy` | `CONFORM`、`BALANCED` 或 `ASSERTIVE`。 |

结构 Group 补充字段：

- `requiredStructureRefs[]`：必须落地的核心结构引用。
- `fillPoolRef`：自由扩张模板池配置。
- `connectionPlan`：可选连接阵列意图；连接结构池可以与 fill pool 重复，不填则整体继承，不能携带坐标、数量或裸 block gap。
- `compositionProfileRef`：结构组成顺序配置；不得携带数量上限。
- `attachedFeatures[]`：只登记归属；不在本案实现景观。

## 校验规则

- `sourceD3Ref` 必须与当前 D3 真值一致，hash 失配立即拒绝。
- 所有配置引用必须存在于 `catalogSnapshotRef` 指向的目录快照中。
- `preferredPatchRefs[]` 至少一个且全部命中 D3；多个 Group 可以共享同一 patch。
- Group ID 必须唯一，关系端点必须存在。
- 必要结构引用不存在时 hard fail。
- AI 不得输出 block 坐标、自由算法名或目录外模板 ID。
- 不支持的 `schemaVersion` 或 `groupKind` 必须显式失败，不能静默忽略。

## 旧 D4 AI 循环处理

正式主链删除：

- AI 逐 slot 选择关键结构。
- AI 比较并选择 `candidateId`。
- AI 逐轮决定阵列方向。
- AI 在碰撞后手工修订坐标。
- 结构群候选图作为 AI 必经输入。

旧候选 session、候选预览和手写 anchor plan 可以保留为显式开发调试入口，但必须与默认 workflow 分离。

## 输出

- `city_blueprint.json`
- `city_blueprint_validation_report.json`
- 蓝图来源、AI 调用次数、输入目录 hash 和失败原因 trace。

## 不做事项

- 不实现候选生成或自动评分。
- 不生成 `StructureAnchorPlan`。
- 不实现景观区域生长。
- 不删除装饰系统。
- 不改 D5/D6/D7。

## 验收口径

- D3 仍只输出地形真值。
- 正式主链只发生一次 AI 城市设计调用。
- AI 一次提交完整蓝图后不再参与后续执行。
- 蓝图能被独立校验，并能拒绝过期 D3、过期目录和非法引用。
- 同一输入上下文能够稳定产生可追溯的蓝图 artifact。
- 未实现案子 04 前，`LANDSCAPE` Group 必须明确报告暂不支持，不能伪装成装饰内容。

## 实现状态（2026-08-02）

案子 01 已升级为 `CityBlueprint v0.4`：版本化 Context / Blueprint / reference catalog、程序化 prepare、单次 submit 预算、强校验、artifact、HTTP/MCP 和 golden tests 均已实现。Group 以空间范围、内部起步方位与疏密表达，不再以固定建筑数表达规模；新增可选 `connectionPlan`，把连接结构、阵列与疏密语义前置到同一次 Blueprint 决策中。v0.1-v0.3 明确不兼容。冻结字段与 reason code 见 `20_contracts/数据契约/CityBlueprint数据契约.md`。

`densityClass` 是算法语义，不是全局建筑覆盖率或数量公式。案子 02 必须把它编译成当前 `algorithmProfileRef` 专属的间距、错位、支路/环形节奏和 LandUse 交接参数；任何结构 anchor 都必须来自同一 Group 持续存在的阵列状态，outward 只能引导阵列槽位方向，不能绕过阵列逐栋选择最近格。

同一城市的全部 STRUCTURE Group 必须形成连接图。AI 决定 Group、偏好 patch、patch 内部起步方位、显式关系、范围档位、疏密档位和阵列算法；程序只负责在 D3 `review.grid` 内实现坐标、碰撞与连接。Group 的 required 核心先按 `preferredPatchZone` 在各自 `preferredPatchRefs[]` 精确成员格并集内播种，首核不得朝其他 Group 偏移；随后程序按显式关系图连接。关系不足时只允许用确定性补边连通已有 Group，不得删除 Group、替换偏好 patch 或凭空改写城市功能。Group 间初始距离只影响连接阶段需要消费的阵列槽位和空间，不构成固定距离拒绝条件。

01 -> 02 已接通，v0.4 Blueprint 可程序化编译为标准锚点并继续 D5/D6；程序从最近一次已提交阵列自动派生 focus 和朝向，复用旧连续外扩候选器，只搜索近圈并确定性选择完整阵列批次。旧 candidate/session/manual anchor 路由只作为 legacy/debug 兼容链保留。D3 v2 正式地形验收仍受案子 00 阻塞，当前 D3 v0.1/v0.2 只用于开发联调，partial D3 明确拒绝。
