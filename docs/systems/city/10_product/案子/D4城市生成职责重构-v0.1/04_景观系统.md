# 案子 04：景观系统

## 目的

建立独立的景观生成能力，处理农田、树林、花田、大型葡萄园、独立公园和绿化隔离带等连续或半连续面域。

景观系统不继承旧装饰系统。它拥有明确的区域所有权、扩张规则、地形适配、内部填充和边缘过渡，是与结构 Group 并列的正式生成类型。

## 景观与其他对象的边界

属于景观：

- 大片树林。
- 田野、农田和作物区。
- 花田。
- 大型葡萄园。
- 独立城市公园。
- 独立占地的绿化隔离带。

不属于景观：

- 喷泉与固定长椅构图：归复合结构。
- 庄园庭院中的固定葡萄棚：归庄园结构。
- 行道树和路灯：归道路附属。
- 动态基台和挡土墙：归 Foundation Program。
- 零散野花和石头：归所属生成器最终填充 pass。

## 两种归属形态

### 独立景观 Group

独立占据起始 patch，能够向未分配的相邻 patch 扩张。

例如：

- 伐木场旁独立占地的管理林。
- 山坡上的大型葡萄园。
- 城市外围的连续农田。

### Attached Landscape

依附结构 Group，不单独占用平级起始 patch，只能在所属 Group 的内部或外缘生成。

例如：

- 住宅区外围绿化带。
- 行政区内部公园。
- 工业区与住宅区之间的植被缓冲。

## CityBlueprint 扩展

案子 04 扩展案子 01 的 Group union，增加 `groupKind=LANDSCAPE`。

景观 Group 字段：

| 字段 | 含义 |
|---|---|
| `groupId` | 蓝图内唯一 ID。 |
| `primaryPatchRef` | 独立景观的起始 patch。 |
| `role` | 景观在城市中的功能。 |
| `landscapeType` | 树林、田野、花田、葡萄园、公园等类型。 |
| `scale` | 期望规模。 |
| `algorithmProfileRef` | 区域生长、带状、噪声或轮廓算法配置。 |
| `terrainPolicy` | `CONFORM`、`BALANCED` 或 `ASSERTIVE`。 |
| `density` | 内部内容密度。 |
| `continuity` | 连续程度。 |
| `edgeStyle` | 边缘过渡方式。 |
| `surfacePaletteRef` | 地表混合配置。 |
| `contentPaletteRef` | 树木、作物和花草内容池。 |
| `relations[]` | 与结构或其他景观 Group 的关系。 |

AI 只引用程序提供的景观算法与 palette 配置，不输出逐格边界或单个物件坐标。

## 程序生成过程

### 1. 景观种子

- 校验起始 patch 与其他平级 Group 不冲突。
- 从 D3 member cells 建立初始区域。
- 检查地形策略、已有结构和硬禁区。

### 2. 区域扩张

- 从开放边缘生成候选景观单元。
- 使用区域生长、噪声、轮廓、带状或其他白名单算法。
- 进入新 patch 前执行原子认领。
- 已分配给其他平级 Group 的 patch 是硬禁区。
- 达到目标规模、最大规模或无合法候选时停止。

### 3. 边界与内部结构

景观区域应支持：

- 多种基础地表混合。
- 有规律的农田或作物阵列。
- 不规则植被斑块。
- 空地与内部通行空间。
- 稀疏边缘和自然过渡。
- 避让结构 collision、道路 corridor 和其他硬 mask。

### 4. 实体化

- 先冻结景观范围和 mask，再生成内部内容。
- 结构与道路拥有更高避让优先级。
- 最终地表细节只作为景观生成器内部 pass，不产生独立装饰计划。
- 所有随机选择使用蓝图 `generationSeed` 派生的稳定子种子。

## 输出

- `landscape_group_plan.json`
- `landscape_extent_map.json`
- `landscape_generation_trace.json`
- `landscape_mask.json`
- 景观范围、内部层次和边缘过渡预览。

输出必须记录：

- 计划规模与 `actualScale`。
- 认领的 patch 和 member cells。
- 每轮扩张候选与停止原因。
- 实际使用的 algorithm、surface palette 和 content palette 版本。
- 因结构、道路、地形或所有权被过滤的区域。

## 失败与降级

- 起始 patch 非法或已被占用：hard fail。
- palette 或算法引用不存在：hard fail。
- 必要景观 Group 无法建立初始区域：hard fail。
- 自由扩张容量不足：允许缩小 `actualScale`，必须记录原因。
- 程序不得把景观 Group 改成零散装饰点。
- 程序不得为了填满面积进入其他 Group 已认领区域。

## 不做事项

- 不处理固定空间构图。
- 不生成结构 anchor。
- 不实现道路或道路附属物。
- 不实现 Foundation Program。
- 不建立独立 Micro Decoration 系统。
- 不负责删除旧装饰代码；删除工作属于案子 03。
- 不改变 D5/D6/D7 的 worldgen 准入规则。

## 验收口径

- 景观拥有可查询的区域所有权，而不是一组无归属散点。
- 农田、树林、花田等能够形成连续或半连续的不规则面域。
- 景观边界能够适应真实地形，并避让结构和道路硬约束。
- 独立景观 Group 与 attached landscape 的所有权边界明确。
- 同一蓝图、目录版本和随机种子产生相同结果。
- 景观失败不会回退成旧装饰系统，也不会静默侵占其他 Group。
