# 案子 03：通用装饰系统退役

## 目的

整体删除通用装饰系统这一独立的中尺度生成层，不是只移除其中的 AI 调用，也不是把它改写成纯程序版本。

旧装饰层同时承担固定构图、连续景观、道路附属和细碎填充，职责边界无法稳定定义和验收。本案只负责退役旧系统并迁移职责归属，不开发替代系统。

## 删除口径

active path 中不再存在：

- 独立的 Decoration / Micro Decoration 系统。
- 让 AI 决定装饰物相对关系或逐个坐标的流程。
- 用散装装饰物拼中尺度空间构图的能力。
- 把整块区域刷成单一材料的通用 LandUse 装饰逻辑。
- 无上下文随机生成道路设施的逻辑。
- `DecorationProgramIntent` 作为正式规划产物或下游必需输入。
- `city_plan_city_dressing` 或同类 dressing endpoint 作为默认 workflow 阶段。

旧入口和 artifact 如需短期兼容，只允许显式报告已退役，不得继续驱动 active path。建议统一返回明确的退役 reason code，例如 `LEGACY_CITY_DECORATION_FLOW_REMOVED`。

## 职责迁移

| 旧装饰内容 | 新归属 |
|---|---|
| 喷泉与环绕长椅 | 喷泉广场结构或复合结构。 |
| 庄园与固定庭院葡萄棚 | 庄园复合结构。 |
| 固定排列的市场摊位 | 市场结构。 |
| 大片农田、树林、花田、葡萄园 | 案子 04 的景观 Group。 |
| 结构 Group 外缘绿化带 | 景观 attached feature。 |
| 行道树、路灯、栅栏 | 后续道路附属生成器。 |
| 城门、跨路拱门 | 结构模板，由道路锚点定位。 |
| 动态基台、挡土墙、台阶、坡道 | 后续 Foundation Program。 |
| 野花、杂草、小石头、落叶 | 所属生成器内部的最终地表细节填充 pass。 |

## 分类规则

- 需要稳定相对位置、方向和构图的内容归结构。
- 需要成片出现、连续占地并随地形改变边界的内容归景观。
- 依赖道路走廊、路口或端点的内容归道路附属。
- 只处理建筑与真实高差连接的内容归地基工程。
- 增减个体不会改变空间构图的极小内容，才允许进入所属生成器的最终填充 pass。

系统中不再保留“介于结构和景观之间的通用装饰”对象类型，也不允许后续仅通过改名重新建立同类中间层。

## 删除清单

进入实现前必须从当前代码与文档生成准确清单，至少覆盖：

- active workflow 中的 dressing 步骤。
- MCP / HTTP 入口。
- 请求与响应 DTO。
- `DecorationProgramIntent` 及关联 artifact。
- planner、executor、renderer 和配置。
- 单元测试、集成测试和预览基线。
- City 方案、契约、代码导览、测试入口与影响面。

不得只删除入口而留下仍被默认 workflow 或下游读取的死契约。

## 迁移策略

- 本案允许旧装饰效果暂时缺席。
- 未完成替代能力时，不以“兼容”为名保留模糊装饰层。
- 固定构图必须先转成结构素材或明确登记缺失。
- 景观需求登记到案子 04，不在本案临时实现。
- 道路附属、Foundation 和最终填充只进入后续清单。
- 删除前确认 D5/D6/D7 没有把 dressing artifact 当作硬依赖。

## 不做事项

- 不实现景观系统。
- 不制作新的结构模板。
- 不实现道路附属物。
- 不实现 Foundation Program。
- 不实现新的通用填充系统。
- 不修改 D4 蓝图与编译器核心算法。

## 验收口径

- 默认 workflow 不再调用任何 dressing / decoration 规划入口。
- active path 不再产出或消费通用装饰 artifact。
- 旧输入进入 active endpoint 时明确失败或报告退役，不静默兼容。
- 所有旧职责都有明确的新归属或明确记录为暂时缺失。
- 删除后 D4 结构主链与 D5/D6/D7 仍可运行。
- 文档、代码导览、测试入口和影响面与实际删除结果一致。
