# City 城市边界与城墙

## 状态

当前实现保留 `v1_debug`、`v2`、`v3`、`v4`、`v5` 五种显式算法分支。它们是同一能力的演进选项，不再维护五份并行产品案。

## 生命周期

```text
D3/D4 城市与结构事实
-> city_plan_d5 生成 wall reservation
-> D6 locked actual footprint
-> city_plan_city_walls 生成 city_wall_plan
-> city_execute_city_walls 放置墙体与塔楼
```

城墙计划必须避让结构 footprint、道路 gate/corridor 和其他硬 mask。计划与执行分离；`city_execute_city_walls` 只有收到 `confirmWorldMutation=true` 才修改世界。

## 版本语义

| `wallVersion` | 当前用途 |
| --- | --- |
| `v1_debug` | 矩形调试基线，只用于定位坐标、执行器和素材问题。 |
| `v2` | `CityWallReservationPlanner` 默认值；使用 D3 patch 边界 reservation，并按真实 RoadWeaver gate 切口。 |
| `v3` | 从结构播种 patch hull，叠加地形、天然边界、gatehouse 与路径规则。 |
| `v4` | 把 D6 actual footprint 作为硬约束，以 city domain 为引导生成墙体图、wall units 和 terrain contour。 |
| `v5` | D5 冻结最终水平墙线；D7 后只做垂直地形适配。必须存在匹配的 v5 reservation。 |

调用方必须显式选择非默认版本。v5 不允许拿其他版本 reservation 临时推导墙线，否则返回 `WALL_V5_REQUIRES_D5_V5_RESERVATION`。

## 共同约束

- 所有坐标、版本、来源 plan hash 和 gate 必须进入 artifact identity。
- 结构 footprint、RoadWeaver 入口与道路切口优先于连续封闭外观。
- 水体、陡坡和天然边界只能按所选版本规则参与，不能静默换成矩形保底。
- 规划失败应返回可解释的 gap、mask 或路径原因，不得补一条穿过建筑的直线墙。
- `debugScan` 只增加地形/mask/gap 报告，不改变正式几何结果。

## 验收重点

分别覆盖版本派发、默认 v2、v5 reservation 一致性、道路裁门、结构避让、天然边界、塔楼/墙段连续性、垂直适配和确定性。现场验收还需检查 gate 是否对准真实道路、墙体是否悬空或埋地，以及跨 chunk 执行是否重复或断裂。
