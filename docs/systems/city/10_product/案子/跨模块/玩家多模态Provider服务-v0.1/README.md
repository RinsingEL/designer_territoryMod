## AI 需求总结

### 职责与拆分方向

2026-09-24 用户提出将地图和 Harness 拆出主 Mod，同时保留 workflow；原话与共同边界见[总调度当前案](../../../../../realm_planning/10_product/案子/AI场景策划与程序执行分工-v0.1/README.md)。本案继续保存现有可选 Provider 的配置与连接需求；下文“内置”描述现有使用入口，不再要求其随主 Mod 打包。模型配置、凭证和执行循环现已迁入可选 Harness 附属 Mod，主流程仍由主 Mod 持有。

### 示意图

```text
游戏内 Provider 设置
  ↓
普通玩家：DeepSeek → 填写 API Key → 测试连接
开发者：自定义 Provider → 填写兼容参数 → 测试连接
  ↓
Mod 自动选择推荐的多模态模型
  ↓

  ↓
成功则继续规划；失败则停在当前位置并提示
```

### 发布版使用方式

**内置 Provider 是可选使用入口，不是外部 Agent 连接 MCP 的前提。** 选择内置方式的普通玩家，**不得要求玩家具备开发经验、手动启动 Node 服务或理解内部调用链**。玩家只需要在游戏内选择支持的模型厂家、填写自己的 API Key 并启用 Provider，Mod 便自动承担后续连接、图像提交、结果接收和规划衔接。

### 游戏内 Provider GUI

Provider 必须提供游戏内 GUI。首发默认入口只要求普通玩家填写 DeepSeek API Key、测试连接并启用或停用自动规划，同时能看到当前连接状态、最近一次失败原因和重试入口；API Key 输入与已保存内容必须以密码形式隐藏。开发者可以进入完整自定义配置，自行指定兼容服务、模型和连接参数，但这些内容不得增加普通玩家默认流程的复杂度。

### 厂家与模型选择

首发内置的普通用户 Provider 预设只要求支持 **DeepSeek**，Mod 自动选用其适合当前规划流程的多模态模型，普通玩家不必查找或输入模型 ID，也不要求首发同时内置其他厂家的专用预设。开发者和高级用户必须能够改用完整的自定义配置，包括自定义 OpenAI-compatible 服务、Base URL、模型 ID、API Key、超时及必要兼容选项；自定义配置与内置 DeepSeek 预设使用同一套能力检查和规划结果门禁。

### 发布运行边界

Provider 调用由发布版 Mod 或配套的 TerraSense 自动承载，玩家安装后即可从游戏内使用。现有本地 Node Provider 网关可以继续用于开发、联调和排错，但**不得成为普通玩家必须单独安装、配置或手动启动的发布步骤**；本案也不要求玩家在本地部署大模型。

### 单机与独立服务器

单人游戏由本机玩家配置并使用 Provider。独立服务器由服务器管理员配置 Provider，普通玩家可以查看规划状态，但不能读取、替换或覆盖服务器使用的 API Key。

### 密钥边界

API Key 只用于调用玩家或服务器管理员选择的模型服务，**不得写入世界存档、规划产物或普通日志，不得同步给无权查看的客户端**。界面、状态信息和错误提示均不得回显完整 Key。

### 自动规划职责

内置方式使用 DeepSeek Harness 承接玩家配置的模型服务，承担公共规划流程中需要 AI 的设计阶段。Mod 的世界资料、进度与执行规则由公共能力提供；外部 Agent 不必配置这份内置 Provider，也不要求内置方式展示外部连接大厅。

### 失败行为

连接测试或能力检查必须明确告诉玩家当前模型是否能满足多模态与规划结果要求。Provider 不可用或调用失败时，当前规划任务停在失败位置并提醒玩家或 Agent，并允许处理后重试；不得静默跳过必要规划阶段，也不得卡住玩家正在游玩的服务器。
