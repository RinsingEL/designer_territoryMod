# 05 D5 / D6 提交阶段衔接

## 修改目的

D4 完成城市结构设计后，再进入提交阶段。D5、D6、dressing、道路和真实 worldgen 不参与 D4 每轮设计，只在 AI 决定完成结构设计后运行。

## 方案

### 1. D5 轻量程序保护层

D5 保留，但定位从设计决策降级为程序自动生成的轻量保护层。D5 不参与 AI 每轮构图，也不负责拉开建筑间距；它只读取最终 D4 结构 plan，根据 `collisionEnvelope` 自动生成小边距 `maskEnvelope`。

D5 应作为快速程序处理阶段运行。AI 最多选择高层策略，例如清植被强度、是否保留树、道路边是否清空、院落或农田是否额外清理；具体 mask 合并、冲突扣除、保护区生成由程序完成。

### 2. D6 preflight 锁定实际 footprint

D6 preflight / dry-run 继续用于在实际 worldgen 前获取 `actualFootprint`、`lockedActualFootprint` 和 `pieceBoxes`。对可稳定预判的结构，后续阶段应优先使用这些锁定结果更新 `collisionEnvelope`；对村庄、强随机扩张或不可稳定预判的结构，继续保留单独的保守例外策略，但不恢复通用 `safetyEnvelope`。

### 3. 真实落地阶段

Dressing、道路和真实 worldgen 只在提交阶段运行，不得被 D4 每轮设计 loop 隐式触发。

## 可验收提交点

1. 整理 D4 完成后的提交入口，让 D5 只读取最终 D4 plan 自动生成小边距 mask，提交接口和测试。
2. 整理 D6 actual footprint 锁定与 D4 / D5 的衔接，提交 D6 preflight 结果使用和测试。
3. 确保 dressing、道路和真实 worldgen 只在提交阶段运行，提交 workflow 衔接、验收入口和测试。

## 验收需求

1. D4 设计 loop 完成前，不得执行 D5、D6、dressing、道路或 worldgen 激活。
2. 提交入口必须能读取最终 D4 structure plan，并生成 D5 小边距 mask。
3. D6 必须在真实 worldgen 前输出或锁定 `actualFootprint`、`lockedActualFootprint` 和 `pieceBoxes`。
4. D5 / D6 衔接必须优先使用 D6 锁定结果更新后续落地计划，不得恢复通用 `safetyEnvelope`。
5. Dressing、道路和真实 worldgen 必须只在提交阶段运行，并能从最终 D4 / D5 / D6 artifact 读取输入。
6. 验证用例必须覆盖完整提交链路：最终 D4 plan -> D5 mask -> D6 lock -> execute/worldgen 等待或完成状态。
