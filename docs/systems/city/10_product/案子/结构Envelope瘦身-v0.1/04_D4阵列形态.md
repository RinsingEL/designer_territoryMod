# 04 D4 阵列形态

## 修改目的

D4 阵列算法需要补足明确的局部构图能力，让建筑组形成紧凑、可读、有生活气息的街坊 / 院落 / 排屋 / 工棚组，而不是旧式散点式避障结果。

## 方案

### 1. 补足可控形态

D4 阵列算法需要补足 `grid`、`courtyard`、`l_shape`、`u_shape`、`organic_compact`、沿线双侧、等高带和 composite 子区阵列。

### 2. compound_cluster 参数化

`compound_cluster` 应显式支持 `rows`、`columns`、`spacingBlocks` 和院落 / 田字形街坊等可控形态。

### 3. 阵列防撞口径

阵列形态仍只以 `collisionEnvelope` 作为结构间硬避让边界，避免回到 `safetyEnvelope` 撑开的旧式散点布局。

### 4. 本轮第一个切片

本轮只交付 D4 阵列形态算法与验收测试，不接 D5/D6 提交阶段、不接 worldgen、不恢复 `safetyEnvelope`。实现范围：

- `city_plan_d4_array_candidates` 支持 `compound_cluster` 读取 `shape`、`rows`、`columns`、`spacingBlocks`，并支持直接 `patterns[]=grid|courtyard|l_shape|u_shape|organic_compact`。
- `array_layout_loop` 的 `compound_cluster` 同步支持上述参数；输出 zone / item / trace 时记录 `arrayShape` 与实际 `spacingBlocks`，便于 artifact 验收。
- `courtyard` 必须生成外圈点位并保留中心空场；`grid` 必须能形成 2x2 方正街坊；`l_shape` / `u_shape` 必须能形成缺角或三边围合；`organic_compact` 必须保持局部紧凑而非散点随机。
- D4 形态 spacing 和冲突判断只看 `collisionEnvelope` / body occupied；`maskEnvelope` 即使互相重叠也不得撑开 anchors。

## 可验收提交点

1. 补足 `compound_cluster` 的 `rows`、`columns`、`spacingBlocks`，提交参数解析、阵列结果和测试。（本轮第一个切片）
2. 补足 `grid`、`courtyard`、`l_shape`、`u_shape` 等可控形态，提交阵列算法和测试。
3. 调整阵列目标为紧凑街坊、院落、排屋或工棚组，提交预览表现和回归测试。

## 验收需求

1. `compound_cluster` 必须实际读取并执行 `rows`、`columns`、`spacingBlocks`，不得只保留文档字段。
2. `grid` 形态必须能生成方正行列阵列；`courtyard` 形态必须能生成外圈围合、中间留空的阵列。
3. `l_shape` 和 `u_shape` 必须能生成对应缺角或三边围合形态。
4. 阵列形态仍必须只用 `collisionEnvelope` 做结构间硬避让。
5. 预览图必须能肉眼区分 grid、courtyard、l_shape、u_shape 和 organic_compact 的布局差异。
6. 验证用例必须覆盖至少一个田字 / 院落式街坊场景，并证明结构间距不被 `safetyEnvelope` 撑开。
