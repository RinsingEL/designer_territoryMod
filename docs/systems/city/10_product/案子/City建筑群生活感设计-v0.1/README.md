# City 案子：建筑群生活感设计 v0.1

## 目的

本案核心是让落地后的建筑群能被玩家读成“有人在这里生产、交易、治理和生活”的聚落，而不只是紧凑、无碰撞、道路全连通的一组建筑。

验收以截图中能否直接辨认农业、商业、行政和人的移动关系为准，不以建筑数量、全连通或无碰撞代替设计验收。

## 方案

- **城市功能结构**：用现有 D4 阵列的先后顺序、分组和 GIS patch 引用表达农业、商业、行政的主次与邻接，不新增功能区 schema，也不恢复旧 `FunctionZoneMap`；D6 后仍由建筑 footprint 生成 LandUse。
- **建筑自动朝向**：阵列项声明门面目标，D4 保持原候选点不变，从模板目录允许旋转中选择最符合目标且不碰撞的一项，并输出可解释结果；显式 rotation 仍优先。
- **功能化装饰**：Decoration 以 LandUse `areaId` 为目标；农业表达生产，商业同时表达交易与物流 / 服务，行政表达公共空间与治理设施，内容只从运行时 catalog 选择。
- **铺装微整地**：新计划的 PAVE 区只补同区域内 1..3 格深的小型封闭坑，再铺硬质表面；开放沟谷、水体、岸线和大面积低地保持自然，不用整区填平制造平台。
- **算法边界**：阵列继续负责紧凑、防撞和落位，不决定功能结构、建筑门面或生活内容；道路拓扑另案处理。
- **首个临水综合城镇**：首轮只消费 GIS 已有的 `water`、`shore`、`waterDistance`、`plain` 与坡度事实，不假设土壤、矿产或产业资源扫描；城镇包含农业、商业和行政三个部分。
