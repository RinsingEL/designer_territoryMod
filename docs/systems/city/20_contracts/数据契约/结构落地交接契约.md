# 结构落地交接契约

## 定位

本文定义 City D3-D6 结构落地主链的当前数据契约。当前主线已破坏性替换旧 `FunctionZoneMap -> BuildableAreaMap -> PlannedFixedPlacementMap -> StructurePoolMap` 流程；旧字段进入 active endpoint 必须返回 `LEGACY_CITY_FUNCTION_ZONE_FLOW_REMOVED`。

## D4 StructureAnchorPlan

推荐路径先调用 `city_plan_d4_candidates` / `city_select_d4_candidates` 生成 `StructureAnchorPlan`，再进入标准 D4。`city_plan_d4` 仍可直接接收手写 anchor plan，作为调试入口。

## StructureEnvelopeFacts

`city_profile_structure_envelopes` 是 D4 前置的非写世界结构大小区间回归接口。

required payload：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `runId` | string | 是 | W/T run ID。 |
| `citySeedId` | string | 是 | 城市种子 ID，用于选取采样参考区域。 |
| `terrasenseProfileSource` | object | 是 | TerraSense `StructureProfile.jsonl` 或 debug catalog。 |
| `structureIds[]` | string[] | 是 | 顶层 configured structure ID。 |
| `sampleCount` | int | 否 | 默认 256。 |

输出文件：`structure_envelope_facts.json`，`schemaVersion=city_structure_envelope_facts.v0.1`。

每个 `structures[]` 至少包含：

- `structureId`
- `profileHash`
- `structureConfigHash`
- `sourcePackHash`
- `generationConfigHash`
- `sampleCount` / `validSampleCount` / `invalidSampleCount` / `invalidRatio`
- `localEnvelopeP50` / `localEnvelopeP90` / `localEnvelopeP95` / `localEnvelopeP99`
- `maxObservedEnvelope`
- `pieceCount` / `areaBlocks`
- `validSamples[]`：每个有效样本的 `sampleIndex`、`localBounds`、`pieceCount`、`areaBlocks`、`bboxGroupKey`
- `bboxGroups[]`：按 `localBounds + pieceCount` 分组的 bbox 形态事实，包含 `groupKey`、`sampleCount`、`ratio`、`localEnvelope`
- `samplePreview[]`
- `failureSummary`

约束：

- 采样对象必须是 `/place structure <id>` 可触发的顶层 configured structure。
- profiling 不写世界，不生成正式 ledger。
- `profileHash` 和 `generationConfigHash` 必须与 D4 消费的 TerraSense profile / 生成配置匹配；不匹配视为 facts 失效。
- 本轮 Trek 测试结构如果 facts 缺失或 hash 不匹配，D4 hard fail，不回退旧保守半径。
- 固定或近固定结构优先使用 `bboxGroups[]` 的 dominant group 或 anchor 显式指定的 `envelopeGroupKey`。
- 非固定结构使用 `localEnvelopeP95` 生成 D4 collision envelope，使用 `localEnvelopeP99` 生成 D5 mask envelope，使用 `maxObservedEnvelope` 生成 safety / trace。

`structureAnchorPlan`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_structure_anchor_plan.v0.1`。 |
| `cityId` | string | 是 | 必须与 D3 审查包一致。 |
| `anchors[]` | object[] | 是 | 结构 anchor。 |

`anchors[]`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `anchorId` | string | 是 | 稳定 anchor ID。 |
| `structureId` | string | 是 | TerraSense approved / debug catalog 中存在的 configured structure ID。 |
| `sourcePatchIds` | string[] | 是 | 引用 D3 `landformPatchId` 或 `mapLabel`。 |
| `anchorBlock` | object | 是 | `{x,z}`，必须落在 D3 grid 和引用 patch 内。 |
| `rotation` | string | 是 | `NONE`、`CLOCKWISE_90` 等。 |
| `intentTerms` | string[] | 是 | AI/Codex 的语义意图，原样记录，不转 City enum。 |
| `priority` | int | 是 | 道路接入和落地顺序参考。 |
| `roadAccessIntent` | string | 是 | 主路 / 支路 / 水岸接入意图。 |
| `envelopeGroupKey` | string | 否 | 固定 / 近固定结构可指定使用哪个 profiling bbox group；不存在时 D4 hard fail。 |
| `smallClearanceBlocks` | int | 否 | 固定 / 近固定结构 bbox group 的小间距，默认 4。 |

## D4 StructureAnchorMap

输出文件：`structure_anchor_map.json`，`schemaVersion=city_structure_anchor_map.v0.1`。

每个 accepted anchor 至少包含：

- `anchorId`
- `structureId`
- `anchorBlock`
- `commandAnchorBlock`
- `plannedFootprint`
- `reservedEnvelope`
- `collisionEnvelope`
- `maskEnvelope`
- `safetyEnvelope`
- `reservedEnvelopePolicy`
- `envelopeMode`
- `selectedEnvelopeGroupKey`
- `availableEnvelopeGroupKeys`：有 envelope facts 时输出，供 D6 校验 actual bbox group 是否被统计覆盖。
- `smallClearanceBlocks`
- `reservedEnvelopeRadiusBlocks`
- `semanticTerms` / `functionTerms` / `styleTerms` / `placementTerms` / `usageTerms` / `qualityTerms`
- `sourcePatches[]`

防撞：

- fixed 结构：`reservedEnvelope = plannedFootprint + clearanceBlocks`。
- 有 envelope facts 且走 `fixed_bbox_group` 的 fixed / 近固定结构：`collisionEnvelope = selected bboxGroup.localEnvelope + smallClearanceBlocks`，并作为 `reservedEnvelope`；默认 `smallClearanceBlocks=4`，不被默认 8 格 clearance 强制放大。
- 有 envelope facts 且走 `fixed_bbox_group` 的 fixed / 近固定结构：`maskEnvelope = selected bboxGroup.localEnvelope + vegetationMarginBlocks`。
- 有 envelope facts 且走 `fixed_depth_statistics` 的 variable 结构：`collisionEnvelope = localEnvelopeP95 + clearanceBlocks`，并作为 `reservedEnvelope`。
- 有 envelope facts 且走 `fixed_depth_statistics` 的 variable 结构：`maskEnvelope = localEnvelopeP99 + vegetationMarginBlocks`。
- 无 envelope facts 的非 Trek jigsaw / variable 结构：`reservedEnvelope = startFootprint + jigsawExpansionRadius + clearanceBlocks + roadAccessMarginBlocks`。
- 默认 `clearanceBlocks=8`，`roadAccessMarginBlocks=6`。
- jigsaw 半径优先用 TerraSense `max_distance_from_center` / `maxDistanceFromCenter`，其次从 expected area 推导，缺失时使用保守默认。
- `envelopeMode` 当前取值：`fixed_bbox_group`、`fixed_depth_statistics`、`fallback_jigsaw_radius`、`fallback_fixed_footprint`、`missing_structure_envelope_facts`。

## D5 ReservationMaskPlan

输出文件：`reservation_mask_plan.json`，`schemaVersion=city_reservation_mask_plan.v0.1`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `cityId` | string | 是 | 城市 ID。 |
| `grid` | object | 是 | 城市局部 grid。 |
| `noVegetationMask[]` | object[] | 是 | 禁树、草、花、藤蔓、灌木、竹子、蘑菇等植被 feature。 |
| `vegetationLimitedMask[]` | object[] | 是 | 结构过渡区，限制高风险植被。 |
| `noVanillaStructureMask[]` | object[] | 是 | 阻止原版自然结构抢占。 |
| `reservationReason[]` | object[] | 是 | mask 来源与原因。 |
| `hookRequirements` | object | 是 | hook 必须可用；不可用 reasonCode 为 `CITY_MASK_HOOK_UNAVAILABLE`。 |

D5 同时输出：

- `road_access_plan.json`
- `build_operation_plan.json`
- `reservation_mask_preview.png`
- `wall_reservation_plan.json`
- `wall_reservation_preview.png`

当前 D5 不再提前规划真实道路。`road_access_plan.json` / `build_operation_plan.json` 作为占位产物保留，必须标记 `roadPlanningStage=d7_after_worldgen_ledger`，且不得包含道路 `surfaceFill` / `clearVegetation` 等会提前决定路线的操作。

默认 `wallVersion=v2` 时，D5 还会生成 `wall_reservation_plan.json`，`schemaVersion=city_wall_reservation_plan.v0.2`。该产物从 D3 patch 真值、D4 anchor source patches 和 D6 locked 结构计划推导非矩形墙带：

- `boundarySource=d3_patch_member_cell_outer_boundary` 或 `v1_debug_anchor_rectangle`
- `wallCenterline[]`
- `wallCorridorMask[]`
- `towerCandidatePoints[]`
- `gateCandidateZones[]`
- `maskContribution`
- `wallBounds`

`wallCorridorMask` 必须合入 `noVegetationMask`、`vegetationLimitedMask` 和 `noVanillaStructureMask`。若 D3 patch 信息不足，`wallVersion=v2` 返回 `WALL_PATCH_BOUNDARY_UNAVAILABLE`；显式 `wallVersion=v1_debug` 可回退到 v0.1 矩形调试墙。

`city_execute_d5`：

- required `confirmWorldMutation=true`。
- required 已存在 D6 locked `structure_materialization_plan.json`；若 D6 未跑或 locked plan 不完整，必须 hard fail，不得回退到 D4 猜测 envelope。
- 激活 server-root `geomantia_city_masks/active_reservation_mask_plan.json`。
- 同时写入 `geomantia_city_masks/active_planned_structure_registry.json`，每个 planned structure 至少包含 `runId`、`citySeedId`、`anchorId`、`structureId`、`anchorChunk`、`anchorBlock`、`lockedActualFootprint`、`lockedCollisionEnvelope`、`expectedStartSignature`、source patch / TerraSense terms。
- active path 不主动执行 WorldEdit road / clear 操作，`world_mutation_report.json` 记录为 skipped / deferred，避免 D5 提前生成目标 chunk。
- hook 缺失或不可用必须 hard fail：`CITY_MASK_HOOK_UNAVAILABLE` / `CITY_WORLDGEN_STRUCTURE_HOOK_UNAVAILABLE`。
- 可选 `roadProvider=auto|roadweaver|worldedit_debug|none`，默认 `auto`。
- 响应包含 `activePlannedStructureCount`、`plannedStructureRegistryPath`、`worldgenPlacementMode=true`、`requiresLockedMaterializationPlan=true`、`roadPlanningStage=d7_after_worldgen_ledger`、`roadProvider`、`roadWeaverAvailable`。
- 输出 `roadweaver_connection_plan.json`、`roadweaver_registration_report.json`、`road_provider_state.json`。
- `roadProvider=roadweaver` 且 RoadWeaver 未加载时 hard fail `ROADWEAVER_UNAVAILABLE`；`roadProvider=auto` 且 RoadWeaver 未加载时保留 D7 WorldEdit debug fallback，并在 state / trace 中标记。

D5 mask 规则：

- noVegetation / noVanillaStructure 在 `city_plan_d5` 阶段可先使用 D4 `maskEnvelope` 生成预案。
- `city_execute_d5` 激活 active mask 时必须使用 D6 locked collision / mask 信息覆盖 D4 猜测 envelope。
- 道路 corridor 不再进入 D5 noVegetation mask；RoadWeaver 连接点在 `city_execute_d5` 注册，WorldEdit debug road 仅在 RoadWeaver 缺失或显式 debug provider 时由 D7 后处理。
- 城墙 corridor 属于 D5 生成期 mask 真值，必须进入 noVegetation / noVanillaStructure；城门仍要等 RoadWeaver 真实道路生成后在 `city_plan_city_walls` 阶段裁剪。
- `build_operation_plan.json` 不再承载 D5 预计算道路 operation；不得在 D5 主动生成目标 chunk。

## D6 StructureMaterializationPlan

`city_plan_d6` required payload：`runId`、`citySeedId`。可选 `dimensionId` / `playerName` 用于定位 ServerLevel。

输入：

- D4 `structure_anchor_map.json`
- D5 `reservation_mask_plan.json`
- 可选既有 `placed_structure_ledger.json`

输出文件：`structure_materialization_plan.json`，`schemaVersion=city_structure_materialization_plan.v0.1`。

`plannedWorldgenStructures[]` 至少包含：

- D4 anchor 原始字段。
- `anchorChunk`：planned anchor 所在 chunk。
- `requiredChunkRange`：由 locked collision envelope 推导的 chunk range；无 locked 信息时才允许用 planned envelope 诊断。
- `reservedEnvelope` / `plannedFootprint` / `actualFootprint`。
- `locked=true`
- `lockedActualFootprint`
- `lockedCollisionEnvelope`
- `lockedBBoxGroupKey`
- `availableEnvelopeGroupKeys`
- `collisionClearanceBlocks`
- `status`：`planned_worldgen` / `already_generated` / `invalid_anchor` / `registry_missing`。
- `reasonCode`：`WAITING_FOR_WORLDGEN`、`STRUCTURE_CHUNK_ALREADY_GENERATED` 等。
- `actualLocalBounds`
- `actualBBoxGroupKey`
- `pieceBoxes`
- `expectedStartSignature`
- `envelopeMode` / `selectedEnvelopeGroupKey`

约束：

- `city_plan_d6` 不写世界，不要求目标 chunk loaded。
- D6 会对 selected anchor 做 non-mutating configured structure preflight，生成 actual bbox、piece boxes、actual bbox group key 和 `expectedStartSignature`。
- D6 是最终防撞准入点：用 `actualFootprint + collisionClearanceBlocks` 检查本轮结构和既有 ledger；默认 `collisionClearanceBlocks=4`。
- 若 actual bbox group 与 D4 dominant / selected group 不一致，但 facts 中存在该 group 且 locked collision 不重叠，D6 应锁定实际 group，而不是直接失败；若 `fixed_bbox_group` 的 actual group 不在 `availableEnvelopeGroupKeys` 中，返回 `BBOX_GROUP_NOT_IN_FACTS`。
- D6 trace 记录 actual bbox、actual local bounds、actual bbox group key、locked collision envelope、collision/mask/safety envelope，便于解释本次生成形态。
- 若尚未执行 `city_execute_d5 confirmWorldMutation=true` 激活 planned structure registry，D6 仍可先产出 planned_worldgen preflight 计划；调用方必须在目标 chunk 首次生成前执行 `city_execute_d5`。
- 未生成 chunk 返回 `planned_worldgen` / `WAITING_FOR_WORLDGEN`，不算失败。
- chunk 已经生成到 `FEATURES` 或之后且没有 worldgen ledger 时，返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，active path 不再允许 late paste。
- 真实 bbox / piece boxes 由 worldgen hook 写入 `worldgen_placement_ledger.json`，再由 `city_execute_d7` 汇总到 placed ledger。

## execute_d7 True-Run

入口名继续使用 `city_execute_d7`，但正式语义为 worldgen ledger / chunk 状态检查。

参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `runId` | string | 是 | W/T run ID。 |
| `citySeedId` | string | 是 | 城市 ID。 |
| `executeStructurePlacement` | bool | 否 | false 只复查 dry-run；true 执行真实落地。 |
| `dimensionId` / `playerName` | string | 否 | 定位维度。 |

规则：

- 读取 D6 `structure_materialization_plan.json`。
- `executeStructurePlacement=true` 默认只检查 worldgen ledger / chunk 状态，不调用 `StructureStart.placeInChunk`。
- 未生成 chunk 返回 `WAITING_FOR_WORLDGEN`。
- chunk 已生成且无 ledger 返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`。
- worldgen hook 已记录时返回 `WORLDGEN_PLACEMENT_RECORDED`，并写 placed ledger / inferred function area。
- 所有 planned structure 都已有 ledger 后，若 RoadWeaver 已注册，则 D7 不再默认生成 WorldEdit 道路；若 `roadProvider=worldedit_debug` 或 `auto` fallback，则基于 ledger 中真实 `actualFootprint` 生成 debug road / boundary 后处理。
- debug road 寻路障碍使用 `actualFootprint + roadAvoidanceMarginBlocks`，默认 `roadAvoidanceMarginBlocks=3`；道路不得穿过结构 body、房顶或墙体。
- 可选 `debugLateMaterialize=true` 才允许旧 `StructureStart.placeInChunk` 诊断路径；trace 必须写 `lateMaterialization=true`，不得作为正式验收通过。

输出：

- `placed_structure_ledger.json`
- `structure_materialization_trace.json`
- `inferred_function_area_map.json`
- `placed_structure_preview.png`

D7 road / terrain 输出字段：

- `roadPostprocessSource=worldgen_ledger_actual_footprint`
- `roadAvoidanceMarginBlocks`
- `roadBlockedByStructureCount`
- `boundarySource=actual_footprint_union`
- `roadProviderState`
- `terrainAdaptationReport`

RoadWeaver 已注册时，`deferredRoadPostprocessReport.status=skipped`，`reasonCode=ROADWEAVER_REGISTERED`，`roadPostprocessSource=roadweaver`。

`wallSegments[]` 中每个非调试旧段必须包含 `wallAxis=X|Z`，表示该墙段的长度主轴。执行层拆 `terrainFitUnit`、生成 `stepSlices[]`、探测嵌坡山体侧、计算墙体厚度时必须沿 `wallAxis` 执行；不得从拆碎后的 unit 长宽重新推断方向，否则会在 9x8 这类近方形 unit 上出现错朝向、墙上叠墙和悬空。

输出 `city_wall_placement_report.json`，`schemaVersion=city_wall_placement_report.v0.1`。

规则：

- 默认 v2 使用 `vanilla_setblock` 后端，不依赖 WorldEdit。
- 城墙边界来源是 D3 patch 贴边 wall reservation，不是功能区边界；v1_debug 才来源于真实落地 structure ledger 外扩矩形。
- `gate_gap` 段跳过放置，保留 7 格缺口。
- `gatehouse` 段按独立结构放置石木混合门楼，并清出内外贯通门洞。
- `natural_boundary` 段跳过连续墙，作为水体 / 峭壁天然屏障记录到 gap debug。
- 执行必须保护 `actualRoadMask`、gate gap 和 structure `actualFootprint`，不得覆盖道路或建筑。
- `wallTerrainPolicy=v3` 时，单段高度差超过 `maxSegmentHeightDeltaBlocks` 跳过并报告 `WALL_TERRAIN_TOO_STEEP` / `WALL_UNIT_SKIPPED_TERRAIN`。
- `wallTerrainPolicy=v3.1` 时，高差 `<=7` 使用 flat / foundation；高差 `8-16` 输出 `STEPPED_WALL_PLACED`；高差 `>16` 优先输出 `WALL_EMBEDDED_IN_SLOPE`，不适合时输出 `NATURAL_CLIFF_BOUNDARY`。
- 低洼处按 `maxFoundationDepthBlocks` 向下补 foundation；`wallTerrainPolicy=v3.1` 的有效 foundation 深度不得小于 `steppedMaxDeltaBlocks`，否则 8-16 高差的阶梯墙会合法放置但局部悬空。
- terrain surface 采样应忽略本轮临时城墙材料的连续顶部，避免重复执行同一 plan 或拐角重叠时把已放墙体当作新地面继续往上叠。
