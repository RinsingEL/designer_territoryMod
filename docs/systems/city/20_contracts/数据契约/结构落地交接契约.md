# 结构落地交接契约

## 定位

本文保留 City D3 patch、LandUse、Decoration、RoadWeaver 与城墙交接细节。建筑 D4-D7 的当前唯一数据真值改由 [City模板建筑主路径数据契约](./City模板建筑主路径数据契约.md) 定义；本文任何 configured structure、Jigsaw、envelope facts、piece boxes、start signature、bbox group、late materialization 或 direct-template 表述均为历史，不得覆盖该契约。

固定 NBT 强制口径：D4 只接受显式 `templateCatalogSource` 和 `templateId/templateRef + variant`；D5 使用 `exact footprint + clearance` 与 `collision + maskMargin`；D6 从当前世界 NBT 重新校验 hash、rawSize、transform、body、collision、mask、owner chunks；D5/worldgen/ledger 只使用 `city_active_template_placement_registry.v0.1` 与 `city_template_placement_ledger.v0.1`。所有 catalog 模板冻结为 `structure_start_beard_thin`，只允许 City 自有单-piece start。旧 configured payload/artifact 返回 `CITY_CONFIGURED_STRUCTURE_FLOW_REMOVED`，不迁移、不 fallback。

## D4 StructureAnchorPlan

推荐路径是 `city_run_workflow` 默认的 `d4CandidateMode=key_then_array`：先按 `DesignSlotPlan.placementOrder` 处理所有关键结构 slot，逐 slot 生成候选、选中并冻结 `collisionEnvelope` / body occupied；再按顺序处理 `array_fill` slot，每个阵列阶段都读取上一阶段已经写出的 `StructureAnchorMap` 做结构 collision 避让。每个阵列候选组选中后会与已有 anchor 合并，并重新调用标准 `city_plan_d4`，最终仍输出标准 `StructureAnchorPlan` / `StructureAnchorMap`。

D4 v2 顺序候选 session、D4 array candidates 和结构群整组候选仍保留为单步调试 / 人工干预入口；`city_plan_d4` 仍可直接接收手写 anchor plan。

提交阶段统一顺序为：最终 D4 `StructureAnchorMap` -> `city_plan_d5` 轻量 reservation mask 预案 -> `city_plan_d6` 当前世界 NBT lock -> 可选 `city_plan_city_dressing` -> `city_execute_d5` 用 D6 locked 结果激活 active mask / template registry -> `createStructures` 注入 City single-piece start -> `city_execute_d7` 查询 template ledger。`city_execute_d5` 和 active registry 只使用 `lockedActualFootprint`、`lockedCollisionEnvelope`、`maskEnvelope` 和 `ownerChunks[]`，不得携带 start signature 或 piece boxes。

## D3 Patch Coverage

`city_plan_d3` 必须按 `grid.blockBounds + patchScanPaddingBlocks` 刷新并合并多个 GIS region。默认 `patchScanPaddingBlocks=128`。

- `grid` 仍是 D4 候选的城市核心约束域。
- padding 只用于 patch/memberCells 上下文，防止结构选在核心边界时，D6 `actualFootprint`、D5 reservation 和 v4 城墙外扩进入未扫描 patch。
- D3 输出必须包含 `patchScanPaddingBlocks`、`patchContextBounds`、`refreshedRegions[]`。
- D3 `landformPatches[]` 必须在有 GIS cell 采样上下文时包含 `biomeSummary`，至少含 `dominantBiome`、`biomeHistogram`、`mixedBiome`、`sampledCellCount`；群系来自 GIS cell 的 `biomeId` 聚合。
- D3 patch 首版不输出 temperature。城市规划阶段以 `biomeSummary` 承载环境语境；温度若后续确有机制需求，再从 biome 或 surface cache 派生。

`landformPatches[].biomeSummary`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `dominantBiome` | string | 是 | patch 内样本数最多的 biome ID；无已知样本时为 `unknown`。 |
| `biomeHistogram` | object | 是 | biome ID 到 cell 数量的计数表，只统计已知 biome。 |
| `mixedBiome` | bool | 是 | `biomeHistogram` 中是否多于一种 biome。 |
| `sampledCellCount` | int | 是 | 参与群系统计的已知 biome cell 数。 |

## D4 PatchSelectionRef 交接 v0.1

City D4 复用国度规划侧 `patch_selection.v0.1`，但只接受 `scopeType=city_d4` 且 `scopeId=当前 citySeedId` 的选择凭证。候选来源必须是当前 `CityLandformReviewPackage` 的 D3 patch；已提交 hard occupied 几何只用于扣除可用 cell 和 stale identity，不进入 Patch Explorer 关系表。只读候选历史、质量报告、时间戳和未选择候选的估算 envelope 不属于 occupied，也不得改变 D4 source identity。

选择记录至少携带：

| 字段 | 说明 |
| --- | --- |
| `patchSelectionRef` | 稳定凭证 ID。 |
| `runId` / `sessionId` / `scopeType` / `scopeId` | 来源作用域。 |
| `candidateId` / `patchType` | AI 实际看过并选择的候选。 |
| `sourcePatchRefs[]` | 对应 D3 `landformPatchId` / `mapLabel`。 |
| `areaBlocks` | 扣除 hard occupied 后当前独立连续候选组件的面积。 |
| `largestContinuousAreaBlocks` | 当前候选组件的最大连续面积；City D4 候选已按连续组件拆分，因此应与 `areaBlocks` 相等。 |
| `originalAreaBlocks` | D3 来源 patch 原始面积。 |
| `selectedComponent` | `schemaVersion=patch_selection_legal_region.v0.1`；含 `cellStepBlocks`、block `bounds` 与完整 `memberCells[]`，是所选连续组件的结构化证据。 |
| `suggestedAnchor` | 选中区域内的建议粗锚点；不直接成为建筑 anchor。 |
| `sourceIdentity` / `scopeSnapshotIdentity` | D3 文件 hash 与规范化、排序后的已提交 occupied 几何身份；不绑定可变候选会话全文。 |
| `confirmationPreview` | 选中区域确认染色图。 |

可在以下计划对象放置 `patchSelectionRef`：`DesignSlotPlan.slots[]`、`ArrayCandidatePlan`、`ArrayLayoutPlan.layoutPlans[]`、`arrayExpansionRequest`。服务端先深拷贝原请求，再校验选择凭证，以 `sourcePatchRefs[]` 覆盖派生的 `candidatePatchRefs[]`，并注入内部 `candidateLegalRegion`。前者仍是 D3 patch 搜索依据；后者是完整 `collisionEnvelope` 必须落入的 member-cell union 硬边界，不能退化为 source patch bbox。

`candidateLegalRegion` 不是调用方字段。HTTP 输入的根对象、`slots[]`、`layoutPlans[]`、`nextArrayLayoutPlanItem` 或 `arrayLayoutPlanItem` 只要手写该字段，就必须以 `PATCH_SELECTION_D4_RESERVED_FIELD_FORBIDDEN` 拒绝。合法对象只能由 `resolveD4*` 在验证 `patchSelectionRef`、scope、D3 + committed occupied source identity、scope snapshot 和组件内容后生成；expansion resolver 可在完成验证后把它内部传播到 nested item。

对 `arrayExpansionRequest`，选择必须只映射一个 D3 来源 patch；服务端派生 `selectedGlobalPatchRef` 并显式设置 `newFunctionalArea=true`。无选择凭证的 v0.5 常规 outward 不走该转换，也不得被强制预选 patch。

以下情况必须 hard fail：凭证不存在、scope 不匹配、D3 或 occupied 来源变化、候选类型/面积/来源 patch/组件 member cells 漂移、选择未在当前会话展示、调用方伪造 `candidateLegalRegion`、全局新功能区选择映射多个来源 patch。

| `anchors[]` | object[] | 是 | 已确认 anchor 摘要；可为空。 |
| `occupiedField` | object | 是 | 下一轮必须读取的 D4 占用场。 |

`occupiedField`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_d4_design_loop_occupied_field.v0.1`。 |

- `occupiedId`

- `city_create_d4_design_loop_state`、`city_read_d4_design_loop_state`、`city_append_d4_design_loop_round`、`city_write_d4_design_loop_state` 都不得触发 D5、D6、dressing、roads、worldgen 或 D7。

| `structureWeights` | object | 否 | `weighted_random` 下的结构 ID 到权重映射；未配置权重的结构按 1.0 处理。 |
| `relationHints[]` | object[] | 否 | 只支持通用空间关系。 |

`key_then_array` 阶段顺序约束：

- `placementOrder` 中所有 `key_structure` / `single_ai_selected` slot 必须出现在任何 `array_fill` slot 之前。
- 一旦出现 `array_fill`，后续不得再出现关键结构 slot；违反时返回 `D4_KEY_STRUCTURES_MUST_PRECEDE_ARRAYS`。
- 如果存在 `array_fill` 但前面没有任何关键结构 slot，返回 `D4_KEY_STRUCTURE_STAGE_REQUIRED`。
- 未显式设置 `placementStrategy` 的旧 slot 按 `key_structure` 处理，保证旧 plan 能作为“全关键结构逐个定锚”继续运行。

模板画像交接规则：

- `structure_profile_jsonl` 的 `StructureProfile.jsonl` 与 `template_catalog.json` 必须同目录发布；也可在 `designSlotPlan.templateCatalog` 显式内嵌同一 schema。
- AI 只选择 TerraSense `structureId`、可选 `variantId` 和落点，不手抄 `templateRef`、hash、尺寸或道路入口。
- D4 candidate session 必须把模板候选的 `structureId` 规范化为 `template:<templateRef>`，并冻结 `templateId`、`templateRef`、`templateHash`、`variantId`、`templateSize`、`roadEntrances`、变换和 `materializationSource=structure_template_nbt`。
- 模板画像缺 companion catalog、目录中不存在该模板、多个 variant 未指定，或变换不在允许集合时，必须在 D4 hard fail；不得延迟到 D6 伪装成 configured structure 后才报 `CONFIGURED_STRUCTURE_REGISTRY_MISSING`。
- 该模板路径服务当前 NBT 模板实机链与调试验收；最终 D7 产品验收仍以 D7 方案定义的 configured structure 入口为准。

## D4 ArrayCandidatePlan / ArrayCandidateSet

`city_plan_d4_array_candidates` 是独立 D4 前置辅助入口，用于让 AI 一次请求一组批量结构候选。它不沿道路、不生成道路、不改世界；候选组只基于 D3 patch、TerraSense profile、envelope facts 和可选 occupied envelope 做几何防撞。选中某个候选组后，调用方直接取该组的 `expandedStructureAnchorPlan` 进入标准 `city_plan_d4`。

约束：

- 候选点必须从 D3 patch `memberCells[]` 或等价可用 cell 集合出发；patch bbox 只作为边界，不作为可填满矩形。
- 防撞只使用结构 `estimatedCollisionEnvelope` / body envelope；结构大小诊断只允许使用 `diagnosticMaxObservedEnvelope`、`maxObservedEnvelope` 或 `bboxGroups` 等 profile/debug 命名。
- `roadAccessMarginBlocks` 不参与 D4 array candidate spacing 或结构防撞。

required payload：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `runId` | string | 是 | W/T run ID。 |
| `citySeedId` | string | 是 | 城市种子 ID。 |
| `terrasenseProfileSource` | object | 是 | 同 `city_plan_d4`。 |
| `arrayCandidatePlan` | object | 是 | 阵列候选请求。 |
| `structureEnvelopeFactsSource` | object | 否 | `{factsPath}`；未传时读取当前 run/city 默认 `structure_envelope_facts.json`。 |
| `occupiedStructureAnchorMapSource` | object | 否 | `{anchorMapPath}` 或 `{structureAnchorMapPath}`；用于避开已选结构。 |
| `occupiedEnvelopes[]` | object[] | 否 | 额外占用，可为 `{minX,minZ,maxX,maxZ}` 或 `{blockBounds:{...}}`。 |

`arrayCandidatePlan`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_d4_array_candidate_plan.v0.1`。 |
| `cityId` | string | 是 | 必须与 D3 审查包一致。 |
| `arrayId` | string | 是 | 本次阵列内稳定 ID。 |
| `displayRole` | string | 否 | 人类 review 文本；程序不当作功能枚举解释。 |
| `candidatePatchRefs[]` | string[] | 条件必填 | D3 `landformPatchId` 或 `mapLabel`；未传 `patchSelectionRef` 时必填。 |
| `patchSelectionRef` | string | 条件必填 | 来自同 city scope 的 D4 Patch Explorer；服务端解析并覆盖 `candidatePatchRefs[]`。 |
| `structureIds[]` | string[] | 是 | TerraSense catalog 中的顶层 configured structure；可按 round-robin、seeded random 或 weighted random 分配到 `arrayCount`。 |

- `arrayPattern`
- `arrayShape`：`compound_cluster` 的实际形态，或直接 pattern 形态；可为 `grid` / `courtyard` / `l_shape` / `u_shape` / `organic_compact`。
- `spacingBlocks`：本组实际使用的阵列间距；显式 `compoundCluster.spacingBlocks` 优先，否则由结构 collision 尺寸推导。
- `items[]`：每个 item 含 `structureId`、`anchorBlock`、`roadPoint`、`arrayShape`、`spacingBlocks`、`sourcePatchRefs[]`、`estimatedCollisionEnvelope`、`estimatedMaskEnvelope`、`diagnosticMaxObservedEnvelope`、`envelopeMode`
- `groupCollisionEnvelope`
- `groupMaskEnvelope`
- `scoreBreakdown`
- `risks[]`
- `expandedStructureAnchorPlan`：标准 `city_structure_anchor_plan.v0.2`，可直接交给 `city_plan_d4`

阵列候选只做 D4 估算防撞。D6 probe-and-lock 仍是最终 actual footprint / collision 真值。

在 `key_then_array` workflow 中，阵列阶段不会直接覆盖最终 D4，而是：

1. 使用上一阶段最新 `structure_anchor_map.json` 作为 `occupiedStructureAnchorMap`。
2. 生成该 `array_fill` slot 的 3-5 组候选。
3. 自动选择最高分 `arrayCandidateId`。
4. 将该组 `expandedStructureAnchorPlan.anchors[]` 追加到当前 staged anchor plan。
5. 重新调用标准 `city_plan_d4` 做全量 hard validation 和 artifact 写出。

## D4 ArrayLayoutLoop v0.2 / v0.3

`array_layout_loop_v0_2` / `array_layout_loop_v0_3` 是显式开发路径，不替换默认 `key_then_array`。它仍遵守“关键结构先定锚”：workflow 会先用 D4 v2 session 完成 key structures，再创建 array layout loop。单独 endpoint 使用时，若已有 `city_d4_<citySeedId>/structure_anchor_plan.json` / `structure_anchor_map.json`，默认作为 base plan 和 occupied。

执行硬规则：

- 阵列候选点必须从 D3 patch `memberCells[]` 或等价可用 cell 集合出发；`subZones[]` 只限制搜索范围，不等于可直接填满的矩形地。

- required item 失败 hard block；fill item 可跳过候选点，但最终不足 `minCount` 必须 hard block，不得自动降低目标数量。

## D4 连续外扩候选 v0.5

v0.5 只改变常规 outward 的候选空间来源，不改变 `create -> query -> plan -> select -> finalize` 的提交边界，也不改变 `newFunctionalArea=true` 的独立全局 patch 搜索。

- 常规 outward 语义输入为父结构引用、方向、目标实体间距和阵列布局参数；不得要求、推导或静默读取 `targetPatchRef`。
- `candidateCount` 为 3-5，缺省 5；`minCandidateCount` 缺省 3。只有调用方显式传 `minCandidateCount=2` 时允许以 2 组完整合法候选成功，未传或小于 2 均不得降低默认门槛。
- 父结构几何必须取已 Plan anchor 的有效 D2 `body` / `collision` bbox；近、中、远候选从其外缘沿方向连续展开。D2 `collisionEnvelopeSource` 继续是碰撞与自动阵列间距真值。
- 近圈只要存在通过结构 collision、D3 member-cell、坡度 / 水体和容量筛选的完整候选，就不得生成中圈或远圈作为替代；近圈全否决时，trace 必须逐项解释后才可扩圈。
- D3 patch 只用于候选点的地形有效性、风险和评分。一个候选可命中多个 patch；patch 边界不得作为阵列边界或拉大首户距离的理由。
- `actualBodyGapBlocks` 是整组 `plannedFootprint` 相对父 `body` 的最小方向 gap。连续 `guide_line_dual_side` 的内侧首排必须落在该 gap，外侧排只能离父结构更远；不得以双侧横移改变近圈语义。
- 连续前沿起点必须使用 `requiredItems`、`featuredItems` 与展开后 `fillPool` 全部成员的 D2 `plannedFootprint` 并集；方向上的最大外伸成员决定首排锚点，避免混合尺寸阵列的后续成员侵入父 body gap。
- 预览产物必须同时有总览和局部放大语义：总览比较近 / 中 / 远候选，局部图显示父结构、首户距离以及 D2 body / collision / mask 图例。设计主图默认隐藏 bbox，调试图才显示三层范围。
- 沿用 `city_d4_array_layout_plan.v0.4`。常规 outward 未传 `targetPatchRef` 时，`arrayExpansionRequest.expansionPolicy` 可含必填 `actualBodyGapMin` / `actualBodyGapMax` 与可选 `frontierExpansionStepBlocks` / `frontierMaxExpansionRounds`。
- query 的 `expansionSpace` 须写 `focusBodyEnvelope`、`expansionMode=continuous_focus_frontier`、`expansionPolicy` 和 `frontierRings[]`。候选须写 `parentBodyEnvelope`、`parentCollisionEnvelope`、`frontierRing`、`actualBodyGapBlocks`、`terrainPatchRefs` 和 `frontierTrace`；候选集另写逐圈 `frontierSearchTrace[]`，跳过原因使用每圈 `reasonCode`。
- 无可用候选返回 `D4_ARRAY_LAYOUT_CONTINUOUS_FRONTIER_UNSATISFIED`；逐圈原因至少可为 `D4_ARRAY_LAYOUT_FRONTIER_NO_TERRAIN_PATCH`、`D4_ARRAY_LAYOUT_FRONTIER_BODY_GAP_UNSATISFIED` 或 `D4_ARRAY_LAYOUT_FRONTIER_COMPLETE_CLUSTER_UNAVAILABLE`。
- 预览固定为 `d4_array_expansion_candidates.png` 总览、`d4_array_expansion_candidate_detail.png` 候选局部、`structure_anchor_cluster_preview.png` 最终锚点最密簇局部；不得把 v0.4 `targetPatchRef` 复制到 v0.5 常规 outward 请求。

## City DecorationProgram v0.3

`city_plan_city_dressing` 是 D4/D5/D6 后的显式通用装饰入口。它读取 D3 patch member cells、D4 array zones、D5 reservation / wall reservation、D6 locked materialization plan 和道路 corridor，生成全局 `DecorationProgram`。装饰不生成结构 anchor，不写 planned structure registry，不注册 RoadWeaver endpoint。

v0.3 继承 v0.2 判别联合并增加内容姿态、连续地形 run 与 foundation。`city_dressing_brush_plan.v0.1`、`dressingLayoutItems[]` 和七种业务 item schema 仍已退场；v0.2 program / catalog 只读兼容，不原地改写，新规划统一输出 v0.3。

素材目录固定为：

```text

  content_index.json
  templates/*.nbt
  styles/<styleProfileId>.json
```

- `content_index.json` 当前 schema 为 `city_decoration_content_index.v0.3`，只接受 prefab；每项必须显式包含 `groundPlaneLocalY`、`embedDepthBlocks`、`clearanceMode=preserve|clear_template_air`，三者参与 contentHash / catalogHash。v0.2 可按 `0 / 0 / preserve` 只读兼容，但 query 必须报告 `contentPoseUpgradeRequired=true`，禁止静默改文件或 hash。
- 农田、水渠和石路使用 1x1 / 1xN tile NBT。可选 `terrainDropFallbackContentRef` 仅适用于 source / fallback 均为 1x1 且 placementMode / replacePolicy / pose 兼容的 tile；引用必须存在于同一 catalog。size / envelope 从 NBT 派生，surface catalog / block palette 配置化放第二切片。
- 运行时 `config/geomantia/city_decoration/` 是唯一真值。`city_query_decoration_catalog` 仅在该根目录不存在时一次性安装打包基础目录：`content_index.json`、`styles/medieval_coastal.json` 和 4 个有效 NBT 模板；根目录已存在时不得覆盖、合并、补齐或修复，缺文件 / 非法内容继续按 catalog 校验失败。
- 每个 `styles/<styleProfileId>.json` 固定为 `schemaVersion=city_decoration_style_profile.v0.1`、同名 `styleProfileId` 与非空 `mappings[]`；mapping 为 `semanticRef` 到 `variants[{contentRef,weight}]`，所有 concrete `contentRef` 必须存在于当前 content catalog。
- 打包基础 `styles/medieval_coastal.json` 至少映射 `crop_tile`、`water_channel_tile`、`field_border`、`gravel_path_tile`；具体 prefab 仍以安装后的运行时 config 为准。
- 规划冻结规范化 prefab 目录与被引用 NBT 的 `catalogHash`，以及风格档案的 `styleProfileHash`；intent、compiled plan、completion 和 active plan 必须透传。激活或落地时 hash 不一致分别返回 `CITY_DECORATION_CATALOG_HASH_MISMATCH`、`CITY_DECORATION_STYLE_PROFILE_HASH_MISMATCH`。
- prefab NBT 只允许方块 palette / blocks；禁止实体 NBT，`entities[]` 非空返回 `CITY_DECORATION_PREFAB_ENTITY_NBT_FORBIDDEN`。
- AI 的 `contentPalette.entries[].contentRef` 只能是所选风格档案中已注册的语义 `semanticRef`，如 `market_stall`，不得提交 concrete content id、内联 block state、NBT 路径或 block operation。规划输出的 compiled plan 才改为 concrete content id，并保留 style id/hash 以便激活校验。

未知引用返回 `CITY_DECORATION_CONTENT_REF_UNKNOWN`。稳定测试引用可使用 `geomantia:prefab/fence_post`、`geomantia:prefab/market_stall_small`、`geomantia:prefab/flower_centerpiece`、`geomantia:prefab/farmland_wheat_tile`、`geomantia:prefab/water_channel_tile`、`geomantia:prefab/gravel_path_tile`，但这些 ID 必须先由测试 catalog 注册，不代表内置正式素材。

`placementMode` / `replacePolicy` 组合：

| placementMode | replacePolicy | 语义 |
| --- | --- | --- |
| `above_surface` | `replaceable_only` | 在统一地表 datum 上方放置摊位、栅栏、灯具等 prefab，只替换空气、植被等可替换方块。 |
| `replace_surface` | `surface_replaceable` | 在 surface Y 替换草地、泥土等允许地表；用于 farmland / water channel / gravel path tile。 |
| `embed_surface` | `surface_replaceable` | 按正数 `embedDepthBlocks` 把模板 ground plane 嵌入地表；不允许隐式挖方或逐列变形。 |

未知 placement mode 返回 `CITY_DECORATION_PLACEMENT_MODE_UNSUPPORTED`；组合不匹配返回 `CITY_DECORATION_PLACEMENT_REPLACE_POLICY_MISMATCH`。统一原点为 `datumY + above_surface?1:0 - groundPlaneLocalY - embedDepthBlocks`。`clearanceMode=preserve` 忽略模板空气，`clear_template_air` 才清理模板显式空气。全部 pose 字段属于冻结 catalog，不允许 AI 在 `DecorationProgram` 中覆盖。

运行时规则：

```text
DecorationProgram
  -> 任一 owner chunk 触发
  -> 仅投影当前 owner chunk 的局部片段与必要 halo
  -> compiled target member cells 求交并检查 hard obstacles
  -> 对当前 owner 查询真实高度、水体、地表、硬占用与 target 可写性
  -> 当前 owner READY fragment 先登记 vegetation suppression
  -> 当前 target state 不可用则仅延后本 fragment，等待本 owner 后续触发
  -> 预检通过后只写当前 owner fragment 并写 fragment ledger
```

- v0.3 active plan 保存全局程序与 frozen terrain plan；预展开 surface operation / placement 只可作为调试产物，不是运行时真值。
- `cross_section_repeat` / `parallel_rows` 在 D5 activation 前按完整 target projection 编译全局 run；runId 与 ordinal 不得按 chunk 重启。水体、局部高差和滑动窗口累计落差在首个不安全槽终止，兼容 fallback 只冻结到最后安全槽的 `END_CAP`。
- `foundationMode=fill_only` 只允许上述两类连续 pattern。D5 用 `ChunkGenerator.getBaseHeight/getBaseColumn` 采样且不加载 chunk；结果冻结进 active plan。噪声阶段 Beardifier 只读 immutable segment，使用正密度、segment 间 max、平滑 shoulder 和最大深度。segment 投影参数在 `[0,1]` 外贡献为零；单点 run 不生成 segment；侧向肩部命中水体 / unavailable 列时 shoulder 收缩为 0。FEATURES 禁止 setBlock 填柱，只做局部复检、datum 对齐和 NBT 放置。
- `fill_only` 的 FEATURES 运行地表必须位于 frozen `targetY ±1` 才可 READY；否则 fragment 以 `CITY_DECORATION_FOUNDATION_NOT_MATERIALIZED` 进入 skipped，datum 为空，不得强抬到 target，也不得归类 deferred。账本中 `foundationPlanned` 表示 `targetY > surfaceY`，`foundationMaterialized` 表示 READY 且 datum 达 target，`foundationApplied` 必须与 materialized 等价。
- `allowWater=false` 在水体前终止；`allowWater=true` 可继续，但 fluid slot 及跨 fluid 间隔不生成 foundation。本版不挖方、不架桥、不打隧道。
- 所有 chunk 共用同一 `programId + seed + coordinateFrame`，禁止按 chunk 独立随机。
- 同一 program 跨 chunk 的几何一致性以 `programId + seed + coordinateFrame` 为边界；worldgen 回调严格按 owner 写入，其他 owner 由自己的回调提交，禁止跨 `WorldGenRegion` 写入。
- 地表内容可逐格贴地；多方块 prefab 必须采样完整 footprint 并使用统一 datum，超过 `maxFootprintHeightSpreadBlocks` 时整体跳过，禁止逐列贴地。
- ledger key 至少包含 `dimensionId + cityId + programId + catalogHash + chunkX + chunkZ + fragmentId`。
- 首期 registry 仍由 `ConfiguredFeature.place` mixin 触发；当前 owner 的 READY fragment 必须在该 feature 继续前登记 `suppressionBounds`，抑制同范围后续植被 feature。
- 无 configured feature 调用的 chunk 可能不触发 decoration registry。这是当前限制，必须在真实验收中单列，不得写成已解决。

- 默认 `clearanceBlocks=8`，`maskMarginBlocks=8`，`roadAccessMarginBlocks=6`；`roadAccessMarginBlocks` 只作为后序 RoadWeaver 接入和 trace 参考字段。
- D4 阶段所有结构 occupied 真值均为 `collisionEnvelope` / body envelope；`maskEnvelope`、profile/debug 诊断范围、道路 corridor、装饰 mask、院落和植被 margin 不得反向修改或撑开 D4 anchors。
- jigsaw 半径优先用 TerraSense `max_distance_from_center` / `maxDistanceFromCenter`，其次从 expected area 推导，缺失时使用保守默认。
- `envelopeMode` 当前取值：`fixed_bbox_group`、`d2_stable_max_envelope`、`fixed_depth_statistics`、`fallback_jigsaw_radius`、`fallback_fixed_footprint`、`missing_structure_envelope_facts`。

- `gate_gap` 段跳过放置，保留 7 格缺口。
- `gatehouse` 段按独立结构放置石木混合门楼，并清出内外贯通门洞。
- `natural_boundary` 段跳过连续墙，作为水体 / 峭壁天然屏障记录到 gap debug。
- 执行必须保护 `actualRoadMask`、gate gap 和 structure `actualFootprint`，不得覆盖道路或建筑。
- `wallTerrainPolicy=v3` 时，单段高度差超过 `maxSegmentHeightDeltaBlocks` 跳过并报告 `WALL_TERRAIN_TOO_STEEP` / `WALL_UNIT_SKIPPED_TERRAIN`。
- `wallTerrainPolicy=v3.1` 时，高差 `<=7` 使用 flat / foundation；高差 `8-16` 输出 `STEPPED_WALL_PLACED`；高差 `>16` 优先输出 `WALL_EMBEDDED_IN_SLOPE`，不适合时输出 `NATURAL_CLIFF_BOUNDARY`。
- 低洼处按 `maxFoundationDepthBlocks` 向下补 foundation；`wallTerrainPolicy=v3.1` 的有效 foundation 深度不得小于 `steppedMaxDeltaBlocks`，否则 8-16 高差的阶梯墙会合法放置但局部悬空。
- terrain surface 采样应忽略本轮临时城墙材料的连续顶部，避免重复执行同一 plan 或拐角重叠时把已放墙体当作新地面继续往上叠。
