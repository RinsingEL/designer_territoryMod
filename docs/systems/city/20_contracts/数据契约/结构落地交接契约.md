# 结构落地交接契约

## 定位

本文定义 City D3-D6 结构落地主链的当前数据契约。当前主线已破坏性替换旧 `FunctionZoneMap -> BuildableAreaMap -> PlannedFixedPlacementMap -> StructurePoolMap` 流程；旧字段进入 active endpoint 必须返回 `LEGACY_CITY_FUNCTION_ZONE_FLOW_REMOVED`。

## D4 StructureAnchorPlan

推荐路径是 `city_run_workflow` 默认的 `d4CandidateMode=key_then_array`：先按 `DesignSlotPlan.placementOrder` 处理所有关键结构 slot，逐 slot 生成候选、选中并冻结 occupied envelope；再按顺序处理 `array_fill` slot，每个阵列阶段都读取上一阶段已经写出的 `StructureAnchorMap` 做 occupied 避让。每个阵列候选组选中后会与已有 anchor 合并，并重新调用标准 `city_plan_d4`，最终仍输出标准 `StructureAnchorPlan` / `StructureAnchorMap`。

D4 v2 顺序候选 session、D4 array candidates 和结构群整组候选仍保留为单步调试 / 人工干预入口；`city_plan_d4` 仍可直接接收手写 anchor plan。

## D3 Patch Coverage

`city_plan_d3` 必须按 `grid.blockBounds + patchScanPaddingBlocks` 刷新并合并多个 GIS region。默认 `patchScanPaddingBlocks=128`。

- `grid` 仍是 D4 候选的城市核心约束域。
- padding 只用于 patch/memberCells 上下文，防止结构选在核心边界时，D6 `actualFootprint`、D5 reservation 和 v4 城墙外扩进入未扫描 patch。
- D3 输出必须包含 `patchScanPaddingBlocks`、`patchContextBounds`、`refreshedRegions[]`。
- D3 `landformPatches[]` 必须在有 GIS cell 采样上下文时包含 `biomeSummary`，至少含 `dominantBiome`、`biomeHistogram`、`mixedBiome`、`sampledCellCount`；群系来自 GIS cell 的 `biomeId` 聚合。
- D3 patch 首版不输出 temperature。城市规划阶段以 `biomeSummary` 承载环境语境；温度若后续确有机制需求，再从 biome 或 surface cache 派生。

`landformPatches[].biomeSummary`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `dominantBiome` | string | 是 | patch 内样本数最多的 biome ID；无已知样本时为 `unknown`。 |
| `biomeHistogram` | object | 是 | biome ID 到 cell 数量的计数表，只统计已知 biome。 |
| `mixedBiome` | bool | 是 | `biomeHistogram` 中是否多于一种 biome。 |
| `sampledCellCount` | int | 是 | 参与群系统计的已知 biome cell 数。 |

- 未显式设置 `placementStrategy` 的旧 slot 按 `key_structure` 处理，保证旧 plan 能作为“全关键结构逐个定锚”继续运行。

## D4 ArrayCandidatePlan / ArrayCandidateSet

`city_plan_d4_array_candidates` 是独立 D4 前置辅助入口，用于让 AI 一次请求一组批量结构候选。它不沿道路、不生成道路、不改世界；候选组只基于 D3 patch、TerraSense profile、envelope facts 和可选 occupied envelope 做几何防撞。选中某个候选组后，调用方直接取该组的 `expandedStructureAnchorPlan` 进入标准 `city_plan_d4`。

required payload：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `runId` | string | 是 | W/T run ID。 |
| `citySeedId` | string | 是 | 城市种子 ID。 |
| `terrasenseProfileSource` | object | 是 | 同 `city_plan_d4`。 |
| `arrayCandidatePlan` | object | 是 | 阵列候选请求。 |
| `structureEnvelopeFactsSource` | object | 否 | `{factsPath}`；未传时读取当前 run/city 默认 `structure_envelope_facts.json`。 |
| `occupiedStructureAnchorMapSource` | object | 否 | `{anchorMapPath}` 或 `{structureAnchorMapPath}`；用于避开已选结构。 |
| `occupiedEnvelopes[]` | object[] | 否 | 额外占用，可为 `{minX,minZ,maxX,maxZ}` 或 `{blockBounds:{...}}`。 |

`arrayCandidatePlan`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_d4_array_candidate_plan.v0.1`。 |
| `cityId` | string | 是 | 必须与 D3 审查包一致。 |
| `arrayId` | string | 是 | 本次阵列内稳定 ID。 |
| `displayRole` | string | 否 | 人类 review 文本；程序不当作功能枚举解释。 |
| `candidatePatchRefs[]` | string[] | 是 | D3 `landformPatchId` 或 `mapLabel`；只作为候选搜索依据。 |
| `structureIds[]` | string[] | 是 | TerraSense catalog 中的顶层 configured structure；可按 round-robin、seeded random 或 weighted random 分配到 `arrayCount`。 |
| `arrayCount` | int | 是 | 必须完整满足；容量不足返回 `D4_ARRAY_COUNT_UNSATISFIED`，不输出部分候选组。 |
| `patterns[]` | string[] | 否 | `loose_cluster` / `patch_axis_band` / `scattered`；缺省三者都生成。 |
| `variantSelectionMode` | string | 否 | `round_robin` / `seeded_random` / `weighted_random`；单独 endpoint 缺省 `round_robin`，workflow `array_fill` 缺省 `seeded_random`。 |
| `variantSeed` | string | 否 | 稳定随机附加 seed。 |
| `structureWeights` | object | 否 | `weighted_random` 权重表。 |

输出文件：`d4_array_candidate_set.json`，`schemaVersion=city_d4_array_candidate_set.v0.1`。

每个 `arrayCandidates[]` 至少包含：

- `arrayCandidateId`
- `arrayPattern`
- `items[]`：每个 item 含 `structureId`、`anchorBlock`、`roadPoint`、`sourcePatchRefs[]`、`estimatedCollisionEnvelope`、`estimatedMaskEnvelope`、`estimatedSafetyEnvelope`、`envelopeMode`
- `groupCollisionEnvelope`
- `groupMaskEnvelope`
- `scoreBreakdown`
- `risks[]`
- `expandedStructureAnchorPlan`：标准 `city_structure_anchor_plan.v0.1`，可直接交给 `city_plan_d4`

阵列候选只做 D4 估算防撞。D6 probe-and-lock 仍是最终 actual footprint / collision 真值。

在 `key_then_array` workflow 中，阵列阶段不会直接覆盖最终 D4，而是：

1. 使用上一阶段最新 `structure_anchor_map.json` 作为 `occupiedStructureAnchorMap`。
2. 生成该 `array_fill` slot 的 3-5 组候选。
3. 自动选择最高分 `arrayCandidateId`。
4. 将该组 `expandedStructureAnchorPlan.anchors[]` 追加到当前 staged anchor plan。
5. 重新调用标准 `city_plan_d4` 做全量 hard validation 和 artifact 写出。

`city_plan_d4_structure_cluster_groups` 是显式调试 / 整城构图实验入口。它读取 `DesignSlotPlan`，一次生成多组完整结构群落脚方案；每个候选组都必须覆盖 `placementOrder` 中的所有 slot。AI/Codex 只需要比较整组质量并选择一个 `groupCandidateId`。推荐主流程已改为 `key_then_array`，避免关键大结构被整组算法一次性锁死。

- 结构群候选内部使用 D4 v2 selection 同口径 occupied：优先 `estimatedSafetyEnvelope`，缺失时回退 `estimatedCollisionEnvelope`。

- D6 probe-and-lock 仍是最终 actual footprint / collision 真值。

每个 `structures[]` 至少包含：

- `structureId`
- `profileHash`
- `structureConfigHash`
- `sourcePackHash`
- `generationConfigHash`
- `sampleCount` / `validSampleCount` / `invalidSampleCount` / `invalidRatio`
- `localEnvelopeP50` / `localEnvelopeP90` / `localEnvelopeP95` / `localEnvelopeP99`
- `maxObservedEnvelope`
- `pieceCount` / `areaBlocks`

约束：

- 固定或近固定结构优先使用 `bboxGroups[]` 的 dominant group 或 anchor 显式指定的 `envelopeGroupKey`。
- 非固定结构使用 `localEnvelopeP95` 生成 D4 collision envelope，使用 `localEnvelopeP99` 生成 D5 mask envelope，使用 `maxObservedEnvelope` 生成 safety / trace。

## D4 StructureAnchorMap

输出文件：`structure_anchor_map.json`，`schemaVersion=city_structure_anchor_map.v0.1`。

每个 accepted anchor 至少包含：

- `anchorId`
- `structureId`
- `anchorBlock`
- `commandAnchorBlock`
- `plannedFootprint`
- `reservedEnvelope`
- `collisionEnvelope`
- `maskEnvelope`
- `safetyEnvelope`
- `reservedEnvelopePolicy`
- `envelopeMode`
- `selectedEnvelopeGroupKey`
- `availableEnvelopeGroupKeys`：有 envelope facts 时输出，供 D6 校验 actual bbox group 是否被统计覆盖。
- `smallClearanceBlocks`
- `reservedEnvelopeRadiusBlocks`
- `semanticTerms` / `functionTerms` / `styleTerms` / `placementTerms` / `usageTerms` / `qualityTerms`
- `sourcePatches[]`

防撞：

- fixed 结构：`reservedEnvelope = plannedFootprint + clearanceBlocks`。
- 有 envelope facts 且走 `fixed_bbox_group` 的 fixed / 近固定结构：`collisionEnvelope = selected bboxGroup.localEnvelope + smallClearanceBlocks`，并作为 `reservedEnvelope`；默认 `smallClearanceBlocks=4`，不被默认 8 格 clearance 强制放大。
- 有 envelope facts 且走 `fixed_bbox_group` 的 fixed / 近固定结构：`maskEnvelope = selected bboxGroup.localEnvelope + vegetationMarginBlocks`。
- 有 envelope facts 且走 `fixed_depth_statistics` 的 variable 结构：`collisionEnvelope = localEnvelopeP95 + clearanceBlocks`，并作为 `reservedEnvelope`。
- 有 envelope facts 且走 `fixed_depth_statistics` 的 variable 结构：`maskEnvelope = localEnvelopeP99 + vegetationMarginBlocks`。
- 无 envelope facts 的非 Trek jigsaw / variable 结构：`reservedEnvelope = startFootprint + jigsawExpansionRadius + clearanceBlocks + roadAccessMarginBlocks`。
- 默认 `clearanceBlocks=8`，`roadAccessMarginBlocks=6`。
- jigsaw 半径优先用 TerraSense `max_distance_from_center` / `maxDistanceFromCenter`，其次从 expected area 推导，缺失时使用保守默认。
- `envelopeMode` 当前取值：`fixed_bbox_group`、`fixed_depth_statistics`、`fallback_jigsaw_radius`、`fallback_fixed_footprint`、`missing_structure_envelope_facts`。

`city_execute_d5`：

- required `confirmWorldMutation=true`。
- required 已存在 D6 locked `structure_materialization_plan.json`；若 D6 未跑或 locked plan 不完整，必须 hard fail，不得回退到 D4 猜测 envelope。
- 激活 server-root `geomantia_city_masks/active_reservation_mask_plan.json`。
- 同时写入 `geomantia_city_masks/active_planned_structure_registry.json`，每个 planned structure 至少包含 `runId`、`citySeedId`、`anchorId`、`structureId`、`anchorChunk`、`anchorBlock`、`lockedActualFootprint`、`lockedCollisionEnvelope`、`expectedStartSignature`、source patch / TerraSense terms。
- active path 不主动执行 WorldEdit road / clear 操作，`world_mutation_report.json` 记录为 skipped / deferred，避免 D5 提前生成目标 chunk。
- hook 缺失或不可用必须 hard fail：`CITY_MASK_HOOK_UNAVAILABLE` / `CITY_WORLDGEN_STRUCTURE_HOOK_UNAVAILABLE`。
- 可选 `roadProvider=auto|roadweaver|worldedit_debug|none`，默认 `auto`。
- 响应包含 `activePlannedStructureCount`、`plannedStructureRegistryPath`、`worldgenPlacementMode=true`、`requiresLockedMaterializationPlan=true`、`roadPlanningStage=d7_after_worldgen_ledger`、`roadProvider`、`roadWeaverAvailable`。
- 输出 `roadweaver_connection_plan.json`、`roadweaver_registration_report.json`、`road_provider_state.json`。
- `roadProvider=roadweaver` 且 RoadWeaver 未加载时 hard fail `ROADWEAVER_UNAVAILABLE`；`roadProvider=auto` 且 RoadWeaver 未加载时跳过道路并在 state / trace 中标记 `ROADWEAVER_UNAVAILABLE`，不得自动启用旧 WorldEdit debug fallback。

D5 mask 规则：

- noVegetation / noVanillaStructure 在 `city_plan_d5` 阶段可先使用 D4 `maskEnvelope` 生成预案。
- `city_execute_d5` 激活 active mask 时必须使用 D6 locked collision / mask 信息覆盖 D4 猜测 envelope。
- 道路 corridor 不再进入 D5 noVegetation mask；RoadWeaver 连接点在 `city_execute_d5` 注册，WorldEdit debug road 仅在显式 `roadProvider=worldedit_debug` 时由 D7 后处理。
- 城墙 corridor 属于 D5 生成期 mask 真值，必须进入 noVegetation / noVanillaStructure；城门仍要等 RoadWeaver 真实道路生成后在 `city_plan_city_walls` 阶段裁剪。
- `build_operation_plan.json` 不再承载 D5 预计算道路 operation；不得在 D5 主动生成目标 chunk。

## D6 StructureMaterializationPlan

`city_plan_d6` required payload：`runId`、`citySeedId`。可选 `dimensionId` / `playerName` 用于定位 ServerLevel。

输入：

- D4 `structure_anchor_map.json`
- D5 `reservation_mask_plan.json`
- 可选既有 `placed_structure_ledger.json`

输出文件：`structure_materialization_plan.json`，`schemaVersion=city_structure_materialization_plan.v0.1`。

`plannedWorldgenStructures[]` 至少包含：

- D4 anchor 原始字段。
- `anchorChunk`：planned anchor 所在 chunk。
- `requiredChunkRange`：由 locked collision envelope 推导的 chunk range；无 locked 信息时才允许用 planned envelope 诊断。
- `reservedEnvelope` / `plannedFootprint` / `actualFootprint`。
- `locked=true`
- `lockedActualFootprint`
- `lockedCollisionEnvelope`
- `lockedBBoxGroupKey`
- `availableEnvelopeGroupKeys`
- `collisionClearanceBlocks`
- `status`：`planned_worldgen` / `already_generated` / `invalid_anchor` / `registry_missing`。
- `reasonCode`：`WAITING_FOR_WORLDGEN`、`STRUCTURE_CHUNK_ALREADY_GENERATED` 等。
- `actualLocalBounds`
- `actualBBoxGroupKey`
- `pieceBoxes`
- `expectedStartSignature`
- `envelopeMode` / `selectedEnvelopeGroupKey`

约束：

- `city_plan_d6` 不写世界，不要求目标 chunk loaded。
- D6 会对 selected anchor 做 non-mutating configured structure preflight，生成 actual bbox、piece boxes、actual bbox group key 和 `expectedStartSignature`。
- D6 是最终防撞准入点：用 `actualFootprint + collisionClearanceBlocks` 检查本轮结构和既有 ledger；默认 `collisionClearanceBlocks=4`。
- 若 actual bbox group 与 D4 dominant / selected group 不一致，但 facts 中存在该 group 且 locked collision 不重叠，D6 应锁定实际 group，而不是直接失败；若 `fixed_bbox_group` 的 actual group 不在 `availableEnvelopeGroupKeys` 中，返回 `BBOX_GROUP_NOT_IN_FACTS`。
- D6 trace 记录 actual bbox、actual local bounds、actual bbox group key、locked collision envelope、collision/mask/safety envelope，便于解释本次生成形态。
- 若尚未执行 `city_execute_d5 confirmWorldMutation=true` 激活 planned structure registry，D6 仍可先产出 planned_worldgen preflight 计划；调用方必须在目标 chunk 首次生成前执行 `city_execute_d5`。
- 未生成 chunk 返回 `planned_worldgen` / `WAITING_FOR_WORLDGEN`，不算失败。
- chunk 已经生成到 `FEATURES` 或之后且没有 worldgen ledger 时，返回 `STRUCTURE_CHUNK_ALREADY_GENERATED`，active path 不再允许 late paste。
- 真实 bbox / piece boxes 由 worldgen hook 写入 `worldgen_placement_ledger.json`，再由 `city_execute_d7` 汇总到 placed ledger。

## execute_d7 True-Run

入口名继续使用 `city_execute_d7`，但正式语义为 worldgen ledger / chunk 状态检查。

参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

- 读取 D6 `structure_materialization_plan.json`。

- `structure_materialization_trace.json`

## Inferred Function Area

真实落地后输出 `inferred_function_area_map.json`，`schemaVersion=city_inferred_function_area_map.v0.1`。

首版按 placed structure 的 TerraSense `functionTerms[0]` 聚类：

- `inferredAreaId`
- `primaryFunctionTerm`
- `structures[]`
- `inferredBounds`

它是落地结果的归类，不是 D4 预设边界。
