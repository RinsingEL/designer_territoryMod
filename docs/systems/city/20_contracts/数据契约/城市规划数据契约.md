# 城市规划数据契约

## 定位

本文定义 City 系统 C1-C4 城市规划过程的结构化产物。字段命名先作为契约草案，进入实现时应保持版本化和兼容说明。

## 版本

| 字段 | 当前值 | 说明 |
| --- | --- | --- |
| `schemaVersion` | `city_planning.v0.1` | City 规划契约初版。 |
| `coordinateUnit` | `block` | 对外坐标默认使用 block 坐标。 |
| `gridUnit` | `cell` | 规划图层可使用局部 cell 网格，并必须提供 block 转换。 |

## PatchGroupPlan

D4 首版的 C2 `PatchGroupPlan` 由 MCP 调用方侧 AI / Codex 看 `landform_review_map.png` 后生成并提交；Java 运行时只做引用校验、功能类型校验、实体化和产物导出，不内置 LLM 调用。D4 使用 D3 `city_landform_review_package.json` 中的 `memberCells` 合并功能区真实 mask；只有缺少成员格子时才显式降级到 envelope。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_patch_group_plan.v0.1`。 |
| `cityId` | string | 是 | 必须与 D3 审查包一致。 |
| `groups` | object[] | 是 | AI 草案功能区分组。 |

`groups[]` 关键字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `groupId` | string | 是 | AI 草案临时 ID。 |
| `zoneName` | string | 是 | 转成 City 功能区后的名称。 |
| `functionType` | string | 是 | 固定枚举之一：`civic_core`、`residential`、`production`、`market`、`farm_or_pasture`、`defense`、`harbor_or_waterfront`、`sacred_or_cultural`。 |
| `patchLabels` | string[] | 否 | 引用 D3 图上 `mapLabel`；与 `landformPatchRefs` 至少提供一个。 |
| `landformPatchRefs` | string[] | 否 | 引用 GIS `landformPatchId`。 |
| `mainBuildingRole` | string | 否 | 给后续 D6 / C5 使用的主要建筑角色，不在 D4 校验结构 catalog。 |
| `supportingBuildingRoles` | string[] | 否 | 辅助建筑角色。 |
| `groupReason` | string | 否 | AI / Codex 看图后的分组理由；远距离拼接无理由时进入 needs_review。 |
| `adjacencyIntent` | string | 否 | 靠近 / 远离意图，仅记录。 |
| `splitRequested` | bool | 否 | D4 v0.1 只记录 warning，不实际切 patch。 |

## TerraSenseStructureProfileSource

D6 输入。描述本轮结构画像从哪个 TerraSense 导出快照读取。D6 只消费 TerraSense 的正式导出或显式 debug catalog，不直接读取 `ScanWorkspace.structures/*` 原始扫描目录。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `terrasense_structure_profile_source.v0.1`。 |
| `sourceType` | string | 是 | `structure_profile_jsonl`、`c3_5_compat_catalog`、`debug_catalog`。 |
| `catalogMode` | string | 是 | `official`、`compat`、`debug`。 |
| `profilePath` | string | 条件必填 | `StructureProfile.jsonl` 路径；`sourceType=structure_profile_jsonl` 时必填。 |
| `compatCatalogPath` | string | 条件必填 | `C3_5_StructureCatalog.preprocessed.json` 路径；`sourceType=c3_5_compat_catalog` 时必填。 |
| `debugCatalogPath` | string | 条件必填 | debug `StructureProfileCatalog` 路径；`sourceType=debug_catalog` 时必填。 |
| `functionEnumPath` | string | 否 | `C3_5_FunctionEnumTable.json` 路径。 |
| `vocabularySnapshotPath` | string | 否 | `StructureVocabulary.snapshot.json` 路径。 |
| `terrasenseRunId` | string | 否 | TerraSense 导出运行 ID。 |
| `allowDebugUnapproved` | bool | 否 | 是否允许 debug 模式读取未 approved 项；正式模式必须为 false。 |
| `quality` | object | 是 | 导入质量报告。 |

导入规则：

- 正式模式只允许 `review_state=approved` 且词表术语为 approved 的结构进入候选。
- `quality_tags` 包含 `reject` 的结构不得进入候选。
- `pending`、`needs_review`、`proposed` 术语只能在 `catalogMode=debug` 时进入 `needs_review`。
- `StructureProfile.jsonl` 是首选输入；`C3_5_StructureCatalog.preprocessed.json` 只是过渡兼容层。

| `source` | object | 是 | 来源 `TerraSenseStructureProfileSource` 摘要。 |
| `catalogMode` | string | 是 | `official`、`compat`、`debug`。 |
| `structures` | object[] | 是 | 结构画像。 |
| `quality` | object | 是 | 目录完整性和 needs_review 记录。 |

`structures[]` 关键字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `structureId` | string | 是 | 原版、mod 或项目结构 ID。 |
| `sourceProfileRef` | string | 是 | 来源 TerraSense `StructureProfile` 或兼容 catalog 记录。 |
| `profileType` | string | 是 | TerraSense `single` 或 `jigsaw_system`。 |
| `sampleType` | string | 否 | TerraSense 样本类型，例如 `single_template`、`structure_assembly`、`jigsaw_assembly`。 |
| `placementKind` | string | 是 | D7 放置入口；真实放置候选必须是 `minecraft_place_structure`，template / jigsaw 画像只能作为 debug 或参考。 |
| `placementCommand` | string | 否 | TerraSense 实际放置命令；`structure_assembly` 候选建议保留，供 D7 trace 和复现使用。 |
| `footprintMode` | string | 是 | `fixed_footprint` 或 `variable_area`。 |
| `functionTags` | string[] | 是 | 适用功能区类型。 |
| `styleTags` | string[] | 否 | 风格标签。 |
| `placementTags` | string[] | 否 | 位置倾向标签，例如临路、临水、广场边。 |
| `usageTags` | string[] | 否 | 用途标签，例如主建筑、装饰、地标、公共核心。 |
| `qualityTags` | string[] | 是 | TerraSense 审核质量标签。 |
| `fixedFootprint` | object | 条件必填 | 固定结构尺寸；仅 `fixed_footprint` 必填。 |

| `clearanceBlocks` | int | 是 | 结构周边预留。 |
| `expectedAreaRange` | object | 条件必填 | 非固定结构建议面积区间；仅 `variable_area` 使用。 |
| `connectorsRef` | string | 否 | TerraSense jigsaw / connector 真值引用；D6 不解析。 |

| `jobId` | string | 是 | 本次 bounded jigsaw job ID。 |
| `sourceStructureId` | string | 是 | D6 选择的 configured structure ID。 |
| `pieces[]` | object[] | 是 | 通过 validator、准备或已经 paste 的 piece。首版可只有 start piece。 |
| `stoppedBranches[]` | object[] | 是 | 被拒绝、停止或 endcap / truncated 的分支记录。 |
| `estimatedFootprint` | object | 否 | accepted pieces 合并 footprint；没有 accepted piece 时可为候选所需范围或缺省。 |
| `visibleAreaCost` | int | 是 | accepted pieces 面积成本。 |
| `requiredChunkRange` | object | 否 | 执行 paste 前需要加载的 chunk 范围。 |
| `quality` | object | 是 | accepted piece 数、stopped branch 数、start-piece-only 标记和 warning。 |

`pieces[]` 至少记录 `pieceId`、`templateId`、`poolId`、`anchorBlock`、`rotation`、`footprint`、`connectorRefs`、`validatorResult`、`ruleDecision`、`ruleResults[]` 和 `visibleAreaCost`；多 piece solver 输出还应记录 `branchId`、`parentPieceId`、`parentConnectorId` 和 `depth`。`templateId` 必须来自可解析的 template 资源 ID；如果 pool element 无法稳定解析 template ID，必须作为 `UNSUPPORTED_POOL_ELEMENT` 拒绝并写入 trace，不得把 MC `StructurePoolElement.toString()` 或诊断字符串伪装成 template ID / D7 真实 `structureId`。由子 pool 发现得到的 candidate 可先带 `adapterScope=child_pool_prototype`、`sourcePoolId`、`prototypeDepth` 和 `prototypePlacementStatus=connector_alignment_pending`；solver 对齐成功后必须写 `adapterScope=child_pool_aligned`、`prototypePlacementStatus=connector_aligned`、`alignmentStatus=aligned`、`alignmentDelta`、`matchedConnectorId`，并将接回父 piece 的 connector 标记为 `consumedByParent=true`。对齐失败时写 `alignmentStatus=failed` 和稳定 reasonCode。

true-run accepted piece paste 后，实际写世界成功的 piece 应补充 `pasteStatus=applied`、`worldMutationApplied=true`、`resolvedPoolId`、`resolvedTemplateId` 和 `clearedVegetationBlocks`；失败时写 `pasteStatus=failed` 与 `pasteReasonCode`，不得进入真实 `appliedPieces[]`。

## BoundedJigsawTrace

D7+ 运行时对象。记录受控 jigsaw 物化的可控性分类、接受 / 拒绝 piece 和失败原因。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_bounded_jigsaw_trace.v0.1`。 |
| `capability` | string | 是 | 例如 `bounded_jigsaw_supported`。 |
| `sourceStructureId` | string | 是 | D6 选择的 configured structure ID。 |
| `structureRegistryKey` | string | 否 | MC registry key。 |
| `startPool` | string | 否 | 解析到的 start pool。 |
| `targetAreaBlocks` | int | 是 | 本次 variable_area 预算。 |
| `plan` | object | 是 | 本次最小或完整 `BoundedJigsawPlan`。 |
| `acceptedPieces[]` | object[] | 是 | 通过 validator 并准备或已经写世界的 piece。 |
| `rejectedPieces[]` | object[] | 是 | 被 allowed area、占用、预算等规则拒绝的 piece。 |
| `stoppedBranches[]` | object[] | 是 | 分支停止 / 收尾记录；start-piece 被拒绝时必须写入对应 stop_branch。 |
| `fallbackUsed` | bool | 否 | 是否降级。首版 bounded 路径不自动 fallback。 |
| `failureSummary` | object | 否 | bounded 内部 reasonCode 聚合。 |
| `metrics` | object | 否 | accepted / rejected / stopped 数量和 visibleAreaCost。 |
| `terrainProbeSummary` | object | 否 | MC 后端对每个 piece footprint 的运行时地形 / 流体 / chunk 覆盖探测汇总。 |

`poolAdapterStatus` 可记录 MC pool adapter 阶段，例如 `start_pool_adapter` 或 `child_pool_discovery`。当 adapter 已读取 connector 指向的子 pool 时，trace 应包含 `poolAdapterReport`：`schemaVersion=city_bounded_jigsaw_pool_adapter_report.v0.1`、`status=child_pool_discovery`、`discoveredPools[]`、`missingPools[]`、`discoveredPoolCount`、`missingPoolCount` 和 `warnings[]`。`worldPasteMode` 可记录真实世界写入模式：`dry_run_plan_only` 表示只产出计划不改世界，`start_piece_adapter` 表示旧过渡模式只真实写 start piece，`accepted_piece_template_paste` 表示 true-run 逐个写入 accepted pieces 并允许多条 piece ledger。

`terrainProbeSummary` 至少记录 `schemaVersion=city_terrain_probe_summary.v0.1`、`waiting`、`missingChunks`、`probeCount` 和 `probes[]`。每个 probe 至少记录 `schemaVersion=city_terrain_probe.v0.1`、`probeId`、`candidateId`、`sampleMode`、`chunkCoverage`、`footprint`、`sampleCount`、`heightMin`、`heightMax`、`heightDelta`、`fluidOverlapBlocks`、`solidSupportRatio` 和阈值参数。chunk 未加载时应写 `JIGSAW_RULE_CHUNK_WAITING` 并让 job waiting；高差、水体或支撑不足应写稳定 reasonCode，不能让对应 piece 进入 accepted paste。

首版 reasonCode 至少包括：

BOUNDED_JIGSAW_PIECE_AMBIGUOUS
