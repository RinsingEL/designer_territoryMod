# 城市规划数据契约

## 定位

本文保留 City 早期 C1-C4 / 旧 D4-D7 规划契约，并记录仍被当前实现复用的少量共享对象。它不是当前结构落地主链的完整契约入口。

当前真值以 `结构落地交接契约.md`、`City模板建筑主路径数据契约.md`、`CityLandformReviewPackage数据契约.md` 和 `City调试MCP接口.md` 为准。

## 契约状态

- 仍被当前实现复用：`Grid`、`RoadIntent`、`BuildOperationPlan`、`WorldMutationReport`、`TerraSenseStructureProfileSource`、`StructureProfileCatalog`、`Quality`。
- 已从实现仓库删除：`PatchGroupPlan`、`FunctionZoneMap`、`FunctionZoneTerrainStats`、`BoundaryIntent`、`BuildableAreaMap`、`FilteredStructureCatalog` 之后的旧 D6/D7 选择与落地对象，以及 `CityConstraintField` / `BoundedJigsawPlan` / `BoundedJigsawTrace`。
- `CityPlanningPackage`、`TerrainPatchMap`、`CityGrammarPlan` 只保留为早期草案，不是 active endpoint artifact。
- 历史章节用于解释旧 artifact 和 hard-fail 隔离规则，不表示运行时仍能生产或消费这些 schema。

## TerraSenseStructureProfileSource

当前结构画像输入。描述本轮结构画像从哪个 TerraSense 导出快照读取。`CityStructureProfileCatalog` 只消费 TerraSense 的正式导出或显式 debug catalog，不直接读取 `ScanWorkspace.structures/*` 原始扫描目录。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `terrasense_structure_profile_source.v0.1`。 |
| `sourceType` | string | 是 | `structure_profile_jsonl`、`debug_catalog`。 |
| `catalogMode` | string | 是 | `official`、`debug`。 |
| `profilePath` | string | 条件必填 | `StructureProfile.jsonl` 路径；`sourceType=structure_profile_jsonl` 时必填。 |
| `debugCatalogPath` | string | 条件必填 | debug `StructureProfileCatalog` 路径；`sourceType=debug_catalog` 时必填。 |
| `vocabularySnapshotPath` | string | 否 | `StructureVocabulary.snapshot.json` 路径。 |
| `terrasenseRunId` | string | 否 | TerraSense 导出运行 ID。 |
| `allowDebugUnapproved` | bool | 否 | 是否允许 debug 模式读取未 approved 项；正式模式必须为 false。 |
| `quality` | object | 是 | 导入质量报告。 |

导入规则：

- 正式模式只允许 `review_state=approved` 且词表术语为 approved 的结构进入候选。
- `review_state` 是唯一准入门禁；拒绝结构使用 `review_state=rejected`，不再叠加 `qualityTerms` 门禁。
- `pending`、`needs_review` 只能在 `catalogMode=debug` 时进入；debug 缺审核状态统一归一为 `unreviewed`，不得向 AI 暴露空字符串。
- `StructureProfile.jsonl` 是正式输入；旧 `C3_5_StructureCatalog.preprocessed.json` / `function_candidates` / `functionTags` 兼容层不再属于当前结构落地主链，缺少 TerraSense `functionTerms` 的结构必须进入 `needs_review` 或被 hard block。

## StructureProfileCatalog

当前 D2/D4 输入。程序从 `TerraSenseStructureProfileSource` 归一得到结构画像目录，供结构目录查询、envelope profiling 和 anchor / array 候选使用。当前模板建筑主路径另读 `CityTemplateCatalog`，不把本目录当作 NBT 模板尺寸真值。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_semantic_profile_catalog.v0.4`。 |
| `source` | object | 是 | 来源 `TerraSenseStructureProfileSource` 摘要。 |
| `catalogMode` | string | 是 | `official`、`debug`。 |
| `semanticProfiles` | object[] | 是 | 结构语义画像。 |
| `quality` | object | 是 | 目录完整性和 needs_review 记录。 |

`semanticProfiles[]` 关键字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `semanticProfileId` | string | 是 | 从 `structureId` 归一得到的结构画像 ID。 |
| `sourceProfileRef` | string | 是 | 来源 TerraSense `StructureProfile` 记录。 |
| `reviewState` | string | 是 | 正式为 `approved`；debug 缺值归一为 `unreviewed`。 |
| `functionTerms` | string[] | 是 | TerraSense 功能术语，至少一项。 |
| `planningRoleTerms` | string[] | 是 | 关键/填充等规划角色；允许为空，不做 Java enum。 |
| `terrainModes` | string[] | 是 | City 固定 placement topology 枚举；正式画像至少一项，值域为 `SURFACE/EMBEDDED/FLOATING`，多值按 OR 解释。 |
| `styleTerms` | string[] | 是 | 风格语义；允许为空，只给 AI / 人工阅读，程序不得据此评分或筛选。 |

## BoundedJigsawPlan（历史，已删除）

D7+ 运行时对象。记录受控 jigsaw 本次准备或已经执行的 piece 计划。当前实现已有 solver 核心，可在已解析 candidate pool 输入下按 connector 生成多 piece plan；MC pool adapter 已能把真实 `StructureTemplatePool` 的 start elements 归一为 solver input，并从 connector 的 `pool` 字段发现子 pool。子 pool piece 作为 prototype 输入，solver 会按当前 branch 的父 connector 做首版几何对齐；无法匹配 name / target 或朝向时必须结构化失败。每个候选 piece 在 accept / reject 前都应写 `ruleDecision` 与 `ruleResults[]`，其中至少能体现 connector、预算、功能区 allowed area、buildable / reserved cell、runtime occupied 和 terrain probe 结果。`targetAreaBlocks` 是评分目标；默认 `budgetHardCapRatio=1.2` 对应的 `areaHardCapBlocks` 才是硬上限。solver 对合法候选应用 `visible_area_target_fit` 优先选择加入后总面积更接近目标的 piece，并在 accepted piece / metrics 中记录面积贴合度；该评分不得自动放大 `maxPieces` / `maxDepth`。true-run bounded 后端只 materialize dry-run 选中的同一份 plan，不重新求解；完整 endcap、台基、地形过渡、嵌入地面和更多真实样本仍需后续继续增强。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | `city_bounded_jigsaw_plan.v0.1`。 |
| `planId` | string | 是 | 稳定计划 ID。 |
| `jobId` | string | 是 | 本次 bounded jigsaw job ID。 |
| `sourceStructureId` | string | 是 | D6 选择的 configured structure ID。 |
| `pieces[]` | object[] | 是 | 通过 validator、准备或已经 paste 的 piece。首版可只有 start piece。 |
| `stoppedBranches[]` | object[] | 是 | 被拒绝、停止或 endcap / truncated 的分支记录。 |
| `estimatedFootprint` | object | 否 | accepted pieces 合并 footprint；没有 accepted piece 时可为候选所需范围或缺省。 |
| `visibleAreaCost` | int | 是 | accepted pieces 面积成本。 |
| `requiredChunkRange` | object | 否 | 执行 paste 前需要加载的 chunk 范围。 |
| `quality` | object | 是 | accepted piece 数、stopped branch 数、start-piece-only 标记、面积贴合度和 warning。 |

`pieces[]` 至少记录 `pieceId`、`templateId`、`poolId`、`anchorBlock`、`rotation`、`footprint`、`connectorRefs`、`validatorResult`、`ruleDecision`、`ruleResults[]` 和 `visibleAreaCost`；accepted piece 可记录 `areaTargetFit`，其中包含 `targetAreaBlocks`、`currentVisibleAreaCost`、`pieceVisibleAreaCost`、`projectedVisibleAreaCost`、`distanceToTargetBlocks` 和 `fillRatio`。多 piece solver 输出还应记录 `branchId`、`parentPieceId`、`parentConnectorId` 和 `depth`。`templateId` 必须来自可解析的 template 资源 ID；如果 pool element 无法稳定解析 template ID，必须作为 `UNSUPPORTED_POOL_ELEMENT` 拒绝并写入 trace，不得把 MC `StructurePoolElement.toString()` 或诊断字符串伪装成 template ID / D7 真实 `structureId`。由子 pool 发现得到的 candidate 可先带 `adapterScope=child_pool_prototype`、`sourcePoolId`、`prototypeDepth` 和 `prototypePlacementStatus=connector_alignment_pending`；solver 对齐成功后必须写 `adapterScope=child_pool_aligned`、`prototypePlacementStatus=connector_aligned`、`alignmentStatus=aligned`、`alignmentDelta`、`matchedConnectorId`，并将接回父 piece 的 connector 标记为 `consumedByParent=true`。对齐失败时写 `alignmentStatus=failed` 和稳定 reasonCode。

true-run accepted piece paste 后，实际写世界成功的 piece 应补充 `pasteStatus=applied`、`worldMutationApplied=true`、`resolvedPoolId`、`resolvedTemplateId` 和 `clearedVegetationBlocks`；失败时写 `pasteStatus=failed` 与 `pasteReasonCode`，不得进入真实 `appliedPieces[]`。

## BoundedJigsawTrace（历史，已删除）

D7+ 运行时对象。记录受控 jigsaw 物化的可控性分类、接受 / 拒绝 piece 和失败原因。

| 字段 | 类型 | 必填 | 说明 |

| `plan` | object | 是 | 本次最小或完整 `BoundedJigsawPlan`。 |
| `acceptedPieces[]` | object[] | 是 | 通过 validator 并准备或已经写世界的 piece。 |
| `rejectedPieces[]` | object[] | 是 | 被 allowed area、占用、预算等规则拒绝的 piece。 |
