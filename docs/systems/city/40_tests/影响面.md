# City LandUse、Decoration 与建筑群生活感影响面

## 主链变化

当前新增可选步骤：`D4 -> D5 预案 -> D6 locked footprint -> LandUse -> Decoration -> execute_d5`。它不改变 D4 先落建筑的职责，也不恢复旧 FunctionZone 主线。

| 环节 | 变化 | 回归重点 |
| --- | --- | --- |
| D3 | 新增 `LandUseTerrainField` 粗格事实；临水生活感切片只消费现有 `water`、`shore`、`waterDistance`、`plain` 与坡度。 | 不主动加载 chunk；原 patch / biomeSummary 不回归；不得引入虚构资源扫描。 |
| D4 | anchor / array / composite 输出稳定 group provenance；阵列项可按中心、水体或 cardinal 目标自动选择模板朝向。 | 不恢复旧 FunctionZone；自动朝向只枚举目录允许旋转，不改变候选点与 collision / mask 口径。 |
| D5 / D6 | D5 仍是轻量预案；D6 locked footprint 成为 LandUse 最终硬排除。 | 不提前冻结 LandUse，不改变结构锁定与城墙 reservation。 |
| LandUse / Decoration | intent v0.3 在本次城市规划中传入 `surfaceAlgorithmDefaults[]`，group 只覆写例外；程序对 64 格内兼容 PAVE / CULTIVATE 做双向引导扩张。扩张完成后，SurfacePrintPlan v0.2 独立选择 `uniform|contour_bands`；后者按连续高程冻结全局 FIELD / 两侧 BANK / WATER spans，Decoration 只保留稀疏内容。 | `autoConnect=false`、超距、异类或地形阻断不得连接；刷地算法和材料变化不得改变扩张结果。contour 跨 chunk 不得重算相位 / role，exclusion 不得回盖，水槽转角与开放端点不得漏水。Surface-owned area 的 `uniform_fill/cross_section_repeat/parallel_rows` Decoration 必须拒绝，scatter / edge / grid 稀疏程序仍可用。 |
| 关键装饰候选 | `city_plan_decoration_anchor_candidates` 在正式 dressing 前，为 required 单点 prefab 生成完整 footprint + clearance 候选；多个关键装饰按顺序选，前面已固定 programs 作为障碍。 | 不改变最终 DecorationProgram schema；只返回相对 `coordinateFramePatch`。普通 Pattern 不进入候选；不得采样地形、加载 chunk、自动选择或伪造空集 fallback。 |
| execute_d5 | 校验 area / SurfacePrintPlan v0.2 / completion identity 与 runtime block 注册状态，预构建 owner index，再与 Decoration frozen plan 一起激活。 | sampler 不加载 chunk；缺 surface artifact、hash 漂移、未注册方块和批量职责冲突在 registry mutation 前 hard fail；旧 SurfacePrintPlan、active registry 或 ledger 明确拒绝并要求清理重规划。 |
| noise worldgen | Decoration foundation 继续进入 Beardifier；后续规划的全部 `geomantia:` 城市模板仍以单-piece `StructureStart` 进入 `beard_thin`。 | LandUse direct-mask 不再提交 run / foundation segment；Decoration segment 按 owner 索引、稳定去重并取最大正贡献，compute 内无 registry mutation / IO / 高度采样。 |
| FEATURES | v0.2 owner 只裁切 prepared 全局 role spans，直接写 FIELD、两侧 BANK、WATER、END_CAP 与 BANK overlay，再写 FIELD-only CROP 和 channel-aware BOUNDARY；全部开放水带端点已按全局邻接冻结。 | 不可写、快照或写入失败仍整 owner 回滚；WATER 邻接与封口不得按 chunk 重判。 |
| worldgen observation | City 写入返回后登记 touched position、声明 block ID 与 `postWriteState`；FEATURES TAIL / retry tick / chunk save 回调读取 `actualState`，入队后由 tick 限量写独立 chunk JSONL。预制体及 LandUse direct 写入以 capture 绑定的 mutation token 标记观测归属。 | 不把逐块状态塞进 owner ledger；物理恢复成功后只删除本 mutation 的期望，恢复失败则保留证据；LandUse 中心与四邻、prefab 重叠位置都不得裸弹栈或按深度截断，以免吞掉交错的失败证据；查询不加载 chunk；当场未落地、后续状态变化和 air 可直接定位到坐标和 source。 |
| MCP 调用边界 | Node 在 handler 前后写 started/completed 事件，统一 `callId`，自动记录 UTC 时间、单调耗时和 timeout 分类。 | 外层中断时至少保留未配对 started；日志失败不影响 stdio 响应；不得用人工文档计时替代。 |
| RoadWeaver | 仍按真实路线后写。 | 道路可覆盖 LandUse，LandUse 不猜路线、不抢最终 surface 权威。 |

本轮 direct-mask 改造减少了 catalog / prefab 级阻断来源，但没有改变 owner chunk 事务粒度：任一不可替换 overlay / crop 或写入失败仍会使整个 owner 回滚。该行为继续留在失败粒度 bug 计划中，不计作本轮已解决项。

## 配置与版本边界

- 新配置根目录 `config/geomantia/city_land_use/` 含 `settings.json` 与 `profiles/<profileId>.json`；默认 `enabledInWorkflow=false`、profile 为 `default_v0_1`，规则档案保持严格 `city_land_use_rules.v0.1`。64 格自动连接距离是程序默认，不进入 profile 或 AI 配置；缺失 bundled 文件才补装，不覆盖用户文件。
- 请求 `enableLandUseLayer` 优先于 settings；未显式开启且配置关闭时，现有 workflow 行为与 artifact 保持不变。
- 独立 `city_plan_land_use` 是显式规划入口，可不传 intent；服务端自动使用空 overrides。
- intent 使用 `city_land_use_intent_plan.v0.3` 严格 schema；v0.2 `global_axis|radial` 明确拒绝。每城材质由本次 intent 的算法默认决定，解析优先级为 group override > 本次 intent algorithm default > policy 内置 fallback；静态 profile 只提供服务端规则兜底。area plan 保持 v0.1，SurfacePrintPlan 只接受 v0.2。旧 LandUse artifact、active registry 和 ledger 必须在升级时清理，随后完整重规划；历史只从 Git 追溯，不提供运行时迁移。
- 当前 material palette 包含 `MICRO_FILL_SUBGRADE=minecraft:dirt` 并进入 `paletteHash`；所有新 active plan 必须携带完整当前 palette，缺键直接拒绝。
- Decoration content index / program 当前为 v0.3。v0.2 可只读解释但 query 必须显式报告 upgrade required；仅 managed 且未改动的旧默认 catalog 可经确认、备份后升级，自定义 catalog 不自动改写。
- 关键装饰候选不新增配置或持久化 selection state；复用当前 decoration catalog/style、program v0.4 target、D5/D6/LandUse 硬障碍和现有相对坐标字段。
- 已到 FEATURES 的 chunk 不回填。启用后只影响未来首次生成 chunk；停用不回滚已写世界。

## 风险与验收责任

- 算法风险：引导目标漏选 / 误选、背向仍扩张、地形阻断失效、大片单色或农田整体矩形。连接继续以 v0.3 `automaticSurfaceConnections[]` 和 64 格边界测试验收；刷地另以 `ContourBandSurfaceClassifierTest`、spans 非 bbox、缓坡等高线轮廓、平地径向回退和固定输入确定性验收，二者不得互相影响。
- 朝向风险：目标引用不可解、入口声明含糊、自动旋转破坏紧凑度或结果不稳定。以候选组合测试、`orientationDecision` 和现场门面复核验收。
- 关键装饰风险：只检查 anchor 点导致大 prefab 越界、AI 独立规划多个点后互相重叠、把未采样地形误报为安全，或空候选时退回手写世界坐标。以完整 footprint/clearance、`fixedDecorationObstacles`、`terrainSampling=not_performed`、空集 rejectionCounts 和候选回填后单 slot 一致性验收。
- 世界写风险：材质覆盖自然 / 结构、BANK overlay 或作物回盖 WATER、转角邻接更新不完整、开放端点漏水、跨 chunk 接缝和 partial write。以冻结全局 role spans、端点封口、系统错误 owner 回滚、crop/boundary role 冲突、`x=15/16` 拼接回归与 ledger 验收；真实 `WorldGenRegion` 跨 chunk 邻接更新仍需实机复验。
- 微整地风险：把开放沟谷误判为坑、跨 owner 判定不一致、邻水造地或局部半填。以同 area halo、连通面积 / span / depth 上限、水体拒绝、当前 palette 严格校验、GameTest 和新区块现场验收。
- 顺序风险：Decoration 早于 LandUse、RoadWeaver 被 LandUse 回盖。以集成测试和新存档实际道路穿越验收。
- 生命周期风险：area / surface / palette hash 漂移、重启重复写或旧 chunk 混入。以 activation 实际写入 owner status preflight、当前 ledger schema 严格拒绝、owner 幂等和跨 owner / restart 一致性验收；不测试或承诺旧 ledger 迁移。
- 性能风险：每 owner 扫全城 area / band spans、全局锁内地形采样或大账本逐 block 写入。以 prepared owner index、owner 级摘要 ledger 和大田 lookup / scan count 测试验收。
- 连续地形风险：D3 粗高程未经插值产生 cell 方格轮廓、局部梯度噪声令条带抖动、平地阈值导致 mode 不稳定、chunk 边界重启相位或 owner 各自猜端点。以 SurfacePrintPlan v0.2 冻结 mode / anchor / role spans、跨 chunk global phase、输入顺序扰动和 restart 测试验收。
- Decoration foundation 风险：噪声递归、过深填充、肩部硬切、端点外延、重复 segment 密度叠高、fluid 下造地。以 common segment view、prepared chunk index、positive max contribution、depth/shoulder、endpoint / lateral water 测试验收；LandUse 不进入该路径。
- Decoration 可观测性风险：计划过 foundation 被误报为已成形，或只写 applied ledger 吞掉 skip / defer / failure。v0.3 必须同时核对 `foundationPlanned/materialized/applied`、fragmentOutcomes、terrain activation trace 和激活 preview。
- 现场证据风险：执行器返回成功后方块被后续 feature 覆盖，或保存前已变成 air，但 AI 仍按 ledger 数量宣称真实落地。必须同时检查 `post_features` 与可用的 `chunk_save` 观测；`pendingSaveVerification=true` 只能表示等待保存检查，不能视为通过。
- 观测性能风险：大模板仍会增加 touched-position 读取与队列内存。首版禁止在 worldgen/save 回调内做 JSON/文件 IO，server tick 每次最多刷 2 条；模板局部 block 列表按 hash 缓存，pending-save 同 chunk 合并。不得扩展为全 chunk 扫描或全服 block listener，真实压测仍需检查 tick 延迟与队列积压。
- 本轮自动测试不能替代区域形态与真实材质效果的人工审阅；生活感切片必须额外由人工判断农业、商业、行政及其活动关系是否可读。
