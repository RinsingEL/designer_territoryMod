# City LandUse、Decoration 与建筑群生活感影响面

## 主链变化

当前新增可选步骤：`D4 -> D5 预案 -> D6 locked footprint -> LandUse -> Decoration -> execute_d5`。它不改变 D4 先落建筑的职责，也不恢复旧 FunctionZone 主线。

| 环节 | 变化 | 回归重点 |
| --- | --- | --- |
| D3 | 新增 `LandUseTerrainField` 粗格事实；临水生活感切片只消费现有 `water`、`shore`、`waterDistance`、`plain` 与坡度。 | 不主动加载 chunk；原 patch / biomeSummary 不回归；不得引入虚构资源扫描。 |
| D4 | anchor / array / composite 输出稳定 group provenance；阵列项可按中心、水体或 cardinal 目标自动选择模板朝向。 | 不恢复旧 FunctionZone；自动朝向只枚举目录允许旋转，不改变候选点与 collision / mask 口径。 |
| D5 / D6 | D5 仍是轻量预案；D6 locked footprint 成为 LandUse 最终硬排除。 | 不提前冻结 LandUse，不改变结构锁定与城墙 reservation。 |
| Decoration | v0.3 content pose、全局连续 run 和 fill-only foundation；生活感切片以 LandUse `areaId` 组织农业、商业和行政内容；同一逻辑区拆成多个不连通组件时合并消费。 | v0.2 只读兼容不改文件；内容必须来自运行时 catalog；不能只消费同 ID 的首个组件；商业不能退化为只摆商店。 |
| execute_d5 | generator 采样并冻结 Decoration run / foundation，再预检和激活。 | sampler 不加载 chunk；缺 ServerLevel 的连续 run hard fail；同一 frozen plan 写 artifact 与 active registry。 |
| noise worldgen | Beardifier 增加受限正密度 foundation；后续规划的全部 `geomantia:` 城市模板以单-piece `StructureStart` 进入 `beard_thin`。 | 目录模型和 D6 强制归一，D5/worldgen 只认冻结值，旧 active plan 不迁移；start 必须在 createStructures 冻结 generator datum，且与 decoration foundation 相交时需实机观察是否过填。 |
| FEATURES | 新 palette 的 PAVE 先做小型封闭坑微填，再写 surface / boundary，最后进入 Decoration；`WorldGenRegion` 不处理更新 flags，连接类方块由 LandUse 执行器显式重算当前格和四个水平邻居。 | 微填只向上 1..3 格且拒绝深坑、长沟、水体和跨 mask 低洼；grading halo 只读；连接回刷最多触达当前 FEATURES write radius 1 内的相邻格，不远写其他 chunk；CULTIVATE 无 interior surface op，ledger 幂等、旧 chunk 拒绝。 |
| RoadWeaver | 仍按真实路线后写。 | 道路可覆盖 LandUse，LandUse 不猜路线、不抢最终 surface 权威。 |

## 配置与兼容

- 新配置根目录 `config/geomantia/city_land_use/` 含 `settings.json` 与 `profiles/<profileId>.json`；默认 `enabledInWorkflow=false`、profile 为 `default_v0_1`。缺失 bundled 文件才补装，不覆盖用户文件；profile 内容进入 `ruleProfileHash`，修改后必须重跑 LandUse，旧 plan 不得激活。
- 请求 `enableLandUseLayer` 优先于 settings；未显式开启且配置关闭时，现有 workflow 行为与 artifact 保持不变。
- 独立 `city_plan_land_use` 是显式规划入口，可不传 intent；服务端自动使用空 overrides。
- intent 与 area plan 均使用 v0.1 严格 schema，不兼容旧 FunctionZone / PatchGroup payload，也不提供自动迁移。
- 默认 material palette 新增 `MICRO_FILL_SUBGRADE=minecraft:dirt` 并进入 `paletteHash`；因此只对新激活计划启用。已冻结的旧 active palette 缺少该键时保持关闭，不因代码升级改变未生成 owner 的地形行为。
- Decoration content index / program 当前为 v0.3。v0.2 可只读解释但 query 必须显式报告 upgrade required；仅 managed 且未改动的旧默认 catalog 可经确认、备份后升级，自定义 catalog 不自动改写。
- 已到 FEATURES 的 chunk 不回填。启用后只影响未来首次生成 chunk；停用不回滚已写世界。

## 风险与验收责任

- 算法风险：大片单色、细长触须、group 拆散、同类未融合、异类竞争不稳定。以 preview、spans、trace 和固定 seed 测试验收。
- 朝向风险：目标引用不可解、入口声明含糊、自动旋转破坏紧凑度或结果不稳定。以候选组合测试、`orientationDecision` 和现场门面复核验收。
- 世界写风险：材质覆盖自然 / 结构、跨 chunk 接缝、partial write。以替换白名单、硬排除、owner transaction、无通知 `x=15/16` 连接回归与 ledger 验收；连接刷新失败必须恢复当前格和四个水平邻居快照。
- 微整地风险：把开放沟谷误判为坑、跨 owner 判定不一致、邻水造地或局部半填。以同 area halo、连通面积 / span / depth 上限、水体拒绝、旧 palette 门控、GameTest 和新区块现场验收。
- 顺序风险：Decoration 早于 LandUse、RoadWeaver 被 LandUse 回盖。以集成测试和新存档实际道路穿越验收。
- 生命周期风险：plan hash 漂移、重启重复写、旧 chunk 混入。以 activation 全 owner status preflight、active registry reload、幂等和三类旧 / 未知 chunk reasonCode 验收。
- 连续地形风险：chunk 边界重启 run、水渠在水体前后不一致、缓降累计穿越阈值、end-cap 各 chunk 猜测不同。以完整 projection run、冻结 outcome 和跨 chunk 单 runId 验收。
- foundation 风险：噪声递归、过深填充、肩部硬切、端点外延、单点径向填充、多个 segment 密度叠高、fluid 下造地。以 activation-only sampler、positive max contribution、depth/shoulder、endpoint / lateral water 测试验收。
- 可观测性风险：计划过 foundation 被误报为已成形，或只写 applied ledger 吞掉 skip / defer / failure。v0.3 必须同时核对 `foundationPlanned/materialized/applied`、fragmentOutcomes、terrain activation trace 和激活 preview。
- 本轮自动测试不能替代区域形态与真实材质效果的人工审阅；生活感切片必须额外由人工判断农业、商业、行政及其活动关系是否可读。
