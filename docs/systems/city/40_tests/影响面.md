# City 当前影响面

## 主链边界

City 当前变化集中在 D3-D7：D3 提供局部地貌与 LandUse terrain field；D4 一次冻结 Blueprint；D5 准备 reservation；D6 锁定当前世界固定 NBT；D6 后编译 Foundation、Landscape、LandUse 与 Decoration；execute_d5 激活生成期 registry；worldgen 与 D7 负责真实落地和观测。

不在当前影响面中的旧路径包括 FunctionZone 先行、configured structure、运行时 Jigsaw、随机 envelope、late materialization，以及用候选 loop 或固定几何替代正式 Blueprint 编译。

## 景观扩张

Landscape/Group 共享总预算。核心 Parcel 先满足最小面积，填充 Parcel 后进入且允许零占地跳过；这会影响 Blueprint schema、编译 trace、预览摘要和自动测试，但不改变固定模板的 D4/D6 identity。

正式填充算法为 `SINGLE_SOURCE_REGION_RELAY`。每个阶段在真实可用域内逐格扩张，后一区域从父区域局部边界继续；AI 选择目录中的类型、权重和占比，程序冻结 source、parent、实际面积与角色 spans。固定图形、全局距离环和 geometry fallback 都是回归。

主要形态风险：核心和填充取得相同权力、可选内容挤掉主题、阶段数大于实际可分区域、窄通道切断剩余空间、重复等宽层、大片单色、输入遍历顺序改变结果，以及 owner chunk 各自重启算法。验收以核心先行、fill skip、区域连通、父子 trace、稳定 seed、跨 chunk 裁切和人工预览共同判断。

## 固定模板与地形

所有 City catalog 模板使用 single-piece StructureStart 与 `structure_start_beard_thin`。NBT rawSize/hash、旋转、镜像和入口是规划及 worldgen 的共同真值。Minecraft Beardifier 内部扩大 bbox 只参与地形计算，不能污染 planning footprint、collision、preview 或 ledger。

主要风险是 processor 方块、跨 chunk owner、旋转镜像 datum、入口变换、重复 hook、重启幂等和现场模板更新。任何现场特例、单次导入数量或某座测试城市状态都不写入当前契约。

## 执行与后处理

LandUse owner 事务仍是当前失败粒度：预检、快照、写入和 finalize 中任一步失败，整个 owner 回滚。旧 chunk 不回填，停用 active plan 不自动撤销既有方块。RoadWeaver 拥有真实道路的最终覆盖权；`auto` 缺失时跳过，不使用 WorldEdit fallback。城墙由所选 wallVersion 规划，v5 必须复用匹配的 D5 v5 reservation。

观测必须区分计划、写后状态、post-features 和 chunk-save。查询不主动加载 chunk；保存前仍 pending 的记录不能视为最终成功。性能风险集中在 owner 索引、跨 chunk spans、观测队列和大模板 touched positions，禁止在 worldgen/save 回调中扩展为全 chunk 扫描或同步大文件写入。

## 文档同步范围

下列变更必须同步更新产品案、数据契约、MCP 契约、代码导览和本测试目录：Blueprint/catalog/schema 升级、正式/legacy 路径切换、景观预算或扩张算法、模板 identity/terrain policy、世界修改确认、owner 事务、RoadWeaver/城墙版本语义。单次 run 坐标、临时预览和已关闭故障只进入过程记录或 Git 历史，不进入当前真值。

测试运行目录和恢复清单属于共享契约。路径变更必须同时更新 `测试运行包契约.md`、City 代码导览和端点测试；单个阶段不得私自新增 `<runId>/city_<stage>_<id>` 同级目录。
