# City LandUse、Decoration 与建筑群生活感影响面

## D4 单次 CityBlueprint 影响面（2026-08-01）

### v0.5 patch 内部方位影响面（2026-08-02）

CityBlueprint 升为 v0.3，每个 Group 新增必填 `preferredPatchZone=CENTER|NORTH|EAST|SOUTH|WEST`。它只决定 required 核心在 `preferredPatchRefs[]` 精确成员格并集中的起步区域，北=-Z、南=+Z、西=-X、东=+X；不提交坐标、不替换 patch、不限制连接阶段。首核及 required 核心不再读取其他 Group 的位置，防止所有组自动挤到 patch 接缝；跨组靠拢只由 connectivity growth 承担。

compile trace 与 group extent 升为 v0.5，新增 `preferredPatchZone`，首个 `blueprintLayout` 另写 `coreSeedCell`。旧 v0.2 Blueprint 明确拒绝；Context、catalog snapshot、validation/submission artifact、标准 D4 anchor、D5/D6/D7 与世界均不变。回归必须覆盖五方位、非世界坐标语义、精确成员格、required 不 outward、确定性连接与现有碰撞/地形/grid 硬约束。

真实 EAST/SOUTH/WEST 三 Group 首轮暴露 connectivity 双重外推：候选器已生成 5 个合法候选，但全部超过组内最大 gap。修复后连接从最近的本组实际结构中心推进，原样 Blueprint 在正常 `runClient` 约 2.62 秒产出 21 anchors，两条边由 228.65/173.93 格收敛到 0 格。长距离 COMPACT 连接段仍呈明显长链，是后续形态质量风险，不在本轮放宽硬约束或替换算法。

### v0.6 Blueprint 连接阵列桥接影响面（2026-08-02）

CityBlueprint 升为 v0.4，新增的可选 `connectionPlan` 只影响 D4 L2 连接求解：连接结构池、算法和疏密可逐项覆写并继承 Group fill 配置，参数只允许表达 cluster shape 或双侧线性带的 side/stagger/width 语义。标准 StructureAnchorPlan/Map、D5/D6/D7、LandUse 和世界执行契约不变；结构水陆能力仍等待人工 placement tag，不从功能字段推断。

连接阶段开始复用 legacy/debug Agent Loop 的 `CityStructureArrayLayoutLoopPlanner.planExpansionCandidates`，但不恢复 AI loop：focus 为离目标最近的本组最后提交阵列，方向和实体 gap 由程序派生，只搜索 near ring，候选由程序稳定选择并整批原子提交。影响范围包括旧连续 frontier 起算、`compound_cluster` 与 `guide_line_dual_side` 参数消费、occupied 中的 array/body provenance，以及 compile trace / group extent v0.6；required/fill 仍使用当前 Blueprint 持续布局器。

主要回归风险是连接又退化为单栋最近点、只在 schema 写 planner 却未实际执行、批次部分提交、后续批次仍错误聚焦 required 首阵列、连接疏密未进入双方 handoff、旧显式 Agent Loop 水域规则被 Blueprint 兼容标记污染，以及 near-only 在真实地形不足时静默放宽到中远圈。自动测试必须覆盖两类 planner、批次至少两栋、逐字段继承、跨 family 参数拒绝、确定性、碰撞/grid/terrain、原子失败和明确 `CITY_BLUEPRINT_CONNECTIVITY_NO_LEGAL_PATH`。HARD 关系复验必须复用 resolved connection handoff；若 Group 内部 DENSE、连接 SPARSE，最终 gap 可大于 16 但不得超过 40，不能在边已 `HANDOFF_READY` 后因内部阈值二次失败。真实三 Group 已以 24 anchors、三批 near 阵列、两条边归零、质量分 100 和重复编译同 hash 通过；预览按模板而非 Group 着色仍是展示层风险。

同一真实 D3 的远距地形样例把临水平原市场保持在 `r.-15.13:p.22`，仅将 `preferredPatchZone` 从 `CENTER` 调为 `SOUTH`，住宅与工坊仍位于东侧森林平原 `r.-14.14:p.9` 和西南森林平原 `r.-15.14:p.31`。三个 required 核点两条显式边初始 gap 为 771.37/527.46 格，最终为 33/0 格，共 83 anchors；352 个 footprint 覆盖 D3 格只命中平原、缓坡、台地和缓和山脊，水域/未知/峭壁为 0，collision 与 grid 越界均为 0。该结果验证方位语义可用于真实路线设计，但不替代后续结构级水陆 placement tag 契约。

本轮接通 `prepare-context -> 单次 submit-blueprint -> programmatic compile` 的正式 D4 主链。案子 01 仍只写 `city_blueprint_<cityId>/` 下的 Context、catalog snapshot、Blueprint、validation report 和 submission trace；案子 02 另在 `city_d4_<cityId>/` 写 compile trace、Group extent、标准 anchor plan/map 和预览。编译不修改世界，D5/D6/D7 artifact 契约不变。

当前主要影响面是 D3 -> D4 契约、TerraSense/template/reference catalog 身份和 MCP 工具表。partial/未知 D3、首都审查未完成、D3/catalog hash 漂移、非法引用、坐标/rotation/candidate/template/free-algorithm 字段、`LANDSCAPE` 都会在新边界 hard fail。同一 context 的非法 AI 提交也消费一次预算；失败不得覆盖最后有效 Blueprint。

`city_run_workflow` 默认已切到 Blueprint。缺输入是 `awaiting_city_blueprint` 可恢复暂停；旧 candidate/session/manual anchor 只有显式 legacy/debug mode 才能进入。v0.4 的回归重点是 required 播种先于 connectivity growth、连接完成先于 fill、preferred member-cell 核心域、Group 共享 patch、collision/occupied、持续阵列 slot、算法化疏密、三 Group 超过旧 64 格距离仍可连接、显式关系与确定性补边、D3 grid 硬边界、连接扩张越过 extent 软目标的解释字段、无通路明确失败、结构拓扑与 LandUse 连通状态分层、HARD 关系、稳定 seed、标准 D5/D6 产物，以及编译阶段 AI/manual candidate selection 计数恒为 0。D3 v2 正式精度与性能仍由案子 00 验收，本轮 fixture/当前 D3 联调不能替代真实地形验收。

主要新增风险是：旧 v0.1 Blueprint 与 v0.2 输入身份错配、Group 被再次拆成单元素阵列、算法 guides 被 member-cell 中心二次吸附、疏密被偷换成统一数量/覆盖率、连接阶段退化为直线桥或最近格旁路、preferred patch 被误当永久边界、D3 scan padding 被误当作规划空间、extent 软目标再次阻断连接、HARD 关系阈值被隐藏修改、同分排序受集合遍历顺序影响，以及 `skipExisting` 下游 artifact 复用。编译入口重算 identity；精确内部 guides 只受 member-cell 合法 mask 裁剪，不吸附回 cell center；每个 anchor 冻结 layout slot，extent map 明确 `landUseConnected=false`。D4 已删除固定 Group 间 64 格门槛；LandUse 自身的 64 格自动连接仍是另一个子系统的现行规则。

2026-08-01 v0.2 真实 run 的旧基线为两个 `MEDIUM/BALANCED` Group 各 5 个 anchor、组间 63 格，并暴露单元素阵列和连接语义问题；该图不再作为 v0.3 形态验收结果。v0.3 必须重新生成真实 preview，检查 COMPACT 是否二维错落、slot 是否连续、outward 是否缩短 handoff gap，以及 `landUseConnected=false` 是否与后续 LandUse artifact 一致。D5/D6 对新 anchor map 的来源身份已有自动测试，真实服务端重算耗时与落地仍待验收。

同日 v0.3 已在同一真实 run 重编译：HTTP 约 1.77 秒，`civic_market=9`、`residential=10`，共 19 个连续 COMPACT slots；两组 anchor 分别覆盖 5x5 与 8x7 个不同 X/Z 值，不再是单轴队列。civic 有 8 次连接优先 outward，最终组间 collision edge gap 从旧 63 格缩到 3 格，低于 BALANCED handoff 24 格；extent map 为 `structureGraphConnected=true`、`landUseConnected=false`。局部 preview 可见两个二维组团和结构前沿接触，实体地表仍等待 LandUse 编译。

### v0.4 Group 连接生长影响面（2026-08-01）

v0.4 把 D4 执行顺序冻结为“全部 Group required 核心播种 -> 关系图连接生长 -> 普通 fill”。required 核心仍只能落在自己的 `preferredPatchRefs[]`；连接阶段可认领 D3 `review.grid` 内符合 terrain policy 的 member cells，并由双方交替消费原持续阵列 slot，直到前沿 gap 小于等于双方 handoff 的严格最小值。显式 `CONNECTION/ADJACENCY/HIERARCHY` 优先，关系不足时才按初始前沿距离确定性补边。

影响仅在 Blueprint compiler L2 求解层和解释 artifact：compile trace / group extent 升为 v0.4，删除 `maxInterGroupGapBlocks`，增加拓扑来源、初始/最终 gap、连接结构数、连接空间需求、扩张距离、claimed patches 与 D3 grid 边界策略。标准 StructureAnchorPlan/Map、D5/D6 输入、世界和 LandUse 自动连接实现均不变。

剩余风险是连接边当前按稳定顺序贪心施工，没有全局回溯；复杂窄通道中前一条边可能占用后一条边的唯一空间，此时必须以 `CITY_BLUEPRINT_CONNECTIVITY_NO_LEGAL_PATH` 明确失败。正常 `runClient` 三 Group 远 patch 已以 296 -> 7 格、22 anchors、约 3.75 秒通过；该单例不能替代更多地形与窄通道形态验收。

## 首都 D3 选址审查影响面（2026-07-26）

本轮只对 `role=capital` 且 `source.siteSelectionMode=ai_candidate_selection` 的新首都增加强制闸门。D3 重算会使旧审查失效；所有 D4 规划、候选、loop 和 finalize 入口都统一检查决策。普通城市、历史首都和 `rule_fixture` 验收首都不强制追溯补决策，避免破坏已有调试 artifact。

影响边界是 D3 -> D4 进入条件，不改变 D3 patch schema、D4 候选算法、模板几何、LandUse、RoadWeaver 或 worldgen 落地逻辑。主要回归风险是 D4 子入口绕过闸门、D3 重算后误用旧决策、以及重选状态被 workflow 当成普通失败继续执行。

## 固定 NBT 唯一主线影响面（2026-07-25）

本轮从 City active path 删除 configured structure、Jigsaw、动态 envelope profiling、外部 `StructureStart` 物化和 late materialization。D4 只接受显式 `templateCatalogSource` 与 `templateId/templateRef + variant`；D5 使用 `exact footprint + clearance` 派生 collision，再加 `maskMargin` 派生 mask；D6 从当前世界重新读取 NBT 并锁定 hash、rawSize、变换、三层几何和 owner chunks；D7 只核对固定模板 ledger。

所有进入 City catalog 的模板都冻结为 `structure_start_beard_thin`。worldgen 仅在 `createStructures` 注入一个 City 自有 exact-footprint piece；`tryGenerateStructure` 只保留自然结构 mask，FEATURES 不再补贴建筑。Minecraft 内部 terrain-adaptation bbox 不得进入规划、registry、ledger 或预览。主要回归面是旋转 / 镜像归一、道路入口变换、clearance 保留、owner chunk 完整性、重复 hook / 重启幂等，以及普通、processor、大型模板的真实 `beard_thin` 验收。

Trek B0.6 只通过离线工具导入 manifest 中 20 个单根模板。结构性 target pool 拒绝，mobs connector 烘焙为 `final_state`，实体清空，processor 使用版本化固定 seed。20 个入口已按固定 NBT 与四视图确认并冻结 evidence block；正式 catalog 仍必须等待运行中的 `city_query_template_metadata` 回读 hash/rawSize。14 个真正的多-piece Jigsaw 不在影响面内，也不提供 fallback。

同一 manifest 额外冻结 20 个固定模板的 TerraSense canonical terms，并可独立导出 official semantic profile 包。该包只改变 D4 的语义候选来源，不改变 NBT、catalog、入口或 worldgen；旧 `trek:...` assembly profile 保留为历史但不得与新 `geomantia:city/trek/...` profile 合并消费。语义 approved 与 catalog ready 是两个独立状态，主要回归风险是旧 identity 混入、新词表缺项，以及误把 `approved_baseline` 当成实机验收完成。

## Patch Explorer v0.1 影响面

本轮只在 D4 候选输入前增加可选的地理探索与选择凭证解析：`city_plan_d4_candidates`、`city_plan_d4_array_candidates`、`city_create_d4_array_layout_loop`、`city_query_d4_array_expansion_space`、`city_plan_d4_array_expansion_candidates`、`city_plan_d4_structure_cluster_groups`、`city_create_d4_candidate_session`。下游 anchor、阵列、整组候选、防撞、occupied 写入和最终 D4 artifact schema 不变。

选择凭证存在时，服务端以同 city D3 来源 patch 覆盖请求中的 `candidatePatchRefs[]`；新功能区 expansion 另派生 `selectedGlobalPatchRef` 与 `newFunctionalArea=true`。选择凭证不存在时，原接口行为保持不变，尤其 D4 v0.5 常规 outward 继续按父结构几何连续扩展，不退化为强制 patch 搜索。

主要风险是来源漂移、凭证与 city scope 串用、D4 扣除 occupied 后总面积与最大连续面积混淆，以及新增适配层意外改写调用方输入。验收必须覆盖 stale hard fail、深拷贝、连续面积容量、选择确认图和无凭证旧路径回归。

## 主链变化

当前新增可选步骤：`D4 -> D5 预案 -> D6 locked footprint -> LandUse -> Decoration -> execute_d5`。它不改变 D4 先落建筑的职责，也不恢复旧 FunctionZone 主线。

## 配置与版本边界

- 新配置根目录 `config/geomantia/city_land_use/` 含 `settings.json` 与 `profiles/<profileId>.json`；默认 `enabledInWorkflow=false`、profile 为 `default_v0_1`，规则档案保持严格 `city_land_use_rules.v0.1`。64 格自动连接距离是程序默认，不进入 profile 或 AI 配置；缺失 bundled 文件才补装，不覆盖用户文件。
- 请求 `enableLandUseLayer` 优先于 settings；未显式开启且配置关闭时，现有 workflow 行为与 artifact 保持不变。
- 独立 `city_plan_land_use` 是显式规划入口，可不传 intent；服务端自动使用空 overrides。
- intent 使用 `city_land_use_intent_plan.v0.3` 严格 schema；v0.2 `global_axis|radial` 明确拒绝。每城材质由本次 intent 的算法默认决定，解析优先级为 group override > 本次 intent algorithm default > policy 内置 fallback；静态 profile 只提供服务端规则兜底。area plan 保持 v0.1，SurfacePrintPlan 只接受 v0.2。旧 LandUse artifact、active registry 和 ledger 必须在升级时清理，随后完整重规划；历史只从 Git 追溯，不提供运行时迁移。
- 当前 material palette 包含 `MICRO_FILL_SUBGRADE=minecraft:dirt` 并进入 `paletteHash`；所有新 active plan 必须携带完整当前 palette，缺键直接拒绝。
- Decoration content index / program 当前为 v0.3。v0.2 可只读解释但 query 必须显式报告 upgrade required；仅 managed 且未改动的旧默认 catalog 可经确认、备份后升级，自定义 catalog 不自动改写。
- 关键装饰候选不新增配置或持久化 selection state；复用当前 decoration catalog/style、program v0.4 target、D5/D6/LandUse 硬障碍和现有相对坐标字段。
- 已到 FEATURES 的 chunk 不回填。启用后只影响未来首次生成 chunk；停用不回滚已写世界。

## 风险与验收责任

- 算法风险：growth region 额度误聚合 / 相互透支、引导目标漏选 / 误选、背向仍扩张、地形阻断失效、大片单色或农田整体矩形。面积粒度以多 anchor 同组独立封顶和 trace 分项测试验收；连接继续以 v0.3 `automaticSurfaceConnections[]` 和 64 格边界测试验收；刷地另以 `ContourBandSurfaceClassifierTest`、spans 非 bbox、缓坡等高线轮廓、平地径向回退和固定输入确定性验收，三者不得互相影响。
- 朝向风险：目标引用不可解、入口声明含糊、自动旋转破坏紧凑度或结果不稳定。以候选组合测试、`orientationDecision` 和现场门面复核验收。
- 关键装饰风险：只检查 anchor 点导致大 prefab 越界、AI 独立规划多个点后互相重叠、把未采样地形误报为安全，或空候选时退回手写世界坐标。以完整 footprint/clearance、`fixedDecorationObstacles`、`terrainSampling=not_performed`、空集 rejectionCounts 和候选回填后单 slot 一致性验收。
- 世界写风险：材质覆盖自然 / 结构、BANK overlay 或作物回盖 WATER、请求作物被 neighbour-shape 解析为空气、转角邻接更新不完整、开放端点漏水、跨 chunk 接缝和 partial write。以冻结全局 role spans、端点封口、精确写后校验、boundary 两阶段 finalize、finalize 独立观测 rollback token、系统错误 owner 回滚、crop/boundary role 冲突与 ledger 验收。2026-07-23 首次真实证据坐标 x=1008..1027，已通过生产 `WorldGenRegion` 验证 20 个 farmland+wheat、20 个 oak fence 和 x=1023/1024 双向接缝；保留旧世界再次运行时，nonce 动态目标 x=15519848..15519867、接缝 x=15519856 也通过相同验收及唯一 cityId ledger，证明不会复用旧 chunk / ledger 假通过。石墙不同 Y 的坡地连续性仍是独立现场风险。
- 微整地风险：把开放沟谷误判为坑、跨 owner 判定不一致、邻水造地或局部半填。以同 area halo、连通面积 / span / depth 上限、水体拒绝、当前 palette 严格校验、GameTest 和新区块现场验收。
- 顺序风险：Decoration 早于 LandUse、RoadWeaver 被 LandUse 回盖。以集成测试和新存档实际道路穿越验收。
- 生命周期风险：area / surface / palette hash 漂移、重启重复写或旧 chunk 混入。以 activation 实际写入 owner status preflight、当前 ledger schema 严格拒绝、owner 幂等和跨 owner / restart 一致性验收；不测试或承诺旧 ledger 迁移。
- 性能风险：每 owner 扫全城 area / band spans、全局锁内地形采样或大账本逐 block 写入。以 prepared owner index、owner 级摘要 ledger 和大田 lookup / scan count 测试验收。
- 连续地形风险：D3 粗高程未经插值产生 cell 方格轮廓、局部梯度噪声令条带抖动、平地阈值导致 mode 不稳定、chunk 边界重启相位或 owner 各自猜端点。以 SurfacePrintPlan v0.2 冻结 mode / anchor / role spans、跨 chunk global phase、输入顺序扰动和 restart 测试验收。
- Decoration foundation 风险：噪声递归、过深填充、肩部硬切、端点外延、重复 segment 密度叠高、fluid 下造地。以 common segment view、prepared chunk index、positive max contribution、depth/shoulder、endpoint / lateral water 测试验收；LandUse 不进入该路径。
- Decoration 可观测性风险：计划过 foundation 被误报为已成形，或只写 applied ledger 吞掉 skip / defer / failure。v0.3 必须同时核对 `foundationPlanned/materialized/applied`、fragmentOutcomes、terrain activation trace 和激活 preview。
- 现场证据风险：执行器返回成功后方块被后续 feature 覆盖，或保存前已变成 air，但 AI 仍按 ledger 数量宣称真实落地。必须同时检查 `post_features` 与可用的 `chunk_save` 观测；`pendingSaveVerification=true` 只能表示等待保存检查，不能视为通过。
- 观测性能风险：大模板仍会增加 touched-position 读取与队列内存。首版禁止在 worldgen/save 回调内做 JSON/文件 IO，server tick 每次最多刷 2 条；模板局部 block 列表按 hash 缓存，pending-save 同 chunk 合并。不得扩展为全 chunk 扫描或全服 block listener，真实压测仍需检查 tick 延迟与队列积压。
- 本轮自动测试不能替代区域形态与真实材质效果的人工审阅；生活感切片必须额外由人工判断农业、商业、行政及其活动关系是否可读。
