# 区域接力实际 Area 小于阶段数

## 状态

规划与 D5 激活复验通过，待用户确认首次 TP/worldgen。实现仓库故障编号：`CITY-DL-20260807-01`。

## 现象

在完全未生成 region `r.26.-19` 前执行正式 City workflow。v0.9 Blueprint 同时声明农田、花田和林场，并为三类景观分别冻结区域接力方案。D4、D5、D6 与 Foundation 均成功，但 `city_plan_land_use` 在生成 SurfacePrintPlan 前以 `RELAY_GROWTH_MASK_TOO_SMALL_FOR_STAGES` hard fail，因此没有进入 D5 激活，也没有加载目标区块。

## 已确认事实

- 真实证据 run 为 `landscape_relay_playtest_20260807_v3`，城市为 `city_realm_salt_kingdom_0_mining`。
- D4 紧凑组最终包含 11 个 anchor；三类 Landscape 以 anchor 为来源展开后，`city_outdoor_intent_plan.json` 共包含 95 个 source。
- `RelayRegionGrowthClassifier` 要求 `allowed.size() >= stages.size()`；农田和林场方案均有五个有序 stage。
- LandUse 竞争与结构 exclusion 发生在 SurfacePrint 分类前。至少一个最终 Area 的 `member-exclusion` 可填格少于五格，触发分类器 hard fail。
- 目标 `.mca` 在三轮规划后仍不存在，玩家未传送；该现象与已生成区块、worldgen 写入或预览渲染无关。

## 原未决问题

- 最先失败的 `areaId/sourceId` 及其竞争前后面积，目前异常没有携带 Area provenance。
- 正式契约应在 Parcel 编译期保证最小可执行面积，还是在竞争后重新判定 required Parcel 的失败归属。
- 同一 Landscape 附着 Group 时是否应该按每个 anchor 派生全部 Parcel，还是按 Group 总体预算分配。

以上业务语义已在本次修复中裁决；原始现场仍保留作为回归证据。

## 已锁定修复契约

- `coreParcelCountMin..Max` 与 `fillParcelCountMin..Max` 均按单个 Landscape/Group 解析一次，不按 anchor 数倍增；required/fill anchors 只提供各自 tier 的候选起点。
- core Parcel 先共同竞争，每个结果必须达到 `max(minAreaBlocks, stageCount)`，否则 `CITY_LANDSCAPE_CORE_BELOW_MINIMUM` hard fail。
- core claims 冻结后，fill Parcel 按稳定 groupId 逐个探测；达标才合并，不足则全部候选 claims 作废并记录 `CITY_LANDSCAPE_OPTIONAL_SKIPPED_INSUFFICIENT_SPACE`、`skipped_insufficient_space`。
- optional skip 是创建前准入裁决；required Parcel 仍不得静默删除，AI 阶段仍不得缩减。
- Reference Catalog 升为 v0.7，防止 v0.6 的同名数量字段被静默重解释。

## 修复约束

- 不得恢复固定图形、bbox、预制 mask、全局距离环或 geometry fallback。
- 不得静默删除 required Parcel、减少 AI 提交的有序 stage，或把失败 Area 当作成功空结果。
- 已准入 Area 仍必须携带完整 provenance；optional 候选在形成正式 Area 前退出，不进入 SurfacePrint。
- 自动回归必须覆盖多 anchor Group、三类同时 Landscape、竞争后小 Area，以及未生成 chunk 全流程。

## 自动验证

- `CityOutdoorBlueprintCompilerTest.fillAnchorsShareOneGroupLevelOptionalParcelBudget`：增加 9 个 fill anchor 后仍只生成固定的 5 个 core + 2 个 fill Parcel。
- `layeredPlanningUsesNoCorridorsAndKeepsOneAreaPerParcelOwner`：间距修复后合成场景的 7 个 Parcel 全部准入，并保持一 Parcel 一 Area、一 Area 一 owner。
- `parcelSeedsReserveBothEstimatedRadiiBeforeApplyingGap`：同一 Landscape 的中心距包含双方预计半径。
- `differentLandscapesShareTheSameParcelSpacingLedger`：不同 Landscape 共享占用表，禁止农田、花田、林场复用种子。
- `d7ResponsePropagatesWaitingForWorldgen`：D7 的 `WAITING_FOR_WORLDGEN` 必须提升为 workflow 可见状态。

## 新区块前复验结果

- 真实 run 仍为 `landscape_relay_playtest_20260807_v3`，Blueprint 结构设计不变，仅重新 prepare v0.7 Context。
- 最终冻结 1 个 Foundation 与 16 个景观 Parcel：农田 6、花田 7、林场 3；全部 `accepted`，warnings=0。
- SurfacePrint 冻结 66 个非空接力 region：农田 30、花田 21、林场 15；没有固定图形或阶段缩减 fallback。
- D5 激活成功，11 个 planned structures 均由 D7 报告 `WAITING_FOR_WORLDGEN`，workflow 正式停在 `waiting_for_worldgen`。
- D7 状态查询会创建 0 字节 `r.26.-19.mca` 文件，但文件没有 region header 或 chunk 数据；查询前后长度均为 0，玩家未传送。用户要求本轮先不 TP，首次 worldgen 与世界视觉验收继续保留。

## 验收目标

同一类正式 Blueprint 能在不加载目标 chunk 的情况下完成 D3 到 D5 激活；每个进入 SurfacePrint 的 Area 都满足已锁定的接力契约，或在更早阶段以携带 Parcel provenance 的明确 reasonCode 拒绝。随后首次加载 owner chunk，验证建筑、Foundation 与三类景观只执行冻结结果。
