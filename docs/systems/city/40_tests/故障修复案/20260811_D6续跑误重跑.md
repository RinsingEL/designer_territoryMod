# D6 续跑误重跑

## 状态

代码与聚焦回归已修复，待新产物实机续跑复验。实现仓库故障编号：`CITY-PW-20260811-01`。

## 现象

真实 run `rtf0810_medium_city_20260810_01` 的城市 `city_rtf0810_greenfield_01` 已在第 4 次 workflow 完成 D4、D5、D6、LandUse 激活和 D7，并停在 `waiting_for_worldgen`。再次以 `skipExisting=true` 续跑时，workflow 仍重新执行 Blueprint D4，随后又执行 D5、D6；D6 在已经生成的 owner chunks 上以 41 项 `STRUCTURE_CHUNK_ALREADY_GENERATED` 失败。

## 根因

- Blueprint 模式的 `workflowRunD4Blueprint` 固定把 skip artifact 传为 `null`，没有遵守 workflow 的 `skipExisting` 语义。
- D4 重新编译会覆盖 `structure_anchor_map.json`。本现场第 5 次结果不仅 `timingMs` 不同，部分 anchor 坐标、朝向状态和模板选择也已变化。
- D5、D6 正确地要求内嵌 `sourceStructureAnchorMap` 与当前 D4 完全一致；D4 被覆盖后，旧 D5/D6 被判为过期并重新规划。
- D6 的当前世界预检正确拒绝已生成 chunk。错误发生在 workflow 错把续跑当成重新规划，不应通过放宽 D6 边界或忽略 anchor 差异来掩盖。
- D6 返回 `ok=false` 时，workflow 步骤只读取顶层 `reasonCode`；当前 D6 具体原因只存在于 `qualityReport.failureSummary`，导致 manifest 中 reasonCode 为空。

## 修复口径

- Blueprint D4 产物必须携带稳定的 accepted Blueprint 来源身份，至少绑定 `contextId` 与 `sourceBlueprintHash`。
- `skipExisting=true` 时，仅当当前 context、accepted submission、Blueprint 文件和 D4 provenance 一致，workflow 才跳过 D4；身份缺失或不一致必须重新编译。
- D5/D6 继续精确比较完整 `sourceStructureAnchorMap`，不得忽略真实 anchor、模板或几何变化。
- D6 失败响应必须把质量报告中的主失败原因提升到顶层，供 workflow manifest 记录。

## 回归要求

- 相同 accepted Blueprint 的第二次 workflow 能识别现有 D4 为当前产物。
- Blueprint 内容或 context 身份变化后不得跳过 D4；旧版无稳定 provenance 的 D4 也不得误跳过。
- D4 未被改写时，既有 D5/D6 的完整来源身份保持匹配并被跳过。
- 单一 D6 失败原因（包括 `STRUCTURE_CHUNK_ALREADY_GENERATED`）必须出现在响应和 workflow step 的顶层 `reasonCode`。

## 自动验证

- `CityPlanningEndpointHandlerTest.workflowBlueprintD4SkipsOnlyForCurrentAcceptedSourceIdentity`：当前 accepted context、submission、Blueprint hash 与 D4 provenance 一致时可跳过；Blueprint 漂移或旧 provenance 缺字段时拒绝跳过。
- `CityPlanningEndpointHandlerTest.workflowArtifactIdentityRequiresExactCurrentAnchorMap`：D5/D6 完整来源身份仍保持严格比较。
- `CityBlueprintCompilerServiceTest.compilesRequiredBeforeFillAndIsDeterministic`：编译器产出的 D4 provenance 携带 `contextId` 与 `sourceBlueprintHash`，并保持同输入确定性。
- `CityStructureTemplateMaterializationPlannerTest.d6ResponsePropagatesSinglePreflightFailureReason`：单一 D6 preflight 原因提升至响应顶层。
- 上述四条定向回归通过；两个主要聚焦测试类整体通过。
- `CityBlueprintCompilerServiceTest` 全类 21 项中 20 项通过；既有 `requiredLandscapeCapacityIsExactAndExcludesAllLaterStructures` 因场景只能形成 2 栋、当前 minimum 要求 3 栋而报 `CITY_BLUEPRINT_GROUP_MINIMUM_UNREACHABLE`，与本案 provenance/续跑改动无关，未在本案中改动 Landscape 规则。

## 实机复验目标

在使用修复后 D4 provenance、完成 D7 并处于 `waiting_for_worldgen` 的 run 上再次执行 `city_run_workflow(skipExisting=true)`：D4、D5、D6 均应显示 skipped，不得改写三阶段冻结产物，也不得因 owner chunk 已生成再次触发 D6 预检。旧 run `city_rtf0810_greenfield_01` 的当前 D4 已被失败续跑覆盖，不能据此猜测并恢复旧 anchor map。
