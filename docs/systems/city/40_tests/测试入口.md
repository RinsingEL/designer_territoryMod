# City 系统测试入口

## 当前状态

City D2 (C0 CitySiteContext)、D3 (C1.5 CityLandformReviewPackage)、D4 (C2/C3 功能区草案实体化)、D5 (C4 道路 / 边界 / 缓冲区计划与 WorldEdit 执行入口)、D6 (结构选择与固定落点规划) 和 D7 (固定结构优先放置 + 剩余结构起点候选生成) 已实现到自动测试可覆盖。

D3 会写出 `landform_review_map.png` 与 `city_landform_review_package.json`；D4 会写出 `function_zone_preview.png`、`function_zone_map.json`、`function_zone_terrain_stats.json` 和 `quality_report.json`；D5 会写出 `road_intent.json`、`boundary_intent.json`、`build_operation_plan.json`、`buildable_area_map.json`、`city_planning_preview.png`、`city_buildability_preview.png`、`quality_report.json`，执行后追加 `world_mutation_report.json`；D6 会写出 `StructureProfileCatalog`、`FilteredStructureCatalog`、`StructureChoicePlan`、`FixedPlacementCandidateSet`、`FixedPlacementSelectionPlan`、`PlannedFixedPlacementMap`、`StructurePoolMap` 和预览图；D7 会写出 `StartCandidateSet`、`PlacedStructureMap`、`StructureGenerationTrace` 和预览图。

D5 真实执行是显式危险操作：必须先完成 `city_plan_d5`，再用 `city_execute_d5 { confirmWorldMutation: true }` 触发 WorldEdit 后端修改世界。

D6 不是真实执行阶段：`city_plan_d6` 只做结构选择与固定落点规划，不进入世界、不调用 `/place structure`。程序通过 `TerraSenseStructureProfileSource` 读取 TerraSense 导出快照，归一成 `StructureProfileCatalog`，再按功能区和 D5 可建区过滤结构；AI 选择 `fixed_footprint` 与 `variable_area`；固定大小结构不填占比，由程序生成落点候选并让 AI 引用 `landingCandidateId`；非固定结构才填写剩余可见面积占比。D6 输出 `PlannedFixedPlacementMap` 和 `StructurePoolMap` 供 D7 消费。

D7 才是真实结构执行阶段：`city_execute_d7` 读取 D6 产物，先完整放置固定结构，再由程序生成 `StartCandidateSet` 并按 seeded random 抽选剩余结构候选。默认 `executeStructurePlacement=false` 只做 dry-run / trace；设置 `executeStructurePlacement=true` 时才通过 MC configured structure registry 校验并调用 `/place structure`。真实执行采用 chunk-driven 可重入口径：chunk 未加载时写 `status=waiting` / `STRUCTURE_CHUNK_NOT_LOADED`，不算结构失败；玩家 TP 或预加载 mod 覆盖目标范围后，再次执行 D7 继续推进。

TerraSense 正式画像未完整接入前，D6-D7 开发和验收使用 `D6-D7临时真实结构测试配置.md`。临时配置允许功能语义错配，但结构 ID 必须真实可放、尺寸 / footprint 必须自洽，并且必须输出预览图。

## D6 结构选择与固定落点验收

| 检查 | 通过口径 |
|---|---|
| TerraSense 输入 | `TerraSenseStructureProfileSource` 必须指向 `StructureProfile.jsonl`、兼容 `C3_5_StructureCatalog.preprocessed.json` 或显式 debug catalog |
| 导入边界 | D6 不直接读取 TerraSense `ScanWorkspace.structures/*` 原始扫描目录 |
| 审核过滤 | 正式模式只允许 `review_state=approved` 且术语 approved 的结构进入候选；`reject` 不得进入候选 |
| debug 降级 | `pending`、`needs_review`、`proposed` 术语只能在 `catalogMode=debug` 时进入 `needs_review`，不得进入正式 `FilteredStructureCatalog` |
| 临时真实结构 | debug catalog 中用于验收的结构 ID 必须能被 MC / Forge 真实放置；语义可错配但必须说明 |
| 结构画像 | `StructureProfileCatalog` 必须区分 `fixed_footprint` 和 `variable_area`；缺少可靠尺寸画像的结构不得作为固定结构 |
| 过滤输入 | 缺 D4 `function_zone_map.json`、`function_zone_terrain_stats.json` 或 D5 `buildable_area_map.json` 必须 hard block |
| 尺寸过滤 | 固定结构 footprint + clearance 肯定超过功能区可建形状时必须过滤 |
| 草案来源 | `StructureChoicePlan` 和 `FixedPlacementSelectionPlan` 由 MCP 调用方侧 AI / Codex 提交，运行时不内置 LLM |
| 引用校验 | 不存在 `zonePatchId` hard block |
| 功能类型 | `functionType` 必须与 D4 功能区一致 |
| 结构 ID | `structureId` 必须是合法资源 ID / 结构 ID 形式 |
| 固定结构选择 | `fixedSelections[]` 不允许出现 `targetVisibleAreaRatio`、最终坐标、jigsaw 深度、半径或 piece budget |
| 非固定结构选择 | `variableSelections[]` 必须包含 `targetVisibleAreaRatio`；占比只针对扣除固定结构后的剩余可见面积 |
| 落点候选 | `FixedPlacementCandidateSet` 只为已选 `fixed_footprint` 生成；候选必须满足大概地形合适、大小不超出功能区、不压道路 / hard reserved |
| 落点选择 | `FixedPlacementSelectionPlan.selections[].landingCandidateId` 必须存在于程序生成的 `FixedPlacementCandidateSet` |
| 坐标边界 | AI 不得自由填写或改写固定结构候选中心点，只能引用 `landingCandidateId` |
| 全局冲突 | 多个固定结构 footprint / clearance 冲突时 hard block，让 AI 重选，不自动替换 |
| 阶段边界 | 不调用 `/place structure`，不解 jigsaw，不 paste template，不把 `PlannedFixedPlacementMap` 当已落地结果 |
| 产物 | 写出 `terrasense_profile_source.json`、`structure_profile_catalog.json`、`filtered_structure_catalog.json`、`structure_choice_plan.json`、`fixed_placement_candidate_set.json`、`fixed_placement_selection_plan.json`、`planned_fixed_placement_map.json`、`structure_pool_map.json`、预览图和 `quality_report.json` |
| 预览图 | D6 必须写出 `structure_choice_preview.png` 和 `fixed_placement_preview.png` |

## D7 条件包装结构生成验收

| 检查 | 通过口径 |
|---|---|
| 城市范围接管 | 城市影响范围外不接管原版 / 其他 mod 结构生成 |
| 固定结构优先 | `fixed_footprint` 必须引用 D6 `PlannedFixedPlacementMap` 并优先完整放置 |
| 固定结构完整性 | 固定大小结构要么完整放置，要么按 `failurePolicy` 失败 / 降级 / 跳过，不允许裁切一块 |
| 剩余面积预算 | `variable_area` 预算必须基于扣除固定结构 footprint / clearance 后的剩余可见面积 |
| 起点候选 | 剩余结构必须先生成 `StartCandidateSet`，不得在功能区内盲随机坐标 |
| 纯程序选点 | D7 trace 中不得出现 AI 选择剩余结构坐标、起点或重试的字段 |
| 可复现抽选 | 起点抽选使用 world seed、cityId、zonePatchId、taskId、structureId 和 attemptIndex 组成的稳定 key |
| 起点冲突 | 起点候选不得压 D6 固定结构、道路、hard reserved 或 runtime occupied footprint |
| 无无限重试 | 每个结构 task 和每个 zone 都有重试上限 |
| Validator | 能区分功能区不匹配、坡度过高、水体重叠、道路保留区冲突、AABB 占用、configured structure registry 缺失等失败原因 |
| Jigsaw 边界 | `variable_area` piece 越出 allowedArea 时停止分支、使用 terminal / endcap，或结构化失败回写；固定结构不走收尾 / 裁切 |
| chunk 等待 | chunk 未加载时写 `waitingSummary`，不得当作 `failureSummary` 或触发固定结构 `failurePolicy` |
| 可重入 ledger | `worldMutationApplied=true` 的已放置结构再次执行时不得重复放置；dry-run 产物不得跳过真实执行 |
| AI 边界 | trace 中不得出现 AI 逐 piece 决策、jigsaw 深度 / 半径 / piece budget 手填 |
| Trace | 写出 `structure_generation_trace.json`、`placed_structure_map.json` 和调试预览 |

## 最小真实游玩验收

1. 确认 `gradle.properties` 的快速启动进入 `新的世界` 配置有效，并用 `.\gradlew.bat runClient` 启动客户端。
2. 确认进入存档后 `/realm/status` 可访问，API server 在 `127.0.0.1:5000`。
3. 使用已有 run `realm_reterraforged_t4_crop_4096_20260614` 或重新跑 `realm_run_acceptance`。
4. 对 `city_realm_green_court_2_port` 调用或复用 D3/D4。
5. 调用 `city_plan_d5`，打开 `city_planning_preview.png` 检查主路、次路、边界、缓冲区和模板 marker；打开 `city_buildability_preview.png` 检查功能区扣除 reserved footprint 后的剩余可建区域。
6. 可选：放入 `run/geomantia_templates/d5/gate_small.schem` 或 `dock_marker.schem`。
7. 调用 `city_execute_d5 { confirmWorldMutation: true }`。
8. 在世界里 tp 到入口、核心区和边界带，确认植被清理、道路 / 缓冲区可见，小模板粘贴成功或在报告中明确 skipped。
9. 检查 `world_mutation_report.json` 与实际世界变化一致。
10. D6 验收不需要真实执行：程序先从 TerraSense 导出快照生成 `StructureProfileCatalog`，再生成过滤后的结构候选和固定落点候选；AI / Codex 提交 `StructureChoicePlan` 与 `FixedPlacementSelectionPlan`；打开 `structure_choice_preview.png` 和 `fixed_placement_preview.png` 检查固定结构只引用 `landingCandidateId`，非固定结构才有可见面积占比。
11. 调用 `city_execute_d7 { executeStructurePlacement: false }`，检查 `start_candidate_set.json`、`placed_structure_map.json`、`structure_generation_trace.json`、`start_candidate_preview.png`、`placed_structure_preview.png`，确认剩余结构起点来自程序生成的 `StartCandidateSet`，trace 中没有 AI 坐标 / AI 重试 / AI 逐 piece 决策字段。
12. TerraSense 正式导出未完成前，D6-D7 使用 `D6-D7临时真实结构测试配置.md` 中列出的 configured structure ID 做临时真实放置验收；这些 ID 必须能被 `/place structure` 识别，不能是 NBT template 路径或 jigsaw pool ID。
13. 调用真实执行 `city_execute_d7 { executeStructurePlacement: true }`。如果 trace 为 `status=waiting` 且 `waitingSummary.STRUCTURE_CHUNK_NOT_LOADED` 存在，先不要判失败。
14. 玩家 TP 到城市 anchor / 目标结构 anchor 附近，或启动预加载 mod 覆盖目标范围，等待若干 tick 让 chunk 加载完成。
15. 再次调用 `city_execute_d7 { executeStructurePlacement: true }`，确认至少 1 个 `fixed_footprint` 在 chunk 覆盖达标后完整落地；至少 1 个 `variable_area` configured structure 成功，或在 `StructureGenerationTrace.failureSummary` / `waitingSummary` 中给出结构化可解释原因。
