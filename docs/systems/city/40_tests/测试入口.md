# City 系统测试入口

## 当前状态

当前 City active path 为 D3 地形 patch 真值 -> configured structure envelope profiling -> D4 `key_then_array` 分阶段主流程（关键结构逐个定锚并冻结 occupied，再按 `array_fill` 阵列填充重复结构）-> 最终 D4 `StructureAnchorMap` -> `city_plan_d5` reservation mask 轻量预案（只读最终 D4 `collisionEnvelope + maskMarginBlocks`，默认 D3 patch 贴边 wall reservation，显式 `wallVersion=v3/v4/v5` 可用结构种子 reservation mask 上下文）-> D6 probe-and-lock（锁定 `actualFootprint` / `pieceBoxes` / `lockedCollisionEnvelope`）-> 可选 City DecorationProgram v0.2 -> execute_d5 用 D6 locked collision 激活 active mask / locked planned registry / 可选装饰 worldgen program / 可选 RoadWeaver 连接 -> worldgen-time placement -> `city_execute_d7` 查询 worldgen ledger / terrain trace -> RoadWeaver 道路；旧 debug 道路仅允许显式 `worldedit_debug` -> `city_plan_city_walls` 扫描 actual road mask 裁门 / 生成墙图 -> `city_execute_city_walls` 放置城墙。D4 v2 顺序候选 session、结构群整组候选、单独阵列候选、显式 `array_layout_loop_v0_3` 和 v0.4 候选选择闭环都保留为调试 / 人工干预路径；v0.4 不切默认 workflow。

可用 `city_run_workflow` 作为调试 / 验收快跑器串联上述阶段并记录每步耗时；它不替代单步接口，遇到 `waiting_for_confirmation` 或 `WAITING_FOR_WORLDGEN` 会暂停，加载 chunk 后可用同一请求复跑并跳过已有 artifact。

旧 FunctionZone / BuildableArea / PlannedFixedPlacement / StructurePool 主链测试只作为历史代码覆盖，不再作为 active endpoint 验收口径。

## 真实游玩测试

标准启动：

```bash
.\gradlew.bat runClient -PgeomantiaDevUseStructurePacks=true -PgeomantiaDevUseRoadWeaver=true
```

规则：

- 使用 vanilla-like 新存档，不加载 RTF / ReTerraForged。
- 启用结构包。
- 启用 RoadWeaver；`gradle.properties` 应保持 `geomantiaDevUseStructurePacks=true`、`geomantiaDevUseRoadWeaver=true`，不得再配置 RTF / ReTerraForged 启动参数。
- `roadProvider=auto` 缺 RoadWeaver 时不得铺旧路；需要旧调试路时必须显式传 `roadProvider=worldedit_debug`。
- 必须使用未生成目标区域，或删除目标区域 region 后测试；不得复用已生成森林现场作为正式验收。
- 不复用旧 `city_realm_green_court_2_port`。
- 从新的 `city_seed_registry.json` 选择未跑过 D3 的新城市。
- 优先非港口样本、较大平地 / 缓坡 patch、少水体切割、离玩家近的城市。

- `wallVersion=v5` 时，执行层必须输出 `v5HeightSegmentation`；同段高差 `<=7` 的 unit 共用墙顶高度，段间 `8..16` 高差标记阶梯过渡，高差 `>=17` 或 unit 内部大落差必须写 `NATURAL_CLIFF_BOUNDARY_NO_WALL` 并把高山当作天然屏障，不得强行拉墙。
- `wallVersion=v5` 时，门楼开口按落点 bounds 自适应，至少形成 `栅栏-空气-栅栏` 的 3 格表达，封顶使用石砖，不应回退为固定木顶宽模板。
- `wallVersion=v5` 时，烽火台应高于普通墙、保留直线梯子；planner 必须按邻近 D5 墙段写 `wallAxis`，执行层按 X / Z 在墙顶走道高度贯通相邻墙段，梯子不得占用该通道；无法满足时必须写降级原因。
- v3 `city_wall_placement_report.json` 应包含 `placementUnitResults[]`；若 `debugScan=true`，缺口能在 `wall_gap_debug_report.json` 找到 `manualInspectTp` 和主原因。
- `city_wall_templates/*.nbt` 可被 MC NBT 读取。
- 原版自然结构不抢占 `noVanillaStructureMask`。
- trace 能解释等待、失败、越界、重叠和耗时。

## 质量阻断

以下情况不得通过验收：

- D4 / D6 仍接受旧 `patchGroupPlan`、`functionType`、`functionTag`、`structureChoicePlan`、`plannedFixedPlacementMap` 等字段。
- active endpoint 仍产出或消费 `function_zone_map.json`、`buildable_area_map.json`、`planned_fixed_placement_map.json`、`structure_pool_map.json`。
- D6 dry-run 修改世界或 execute_d7 false 写入真实 ledger。
- `city_execute_d5` 在没有 D6 locked plan 时仍激活 registry。
- D5 仍提前生成真实道路 operation。
- execute_d7 正式路径调用 `StructureStart.placeInChunk` late paste。
- D7 道路仍使用 D5 预计算路线，而不是 worldgen ledger actual footprint。
- RoadWeaver 已注册时 D7 仍默认用 WorldEdit 覆盖道路。
- RoadWeaver 缺失且 `roadProvider=auto` 时 D7 仍生成旧 WorldEdit/debug 道路。
- terrain adaptation hook 不可用却声称 Beardifier 成功。
- 城墙 v2 边界来源于功能区边界、纯矩形外框或 D7 后猜测，而不是 D3 patch 贴边 wall reservation。
- 城墙覆盖 RoadWeaver actual road mask，或 road-wall intersection 没有生成 gate / skip reason。
- Trek 测试结构缺少 envelope facts 却回退旧保守半径。
- debugLateMaterialize 结果被当作正式验收通过。
- mask hook 不可用却静默退化。
- chunk waiting 被当作结构失败。
