# City 系统测试入口

## 当前状态

City 新主链尚未实现，当前没有可执行自动测试入口。本文定义后续开发时必须补齐的测试和验收口径。

## 自动测试分层

| 测试类型 | 目标 |
| --- | --- |
| 契约测试 | 校验 `CityPlanningPackage`、`FunctionZoneMap`、`StructureLandingIntent` 必填字段、版本和引用关系。 |
| synthetic 地貌测试 | 在人工构造的平原、河岸、山麓、水岸、边境场景中验证功能区和道路结果。 |
| 回归测试 | 确认 T4 `CitySeedRegistry` 能被 City 消费，且不破坏 W / T 现有入口。 |
| 真实存档测试 | 在真实 Minecraft 世界中选择一个城市种子，生成规划图和结构落地意图。 |
| 可视验收 | 输出局部地貌图、功能区图、道路图、综合规划图和 legend。 |

## C1-C4 城市规划验收

| 检查 | 通过口径 |
| --- | --- |
| 局部地貌 | `TerrainPatchMap` 的 step、范围、patch、preview manifest 齐全。 |
| 城市语法 | `CityGrammarPlan` 与国度风格、城市类型和地貌摘要一致。 |
| 功能区 | 功能区不越界，面积比例合理，支持同类多实例。 |
| 道路连通 | 入口、核心区和主要功能区连通。 |
| 边界对象 | 功能区边界能转为道路、墙、水岸、绿化或软过渡等对象。 |
| 质量报告 | hard block、warning 和 score 能解释失败原因。 |

## C5-C8 交接验收

| 检查 | 通过口径 |
| --- | --- |
| Anchor | 必需 anchor 有候选范围、优先级和失败策略。 |
| 保留区 | 主路、中心公共空间和 anchor 范围被保留。 |
| 约束输入 | hard / soft 约束来源能回溯到 C1-C4 产物。 |
| 预算输入 | 功能区面积、可用面积、密度和机器预算字段齐全。 |
| trace 回写 | 结构落地失败后能索引 `MaterializationTrace`。 |

## 最小真实游玩验收

第一版实现完成后，至少执行一次：

1. 新世界或指定真实存档完成 W / T。
2. 从 `CitySeedRegistry` 选择一个新手村或小镇。
3. 生成 C1-C4 `CityPlanningPackage`。
4. 人工查看局部地貌图、功能区图、道路图和综合规划图。
5. 生成 `StructureLandingIntent`。
6. 结构落地层放置 3-5 个建筑或公共空间。
7. 记录用时、数据量、失败原因和截图。

## 质量阻断

以下情况不得进入结构落地：

- 城市核心区越出所属国度允许范围。
- 功能区图没有道路接入中心区。
- `FunctionZoneMap` 缺少面积或边界。
- `StructureLandingIntent` 缺少必需 anchor 或保留区。
- AI 直接写入不可解释的 jigsaw 深度、半径或 piece budget。
