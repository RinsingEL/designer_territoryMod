# City 系统测试入口

## 当前状态

当前 City active path 为 D3 地形 patch 真值 -> configured structure envelope profiling -> D4 `key_then_array` 分阶段主流程（关键结构逐个定锚并冻结 occupied，再按 `array_fill` 阵列填充重复结构）-> D4 `StructureAnchorMap` -> D6 probe-and-lock -> D5 reservation mask 预案（默认 D3 patch 贴边 wall reservation，显式 `wallVersion=v3/v4/v5` 可用结构种子 reservation mask 上下文）-> execute_d5 激活 locked planned registry 和可选 RoadWeaver 连接 -> worldgen-time placement -> `city_execute_d7` 查询 worldgen ledger / terrain trace -> RoadWeaver 道路；旧 debug 道路仅允许显式 `worldedit_debug` -> `city_plan_city_walls` 扫描 actual road mask 裁门 / 生成墙图 -> `city_execute_city_walls` 放置城墙。D4 v2 顺序候选 session、结构群整组候选和单独阵列候选仍保留为调试 / 人工干预路径；v3/v4/v5 城墙口径保持不变。

可用 `city_run_workflow` 作为调试 / 验收快跑器串联上述阶段并记录每步耗时；它不替代单步接口，遇到 `waiting_for_confirmation` 或 `WAITING_FOR_WORLDGEN` 会暂停，加载 chunk 后可用同一请求复跑并跳过已有 artifact。

旧 FunctionZone / BuildableArea / PlannedFixedPlacement / StructurePool 主链测试只作为历史代码覆盖，不再作为 active endpoint 验收口径。

## 真实游玩测试

标准启动：

```bash
.\gradlew.bat runClient -PgeomantiaDevUseStructurePacks=true -PgeomantiaDevUseRoadWeaver=true
```

规则：

- 使用 vanilla-like 新存档，不加载 RTF / ReTerraForged。
- 启用结构包。
- 启用 RoadWeaver；`gradle.properties` 应保持 `geomantiaDevUseStructurePacks=true`、`geomantiaDevUseRoadWeaver=true`，不得再配置 RTF / ReTerraForged 启动参数。
- `roadProvider=auto` 缺 RoadWeaver 时不得铺旧路；需要旧调试路时必须显式传 `roadProvider=worldedit_debug`。
- 必须使用未生成目标区域，或删除目标区域 region 后测试；不得复用已生成森林现场作为正式验收。
- 不复用旧 `city_realm_green_court_2_port`。
- 从新的 `city_seed_registry.json` 选择未跑过 D3 的新城市。
- 优先非港口样本、较大平地 / 缓坡 patch、少水体切割、离玩家近的城市。

workflow 验收口径：

- `city_workflow_report.json` 必须记录每步时间戳和耗时，失败 / 暂停时必须有 `reasonCode`。
- 首跑 D3 不得只刷新中心 GIS region；若城市核心或 v4 城墙接近 region 边界，`city_landform_review_package.json.refreshedRegions[]` 应覆盖 `patchContextBounds` 触达的所有 region。
- `skipExisting=true` 复跑时必须跳过已有 D3 / profiling / D4 / D5 / D6 artifact，避免等待 worldgen 后重复设计城市。
- `skipExisting=true` 复跑城墙时必须校验已有 `city_wall_plan.json` 的 `wallVersion` / `wallDesignPolicy` / `wallTerrainPolicy` 与请求一致；从 v3.2/v3.3 切到 v4 时不得误跳过旧城墙 plan。
- workflow 不得绕过 D5 locked registry、D7 worldgen ledger 或城墙 debug report；最终问题仍回到对应阶段 artifact 判断。

chunk 未生成：

- 如果 D6 / D7 trace 出现 `WAITING_FOR_WORLDGEN`，按 trace 中 anchor / required chunk range 从目标 chunk 外侧触发首次生成。
- 真实验收需要传送、切时间、清天气或切模式时，可以用 `realm_debug_command` 调用 MC 命令；该工具只用于调试便利，不得绕过 D5 / D6 / D7 的状态检查或 worldgen-time placement。
- worldgen 后重复 `city_execute_d7` 查询 ledger。
- waiting 不算失败。
- `city_execute_d5` 必须在 D6 locked plan 完整后执行，否则应失败。

真实验收：

- D4 `key_then_array` 默认 workflow 必须先完成关键结构阶段，再进入任何 `array_fill` 阶段；array 先于 key 或 array 后再出现 key 必须 hard fail `D4_KEY_STRUCTURES_MUST_PRECEDE_ARRAYS`。
- `d4_staged_plan.json` 必须列出 key stage 和 array stages；`d4_staged_trace.json` 必须记录每个 array stage 选择的 `arrayCandidateId`、item count 和 `variantSelectionMode`。
- 每个 `array_fill` 阶段必须读取上一阶段最新 `structure_anchor_map.json` 作为 occupied，生成的阵列 item 不得与已选关键结构或前序阵列结构 collision overlap。
- 最终 `structure_anchor_map.json` 必须同时包含关键结构 anchor 和所有阵列 anchor，并可直接进入 D5/D6/D7，无需下游特殊分支。
- D4 structure cluster groups 作为显式调试路径时仍应默认输出 5 组完整候选；每组包含 `placementOrder` 中所有 slot，且组内 `estimatedCollisionEnvelope` 不重叠。
- `structure_cluster_group_candidates.png` 必须在一张图里显示所有待选组；一种颜色只代表一个完整候选组，点标签只标 slot 简写，主图不得绘制 bbox / mask / collision envelope。
- D4 v2 每次只返回当前 slot 候选，选择后下一个 slot 候选会显示新的 occupied envelope。
- D4 v2 `d4_design_time_report.json` 能回答 `totalWallClockMs`、`toolRuntimeMs`、`agentThinkTimeMs` 和每个 slot 的耗时。
- D4 reservedEnvelope / collisionEnvelope 之间不重叠；正式 artifact 不得再输出 `safetyEnvelope` / `estimatedSafetyEnvelope` / `groupSafetyEnvelope`，结构大小诊断回到 `diagnosticMaxObservedEnvelope` 或 profile facts。
- D4 candidate preview 能显示 D3 patch 底图、已冻结 anchor、当前 slot 的候选点、估算 collision/mask envelope、score 和选择理由；红色冲突只表示 collision envelope 与 occupied 冲突，图面上候选只用 `C1/C2...` 编号，完整候选 id 放右侧 legend，不允许长 label 覆盖候选区造成“候选重叠像最终重叠”的误判。
- D4 final `structure_anchor_preview.png` 能显示 D3 patch 底图和最终选中 anchors，用于复核城市构图与地形 patch 的关系。
- `city_finalize_d4_candidate_session` 输出的 `structure_anchor_map.json` 可直接进入 D5/D6/D7，无需下游特殊分支。
- Trek 测试结构有 `structure_envelope_facts.json`，固定 / 近固定结构 D4 使用 `fixed_bbox_group`，非固定结构 D4 使用 P95 collision envelope；D4/D5 mask 从 collision envelope 加 `maskMarginBlocks` 派生。
- `structure_envelope_facts.json` 有 `validSamples[]`、`bboxGroups[]` 和 `generationConfigHash`。
- 固定 / 近固定结构的 `collisionEnvelope` 不应被默认 8 格 clearance 过度放大，默认使用 `smallClearanceBlocks=4`。
- D6 locked collision envelope 之间不重叠，且不与既有 ledger 重叠。
- worldgen hook 写入的 actual bbox 未突破 D6 locked collision envelope。
- D6 trace 能输出 `actualLocalBounds` / `actualBBoxGroupKey` / `lockedBBoxGroupKey` / `lockedCollisionEnvelope`，解释实际生成形态与 selected bbox group 是否匹配。
- D6 plannedWorldgenStructures 的 `maskEnvelope` 必须由 `lockedCollisionEnvelope + maskMarginBlocks` 派生，不能沿用 D4 旧 mask。
- D6/D7 plannedWorldgenStructures、active planned registry 和 placed ledger 均不得再写出 `safetyEnvelope`。
- D7 ledger `startSignature` 与 worldgen hook 记录一致。
- D7 `placed_structure_preview.png` 能显示 D3 patch 底图、真实 `actualFootprint`、collision/mask envelope 和 piece boxes，用于判断真实落地结果是否仍贴合原 patch。
- `placed_structure_ledger.json` 无重复、无重叠。
- 结构没有漂移、错位或压到其他结构。
- 新生成 chunk 的 structure mask 内不生成树。
- D7 道路基于 ledger `actualFootprint` 避障，不上房顶、不穿墙、不穿结构 body。
- RoadWeaver 可用时，D5 已注册 endpoint / connection，D7 不再覆盖 RoadWeaver 道路。
- RoadWeaver 缺失时，`roadProvider=auto` 不得生成旧 WorldEdit/debug 道路，必须明确标记 `skipped`、`ROADWEAVER_UNAVAILABLE` 和 `useWorldEditDebugFallback=false`；只有 `roadProvider=worldedit_debug` 可生成旧 debug road。
- D7 trace 有 `terrainAdaptationReport`，能说明 Beardifier / terrain adaptation hook 是否被观察到。
- D5 `wall_reservation_plan.json` 来自 D3 patch 贴边墙带，`wallCorridorMask` 进入 noVegetation / noVanillaStructure；预览图不应是单纯矩形外框。
- 显式 `wallVersion=v3` 时，`wall_reservation_plan.json` 应为 `city_wall_reservation_plan.v0.3`，包含 `cityDomainMask`、`domainCleanupReport`、`outerWallRing` 和 `wallReservationDebug`。
- `actual_road_mask.json` 能识别 RoadWeaver 真实道路；道路穿墙处生成 `WALL_GATE_FROM_ROAD` gate，而不是墙体覆盖道路。
- v3 下内部道路应进入 `insideRoadIgnoredIntersections[]`，外部入城道路应进入 `gateClusters[]`，不应为同一道路生成一串碎 gate。
- `wallDesignPolicy=v3.2` 时，大片水体 / shore / cliff 相邻边界可进入 `naturalBoundaries[]` 并生成 `natural_boundary` segment，不应强行连续筑墙。
- `wallDesignPolicy=v3.2` 时，贴墙 / 擦边 / 只有少量方块触碰墙的道路应进入 `roadTrendSkippedIntersections[]`，不应生成碎门。
- `wallDesignPolicy=v3.2` 时，外部入城道路应生成 `gatehouse` segment，模板为 `gatehouse_9` / `gatehouse_13`，门洞必须覆盖内外道路通廊；相邻道路应受 `minGateSpacingBlocks` 合并，不应出现过密城门。
- `wallDesignPolicy=v3.3` 时，外部道路未真正穿墙但距离墙体不超过 `roadProjectionMaxDistanceBlocks` 且可投影到墙段，应进入 `projectedRoadGateCandidates[]` 并生成 `WALL_GATE_FROM_ROAD_PROJECTION` gatehouse；内部道路和 touch-only 碎路仍不得开门。
- `wallDesignPolicy=v3.3` 时，没有直接门或投影门的 fallback 应写 `NO_VALID_GATE_CANDIDATE_AFTER_FILTER`，避免误判为没有扫描到道路。
- 城墙 / 塔楼不压建筑、不覆盖 `actualRoadMask`。
- `wallTerrainPolicy=v3.1` 时，8-16 高差处应输出 `STEPPED_WALL_PLACED` 和 `stepSlices[]`；高差更大处应输出 `WALL_EMBEDDED_IN_SLOPE` / `mountainProbe` 或 `NATURAL_CLIFF_BOUNDARY`，低洼处有 foundation。
- v3 / v3.1 的 `wallSegments[]` 应包含 `wallAxis=X|Z`；`placementUnitResults[]` 中的 unit / `stepSlices[]` 必须沿 `wallAxis` 切分，不得出现大量与原墙段主轴相反的切片。
- 重复执行同一 `city_wall_plan.json` 不应把已有临时城墙当作地面继续向上叠；现场不得出现成片“墙上还有墙”、错朝向墙片导致墙洞，或 8-16 高差处低侧明显悬空。
- v3.2 塔节点不得退化成一两片墙柱；`watchtower_5x5` / `beacon_5x5` 应至少保留可站立内部空间或明确跳过。
- `wallVersion=v4` 时，`wallBoundaryMode` 必须为 `actual_footprint_land_ring`，`wallBounds` 必须包住 D7 `actualFootprint`，不得因 source patch 偏小而漏掉结构。
- `wallVersion=v4` 时，若 D5 `cityDomainMask[]` 含 `maskType=city_domain_cell`，`wallContourMode` 应为 `terrain_adaptive_domain_guided_land_ring`，并用 `terrainContourEvents[]` / `wallGraphValidation.terrainContourAdjustedUnitCount` 说明哪些 unit 被地形 / 城市域外缘轻量拉动；预览图 olive 图层应显示这些非矩形收放和 `terrain_contour_link`。
- `wallVersion=v4` 时，D5 `seedPatches[]` 应保留 D3 `memberCells[]`；水体判定应优先使用 member cell，不得因大型 water patch envelope 把整圈墙误判为 `natural_boundary_gap`。
- `wallVersion=v4` 时，连续水体 run 达阈值后普通 wall unit 不应落入湖 / 海；退避失败必须输出 `natural_boundary_gap` 和 `wallGraphValidation.breaks[]`。
- `wallVersion=v4` 时，`actualRoadMask` 不得把旧城墙 / 塔 / 门楼的石砖、圆石、安山岩等材料当作道路，避免右上角 / 长边被大量 `ROAD_MASK_GATEHOUSE_OPENING` 打断。
- `wallVersion=v4` 时，每个 `wallNode` / `wallUnit` 都必须写 `surfaceMedianY`、`targetY`、`heightMode`；全局 `cityWallDatumY` 使用 trimmed median，局部高度使用 local median + datum clamp。
- `wallVersion=v4` 时，高差 `3..6` 应生成 `stepped_wall_unit` 或 `stair_link` connector；高差 `>6` 应生成 `terrace_node` 或明确 height break reason。
- `wallVersion=v4` 时，执行层必须按 `wallUnits[]` / `nodeConnectorUnits[]` 放置，不得把长段重新切成重叠墙片；重复执行不得把旧墙 / 塔 / 门楼材料当作地面继续叠高。
- `wallVersion=v5` 时，坑位水平地板必须按原始 1-block surface sample 填实到台基，现场不得在墙底边缘出现小悬空洞。
- `wallVersion=v5` 时，执行层必须输出 `v5HeightSegmentation`；同段高差 `<=7` 的 unit 共用墙顶高度，段间 `8..16` 高差标记阶梯过渡，高差 `>=17` 或 unit 内部大落差必须写 `NATURAL_CLIFF_BOUNDARY_NO_WALL` 并把高山当作天然屏障，不得强行拉墙。
- `wallVersion=v5` 时，门楼开口按落点 bounds 自适应，至少形成 `栅栏-空气-栅栏` 的 3 格表达，封顶使用石砖，不应回退为固定木顶宽模板。
- `wallVersion=v5` 时，烽火台应高于普通墙、保留直线梯子；planner 必须按邻近 D5 墙段写 `wallAxis`，执行层按 X / Z 在墙顶走道高度贯通相邻墙段，梯子不得占用该通道；无法满足时必须写降级原因。
- v3 `city_wall_placement_report.json` 应包含 `placementUnitResults[]`；若 `debugScan=true`，缺口能在 `wall_gap_debug_report.json` 找到 `manualInspectTp` 和主原因。
- `city_wall_templates/*.nbt` 可被 MC NBT 读取。
- 原版自然结构不抢占 `noVanillaStructureMask`。
- trace 能解释等待、失败、越界、重叠和耗时。

## 质量阻断

以下情况不得通过验收：

- D4 / D6 仍接受旧 `patchGroupPlan`、`functionType`、`functionTag`、`structureChoicePlan`、`plannedFixedPlacementMap` 等字段。
- active endpoint 仍产出或消费 `function_zone_map.json`、`buildable_area_map.json`、`planned_fixed_placement_map.json`、`structure_pool_map.json`。
- D6 dry-run 修改世界或 execute_d7 false 写入真实 ledger。
- `city_execute_d5` 在没有 D6 locked plan 时仍激活 registry。
- D5 仍提前生成真实道路 operation。
- execute_d7 正式路径调用 `StructureStart.placeInChunk` late paste。
- D7 道路仍使用 D5 预计算路线，而不是 worldgen ledger actual footprint。
- RoadWeaver 已注册时 D7 仍默认用 WorldEdit 覆盖道路。
- RoadWeaver 缺失且 `roadProvider=auto` 时 D7 仍生成旧 WorldEdit/debug 道路。
- terrain adaptation hook 不可用却声称 Beardifier 成功。
- 城墙 v2 边界来源于功能区边界、纯矩形外框或 D7 后猜测，而不是 D3 patch 贴边 wall reservation。
- 城墙覆盖 RoadWeaver actual road mask，或 road-wall intersection 没有生成 gate / skip reason。
- Trek 测试结构缺少 envelope facts 却回退旧保守半径。
- debugLateMaterialize 结果被当作正式验收通过。
- mask hook 不可用却静默退化。
- chunk waiting 被当作结构失败。
