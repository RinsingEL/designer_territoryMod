# City 系统测试入口

## 当前状态

City D2 (C0 CitySiteContext)、D3 (C1.5 CityLandformReviewPackage)、D4 (C2/C3 功能区草案实体化) 和 D5 (C4 道路 / 边界 / 缓冲区计划与 WorldEdit 执行入口) 已实现到自动测试可覆盖。

D3 会写出 `landform_review_map.png` 与 `city_landform_review_package.json`；D4 会写出 `function_zone_preview.png`、`function_zone_map.json`、`function_zone_terrain_stats.json` 和 `quality_report.json`；D5 会写出 `road_intent.json`、`boundary_intent.json`、`build_operation_plan.json`、`city_planning_preview.png`、`quality_report.json`，执行后追加 `world_mutation_report.json`。

D5 真实执行是显式危险操作：必须先完成 `city_plan_d5`，再用 `city_execute_d5 { confirmWorldMutation: true }` 触发 WorldEdit 后端修改世界。

## D2 CitySiteContext 验收

| 检查 | 通过口径 |
|---|---|
| 必填字段 | schemaVersion、cityId、realmId、grid、bounds、anchorBlock、entryCandidates、territoryCheckResult 齐全 |
| 规模映射 | hamlet/village/town/city 正确映射，T4 capital -> city |
| 网格 | 未显式传 `cellStepBlocks` 时从 `world_survey_manifest.json` 恢复 W/T 采样步长，City 本地 grid cellStep 再按规模夹取 |
| GIS 兼容 | City grid cellStep 必须保持 GIS region 可整除，避免 D3 局部刷新失败 |
| 锚点 | 优先使用 T4 seed 的 `anchorBlock`，不得用 MCP 默认 cellStep 重算错位 |
| 入口 | 含 main_gate + 4 方向 gates，TOWN/CITY 加对角线 |
| 领地检查 | 优先读取 `realm_territory_map.json` 中同 realm 的 owned cells；anchor 不在 -> outside，边界超 10% -> border，无数据 -> unknown |

## D3 CityLandformReviewPackage 验收

| 检查 | 通过口径 |
|---|---|
| patch 过滤 | 只包含与城市 bounds 相交的 patch |
| 标签分配 | mapLabel 按地貌类型分组、组内 cellCount 降序，格式 平原01、海岸02 |
| 邻域检测 | 边相邻 patch 在 neighborLandformPatchIds 中，角接触不计 |
| 事实生成 | 大 patch 含面积事实，水岸 patch 含水距事实，陡坡 patch 含坡度 warning |
| 图例 | 覆盖所有出现的地貌类型 |
| AI 上下文 | 含规模和城市类型 |
| 审查图 | D3 HTTP/MCP 产物必须写出 `landform_review_map.png` 并在 `reviewMapImage`/`debugRefs` 中引用 |
| 落盘包 | D3 HTTP/MCP 产物必须写出 `city_landform_review_package.json`，供 D4 读取 |
| 成员格子 | 真实运行 D3 应输出 `landformPatches[].memberCells`；缺失时只能显式降级为 envelope |
| 阶段边界 | C1.5 只复述 GIS facts，不输出“建议建设区域/适合建设”等 C2 决策文案 |

## D4 FunctionZoneMap 验收

| 检查 | 通过口径 |
|---|---|
| 草案来源 | `PatchGroupPlan` 由 MCP 调用方侧 AI / Codex 提交，运行时不内置 LLM |
| 引用校验 | 不存在 `mapLabel` / `landformPatchId` 时 hard block |
| 功能类型 | 只接受 8 个固定 `functionType`，未知类型 hard block |
| 多实例 | 同类功能区允许多个实例 |
| split | `splitRequested` 只记录 warning，不实际裁剪 |
| 几何口径 | 优先输出 `patch_member_cells` / `patch_member_cells_union`；只有 D3 缺少成员格子时降级为 envelope |
| 产物 | 写出 `patch_group_plan.json`、`function_zone_map.json`、`function_zone_terrain_stats.json`、`function_zone_preview.png`、`quality_report.json` |

## D5 Road / Boundary / WorldEdit 验收

| 检查 | 通过口径 |
|---|---|
| 两步执行 | `city_plan_d5` 只生成计划和预览，不改世界；`city_execute_d5` 才改世界 |
| 确认门 | `city_execute_d5` 缺少 `confirmWorldMutation: true` 必须 hard block |
| 上游产物 | 缺 D3 `city_landform_review_package.json` 或 D4 `function_zone_map.json` / `function_zone_terrain_stats.json` 必须 hard block |
| 核心区 | 优先 `civic_core`，否则 `market`，否则最大非水岸功能区；找不到必须 hard block |
| 入口 | 优先 `main_gate`，否则最近 entry candidate；找不到必须 hard block |
| 道路 | 主路连接入口到核心区；非核心功能区生成 secondary/access 接入 |
| 操作计划 | 每条 road edge 至少生成 `clearVegetation` 和 `surfaceFill`，边缘生成 `surfaceReplace` |
| 边界 / 缓冲区 | `green_buffer` / `soft_transition` 等边界生成清植被和地表替换 / 缓冲操作 |
| 模板 | `gate_small` / `dock_marker` / `waystone_small` 缺文件只 skipped + warning，不阻断道路和缓冲区 |
| WorldEdit 隔离 | City 规划层不得直接调用 WorldEdit API，只能通过 `WorldMutationBackend` |
| 执行报告 | 写出 `world_mutation_report.json`，包含 backend、executed/skipped/failed、changedBlocks、warnings、failures、`undoSupported=false` |

## 运行方式

```bash
# City 自动测试
./gradlew.bat test --tests "com.rinsing.geomantia.systems.city.*" --tests "com.rinsing.geomantia.platform.http.CityPlanningEndpointHandlerTest"

# MCP TypeScript 编译
cd country_designer_mcp
.\node_modules\.bin\tsc.cmd --noEmit

# MCP 真实游玩（需 MC 运行中）
city_plan_d3 { runId: "realm_reterraforged_t4_crop_4096_20260614", citySeedId: "city_realm_green_court_2_port" }
city_plan_d4 { runId: "realm_reterraforged_t4_crop_4096_20260614", citySeedId: "city_realm_green_court_2_port", patchGroupPlan: { ... } }
city_plan_d5 { runId: "realm_reterraforged_t4_crop_4096_20260614", citySeedId: "city_realm_green_court_2_port" }
city_execute_d5 { runId: "realm_reterraforged_t4_crop_4096_20260614", citySeedId: "city_realm_green_court_2_port", confirmWorldMutation: true }
```

## 最小真实游玩验收

1. 确认 `gradle.properties` 的快速启动进入 `新的世界` 配置有效，并用 `.\gradlew.bat runClient` 启动客户端。
2. 确认进入存档后 `/realm/status` 可访问，API server 在 `127.0.0.1:5000`。
3. 使用已有 run `realm_reterraforged_t4_crop_4096_20260614` 或重新跑 `realm_run_acceptance`。
4. 对 `city_realm_green_court_2_port` 调用或复用 D3/D4。
5. 调用 `city_plan_d5`，打开 `city_planning_preview.png` 检查主路、次路、边界、缓冲区和模板 marker。
6. 可选：放入 `run/geomantia_templates/d5/gate_small.schem` 或 `dock_marker.schem`。
7. 调用 `city_execute_d5 { confirmWorldMutation: true }`。
8. 在世界里 tp 到入口、核心区和边界带，确认植被清理、道路 / 缓冲区可见，小模板粘贴成功或在报告中明确 skipped。
9. 检查 `world_mutation_report.json` 与实际世界变化一致。

## 质量阻断

以下情况不得进入结构落地或真实执行：

- 城市核心区越出所属国度允许范围。
- D4 `FunctionZoneMap` 缺少面积、边界或核心功能区候选。
- D5 没有入口到核心区的主路。
- `city_execute_d5` 缺少显式确认。
- `BuildOperationPlan` 为空或包含未知 operation type。
- AI 直接写入不可解释的 jigsaw 深度、半径或 piece budget。
