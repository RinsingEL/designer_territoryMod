# City 系统测试入口

## 当前状态

City D2 (C0 CitySiteContext)、D3 (C1.5 CityLandformReviewPackage) 和 D4 (C2/C3 功能区草案实体化) 已实现到自动测试可通过；D3 已补 `landform_review_map.png` 与 `city_landform_review_package.json`，D4 已补 `function_zone_preview.png`、`function_zone_map.json`、`function_zone_terrain_stats.json` 和 `quality_report.json` 调试产物。

真实 Minecraft/MCP 游玩验收尚未完成，不能据此宣称 D2-D4 已完成实机验收。

## D2 CitySiteContext 验收

| 检查 | 通过口径 |
|---|---|
| 必填字段 | schemaVersion、cityId、realmId、grid、bounds、anchorBlock、entryCandidates、territoryCheckResult 齐全 |
| 规模映射 | hamlet/village/town/city 正确映射，T4 capital→city |
| 网格 | 未显式传 `cellStepBlocks` 时从 `world_survey_manifest.json` 恢复 W/T 采样步长，City 本地 grid cellStep 再按规模夹取 |
| GIS 兼容 | City grid cellStep 必须保持 GIS region 可整除，避免 D3 局部刷新失败 |
| 锚点 | 优先使用 T4 seed 的 `anchorBlock`，不得用 MCP 默认 cellStep 重算错位 |
| 入口 | 含 main_gate + 4 方向 gates，TOWN/CITY 加对角线 |
| 领地检查 | 优先读取 `realm_territory_map.json` 中同 realm 的 owned cells；anchor 不在 → outside，边界超 10% → border，无数据 → unknown |

## D3 CityLandformReviewPackage 验收

| 检查 | 通过口径 |
|---|---|
| patch 过滤 | 只包含与城市 bounds 相交的 patch |
| 标签分配 | mapLabel 按地貌类型分组、组内 cellCount 降序，格式 平原01、海岸02 |
| 邻域检测 | 边相邻 patch 在 neighborLandformPatchIds 中，角接触不计 |
| 事实生成 | 大 patch 含面积事实，水岸 patch 含水距事实，陡坡 patch 含坡度警告 |
| 图例 | 覆盖所有出现的地貌类型 |
| AI 上下文 | 含规模和城市类型 |
| 审查图 | D3 HTTP/MCP 产物必须写出 `landform_review_map.png` 并在 `reviewMapImage`/`debugRefs` 中引用 |
| 落盘包 | D3 HTTP/MCP 产物必须写出 `city_landform_review_package.json`，供 D4 读取 |
| 成员格子 | 真实运行 D3 应输出 `landformPatches[].memberCells`；缺失时只能显式降级为 envelope |
| 阶段边界 | C1.5 只复述 GIS facts，不输出“建议建设区域/适合建设”等 C2 决策文案 |

## D4 FunctionZoneMap 验收

| 检查 | 通过口径 |
|---|---|
| 草案来源 | `PatchGroupPlan` 由 MCP 调用方侧 AI / Codex 提交，运行时不内置 LLM |
| 引用校验 | 不存在 `mapLabel` / `landformPatchId` 时 hard block |
| 功能类型 | 只接受 8 个固定 `functionType`，未知类型 hard block |
| 多实例 | 同类功能区允许多个实例 |
| split | `splitRequested` 只记录 warning，不实际裁剪 |
| 几何口径 | 优先输出 `patch_member_cells` / `patch_member_cells_union`；只有 D3 缺少成员格子时降级为 envelope |
| 产物 | 写出 `patch_group_plan.json`、`function_zone_map.json`、`function_zone_terrain_stats.json`、`function_zone_preview.png`、`quality_report.json` |

## 运行方式

```bash
# 单元测试
./gradlew test --tests "com.rinsing.geomantia.systems.city.*"

# 真实 sealed run 数据测试（无需 MC）
./gradlew test --tests "com.rinsing.geomantia.systems.city.CityRealDataTest"

# D2 HTTP 适配层测试（无需 MC）
./gradlew test --tests "com.rinsing.geomantia.platform.http.CityPlanningEndpointHandlerTest"

# MCP 真实游玩（需 MC 运行中；本项仍待执行）
city_plan_d3 { runId: "realm_reterraforged_t4_crop_4096_20260614", citySeedId: "city_realm_salt_kingdom_0_capital" }
city_plan_d4 { runId: "realm_reterraforged_t4_crop_4096_20260614", citySeedId: "city_realm_salt_kingdom_0_capital", patchGroupPlan: { ... } }
```

## 最小真实游玩验收

1. 启动 Minecraft，进入世界；当前 `新的世界` 是 ReTerraForged 存档，`gradle.properties` 必须启用 `geomantiaDevUseReTerraForged=true`
2. 运行 `realm_run_acceptance` 或使用已有 run
3. 调用 `city_plan_d3`（指定 runId + citySeedId）
4. 人工确认返回 JSON 的 `landformPatches` 有正确标签、legend 完整，`reviewMapImage` 指向已生成 PNG
5. 打开 `run/realm_debug/<runId>/city_d3_<citySeedId>/landform_review_map.png`，检查锚点、patch 标签、边界是否能对应实际地貌
6. 由 AI / Codex 基于 D3 图包生成 `PatchGroupPlan`，调用 `city_plan_d4`
7. 打开 D4 `function_zone_preview.png` 与 `quality_report.json`，确认功能区引用、stats 和 hard block / warning 合理
8. 在世界中到 `anchorBlock` 附近实地确认地形和图包大体一致
9. 选另一个 citySeedId 复查不同城市类型的输出

## 质量阻断

以下情况不得进入结构落地：

- 城市核心区越出所属国度允许范围。
- 功能区图没有道路接入中心区。
- `FunctionZoneMap` 缺少面积或边界。
- `StructureLandingIntent` 缺少必需 anchor 或保留区。
- AI 直接写入不可解释的 jigsaw 深度、半径或 piece budget。
