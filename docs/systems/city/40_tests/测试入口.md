# City 测试入口

## 当前验收对象

正式链路是 D3 地貌事实 -> CityBlueprint v0.11 -> D4 required 建筑/景观容量联合求解 -> D5 reservation -> D6 固定 NBT 锁定 -> Foundation/Landscape/SurfacePrintPlan v0.6 -> execute_d5 激活 -> owner-chunk worldgen -> D7 ledger/observation -> RoadWeaver/城墙。

测试必须区分三类结论：纯算法/codec、服务端 artifact 链、真实新区块 worldgen。前两类通过不能代替第三类现场验收。

## 测试运行包

一次 City 端到端测试以 `runId + citySeedId` 为身份，完整产物位于：

```text
run/realm_debug/<runId>/city_test_runs/<citySeedId>/
```

`test_run_manifest.json` 是恢复入口，D3、Blueprint、D4-D7、LandUse、Decoration 和 walls 产物都位于该目录的 `steps/` 下。续跑同一测试必须复用该包并追加 `attempts[]`，不得再到 `<runId>/city_d3_<id>`、`city_d4_<id>` 等散落目录逐步猜测现场。完整字段和 legacy 规则见 `../../../03_shared_contracts/测试运行包契约.md`。

## 自动测试命令

在实现仓库根目录执行完整 Java 测试：

```powershell
.\gradlew.bat test
```

按类聚焦回归：

```powershell
.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.application.CityBlueprintServiceTest"
.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.application.outdoor.CityOutdoorBlueprintCompilerTest"
.\gradlew.bat test --tests "com.rinsing.geomantia.systems.city.algorithm.landuse.RelayRegionGrowthClassifierTest"
.\gradlew.bat test --tests "com.rinsing.geomantia.platform.http.CityPlanningEndpointHandlerTest"
```

MCP schema 与 handler 适配测试：

```powershell
Set-Location country_designer_mcp
npm test
```

## 预览验收

正式设计验收停在 D4 编译后的 preview，不需要先执行世界写入。为了缩短迭代，只要 D3 artifact 身份仍匹配，应复用冻结 D3，从 `prepare -> submit -> compile` 重跑一次 D4；不要为了修改 Blueprint 参数重新扫描城市或重跑 D2/D3。

预览至少检查：

- 核心结构和 Landscape 是否先取得合理空间，可选小项抢不过时是否正常停止。
- Foundation 是否连续，是否出现窄桥、结构洞或 bbox 填满。
- 农田、花田、林场是否由多个不规则接力区域构成，而不是圆、菱形、同心环或完全等宽模板。
- 角色比例是否符合 Blueprint 权重；主题内容是否明显强于水渠、岸、叶片、石路等间隔内容。
- 在景观组合多样性功能完成前，不得把 Blueprint 中存在 `selectionWeight` 或 `contentWeights` 字段当作多方案、多作物、多花种或多树种已经落地的证据。
- region source、parent、面积、跳过原因和预算 trace 是否能解释图形。
- 建筑入口、道路交接、gate 与城墙 reservation 是否互相一致。

预览只证明规划输出，不证明目标区块已生成或方块已经落地。

## 新区块现场验收

真实 worldgen 必须选择此前未加载的目标区块。先完成 `city_execute_d5 confirmWorldMutation=true` 激活，再由玩家移动或传送触发 chunk 首次生成；不能先传送再声称测试了生成期注册。

现场按以下顺序核对：

1. D6 owner chunks 在激活前未生成，run/city/dimension identity 与当前世界一致。
2. 固定模板实际 hash、方向、入口和 footprint 与 D6/preview 一致。
3. LandUse/Decoration ledger 有 owner 成功记录，没有 partial apply 或旧 schema 混入。
4. `city_query_worldgen_observations` 区分 `post_features` 与 `chunk_save`；`pendingSaveVerification=true` 不算最终通过。
5. 跨 chunk 的地表、作物、水、边界、装饰和建筑没有接缝、重复或漏写。
6. RoadWeaver 道路后写没有被 LandUse 回盖，城墙 gate 对齐真实道路。
7. `full_footprint_support` 建筑以完整占地中位 datum 落地，建筑四角和内部均有台基承托且不浮空；外围 Foundation 穿过可承载的小坑、沟槽和流体时连续，小土坡在 12 格切方上限内削平，未改高度列仍完整铺面。D4 对结构完整占地的 water/slope/localRelief/elevation range 必须先做硬门禁；农田、林场和牧场保持自然地形且不得跨越对应 terrain policy 的相邻高程断崖。

## 失败分类

- schema/hash/identity 不匹配：清理本 run 的旧下游 artifact 后，从最早失效阶段重跑。
- D4 图形或权重不合格：只修 Blueprint/catalog/编译器并重跑 D4，不先扩大到 worldgen。
- `waiting_for_confirmation`：补世界修改确认，不重跑已经冻结且身份匹配的规划。
- `waiting_for_worldgen`：说明计划已激活但 owner chunk 尚未首次生成；不得用 ledger 计划数冒充现场结果。
- 现场不一致：先对齐 plan、active registry、owner ledger 和 block observation，定位是资源、规划、激活、worldgen 还是后写层。

恢复测试时不得先重放所有步骤。先打开运行包清单，核对 world identity 和 `latestRequest`，再根据 `nextAction` 只执行需要继续的入口；已有且身份匹配的阶段由 `skipExisting` 复用。

当前尚待复验的问题见 `故障修复案/README.md`。完成现场验收后应更新或删除对应故障案，避免把已关闭案例继续作为现行规则。
