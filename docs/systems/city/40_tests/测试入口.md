## 当前状态

当前 City active path 为 D3 地形 patch + LandUse terrain field 真值 -> configured structure envelope profiling -> D4 `key_then_array` 与 group provenance -> 最终 D4 `StructureAnchorMap` -> `city_plan_d5` reservation mask 轻量预案 -> D6 probe-and-lock -> 可选 block 级 LandUseAreaPlan + SurfacePrintPlan -> 可选 City DecorationProgram intent v0.4 -> execute_d5 校验并激活 registries -> 首次 owner-chunk worldgen 执行 LandUse `BASE -> NBT -> CROP -> BOUNDARY`、再执行稀疏 Decoration -> `city_execute_d7` 查询 ledger -> RoadWeaver 真实道路后写覆盖 -> CityWalls。

旧 FunctionZone / BuildableArea / PlannedFixedPlacement / StructurePool / bounded jigsaw 实现及其测试已删除。active endpoint 对旧字段和旧 artifact 的 hard-fail 隔离测试必须保留。

## 质量阻断

以下情况不得通过验收：

- D4 / D6 仍接受旧 `patchGroupPlan`、`functionType`、`functionTag`、`structureChoicePlan`、`plannedFixedPlacementMap` 等字段。
- 为生活感切片新建或恢复旧 `FunctionZoneMap`，或要求功能区覆盖全部城市范围。
- 自动朝向静默使用目录首个旋转、输出 rotation 与 `orientationDecision` 不一致，或改变原候选点来换取朝向。
- 临水样本以矿产、土壤或其他不存在的资源扫描作为农业 / 商业 / 行政选址证据。
- active endpoint 仍产出或消费 `function_zone_map.json`、`buildable_area_map.json`、`planned_fixed_placement_map.json`、`structure_pool_map.json`。
- D6 dry-run 修改世界或 execute_d7 false 写入真实 ledger。
- `city_execute_d5` 在没有 D6 locked plan 时仍激活 registry。
- D5 仍提前生成真实道路 operation。
- execute_d7 正式路径调用 `StructureStart.placeInChunk` late paste。
- D7 道路仍使用 D5 预计算路线，而不是 worldgen ledger actual footprint。
- LandUse 在 D6 locked footprint 前定稿，或从 D4 planned bbox 反推最终排除区。
- LandUse 恢复旧 `FunctionZoneMap`、要求把城市规划范围分满，或把全部 area spans 直接复制成 no-vegetation mask。
- workflow 默认启用 LandUse、请求覆写不优先于 settings，或独立 `city_plan_land_use` 被 workflow 开关错误阻止。
- AI intent 可以提交裸面积 / 行动力 / 成本 / block mask；`set_rule` / `exclude` 条件或未知字段未严格拒绝。

- 城墙 v2 边界来源于功能区边界、纯矩形外框或 D7 后猜测，而不是 D3 patch 贴边 wall reservation。

- 使用新 vanilla-like 存档和未生成目标 chunk，准备至少两个不同尺寸 / 入口的 City NBT 模板；D2 目录 hash、D4 plan、D6 locked plan、D7 ledger 的 identity 必须逐项相同。

- 至少一个模板的 `lockedActualFootprint` 必须跨越两个或更多 owner chunk。每个 owner 只写本 chunk 可见 fragment；未覆盖完时 D7 保持 waiting 且 completed ledger 不得出现该模板，最后一个 owner 生成后仅生成一条 `TEMPLATE_MATERIALIZATION_RECORDED` final ledger，并写正确 `templateFragmentCount`。
- 现场确认模板实际方块范围与计划 closed `actualBBox` 一致，`max = anchor + transformedSize - 1`；不得出现把 half-open max 当成实际方块、整体平移一格或按旧最大包络放大的现象。
- 对非正方形模板的每种 rotation / mirror，实际所有非空气方块必须位于 D6 locked footprint 和各自 owner fragment 内；不得因 Minecraft rotation pivot 与规划归一化坐标重复变换而沿单轴偏移、被 owner `BoundingBox` 裁掉，或在 completed ledger 下出现缺块。
- 改变 rotation / mirror 后，模板 footprint、道路入口坐标和方向必须同步改变；RoadWeaver 入口必须落在模板声明的 transformed entrance 上，不得出现在 bbox 外侧伪造位置。
- 启用 RoadWeaver 且 `roadProvider=auto`，确认 D5 在目标 chunk 首次生成前注册 endpoint / connection，RoadWeaver 生成道路，D7 不覆盖道路；同时关闭 `spawnCabinEnabled` 和 `roadsideStructure.enabled` 以隔离验收对象。
- 不加载 RoadWeaver 时，`auto` 必须只跳过道路并记录 `ROADWEAVER_UNAVAILABLE`；`roadweaver` 必须 hard fail；只有显式 `worldedit_debug` 可见旧调试道路，且不改变模板建筑结果。
- 重载或替换模板 NBT 后使 hash 改变，旧 active registry / plan 必须被拒绝并要求重新规划；不得用旧 hash、旧 bbox 或旧入口继续落地。
- 观察运行日志、trace 和 ledger，确认非 `structure_start_beard_thin` City 模板没有外部 `Registries.STRUCTURE` 查询、StructureStart 创建或 Jigsaw 展开；启用该 policy 的实测模板必须只创建 City 注册的单-piece start，并记录 `terrainAdaptation=beard_thin`。相关旧 configured-structure 测试 / 日志只作为历史隔离证据。
