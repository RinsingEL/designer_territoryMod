# GIS 验收计划

本文定义 GIS 从文档方案进入实现后的验收标准。

## G1 基础采样验收

- 能围绕中心点采样指定半径内的 AtlasCell。
- 默认使用生成器先验采样，不主动预生成大范围 chunk。
- 每个 Cell 有基础高度、水体关系、生物群系、可预测表面类型。
- Cell 能记录 sampleSource，v1 默认 prior。
- Region 坐标和 Cell 坐标转换稳定。
- 同一输入重复运行结果一致。

## G2 指标层验收

- 坡度、局部起伏、粗糙度、小尺度 TPI、大尺度 TPI 可输出。
- 指标依赖不足时，Cell 被标记为未完成或 edgeDirty。
- 至少输出一张坡度图和一张 TPI 图用于人工检查。

## G3 地貌分类验收

- 能把 Cell 分类为 water、shore、plain、terrace、slope、cliff、ridge、valley、basin、unknown。
- 能把相邻同类 Cell 合并为 LandformPatch。
- Patch 输出面积、高度、坡度、水距、水体接触等摘要。
- PatchEnvelope 只能作为查询候选粗筛；真实命中和预览形状应能回到成员 Cell 或 PatchShape。
- 固定样例中明显平原、山脊、谷地、岸线应基本符合肉眼判断。

## G4 半径刷新验收

- 能按区块环逐步刷新。
- 中心稳定区可以先完成，边缘依赖区正确标记。
- 低优先级刷新可被预算限制，不长时间阻塞。
- 相邻刷新请求可以复用已有 Region 数据。
- v1 基线增加轻量 Region 快照读写，用于测试复现和现场还原；不实现完整生产级 SavedData / 二进制长期持久层。

## G5 运行中 Progress Preview 验收

- RefreshJob 运行过程中能低频输出 `progress.png`。
- 能输出 `progress_manifest.json`。
- manifest 中包含 runId、中心点、半径、Cell 总数、各状态计数、currentRing、status。
- 进度图能区分 pending、sampled、metrics、classified、patched、edgeDirty、failed。
- Progress Preview 允许覆盖写入，不作为最终验收真值。

## G6 调试输出验收

- 能输出 PreviewManifest。
- 能输出 elevation、water、slope、tpiSmall、tpiLarge、landform、patch 至少其中核心图层。
- 每次 preview 输出必须附带图例，说明地貌颜色、patch 边界和 unknown/未处理区域。
- Manifest 能追溯 seed、中心点、半径、配置版本和输出图层。

## G7 自动测试验收

- `./gradlew.bat test` 能运行 GIS 的 JVM 单元测试和人造网格算法测试。
- Forge GameTest 能在固定 seed 测试世界中运行 prior 采样；固定测试存档仅用于后验对照。
- 自动测试能触发 GIS refresh、等待完成、导出 progress、preview 和 `test_report.json`。
- `test_report.json` 能记录 passed、durationMs、cellCounts、landformCounts、patchCounts、failures 和 artifacts。
- 固定样例至少覆盖 plain、mountain、water、mixed 四类。
- 可选后验对照只针对已加载或小范围验证 chunk，不作为所有样例的前置条件。

## G8 消费接入验收

G8 消费接入不纳入 GIS v1 基线开发目标。本节保留为后续消费者接入验收口径。

- City 可以查询地貌 Patch，并按城市 profile 自行筛选候选区域。
- Roads 可以查询坡度、水体、山脊、谷地或道路代价基础数据。
- Structure 可以查询地貌事实，并按结构 profile 自行筛选候选落点。
- 消费者不直接重复大范围扫描世界。
