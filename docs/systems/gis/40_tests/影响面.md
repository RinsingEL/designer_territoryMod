# GIS 影响面

GIS 是基础系统，影响面比 city 子模块更大。任何字段、刷新流程、缓存策略变化，都需要检查消费者是否仍能正确读取地貌事实。

## 直接影响

| 系统 | 影响 |
| --- | --- |
| City | 城市选址、可建区域、临水评价、地形适配。 |
| Roads | 道路代价、避水、避陡坡、沿谷地或岸线连接。 |
| Realm | 区域边界、天然屏障、势力范围扩张。 |
| Structure | 结构群落分布、结构偏好地貌、落点筛选。 |
| Debug Tools | 预览图、验收报告、人工校准流程。 |

v1 GIS 主要影响地表规划，不直接追踪树、草、矿物、洞穴、原版结构最终落位或玩家改动。结构物化阶段可以做局部真实 chunk 校验，但这不改变 Atlas 默认 prior 采样口径。

## 高风险变更

- 修改 `cellStepBlocks`。
- 修改 Region 尺寸。
- 修改 TPI 半径。
- 修改 sampleMode 或 sampleSource 语义。
- 修改 landformType 枚举。
- 修改消费者适配评分所依赖的 GIS 事实字段。
- 修改 Patch 合并规则。
- 修改 PatchShape、成员 Cell 映射或 PatchEnvelope 查询语义。
- 修改 RefreshJob 状态机。
- 修改 Chunk 生成基准的 ticket 半径、FULL 完成口径、新旧 Chunk 判定或清理路径。
- 修改 prior 从 `getBaseHeight` / `getBaseColumn` 还原 surface、ocean floor、水体或水深的方式。

这些变更需要同步检查产品方案、数据契约、代码导览和测试入口。

## 兼容策略

- Atlas 数据格式变化时提升 `atlasVersion`。
- 阈值配置变化时更新 `configVersion`。
- 新增地貌类型时，消费者必须先能处理 unknown 或 fallback 类型。
- PreviewManifest 必须记录版本，避免新旧图层混淆。
- PatchEnvelope 命中的结果只能作为 candidate；消费者最终命中必须通过 PatchShape、成员 Cell 或局部校验确认。
- Chunk 生成基准必须保持显式确认、单任务运行和终态清票；不得静默进入 GIS refresh、City D3 或服务器启动流程。
- 单柱优化必须使用生成器公开的 Column / Heightmap 语义并做同 seed 产物对照；非标准生成器若 `getBaseColumn` 与 `getBaseHeight` 语义不一致，需要能力探测或明确失败，禁止静默接受偏差。
