# GIS 代码导览

本文是 GIS 目标代码结构导览。当前实现可以尚未完全存在，但后续代码应尽量按本文分层，避免重回 legacy 式大文件堆叠。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| cell | AtlasCell 数据结构、状态标记、基础字段访问。 |
| region | AtlasRegion 切分、缓存、Region 坐标转换。 |
| refresh | RefreshJob 调度、半径环刷新、预算执行、脏区管理。 |
| metrics | 坡度、局部起伏、粗糙度、TPI、水距、可建性计算。 |
| landform | Cell 分类、Patch 合并、地貌类型规则。 |
| preview | 调试图导出、PreviewManifest 写出。 |
| query | 给 city、roads、realm、structure 使用的查询接口。 |

## 实现顺序

1. `cell` 和 `region` 先落地，保证数据结构独立可测。
2. `refresh` 只做基础采样和状态推进，不直接塞分类规则。
3. `metrics` 逐个指标补实现，每个指标单独测试和预览。
4. `landform` 基于指标层做规则分类和 Patch 合并。
5. `preview` 作为验收工具尽早接入，不等全部功能完成。
6. `query` 最后提供稳定的消费者入口。

## 依赖方向

```mermaid
flowchart TD
  A["cell"] --> B["region"]
  B --> C["refresh"]
  B --> D["metrics"]
  D --> E["landform"]
  E --> F["query"]
  B --> G["preview"]
  D --> G
  E --> G
```

依赖原则：

- `metrics` 不依赖 `city`、`roads`、`realm`、`structure`。
- `landform` 不直接做城市选址。
- `query` 是消费者边界，消费者不应绕过它大范围扫描 Atlas 内部结构。
- `preview` 可以读取内部数据，但不应成为运行时主流程依赖。
