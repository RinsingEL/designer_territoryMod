# 半径刷新实现指南

本文说明一次 GIS 半径刷新如何在当前实现代码中执行。它面向开发和 review，不重新定义产品边界或数据字段；产品真值见 `../../10_product/`，契约真值见 `../../20_contracts/`。

## 适用范围

适用于以下入口触发的同一条 GIS 主链：

- `/geomantia gis refresh <radiusChunks> [sampleMode]`
- `POST /gis/refresh`
- MCP 工具 `gis_refresh`
- 合成测试中的 `GisTestRunner.runCase`

不适用于未来 G8 消费者查询接口、生产级 SavedData 持久层或结构物化前的局部 `verifySurface` 强校验流程。

## 入口与触发方式

| 入口 | 代码 | 输入来源 | 输出 |
| --- | --- | --- | --- |
| Forge 命令 | `GisPlatformEvents.refresh` | 命令参数、命令源位置和维度 | 聊天提示、`run/gis_debug/<runId>/` |
| HTTP 接口 | `GisHttpController.handleRefresh` | JSON body、在线玩家或显式中心点 | JSON 响应、`run/gis_debug/<runId>/` |
| MCP 工具 | `country_designer_mcp/src/gis/handlers.ts` | MCP tool arguments | 格式化 JSON 文本 |
| 合成测试 | `GisTestRunner.runCase` | `GisTestCase` 固定样例 | `test_report.json`、`region_snapshot.json` |

HTTP 入口必须通过 `callOnServerThread` 回到 Minecraft server thread 后再读取玩家、维度和执行刷新。

## 前置条件

- 有可用 `MinecraftServer` 或合成测试配置。
- `radiusChunks` 在 `1..64` 范围内。
- 没有在线玩家时，HTTP refresh 必须显式传 `centerBlockX` 和 `centerBlockZ`。
- 常规刷新默认使用 `SampleMode.PRIOR`；`verifySurface` 不应作为大范围 Atlas 建库默认路径。
- debug 产物根目录为 `server.getServerDirectory()/gis_debug` 或测试传入的 `debugRoot`。

## 主调用链

当前 GIS 系统代码已内聚到 `com.rinsing.geomantia.systems.gis`：

- `application.refresh` 承载刷新 workflow / 用例编排。
- `application.sample` 承载采样端口与采样结果。
- `domain.*` 承载 AtlasCell、AtlasRegion、LandformPatch 等领域对象。
- `algorithm.*` 承载指标计算、地貌分类和 Patch 合并。
- `adapter.minecraft`、`adapter.snapshot` 承载 Minecraft prior 采样和轻量快照 IO。
- `preview` 承载调试图、manifest 和 progress 导出。
- `testsupport` 承载固定样例、测试 runner 与 GameTest。

真实世界刷新主链：

```text
GisPlatformEvents.refresh 或 GisHttpController.runRefresh
  -> new GisRefreshService(...)
  -> GisRefreshService.refresh(...)
  -> AtlasRegionStore.regionForBlock(...)
  -> GisRefreshService.run(...)
  -> RadiusRefreshPlanner.plan(...)
  -> AtlasSampler.sample(...)
  -> AtlasMetricsComputer.compute(...)
  -> LandformClassifier.classify(...)
  -> PatchMerger.merge(...)
  -> ProgressExporter / PreviewExporter
  -> RefreshResult
```

合成测试主链：

```text
GisTestRunner.runCase
  -> new GisRefreshService(... SyntheticAtlasSampler ...)
  -> GisRefreshService.refresh(...)
  -> AtlasRegionSnapshotIo.write(...)
  -> GisTestReport
```

## 步骤明细

### 1. 参数归一与运行上下文

| 字段 | 内容 |
| --- | --- |
| 目标 | 把命令、HTTP 或 MCP 输入转换为刷新中心、维度、半径和采样模式。 |
| 输入 | `radiusChunks`、`sampleMode`、`centerBlockX/Z`、`dimensionId`、`playerName`、命令源位置。 |
| 输出 | `ServerLevel`、中心 `BlockPos`、`SampleMode`、debugRoot。 |
| 允许读 | Minecraft server、在线玩家列表、请求 JSON、命令上下文。 |
| 允许写 | HTTP/MCP 日志、错误响应、命令成功/失败提示。 |
| 禁止事项 | 入口层不得复制 sampler、metrics、classifier、patch 业务逻辑。 |
| 失败处理 | 参数错误返回 400 或命令失败消息；未知维度/玩家必须显式报错。 |
| 测试锚点 | MCP `gis_status`、`gis_refresh`；命令 `/geomantia gis refresh`。 |

当前实现说明：

- Forge 命令入口从 `CommandSourceStack` 获取 `ServerLevel` 和玩家位置。
- HTTP 入口允许省略中心点，此时使用指定玩家或首个在线玩家；无玩家且无中心点会失败。
- MCP 只做参数整理并转发 HTTP，不持有业务状态。

### 2. RefreshJob 与 Region 创建

| 字段 | 内容 |
| --- | --- |
| 目标 | 创建一次可追踪的刷新任务，并定位中心点所在 AtlasRegion。 |
| 输入 | `dimensionId`、中心坐标、半径、`GisSampleConfig`、`SampleMode`、`RefreshPriority`。 |
| 输出 | `RefreshJob`、`AtlasRegion`、`runDirectory`。 |
| 允许读 | `GisSampleConfig.defaults()`、`AtlasRegionStore`。 |
| 允许写 | `RefreshJob` 初始字段、Region 内存对象。 |
| 禁止事项 | 不在这里计算指标、分类或写 preview；不把 JSON debug 输出当主缓存。 |
| 失败处理 | 创建失败由 `GisRefreshService.run` 外层捕获并写入 failed progress。 |
| 测试锚点 | `RefreshJob.md` 契约；`progress_manifest.json` 的 runId、center、radius。 |

当前实现说明：

- `GisRefreshService.refresh` 生成 `gis_<time>_<uuid>` 形式 jobId。
- `RefreshJob` 记录 `dependencyMarginCells`、`cellStepBlocks` 和 `budgetCellsPerBatch`。
- `AtlasRegionStore.regionForBlock` 返回中心点所在 Region；当前 v1 只刷新单 Region 内的 planned cells。

### 3. 半径规划

| 字段 | 内容 |
| --- | --- |
| 目标 | 把区块半径换算为 Cell 半径，列出需要采样的 planned cells。 |
| 输入 | `AtlasRegion`、`RefreshJob`、`GisSampleConfig`。 |
| 输出 | `List<PlannedCell>`，包含 cell、ring、stable。 |
| 允许读 | Region 内所有 Cell 坐标、配置中的 cellStep 和 dependency margin。 |
| 允许写 | `job.totalCells`、`job.dirtyRegions`、后续采样阶段的进度字段。 |
| 禁止事项 | Planner 不应采样地形、不应写 Cell 数据、不应改变 Region 状态。 |
| 失败处理 | 若 planned cells 为空，应由测试或报告暴露；当前没有专门错误。 |
| 测试锚点 | progress manifest 的 `totalCells`；半径刷新测试输出。 |

当前实现说明：

- `stableRadiusCells = radiusChunks * 16 / cellStepBlocks`。
- `sampleRadiusCells = stableRadiusCells + dependencyMarginCells`。
- `stable=false` 的 cell 会在采样阶段标记 `EDGE_DIRTY`。
- planned cells 按 ring、localCellZ、localCellX 排序，保证输出相对稳定。

### 4. prior 采样

| 字段 | 内容 |
| --- | --- |
| 目标 | 为 planned cells 填充基础地貌事实。 |
| 输入 | `PlannedCell`、`SampleMode`、`ServerLevel` 或合成 terrain profile。 |
| 输出 | Cell 的 sampleSource、elevation、surfaceType、biomeId、isWater、waterDepth。 |
| 允许读 | `ChunkGenerator#getBaseHeight`、`getBaseColumn`、`getUncachedNoiseBiome`、合成 profile。 |
| 允许写 | `AtlasCell.setSample(...)`、`EDGE_DIRTY` flag、`job.completedCells`、`job.currentRing`。 |
| 禁止事项 | 大范围 prior 刷新不得主动预生成 chunk；不得在 sampler 中计算指标或分类。 |
| 失败处理 | 采样异常会使 job failed，并写出 progress。 |
| 测试锚点 | `sourceCounts.prior`、`cellCounts.sampled/patched`、真实 refresh 和合成 test_run。 |

当前实现说明：

- `MinecraftPriorAtlasSampler` 当前无论传入何种 `SampleMode`，都返回 `SampleSource.PRIOR`；`observedIfLoaded` 和 `verifySurface` 尚未实现后验分支。
- `SyntheticAtlasSampler` 用于自动测试，不依赖 Minecraft chunk。
- 每处理 `budgetCellsPerBatch` 个 cell 或最后一个 cell，会写一次 progress。

### 5. 指标计算

| 字段 | 内容 |
| --- | --- |
| 目标 | 基于已采样 Cell 计算坡度、起伏、粗糙度、TPI 和水距。 |
| 输入 | 已 `SAMPLED` 的 AtlasCell 网格、`GisSampleConfig`。 |
| 输出 | small metrics、large metrics、Region `METRICS_PARTIAL`。 |
| 允许读 | Region 内 sampled cells、邻域半径配置。 |
| 允许写 | `AtlasCell.setSmallMetrics(...)`、`setLargeMetrics(...)`、`EDGE_DIRTY`、Region status。 |
| 禁止事项 | 不应改 sampleSource、elevation、landformType 或 patch；不应绕过未采样邻域假装稳定。 |
| 失败处理 | 指标异常走 job failed；邻域不足不失败，只标记 edgeDirty。 |
| 测试锚点 | JVM 算法测试、preview 的 slope/tpi 图、`edgeDirty` 计数。 |

当前实现说明：

- `AtlasMetricsComputer.compute` 跳过未采样 Cell。
- 小/大邻域不足时会标记 `EDGE_DIRTY`。
- waterDistance 使用 BFS，从 water cell 向外传播到配置上限。

### 6. Cell 级地貌分类

| 字段 | 内容 |
| --- | --- |
| 目标 | 把指标层结果转换为 Cell 级 `LandformType`。 |
| 输入 | `SAMPLED`、`METRICS_READY_SMALL`、`METRICS_READY_LARGE` 的 AtlasCell。 |
| 输出 | `landformType` 和 `LANDFORM_READY` flag。 |
| 允许读 | `GisClassifierConfig`、Cell 指标字段、水体字段。 |
| 允许写 | `AtlasCell.setLandformType(...)`。 |
| 禁止事项 | 不应生成 Patch、不应写 preview、不应替消费者计算 buildability。 |
| 失败处理 | 不满足状态条件的 Cell 直接跳过，保持 unknown/未 ready。 |
| 测试锚点 | `GisTestCase` 的 mustContain、dominant、unknownRatio；`landform.png`。 |

当前实现说明：

- 分类顺序为 water、shore、cliff、ridge、valley、basin、terrace、plain、slope、unknown。
- 只有指标 ready 的 Cell 才会进入分类。
- GIS 不输出通用可建性，消费者后续按 profile 自算适配度。

### 7. Patch 合并

| 字段 | 内容 |
| --- | --- |
| 目标 | 把相邻同类 Cell 合并成 LandformPatch 摘要。 |
| 输入 | `LANDFORM_READY` 的 AtlasCell、`GisClassifierConfig`。 |
| 输出 | Region patches、Cell `PATCH_READY` flag、Region `READY`。 |
| 允许读 | Cell landformType、elevation、slope、waterDistance、edgeDirty、Region 边界。 |
| 允许写 | `region.replacePatches(...)`、`RegionStatus.READY`、`PATCH_READY` flag。 |
| 禁止事项 | 当前 v1 不应假装已有跨 Region 缝合、近似地貌兼并或真实多边形轮廓。 |
| 失败处理 | patch 为空会被 `GisTestRunner` 作为失败；运行异常走 job failed。 |
| 测试锚点 | `patchCounts.total`、`maxPatchCells`、`LandformPatch.md`、`patch.png`。 |

当前实现说明：

- `PatchMerger` 使用四邻接 flood fill，只合并完全相同 `LandformType`。
- `fragment`、`edgeDirty`、`crossRegionCandidate` 通过 Patch flag 暴露。
- `PatchMerger` 为每个成员 Cell 写入 `patchId`，作为当前 PatchShape 的成员映射。
- `LandformPatch` 当前保存摘要和 PatchEnvelope，不保存独立成员 Cell 集合或多边形轮廓。
- 当前 PatchEnvelope 只能用于粗筛、定位和报告，不代表真实 Patch shape。
- `patch.png` 当前基于 Cell `patchId` 渲染 Patch 成员边界，不使用 PatchEnvelope 画形状。

### 8. 调试导出与结果汇总

| 字段 | 内容 |
| --- | --- |
| 目标 | 生成可复查的 progress、preview 和结果摘要。 |
| 输入 | `RefreshJob`、Region、patches、统计结果。 |
| 输出 | `progress.png`、`progress_manifest.json`、preview 图层、`preview_manifest.json`、`RefreshResult`。 |
| 允许读 | Job 状态、Region cells、patches。 |
| 允许写 | debug runDirectory 下的调试产物。 |
| 禁止事项 | preview/export 不应反向影响主数据；debug JSON 不应被当作生产主缓存。 |
| 失败处理 | 失败时也应尽量写出 failed progress manifest。 |
| 测试锚点 | `run/gis_debug/<runId>/`、MCP/HTTP 返回的 artifacts、结果报告。 |

当前实现说明：

- `GisRefreshService` 在 sampling、metrics、classifying、patching、completed/failed 阶段写 progress。
- `PreviewExporter` 输出 elevation、water、slope、tpiSmall、tpiLarge、landform、patch 图层和 `legend.png`。
- `RefreshResult` 返回 job、region、patches、cellCounts、landformCounts、runDirectory。

### 9. 合成测试报告与快照

| 字段 | 内容 |
| --- | --- |
| 目标 | 让固定样例可重复、可回放、可现场还原。 |
| 输入 | `GisTestCase`、`SyntheticAtlasSampler`、debugRoot。 |
| 输出 | `test_report.json`、`region_snapshot.json`。 |
| 允许读 | 合成 terrain profile、RefreshResult。 |
| 允许写 | 测试 runDirectory 下的报告和轻量快照。 |
| 禁止事项 | 轻量快照不能被描述为生产级 SavedData 或长期主缓存。 |
| 失败处理 | `GisTestReport.failures` 写明 unknownRatio、mustContain、patch count 等失败。 |
| 测试锚点 | `gis_test_run`、`GisGameTests.gisPriorSyntheticBaseline`。 |

当前实现说明：

- `AtlasRegionSnapshotIo` 写入 `snapshotPurpose=test-reproduction-and-field-restore` 和 `productionPersistence=false`。
- `GisTestRunner` 校验 failed cell、unknown ratio、mustContain、dominantLandform 和 patch count。

## 状态推进

主链状态推进必须保持以下顺序：

```text
RefreshJob.QUEUED
  -> SAMPLING
  -> METRICS
  -> CLASSIFYING
  -> PATCHING
  -> COMPLETED
```

失败时：

```text
任意阶段异常 -> FAILED + errorMessage + failed progress
```

Region 状态当前实现：

```text
EMPTY
  -> SAMPLED
  -> METRICS_PARTIAL
  -> READY
```

Cell flag 当前实现：

```text
SAMPLED
  -> METRICS_READY_SMALL
  -> METRICS_READY_LARGE
  -> LANDFORM_READY
  -> PATCH_READY
```

`EDGE_DIRTY` 可以在规划边界或指标邻域不足时附加，不阻塞本次 debug 产物输出。

## 读写边界

| 模块 | 允许写 | 不应写 |
| --- | --- | --- |
| 入口层 | 参数校验结果、HTTP/命令响应、MCP 文本 | Cell 指标、分类、Patch 业务状态 |
| Planner | planned cell 列表 | Cell 数据、Region 状态 |
| Sampler | 基础采样字段、sample flag、采样进度 | 指标、分类、Patch |
| Metrics | 指标字段、metrics flag、edgeDirty | sampleSource、landformType、patches |
| Classifier | landformType、landform flag | Patch、preview、消费者评分 |
| PatchMerger | patches、patch flag、Region ready | 采样字段、指标字段 |
| Preview/Progress | debug 产物 | 主数据反写 |
| SnapshotIo | 轻量 JSON 快照 | 生产级持久层语义 |

## 失败处理

- 参数错误应在入口层变成 400 响应或命令 failure。
- 主流程异常由 `GisRefreshService.run` 捕获，设置 `job.fail(errorMessage)` 并写 progress。
- 合成测试失败应写入 `test_report.json` 的 `failures`，不要只依赖日志。
- 预览图异常属于验收阻断，因为 GIS v1 需要图像可检查。

## 常见改动路径

| 想改什么 | 优先改哪里 | 必须同步检查 |
| --- | --- | --- |
| 新增采样模式 | `AtlasSampler`、具体 sampler、`SampleMode` | `AtlasCell.md`、`RefreshJob.md`、测试入口。 |
| 调整邻域指标 | `GisSampleConfig`、`AtlasMetricsComputer` | `GIS指标层.md`、配置表、preview 图。 |
| 调整分类阈值 | `GisClassifierConfig`、`LandformClassifier` | 地貌分类方案、阈值配置、合成样例。 |
| 优化 Patch 合并 | `PatchMerger`、PatchShape 或 Patch 成员映射 | `LandformPatch.md`、review 清单、patch preview。 |
| 改 preview 表达 | `PreviewExporter` | `PreviewManifest.md`、测试入口、结果报告。 |
| 改 HTTP/MCP 输出 | `GisHttpController`、MCP handlers | `GIS调试MCP接口.md`、MCP build。 |
