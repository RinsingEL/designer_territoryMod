# 地貌分类与地貌区

地貌分类负责把数值指标转换成可被规划系统理解的标签。地貌区负责把相邻且相似的 Cell 合并成区域对象，避免消费者直接处理大量离散 Cell。

## Cell 级地貌分类

v1 分类以规则为主，不引入机器学习。

| 地貌类型 | 典型特征 | 主要用途 |
| --- | --- | --- |
| water | 水体或深水区域。 | 道路避障、港口、岸线结构。 |
| shore | 靠近水体且坡度适中的岸线。 | 港口、滨水城区、桥位候选。 |
| plain | 坡度低、局部起伏低、TPI 接近 0。 | 城市主体、村镇、结构群落。 |
| terrace | 整体较高但内部平缓。 | 城堡、神殿、观景结构、城市台地。 |
| slope | 有连续坡度但不极端。 | 山城边缘、道路爬升、过渡地带。 |
| cliff | 坡度极高或局部起伏极强。 | 避让、景观边界、特殊结构。 |
| ridge | 大尺度 TPI 为正且呈连续带状。 | 山脊道路、边界、哨塔、地标。 |
| valley | 大尺度 TPI 为负且呈连续带状。 | 道路走廊、河谷、聚落轴线。 |
| basin | 周围高、中间低且面积连续。 | 湖盆、盆地城市、封闭聚落。 |

## 分类顺序

分类应按约束强度从高到低执行：

1. 水体和深水优先。
2. 岸线优先于普通平原。
3. 极端坡度优先判为 cliff。
4. 大尺度 TPI 判断 ridge、valley、basin、terrace。
5. 坡度和局部起伏判断 plain、slope。
6. 无法稳定判断时标记为 unknown，并保留指标供调试。

## Patch 合并

Landform Patch 是相邻同类或近似同类 Cell 的合并结果。

合并规则：

- 只合并相邻 Cell，v1 可先使用四邻接。
- 类型一致时直接合并。
- 类型相近时允许按策略合并，例如 plain 与 terrace 内部可以按用途保留分界，也可以合并为同一类平缓地貌 Patch。
- Patch 面积太小时可标记为 fragment，供消费者忽略或作为细节使用。
- 跨 Region 的 Patch v1 可先断开，后续再做边界缝合。

## Patch 输出字段

每个 Patch 至少需要输出：

- 地貌类型。
- 包围盒。
- Cell 数量和估算面积。
- 平均高度、高度范围、平均坡度。
- 平均水距、水体接触和边缘接触状态。
- 是否接触水体。
- 是否接触 Region 边缘。
- 置信度或完整度状态。

## 消费方式

消费者优先查询 Patch，再按需回退到 Cell。

- 城市选址：优先找面积足够、坡度低、水距合适的 plain 或 terrace patch。
- 道路连接：优先沿 valley、shore、低坡度 slope 通过，尽量避开 cliff 和深水。
- 国度边界：优先参考 ridge、水体、海岸、盆地边缘等天然边界。
- 结构分布：根据结构 profile 匹配地貌类型、坡度、水深、岸线和面积等事实。

GIS 不输出通用可建性。消费者可以基于 Patch 和 Cell 的事实字段自行计算适配度，但这个适配度属于消费者结果，不回写为 GIS 真值字段。
