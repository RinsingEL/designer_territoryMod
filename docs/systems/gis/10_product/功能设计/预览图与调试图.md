# 预览图与调试图

GIS 必须有调试预览能力。地貌分类如果只能在代码里看字段，很难判断它到底像不像真实地貌，也很难发现阈值问题。

## 输出目标

- 让人能快速判断高度、水体、坡度、TPI、地貌分类是否合理。
- 让测试能固定 seed、固定中心点、固定半径后生成可对比产物。
- 让后续城市、道路、结构系统能把自己的结果叠加到同一张 GIS 底图上。
- 让开发 agent 在自动测试中看到 Cell 处理进度和卡点。

## 运行中 Progress Preview

Progress Preview 是运行中的轻量进度图，不是最终验收图。它用于观察一次 RefreshJob 中每个 Cell 当前处于什么阶段。

首版建议每隔 `0.5s ~ 2s`，或每处理完一批 Cell，写出：

```text
run/gis_debug/<runId>/
  progress.png
  progress_manifest.json
```

`progress.png` 使用 Cell 网格着色：

| 状态 | 颜色建议 | 含义 |
| --- | --- | --- |
| pending | 灰色 | 尚未处理。 |
| sampled | 蓝色 | 基础采样完成。 |
| metricsSmall | 青色 | 小邻域指标完成。 |
| metricsLarge | 紫色 | 大邻域指标完成。 |
| classified | 黄色 | 地貌分类完成。 |
| patched | 绿色 | 已参与 Patch 合并。 |
| edgeDirty | 橙色 | 边缘依赖不足，需要后续重算。 |
| failed | 红色 | 处理失败。 |

`progress_manifest.json` 至少记录：

| 字段 | 说明 |
| --- | --- |
| runId | 当前 RefreshJob 或测试运行标识。 |
| center | 中心方块坐标。 |
| radiusChunks | 刷新区块半径。 |
| cellStepBlocks | Cell 采样步长。 |
| totalCells | 总 Cell 数。 |
| counts | 各状态 Cell 数量。 |
| currentRing | 当前处理到的区块环。 |
| status | queued、sampling、metrics、classifying、patching、completed、failed。 |
| updatedAt | 更新时间。 |

Progress Preview 可以被覆盖写入，不要求长期归档。最终验收以 PreviewManifest 和 test_report 为准。

## 首版预览图层

| 图层 | 内容 |
| --- | --- |
| elevation | 高度灰度图或分级色带。 |
| water | 水体、水深、岸线候选。 |
| slope | 坡度热力图。 |
| tpiSmall | 小尺度 TPI 正负分布。 |
| tpiLarge | 大尺度 TPI 正负分布。 |
| landform | Cell 级地貌分类色块。 |
| patch | Landform Patch 边界和编号。 |
| buildability | 可建性评分热力图。 |
| dirty | 未完成、边缘脏区、低置信区域。 |

## Preview Manifest

每次导出预览图时，必须同时写出清单，记录：

- seed 或世界标识。
- 维度。
- 中心点。
- 半径。
- cellStepBlocks。
- atlasVersion。
- 指标配置版本。
- 输出图层列表。
- 生成时间。
- 是否存在 edgeDirty 或 unknown 区域。

## 验收方式

预览图不是美术资源，而是验收证据。

每次调整地貌阈值或刷新流程时，至少保留一组固定样例：

- 平原与缓坡样例。
- 山脊与谷地样例。
- 水域与岸线样例。
- 高低差复杂区域样例。

如果预览图看起来不合理，优先回查对应指标层，而不是直接在消费者系统里补丁式规避。
