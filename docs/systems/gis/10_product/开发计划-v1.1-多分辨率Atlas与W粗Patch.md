# GIS v1.1 开发计划：Step 参数化最小闭环

## 定位

本文记录 GIS v1.1 的当前开发口径。v1.1 的 GIS 内核目标不是一次性实现 W / T 调度，也不是在 GIS 内建立完整命名 profile 体系，而是让已落地的 GIS v1 主链支持可传入的 `cellStepBlocks`。

核心判断：

```text
GIS v1.1 只提供可参数化 step 的地貌事实主链；
W / T / C / Materialization 后续按消费场景选择 step。
```

## 本轮目标

- 复用 GIS 已有 sample / metrics / classify / patch / preview 主链。
- 允许调试刷新入口传入 `cellStepBlocks`，默认仍为 `4`。
- 同一维度、同一 Region 坐标但 step 不同的数据必须隔离。
- 调试产物必须记录 step，以及指标半径换算后的 block 尺度。
- 保证默认 step=4 的 v1 行为和自动测试不退化。

## 本轮非目标

- 不实现 W 阶段调度。
- 不输出独立 `WorldPatchMap` 产物编排。
- 不实现 T1 / T2 AI 看图选点、国度落脚、首都选点或国度扩张。
- 不新增 `world_coarse`、`city_fine`、`verify_surface` 命名 profile 注册表。
- 不为不同 step 校准独立分类阈值。
- 不在 GIS 内输出通用可建性评分。
- 不改变 Atlas 数据格式版本。

## Step 使用口径

GIS 内核只关心传入的 `cellStepBlocks`。不同消费层可以后续自行选择 step，例如：

| 消费场景 | 典型 step | 当前口径 |
| --- | --- | --- |
| 世界粗扫 / W 粗 patch | 64 / 128 / 256 blocks | 属于 W 消费层后续接入，不在本轮 GIS 内实现调度。 |
| 城市局部地貌 / C1 | 4 / 8 / 16 blocks | 默认 step=4 保持现有 v1 行为。 |
| 物化前局部校验 | 1 / 2 / 4 blocks | 后续由 Materialization 消费层按小范围调用。 |

具体 step 不在 GIS 内拍死；粗 step 的阈值效果需要消费层结合固定 seed、预览图和性能测试校准。

## 实现改造点

### 1. Step 配置入口

`GisSampleConfig` 继续作为采样配置来源，新增按请求派生 `cellStepBlocks` 的能力。入口层从固定 `defaults()` 改为：

```text
GisSampleConfig.defaults().withCellStepBlocks(request.cellStepBlocks)
```

约束：

- 未传入时使用默认值 `4`。
- 合法范围为 `1..256`。
- `regionSizeChunks * 16` 必须能被 `cellStepBlocks` 整除。

### 2. Region 隔离

不同 step 不能复用同一个 Region key。Region ID 至少要表达：

```text
dimensionId + cellStepBlocks + regionX + regionZ
```

否则 `step=4` 和 `step=128` 会把同一个 region 坐标解释成不同网格，导致 Cell、Patch、preview 和 snapshot 混乱。

### 3. 调试产物追溯

以下产物必须记录 `cellStepBlocks`：

- `RefreshJob` / HTTP 返回。
- `progress_manifest.json`。
- `preview_manifest.json`。
- `region_snapshot.json`。
- `test_report.json`。

`preview_manifest.json` 还应记录：

- `metricRadiiCells`：指标半径的 Cell 单位。
- `metricRadiiBlocks`：按当前 step 换算后的 block 尺度。

### 4. 接口参数

调试接口新增可选参数：

```json
{
  "radiusChunks": 8,
  "sampleMode": "prior",
  "cellStepBlocks": 8
}
```

MCP `gis_refresh` 只负责透传该参数。Forge 命令保留旧参数形式，并允许追加 step：

```text
/geomantia gis refresh <radiusChunks> [sampleMode] [cellStepBlocks]
```

### 5. 消费层后续使用

W 粗 patch、T1/T2 看图选点和 C1 局部 TerrainPatchMap 都可以复用 GIS step 参数化能力，但它们属于各自消费层的后续任务：

- W 可以用较大 step 调用 GIS 主链，生成粗尺度地貌事实。
- T 可以读取 W 产物或 GIS 粗 preview 作为国度规划输入。
- C1 可以用较小 step 在城市候选范围内刷新局部地貌事实。

GIS 本轮只保证“能按不同 step 生成、隔离、追溯”，不承诺消费层语义和阈值效果已经校准完成。

## 开发阶段

| 阶段 | 目标 | 主要产物 | 验收重点 |
| --- | --- | --- | --- |
| M1 Step 配置 | 支持从入口传入 `cellStepBlocks`。 | 配置派生、HTTP/MCP/命令参数。 | 未传 step 时保持默认 `4`。 |
| M2 Region 隔离 | Region / Patch / snapshot 按 step 隔离。 | step-aware region ID。 | 不同 step 的同一区域不会互相覆盖。 |
| M3 Manifest 追溯 | 调试产物记录 step 和 block 尺度。 | progress / preview / snapshot / report 字段。 | 能从产物判断本次扫描 step 和指标覆盖范围。 |
| M4 回归测试 | 覆盖默认兼容和非默认 step 运行链路。 | 自动测试、MCP build。 | step=4 旧测试不退化；非默认 step 产物字段齐全。 |

## 验收口径

- `./gradlew.bat test` 通过。
- `country_designer_mcp` 下 `npm run build` 通过。
- 默认 step=4 的固定样例仍通过原有断言。
- 非默认 step 的 synthetic run 至少能导出 report、snapshot、progress manifest 和 preview manifest，并写入对应 `cellStepBlocks`。
- 同一维度、同一 Region 坐标、不同 step 的 `regionId` 不同。

## 风险

- step 变大后，指标数值语义会变化，不能只改 `cellStepBlocks` 就宣布粗扫可用于 W / T 正式决策。
- 粗 step 可能抹掉窄河、细岸线和小丘陵，这属于消费层后续校准问题。
- 如果 Region key 不带 step，会产生严重缓存污染。
- 本轮未引入命名 profile，因此后续消费层需要自己记录选择 step 的原因和验收结果。
