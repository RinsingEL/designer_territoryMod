# GIS v1 开发计划

本文记录 GIS v1 系统基线的阶段计划。v1 已作为当前地貌基础设施基线落地，本文主要用于说明 v1 范围、验收口径和后续回看时的版本边界。

后续扩展不要继续混写进本文。v1.1 多分辨率 Profile 与 W 粗 Patch 计划见 `开发计划-v1.1-多分辨率Atlas与W粗Patch.md`。

## 阶段总览

| 阶段 | 目标 | 主要产物 | 验收重点 |
| --- | --- | --- | --- |
| G0 文档定基线 | 固定 GIS 的定位、数据对象、刷新流程和验收方式。 | 当前文档、契约草案、测试入口。 | 文档能指导实现，不再依赖 legacy 旧方案。 |
| G1 基础采样 | 能把指定半径内的 Minecraft 世界生成器先验采样成 Atlas Cell。 | 高度、水体关系、生物群系、可预测表面类型。 | 不主动生成 chunk，同一区域重复采样结果稳定，耗时可控。 |
| G2 指标层 | 计算坡度、局部起伏、粗糙度、TPI、水距。 | GIS 指标层缓存。 | 指标值可解释，边界 Cell 标记为待补全或脏。 |
| G3 地貌分类 | 按 Cell 分类并合并为 Landform Patch。 | 地貌分类图、Patch 列表。 | 平原、山脊、谷地、岸线等结果肉眼合理。 |
| G4 半径刷新与缓存 | 支持按中心点环向外刷新、增量重算、Region 缓存。 | RefreshJob、Region 缓存、脏区机制。 | 玩家或调试中心移动时不会全量重扫。 |
| G5 运行中进度预览 | 在 GIS 刷新过程中低频输出 Cell 处理进度。 | progress.png、progress_manifest.json。 | agent 和人工能看到 sampled、metrics、classified、patched、edgeDirty 的进度。 |
| G6 调试预览 | 输出高度、坡度、TPI、地貌、Patch 等调试图。 | PreviewManifest、PNG 或调试覆盖层。 | 能用图快速定位分类错误。 |
| G7 自动测试接入 | 支持 agent 通过 Forge 快速启动固定 seed/prior 样例并自动跑 GIS。 | GameTest 或调试命令、test_report.json。 | 固定样例能自动刷新、导出、断言和报告；固定存档仅用于后验对照。 |
| G8 消费接入 | City、Roads、Realm、Structure 开始通过 GIS 查询地形事实。 | 查询接口、消费侧文档。 | 消费者不再直接扫描大范围地形。 |

## v1 初版稳定版目标

v1 目标是完整交付“能被消费的地貌事实层”，不是做临时 MVP，也不是立即生成完整城市。该版本完成后应能稳定支撑后续城市、道路、国度和结构系统接入。

必须完成：

- Atlas Cell 和 Atlas Region 的数据契约。
- 半径刷新任务的基本流程。
- 生成器先验采样模式，不依赖大范围 chunk 预生成。
- 高度、水体、坡度、局部起伏、TPI、水距等地形事实指标。
- Cell 级地貌分类。
- Patch 合并。
- 运行中 progress 预览。
- 至少一套调试预览输出。
- 一条 agent 可执行的自动测试路径。

v1 非目标：

- 全世界持久索引。
- 大范围 chunk FULL 预生成。
- 真实河网和流域分析。
- 树、草、矿物、洞穴、原版结构最终落位和玩家改动追踪。
- 复杂生态区、资源区、势力区联动。
- 城市内部规划和建筑落点执行。

## 开发顺序建议

1. 先实现生成器先验采样器，能在不生成 chunk 的情况下读取一个半径范围。
2. 再实现 Atlas Cell 的内存结构和 Region 切分。
3. 再做指标层，优先坡度、局部起伏、小尺度 TPI。
4. 再做地貌分类和 Patch 合并。
5. 再补缓存、脏区、半径环刷新。
6. 再接运行中 progress 预览和最终调试图。
7. 补 Forge 固定 seed/prior 自动测试入口，后续再加固定存档后验对照。
8. 最后接消费者查询接口。

## 验收节奏

- 每完成一个指标层，都输出一张预览图或一份统计摘要。
- 每完成一种地貌分类，都准备 2 到 3 个固定 seed 的对照样例。
- 每完成一次半径刷新链路，都输出 progress 图和测试报告。
- 每接入一个消费者，都补充一份“消费者如何使用 GIS”的方案文档。
