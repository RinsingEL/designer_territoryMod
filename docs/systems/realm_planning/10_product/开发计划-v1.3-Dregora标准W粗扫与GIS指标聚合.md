# 国度规划系统 v1.3 开发计划：Dregora 标准 W 粗扫与 GIS 指标聚合

## Summary

本轮目标是把 W 粗扫标准提升到接近 Dregora 体感的大世界规模，并修正当前 GIS 指标随 `cellStepBlocks` 放大而失真的问题。

默认验收标准：

```text
planningRadiusBlocks = 16384
diameter = 32768 x 32768 blocks
cellStepBlocks = 128
```

该范围约等于 4 倍于当前 8192 半径真实验收的 tile 数，预计当前粗扫耗时约 5.5-6 分钟，产物约 110-120 MB。加入细尺度指标后，必须通过采样预算、分片缓存和自适应加密控制成本，不能把全世界 16 block 或更细尺度直接全量扫描。

## 背景

当前真实验收结果：

| 项 | 数值 |
| --- | ---: |
| 存档 | `新的世界 (1)` |
| seed | `9161139915381784808` |
| `planningRadiusBlocks` | `8192` |
| `cellStepBlocks` | `128` |
| 实际覆盖直径 | `16896 x 16896 block` |
| grid | `132 x 132 = 17424 cells` |
| tile | `1089` |
| 首次 W 扫描耗时 | 约 `87.6s` |
| 产物数据量 | 约 `29.0 MB` |
| `world_patch_map.json` | `17424 cells / 4391 patches / 305 continents` |

该 run 证明分片扫描、缓存、sealed survey 和 W/T 链路可以工作，但也暴露两个质量问题：

- W 粗扫预览中 `cliff` 过量。
- `cellStepBlocks=128` 时，GIS 仍按 coarse cell 与邻近 coarse cell 的高度差计算 slope / relief，导致局部地貌指标语义失真。

## Scope

本轮包含：

- 以 `planningRadiusBlocks=16384` 建立 Dregora 体感标准 W 粗扫验收档。
- GIS 指标层拆分 `cellStepBlocks` 和 `metricSampleStrideBlocks` / `localSlopeRadiusBlocks`。
- 在粗 cell 内做有限 micro-sampling，聚合为 W/T 可消费的稳定指标。
- W manifest、WorldPatchMap、score manifest 中记录 micro-sampling 是否真实执行、采样预算和耗时。
- 让 `cliff` 从大面积主地貌误判，收敛为局部陡坡 tag / steep fraction。
- 保持 tile 分片缓存、可恢复扫描和 sealed 后才能进入 T。

本轮不包含：

- 不扫描 Minecraft 理论 6000 万直径世界边界。
- 不把 `cellStepBlocks=16` 全图作为默认 W 粗扫。
- 不进入 C 阶段城市内部精扫。
- 不实现最终 T3 行动力扩张模型；v1.3 只保证 W 输入质量和大世界扫描标准。
- 不引入生产级长期二进制数据库；可先优化 JSON 体积和 manifest 追踪。

## Dregora 标准档

| 档位 | `planningRadiusBlocks` | 直径 | 目标 |
| --- | ---: | ---: | --- |
| 开发 smoke | `8192` | 约 `16384` | 快速回归、链路验证。 |
| Dregora 标准 | `16384` | `32768` | 默认真实游玩验收档。 |
| Dregora 扩展 | `20000` | `40000` | 压力验收，接近 20k 旅程。 |
| 超大沙盒 | `32768+` | `65536+` | 后续异步 / 可扩展扫描，不阻塞开局。 |

v1.3 默认开发目标是 Dregora 标准档。扩展档只作为性能观测，不作为本轮必须通过标准。

| 模式 | 目标 |
| --- | --- |
| 纯粗扫 `16384` | 首次扫描不超过 `8 min`。 |

## GIS 指标层改造

### 当前问题

当前 GIS 配置中：

```text
cellStepBlocks = 128
slopeRadiusCells = 1
localReliefRadiusCells = 2
tpiLargeRadiusCells = 12
```

这意味着 slope 实际上会比较相隔 128 block 的 coarse cell 高度差。原本为 step=4 或小 step 设计的 cliff 阈值，在 step=128 下会把大尺度起伏误判为局部悬崖。

### 目标设计

拆分规划格和指标采样：

```text
cellStepBlocks = 128              // W/T 规划格大小
metricSampleStrideBlocks = 32     // cell 内采样间隔
localSlopeRadiusBlocks = 4 或 8   // 每个 micro sample 附近的局部坡度半径
```

每个粗 cell 内部先生成采样点集合，再聚合指标：

| 指标 | 说明 |
| --- | --- |
| `heightP10/P50/P90` | 稳健高度分位，替代单点高度。 |
| `robustRelief` | `P90 - P10`，减少离群值影响。 |
| `localSlopeMean/P90` | 每个 micro sample 的局部坡度统计。 |
| `steepFrac` | cell 内达到陡坡阈值的采样点比例。 |
| `waterFrac` | cell 内水体比例。 |
| `biomeHist` | cell 内主要 biome 分布。 |
| `microSampleCount` | 本 cell 实际采样点数。 |
| `microSamplingImplemented` | 是否真实执行 micro-sampling。 |

### cliff 判定调整

`cliff` 不应继续作为大面积主地貌默认结果。建议：

- `baseLandform` 表达 `water / shore / lowland / upland / ridge / valley / unknown`。
- `cliff` / `steep` 进入 `landformTags[]`。
- 只有 `steepFrac` 超阈值，且局部坡度 / 起伏 / 边缘形态证据足够时，才在 tag 中标记 cliff。
- W 预览图默认按 `baseLandform` 着色，`cliff` 只作为叠加纹理或边缘标记。

## 采样策略

### 分层策略

| 层 | 用途 | 建议 |
| --- | --- | --- |
| W 粗规划 | 国度、大陆、城市候选 | `cellStepBlocks=128`。 |
| W 指标 micro | cell 内稳健统计 | 默认 `metricSampleStrideBlocks=32`。 |
| W 局部坡度 | 判断真实局部陡坡 | 每个 micro sample 周围 `4/8 block`。 |
| C 阶段精扫 | 城市内部规划 | 单独局部扫描，不在 W 全图做。 |

### 自适应加密

为了避免全世界高密度采样，v1.3 应支持两阶段：

1. 轻量初扫
   - 每个 coarse cell 采中心点和少量局部邻域。
   - 识别可疑区域：高起伏、海岸、cliff 候选、国度候选区域。

2. 自适应加密
   - 只对可疑区域或 T 消费层要求的区域做 stride=32 micro-sampling。
   - 非可疑区域保留轻量统计。

如果实现成本过高，本轮可先做固定 stride=32 的小范围配置测试，再切成自适应。

## 实现步骤

### Step 1：配置与契约

- 在 GIS 配置中新增 `metricSampleStrideBlocks`、`localSlopeRadiusBlocks`。
- HTTP/MCP W / GIS refresh 入口允许传入或使用默认值。
- manifest 写入指标采样配置。
- 文档同步数据契约和测试入口。

### Step 2：轻量局部坡度修正

- 当前每个 coarse cell 代表点采样后，额外读取代表点周围 `4/8 block` 的局部高度差。
- 将 `slope` 从 coarse cell-to-cell 高差改为局部坡度优先。
- 保留 coarse TPI / 大尺度起伏作为 ridge / valley / upland 辅助指标。
- 目标：Dregora 标准档耗时不超过 `12-25 min`。

### Step 3：cell 内 micro-sampling 聚合

- 对 `cellStepBlocks=128` 的 W 粗扫，默认 `metricSampleStrideBlocks=32`。
- 每 cell 最多采 16 个 micro sample。
- 每个 sample 记录高度、水体、biome、局部坡度。
- 聚合写入 `heightStats`、`slopeStats`、`waterFrac`、`microSampleCount`。
- 目标：Dregora 标准档耗时不超过 `15-35 min`。

### Step 4：地貌分类调整

- 调整 `LandformClassifier` 或 W 消费层分类映射。
- `baseLandform` 按聚合指标判断。
- `cliff` 改为 tag，不再大面积主地貌。
- preview 默认显示 `baseLandform`，可选叠加 steep / cliff。

### Step 5：W 分片性能与缓存

- tile cache 中记录采样配置 hash，避免不同 step / stride / seed 误复用。
- world survey manifest 记录采样点数、平均每 tile 耗时、最大 tile 耗时。
- 恢复扫描必须验证配置一致。
- 可选：压缩 `world_patch_map.json` 或拆分分页，避免 Dregora 标准档产物过大。

### Step 6：真实验收

- 使用存档 `新的世界 (1)` 或指定验收存档。
- 跑：

```text
planningRadiusBlocks=16384
cellStepBlocks=128
metricSampleStrideBlocks=32
qualityMode=strict
```

- 记录：
  - tile 数
  - grid cells
  - micro sample count
  - W 扫描耗时
  - 恢复扫描耗时
  - 产物数据量
  - cliff 主地貌比例
  - steep tag 比例
  - T3 / T4 质量分
  - 人工预览图结论

## 测试计划

### 单元 / JVM

- `cellStepBlocks=128` 时，局部坡度不应直接等于 128 block 邻接高度差。
- synthetic 山峰 / 平原 / 海岸样例输出合理 `baseLandform` 和 `landformTags`。
- `microSampleStrideBlocks=32` 时，每 128 cell 的 `microSampleCount` 符合预期。
- 配置 hash 不一致时 tile cache 不应复用。
- 未启用 micro-sampling 时，manifest 必须写 `microSamplingImplemented=false` 并进入 warning。

### MCP / HTTP

- `realm_run_acceptance` 支持 Dregora 标准档参数。
- `score_manifest.json` 包含新 W 子分字段。
- `world_survey_manifest.json` 记录 micro 采样配置和采样点数。
- `npm run build` 通过。

### Forge / 真实世界

- `./gradlew.bat runGameTestServer` 通过。
- 真实存档跑 `planningRadiusBlocks=16384` 首次扫描。
- 同 runId 恢复扫描命中缓存。
- 人工打开预览图确认：
  - cliff 不再占据大面积主大陆色块。
  - 海岸、低地、高地、山脊整体可读。
  - T3 国境仍能读出国度范围。
  - T4 城市种子不集中在一块。

## 2026-06-12 实际验收结果

- 标准档 run：`run/realm_debug/realm_v13_v14_real_16384_20260612`。
- 参数：`planningRadiusBlocks=16384`、`cellStepBlocks=128`、`microSampleStrideBlocks=32`、`localSlopeRadiusBlocks=8`、`qualityMode=strict`。
- 首次真实 W 扫描：`4225` tile scanned、`0` failed，HTTP 调用约 `1188s`，W survey 记录 `1181062ms`。
- micro-sampling：`microSamplingImplemented=true`，`microSampleCount=1081600`，输出 `world_feature_grid.json`。
- 缓存复跑：最终验收 `0` tile scanned、`4225` tile cached、`0` failed，HTTP 调用约 `17.92s`。
- 产物：`world_feature_grid.json` 约 `26.86MB`，W/T/score/acceptance 产物齐全。
- 最终评分：`acceptance_report.passed=true`，`score_manifest.totalScore=82.95`，`hardBlocks=[]`，W 子分 `84.9`。
- 人工预览结论：Dregora 高 steep tag 有 slopeStats 支撑；T3 国境可读，仍保留大面积荒野；T4 城市锚点未集中在单块。

## 风险

- `metricSampleStrideBlocks=32` 全范围采样可能接近 1 小时，必须优先做采样预算和性能观测。
- 频繁调用 Minecraft `ChunkGenerator` / biome sampling 可能成为瓶颈。
- JSON 产物在 Dregora 标准档可能超过 100 MB，后续需要分页、压缩或摘要化。
- 当前 T3 面积模型仍是 quota 过渡方案；W 质量提升不等于 T3 最终模型完成。
- `cliff` 从主地貌改 tag 后会影响 T3 mountainAffinity、T4 mining / border candidate scoring，需要同步调整消费层含义。

## 非目标提醒

本计划的核心是让 W 粗扫在 32768 直径世界内“足够可信、可缓存、可验收”。它不是把 Minecraft 6000 万直径理论世界扫完，也不是把 W 阶段变成 C 阶段精细扫描。
