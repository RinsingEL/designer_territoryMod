# 国度规划系统 v1.2 开发计划：W 粗扫、T3 国境与 T4 城市种子质量重构

## 定位

本文承接 v1.1 真实世界验收后的结果复盘。v1.1 已证明 W / T 主链、分片扫描、缓存恢复、MCP 验收和基础产物落盘可运行；v1.2 的目标不是继续扩接口数量，而是把“可运行”升级为“结果可玩、可审、可阻断”。

v1.2 聚焦四件事：

```text
W 粗扫质量修复
  -> T3 连通国境扩张
  -> 质量评分与阻断
  -> T4 单国度城市种子规划
```

## 背景问题

真实世界验收 `realm_full_world_survey_8192_ai_configured` 暴露出这些问题：

| 问题 | 现象 | 判断 |
| --- | --- | --- |
| `cliff` 过多 | 全图 `cliff` 约 44%，主大陆约 85%。 | W 地貌分类链路偏噪，`cliff` 不适合作为大片主地貌。 |
| patch 过碎 | `4391` 个 patch，平均约 `4` 个 cell，单格 patch 很多。 | W 缺少全图清洗、跨 tile merge 和小斑块合并。 |
| 国境飞地多 | 非海权国家出现大量 disconnected component。 | T3 采用全局 cell cost 排序抢占，不保证 frontier 连通扩张。 |
| 城市种子集中 / 撞点 | 矿业镇与边境堡可能同格，首都之间过近。 | T4 目前是规则占位版，没有城市网络规划和距离 / 角色约束。 |
| 验收过宽 | `passed=true` 只能证明链路跑通。 | 缺少自动评分、硬阻断和人工 review 口径。 |

## 本轮目标

- W 保留 `cellStepBlocks=128` 作为规划 cell，但新增 cell 内 micro-sampling 和稳健统计。
- W 把 `cliff` 从互斥主地貌降级为 tag / overlay，主地貌改为更稳定的面状类别。
- W 在全图范围做 land mask 清洗、continent / patch 全局连通、跨 tile merge、小斑块合并和孔洞填补。
- T3 从“全图抢格子”改为“多源 frontier 扩张 + 动态 quota + edge cost + topology repair”。
- T3 输出连通性、飞地、孔洞、自然边界贴合等质量指标。
- T4 改成每个国度单独裁剪候选图，生成二级区域和 role-specific 候选池，再由 AI / 程序共同确定有限 CitySeed。
- 新增 `score_manifest.json`，把 W / T3 / T4 的自动分、硬阻断、人工 review 清单统一收口。

## 本轮非目标

- 不把 W 一次性升级为完整水文 / geomorphons / graph partitioning 高质量模式。
- 不在 T4 生成城市边界、功能区、道路、建筑点或 jigsaw 参数。
- 不让 AI 填底层扫描阈值、Dijkstra edge cost 或 smoothing 参数。
- 不把 chunk 加载时的 opportunistic 条件触发当成“城市是否存在”的决策来源。
- 不用固定世界中心附近的首次加载顺序决定有限城市名额。

## W 阶段 v1.2 方案

### 粗格与微采样

`cellStepBlocks=128` 继续作为 T 阶段规划 cell。v1.2 不靠单纯把 step 改小解决问题，而是在每个 128 block planning cell 内新增 16 或 32 block stride 的 micro-sampling / feature grid。

历史实现口径：v1.2 时 `microSampleStrideBlocks` 只进入 W / MCP / manifest / score manifest，用于声明期望的 feature 提取尺度；正式 cell 内 micro-sampling 尚未落地。该缺口已由 v1.3 承接：分片 W survey 现在输出真实 `WorldFeatureGrid`，strict 验收应看到 `microSamplingImplemented=true` 和 `microSampleCount>0`。

每个 planning cell 至少聚合这些指标：

| 指标 | 用途 |
| --- | --- |
| `heightP10 / heightP50 / heightP90` | 稳健高度统计，避免 max/min 离群值主导。 |
| `robustRelief` | 建议为 `heightP90 - heightP10`。 |
| `slopeMean / slopeP90 / steepFrac` | 坡度主信号，来源于 micro DEM 的局部梯度。 |
| `roughnessTri` | 地形粗糙度或局部高差 RMSD。 |
| `dev32 / dev64 / dev128` | 多尺度相对地形位置。 |
| `waterFrac` | cell 内水体占比。 |
| `shoreDist` | 到水体 / 海岸距离。 |
| `biomeHist / biomeEntropy` | 群系混合和风格输入。 |
| `passability` | 后续 T3 / T4 图距离和可达性。 |
| `barrierCostN/E/S/W` | cell 边上的自然屏障成本。 |

### 主地貌与 tag

主地貌只表达面状规划语义，建议先收敛为：

```text
water / shore / lowland / upland / ridge / valley / unknown
```

`cliff` 不再作为大面积主地貌，而是 `landformTags[]` 中的二级 tag。只有同时满足“高坡度、高相对起伏、边缘带 / 坡折形态明显”时，才打 `cliff` 或 `steep` tag。

示例：

```json
{
  "baseLandform": "upland",
  "landformTags": ["steep", "mountain_front"],
  "slopeStats": { "mean": 0.31, "p90": 0.72, "steepFrac": 0.18 }
}
```

### 全图清洗与聚类

W v1.2 的 continent / patch 不应直接基于噪声标签逐 tile 输出。建议流水线：

1. 对 land / water / unknown mask 做 opening / closing 类清洗。
2. 删除小于阈值的小斑块，填补小孔洞。
3. 用 4 邻接生成 clean continent，避免角点相接岛屿误融合。
4. 对同类主地貌、coastal zone、biome group 做 macro patch 连通。
5. 对小 patch 按邻接相似度、屏障成本和面积阈值并入周边 patch。
6. 记录 `continentIdClean`、`patchIdClean`，旧 id 可作为 debug 来源保留。

## T3 阶段 v1.2 方案

### 主算法

T3 主算法改为多源 frontier 扩张：

```text
build land graph on target continent
seed each realm at accepted RealmSeed
while realm area is below target:
  choose realm by quota urgency and frontier best cost
  pop candidate from that realm frontier
  require candidate adjacent to that realm territory
  claim cell
  push traversable neighbors with accumulated edge cost
postprocess:
  repair detached components
  fill small holes
  smooth disputed boundary belt
  preserve strong natural barriers
```

关键变化：

| 旧 v1.1 | v1.2 |
| --- | --- |
| 每个 cell 对每个国度算静态 cost。 | 每条边计算穿越 cost，按 frontier 累积扩张。 |
| 全局排序抢 cell。 | 只能从本国已有边界继续扩张。 |
| quota 只控制抢多少。 | quota urgency 控制谁先扩，不破坏连通约束。 |
| 不记录飞地 / 空洞。 | 输出 topology metrics 和 repair log。 |

### Edge cost

自然边界发生在 cell 边上，因此 T3 应优先使用 edge cost，而不是只给 cell 打分：

| 成本 | 来源 | 说明 |
| --- | --- | --- |
| `slopeCrossCost` | W micro slope / barrier edge | 翻越陡坡更贵。 |
| `ridgeBarrierCost` | `ridge` 主类或 `mountain_front` tag | 山脉可形成自然国界。 |
| `waterCrossCost` | water / shore / sea connectivity | 默认不跨海，河流 / 海湾作为屏障。 |
| `coastMoveCost` | shoreDist / coastal tag | 海权国可沿岸扩张，但不等同于低价跨海。 |
| `passabilityCost` | W passability | 避免穿越不可通行地带。 |
| `compactnessPenalty` | 扩张形状 | 控制细长走廊和离种子过远。 |
| `profileAffinityPenalty` | RealmProfile 编译权重 | 亲水、亲山、资源倾向只影响局部偏好。 |

### AI 配置编译

AI 仍只配置语义化 `expansionStyle`。程序把它编译为有界内部权重：

| AI 语义 | 内部倾向 |
| --- | --- |
| `waterAffinity` | 降低近水 / 岸线腹地成本，不自动降低跨海成本。 |
| `coastalBias` | 增加沿岸扩张和港口候选倾向。 |
| `mountainAffinity` | 偏好高地 / 山前带，不等同于低价翻山。 |
| `compactness` | 提高离种子距离、细长走廊和破碎边界惩罚。 |
| `resourceSeeking` | 偏好资源代理 patch，不允许无连通飞地抢占。 |
| `seaCrossingPolicy` | 解锁有限跨海 bridgehead，默认 none。 |

### Topology repair

扩张后必须做拓扑修复和记录：

- 每个非海权国最大连通块占比应接近 `1.0`。
- 小 detached component 默认并入相邻国家或最近主块。
- 小孔洞可填补；大湖 / 内海不能误填。
- 边界 smoothing 只允许在 disputed belt 内进行，不能跨强 barrier。
- 海权国可保留少量 bridgehead，但必须记录水路来源、长度和数量。

## T4 阶段 v1.2 方案

### 阶段定位

T4 产出的是有限、稳定、带坐标的城市种子名册。它不应该只产出“某种城市可在某种地形条件下生成”的模板，否则 C 阶段按 chunk 加载顺序触发时，会让城市自然集中到玩家活动中心。

T4 的边界：

| T4 决定 | C 阶段决定 |
| --- | --- |
| 城市是否存在。 | 城市真实边界。 |
| 城市名称、角色、理论规模。 | 功能区形状和道路骨架。 |
| 城市粗锚点 / 候选范围。 | 建筑落点和结构池。 |
| 宏观生成条件和核心功能。 | 局部地貌适配和物化。 |

### 单国度候选图

T4 不把整张世界图发给 AI。每个国度生成单独的城市候选图包：

```text
RealmCityCandidateMapPackage
  -> 只显示本国领土、边境、邻国、水体、主要 patch、二级区域
  -> 标出首都、港口、矿区、边境关隘、腹地平原、交通廊道候选点
  -> 每个候选点带编号、grid 坐标、roleFit 和约束摘要
```

### 二级区域与候选池

T4 先把国度内部切成二级区域，再按城市角色生成候选：

| 二级区域来源 | 用途 |
| --- | --- |
| macro patch | 港口、矿业、农业、山地聚落等地貌条件。 |
| basin / half-basin | 水系、腹地和自然交通。 |
| cost corridor / skeleton | 首都到港口、边堡、资源点的通路网络。 |
| border belt | 边境堡、贸易关卡、军事城市。 |

角色候选规则：

| 角色 | 主要评分 |
| --- | --- |
| capital | 中央性、安全纵深、可建设性、淡水 / 通路、文化象征位。 |
| port | 岸线质量、海湾 / 外海可达、腹地 corridor。 |
| mining_town | 资源代理、山前 / 高地、平整建造面、通路可达。 |
| border_fort | 边界带、关隘、局部高地、pass control。 |
| market_town | 多 corridor 交汇、腹地覆盖、与大城距离适中。 |
| sacred / academic | 国度风格、特殊地貌、孤立性或象征性。 |

### 城市间空间约束

T4 不使用固定最小距离，而使用“规模半径 + 角色关系 + 图距离”约束：

```text
graphDistance(cityA, cityB)
  >= planningRadius(A) + planningRadius(B) + roleBuffer(A, B)
```

例外必须显式建模：

- 首都港口可以合并为同一城市的港区，而不是两个重叠 CitySeed。
- 边境堡可以靠近城市，但应标记为卫星军事节点。
- 卫星镇、矿区营地、关卡不等同于完整城市，规模半径和触发条件不同。

### AI 与程序分工

| 执行方 | 职责 |
| --- | --- |
| 程序 | 生成单国度候选图、候选池、评分、距离约束、合法性校验、落盘。 |
| AI | 给城市命名、选择候选编号、解释国度城市网络与功能分布。 |
| 程序 | 校验 AI 选择，不合格时要求换候选或降级为卫星节点。 |

## 质量评分与阻断

新增 `score_manifest.json`，每次验收输出总分、子分、硬阻断和人工 review 清单。

| 子项 | 权重 | 自动指标 | 硬阻断建议 |
| --- | ---: | --- | --- |
| W 地貌分类质量 | 15 | `cliffFalsePositiveProxy`、`isolatedClassRate`、`multiscaleFlipRate` | `cliffFalsePositiveProxy > 0.30` |
| W patch 粒度 | 10 | `singletonPatchRatio`、`tinyPatchAreaRatio`、`medianPatchCells` | `singletonPatchRatio > 0.25` |
| continent 合理性 | 10 | `smallComponentAreaRatio`、`effectiveContinentCount`、`mainlandShare` | 主大陆模式下 `smallComponentAreaRatio > 0.20` |
| T3 连通性 | 20 | 面积加权 `largestComponentRatio` | 任一非海权国 `< 0.90` |
| 飞地 / 孔洞 / 碎边界 | 10 | `detachedAreaRatio`、`holeAreaRatio`、`boundaryJaggedness` | `detachedAreaRatio > 0.05` 或 `holeAreaRatio > 0.03` |
| 面积比例误差 | 10 | 平均 / 最大 `abs(actual-target)`，并校验 `actualAreaRatio` 是否落在 `scalePlan.minAreaRatio/maxAreaRatio` 内 | strict 模式下任一国家超出 `minAreaRatio/maxAreaRatio` |
| 自然边界贴合 | 10 | `boundaryEdgesOnBarrier / allBoundaryEdges` | `< 0.35` |
| 城市种子分布 | 10 | `minGraphDistanceOk`、`subregionCoverage`、`roleFit` | 同格重叠直接阻断 |
| 预览图可读性 | 5 | 图例、标签、边界清晰度 | 人审 2/5 以下阻断 |

人工 review 保留五问：

1. 一眼能否看出大陆轮廓？
2. 国界是否大体顺着山脉、海岸、水体或荒地？
3. 是否存在明显不合常识的远端飞地？
4. 城市图标是否互相压住或集中在一块？
5. 图例、坐标和颜色是否可读？

| 产物 | 阶段 | 说明 |

## 开发顺序

1. **W 最低可用修复**：新增 micro-sampling、稳健统计、`cliff` tag 化、clean continent / macro patch。
2. **T3 连通扩张**：替换全局抢格子，加入 frontier、edge cost、动态 quota 和 topology repair。
3. **评分阻断**：输出 `score_manifest.json`，让坏结果不能再以 `passed=true` 混过验收。
4. **T4 城市规划**：单国度候选图、二级区域、role-specific 候选池、AI 选候选编号、程序校验。
5. **可视化增强**：固定图例、坐标标签、飞地标记、城市规模半径圈和 role 符号。

## 验收用例

| 用例 | 覆盖 |
| --- | --- |
| 单大陆平原 | 基础 land / patch / T3 连通。 |
| 山脉横贯主大陆 | 自然边界、山地国、翻山成本。 |
| 内海 / 大湖 | hole 识别，不误填大型水体。 |
| 多岛链 | 默认不跨海，海权国有限 bridgehead。 |
| 1-cell 狭海峡 | strait merge 与大陆边界。 |
| 跨 tile 边界 | clean continent / patch 跨 tile merge。 |
| 城市角色分布 | 首都、港口、矿业镇、边境堡不撞点，覆盖二级区域。 |

## 实现前待确认

- micro-sampling 初始 stride 用 `16` 还是 `32`。
- `cliff` tag 阈值是否先用经验值，还是先用 fixture 校准。
- T3 是否允许 wild land 未被国家占领。
- 海权国 bridgehead 的最大数量和最大水路长度。
- T4 城市数量按国度面积、叙事等级、二级区域数还是混合公式决定。
- AI 在 T4 返回候选编号还是直接返回 grid 坐标；建议候选编号为主，grid 坐标为校验字段。
