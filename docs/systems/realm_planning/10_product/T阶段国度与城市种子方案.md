# T 阶段国度与城市种子方案

## 定位

T 阶段负责把 W 阶段的世界主题、海陆格局、大陆摘要、粗尺度 patch 和地貌图集，转化为国度配置、国度扩张结果、城市名册、城市生成条件和城市生长种子。

它不负责城市内部规划，也不决定具体建筑落点。城市边界、功能区、道路骨架和结构物化都留给后续 C 阶段。

一句话：

```text
T 决定世界上有哪些国度、有哪些城市、城市从哪里长出来、理论上长多大；
C 决定这座城在当前地貌上具体怎么长。
```

## 和旧 W / T 的关系

旧 W / T 资料可以作为参考，但当前主线要重新归位：

- 旧 W1 的世界主题与约束，保留为 T 的上游输入。
- 旧 W3 的大陆 / 海洋聚类，保留为国度分配和扩张的背景事实。
- 旧 W4 的地貌图集和候选图思路，保留为 W 粗 patch、AI 看图选坐标和程序校验的参考。
- 旧 T1 / T2 的“阶段产物、AI 看图、程序落盘”思路可以参考；“AI 填参数、选簇、选方向”的旧流程废弃。
- 旧 T3 的多国度统一扩张思路保留，是当前 T 阶段的重要资产。
- 旧 T4 中“默认 bootstrap 城市”的语义废弃；新的 T4 只登记城市名册与生成条件，不创建城市实例。
- 旧代码迁移时要特别注意：旧 T3 结束后只定义了首都城市，其他后续城市的生成条件配置没有完成，不能把这个缺口当成已实现能力。

## 阶段边界

| 阶段 | 职责 | 主执行方 | 产物 |
| --- | --- | --- | --- |
| W | 形成世界主题、粗尺度地理事实、大陆 / 海洋摘要、粗 WorldPatchMap 和地貌图集。 | 程序 + AI 总结。 | WorldSurveyContext。 |
| T1 | 生成国度设定，并为每个国度准备带网格坐标的候选图包。 | 程序生成候选图和约束摘要，AI 参与叙事与高层偏好。 | RealmProfile + RealmCandidateMapPackage。 |
| T2 | 从候选图直接确定核心坐标、首都种子和扩张参数。 | AI 选网格坐标，程序转换、校验和落盘。 | RealmCoordinateSelection + RealmSeed + CapitalCitySeed。 |
| T3 | 根据所有国度种子统一扩张势力范围。 | 程序。 | RealmTerritoryMap。 |
| T4 | 基于国度配置和扩张结果生成全城市名册、城市数量、理论规模和城市生成条件。 | AI + 程序约束。 | CitySeedRegistry。 |

T1-T3 保留旧阶段分工思想，后续代码迁移时应优先评估旧实现；T1 / T2 的旧候选簇与方向选择流程不迁回主线。T4 是新语义，专门补“除首都以外的城市生成条件”。

## T 阶段输入

T 阶段最少需要这些上游材料：

- 世界主题：世界观、时代感、文明基调、硬约束、奇观偏好。
- 大陆 / 海洋摘要：区域 id、面积、中心点、海陆关系、主要气候和群系。
- 粗尺度地貌图：高地、平原、海岸、河流、山脉、盆地、森林、沙漠等宏观特征。
- 粗 WorldPatchMap：由 W 阶段大 step 扫描生成的宏观 patch，用于国度落脚、扩张背景和首都选点，不用于城市内部规划。
- 地貌图集或预览图：给 AI / 人类判断国度落脚点；首都选点时应提供带网格坐标的版本，让 AI 可以直接返回坐标。
- 国家或势力数量：每个大陆分配多少国度，是否有海权国、山地国、边境国等特殊类型。

当前 GIS v1 还不是 W 阶段全世界粗扫系统，但它已经提供了后续局部 C1 所需的地貌事实底座。W / T 的粗扫实现可以复用 GIS 的思想和部分采样能力，但不要求逐块构建全世界精细 Atlas。

## GIS 使用口径

国度规划系统是 GIS 的下游消费者。T 阶段使用 GIS 的方式应保持粗粒度、可解释和可回退，不把城市内部精细规划提前到国度阶段。

T 阶段可使用：

- W 阶段产出的粗 WorldPatchMap。
- GIS v1.1 按消费层传入较大 `cellStepBlocks` 生成的粗 Landform Patch。
- 粗尺度地貌图、patch 边界图和带网格坐标的预览图。
- patch 摘要：地貌类型、面积、中心、外接范围、平均高度、坡度、水距、是否临水、是否接近边缘。
- 自然群系和气候摘要：作为国度风格、材料、产业和扩张偏好的输入。

T 阶段不应使用：

- `city_fine` profile 生成的 C1 局部 TerrainPatchMap，除非某座 CitySeed 已经进入 C 链。
- 物化前 `verify_surface` 结果。
- 城市内部 step=1 或接近逐方块的扫描结果。
- 结构落点、功能区边界、道路细线和 jigsaw / prefab 执行参数。

GIS 在 T 阶段的作用是提供候选事实，而不是替 T 做最终叙事判断，也不是替 C 做城市规划。程序可以用 GIS patch 生成候选图、校验坐标和有限 snap；AI 可以看带网格坐标的预览图直接选择落脚 / 首都候选坐标，并解释国度为什么在这里生长。

如果 GIS v1.1 尚未落地，T 阶段可以先使用 W 阶段已有粗扫、legacy 调试图或手动调试图作为临时输入；但临时输入必须在产物中标记来源，不能伪装成已校准的 GIS 粗扫结果。

## T1：国度设定与候选图包

T1 保留旧 T1 的核心价值：程序提供大陆 / 地貌候选材料，AI 帮助整理国度设定和落脚理由。旧式“AI 填参数、程序按参数扫候选簇、AI 再选簇”的流程不再作为当前主线。

T1 应完成：

- 为每个国度生成 RealmProfile。
- 读取 W 阶段的大陆、海洋、地貌图集和预览图。
- 程序按国度偏好和禁用规则生成带网格坐标的候选图包。
- 候选图包说明 grid 坐标、world block 坐标换算、patch id、continent id、禁用区域和已占用点。
- AI 可以根据图像、摘要和国度设定提出落脚意图，但不直接填写底层扫描阈值或扩张 cost。
- 程序保证候选图只暴露可解释、可校验的选择空间。

T1 不应完成：

- 不确定精确城市边界。
- 不创建城市实例。
- 不逐格分配国土。
- 不进入 jigsaw / prefab。

## RealmProfile

RealmProfile 是国度配置，用来给整个国度定基调。它可以由 AI 生成，再由程序做结构校验。

它应表达：

- 国度名称、主题、叙事风格。
- 生活偏好：聚居、游牧、海贸、山居、农耕、矿业、宗教中心等。
- 材料偏好：木、石、砖、砂岩、铜、冰雪、黑石等。
- 宗教 / 文化 / 权力结构倾向。
- 产业倾向：贸易、农业、矿业、航海、军事、学术、工匠、渔业等。
- 地貌偏好：喜欢海岸、河谷、台地、山麓、平原、森林边缘等。
- 规模计划：小国、中等国、大国、帝国，以及在目标大陆 / 大区内的面积比例范围。
- 扩张偏好：避水、亲水、避山、依山、偏紧凑、偏长条、沿海扩张、边境竞争性等。
- 结构池倾向：后续 C7 选择结构池时使用的风格和功能偏好。

RealmProfile 不直接列出每座建筑，也不规定城市内部功能区边界。AI 可以一起给出 `scalePlan` 和 `expansionStyle` 的语义化数值；程序负责归一化、clamp，并把它们翻译为 T3 内部扩张 cost。

## T2：坐标选择、核心点与首都种子

T2 保留旧 T2 的核心价值：AI 做最终落脚判断，程序把结果写成可扩张的国度种子。不同的是，AI 不再选旧候选簇或方向，而是从带网格坐标的候选图中直接返回坐标。

T2 应完成：

- 读取 W 粗 patch 和带网格坐标的候选图，让 AI 直接选择首都 / 核心候选坐标。
- 支持 AI 返回主坐标、少量备选坐标和选择理由。
- 程序将 grid 坐标转换为 world block 坐标，并记录转换依据。
- 生成 RealmSeed，用于 T3 扩张。
- 生成 CapitalCitySeed，用于说明这个国度的首都一定存在。
- 继承并记录 RealmProfile 中已归一化的 `scalePlan` 和 `expansionStyle`。
- 程序校验核心点是否在目标大陆、目标 patch 或候选范围内；有限 snap 必须可追溯，不能静默跨大陆、跨海或跨禁用 patch。

T2 不应完成：

- 不生成除首都以外的城市名册。
- 不生成首都边界。
- 不生成首都功能区。
- 不直接创建城市实例。

旧实现迁移时要检查：

- 坐标选择和最终点位是否稳定复现。
- `region_id` / continent id 是否对齐。
- 点位 snap 到合法区域时是否会偷偷跨大陆、跨海或跨禁用区域。
- 旧 pending selection / Q1 / Q2 / 方向候选文件流应废弃或仅作 archive/debug 参考。

## T3：国度扩张

T3 保留旧 T3 的核心价值：所有国度核心点确定后，由程序统一扩张国土。

T3 应完成：

- 检查本大陆 / 本大区所有国度是否完成 T1 / T2。
- 根据 RealmSeed 统一运行多源扩张。
- 以 `scalePlan` 控制每个国度的目标面积比例，以 `expansionStyle` 派生扩张 cost。
- 输出 RealmTerritoryMap。
- 统计国度面积、邻国、海岸占比、主要地貌、主要群系等摘要。
- 给后续 T4 提供城市名册生成依据。

T3 不应完成：

- 不创建城市实例。
- 不决定所有城市边界。
- 不决定城市内部功能区。

旧实现迁移时要检查：

- 首都点 snap 到合法 region 的逻辑。
- 负坐标下 world block 到粗网格 cell 的换算。
- 多国度扩张前置校验。
- `region_id` / continent id 对齐。
- biome preference 是否真的进入扩张 cost。
- 扩张结果是否稳定复现。
- 是否存在飞地、空洞、跨海扩张等需要当前方案重新判定的问题。

## T4：城市名册与生成条件

T4 是新语义，不沿用旧 T4 的城市 bootstrap 默认行为。

旧 T3 结束后只定义了首都城市，后续城市的数量、规模和生成条件配置没有真正完成。新的 T4 专门补这个缺口：它根据 RealmProfile、CapitalCitySeed、RealmTerritoryMap 和世界地理事实，生成整个国度未来会拥有的城市名册、城市数量、理论规模分布和城市生成条件。

T4 应完成：

- 决定每个国度未来应拥有多少城市，以及各规模城市的大致数量。
- 生成首都、港口城、边境城、矿业城、贸易节点、宗教城、农业集镇等 CitySeed。
- 为每座城市确定身份、理论规模、生长锚点、核心功能清单和触发条件。
- 为每座有限城市确定稳定粗锚点或候选编号，不能只留下“满足条件时生成”的无坐标模板。
- 使用单国度候选图和二级区域摘要，让 AI / 人类在本国领土内规划城市网络，而不是读取整张世界图。
- 校验城市间的规模半径、角色关系和国度内图距离，避免城市撞点或全部挤到玩家最先加载区域。
- 标记哪些城市必定生成，哪些城市由玩家接近、国度发展或剧情阶段触发。
- 写明城市生成条件，例如需要海岸 / 河流 / 矿区 / 边境 / 交通廊道 / 宗教圣地 / 农业腹地等宏观条件。
- 为城市分配稳定 ID 和可追溯来源。
- 输出 CitySeedRegistry，供 C 阶段按需消费。

T4 不应完成：

- 不创建城市实例。
- 不扫描城市内部 step=1 地貌。
- 不生成城市边界。
- 不生成功能区。
- 不落关键建筑。

旧 T4 的战略场 / 全境摘要思路可以参考；旧 T4 的首都 bootstrap 默认路径不迁回主线。

## CitySeedRegistry

T 阶段最终应产出城市名册。这里的城市是“板上钉钉会存在的城市”，但还不是已规划完成的城市。

每个 CitySeed 表达：

- 城市身份：首都、港口、边境城、矿业城、宗教城、学术城、农业集镇、要塞、贸易节点等。
- 所属国度。
- 理论规模：村镇、小城、中城、大城、首都。
- 生成条件：该城市为什么应该存在，需要哪些宏观地理或叙事条件。
- 生长锚点：海岸、河口、山麓、台地、平原交通点、矿区附近、边境要冲等。
- 粗略中心或候选范围。
- 所属二级区域：macro patch、basin、corridor、border belt 或其他可追溯区域。
- 与其他城市的空间关系：图距离、规模半径、是否为卫星节点或复合城市组成部分。
- 生长方向偏好：沿水、沿路、依山、围核心、线性展开、双核心展开等。
- 核心功能清单：港口、市场、住宅、防御、行政、宗教、工业、仓储、农田、学术等。
- 触发方式：玩家接近、国度发展推进、调试命令、剧情阶段等。

CitySeed 不包含：

- 真实城市边界。
- 命名功能区图。
- 道路网络。
- 关键建筑坐标。
- jigsaw 深度、结构池权重或建筑落点。

这些都属于 C2 以后。

## T 到 C 的交接

当某个 CitySeed 需要真正生成时，进入 C 链：

1. C1 在城市候选范围内读取或刷新 GIS 地貌事实，形成局部地貌底图。
2. C2 把 CitySeed 和 RealmProfile 翻译成当前地貌上的城市语法。
3. C3 生成命名功能区。
4. C4 处理功能区边界、道路骨架和外缘。
5. C5+ 才进入关键建筑、约束场、结构池和物化执行。

因此：

- T 锁定城市存在性、身份、规模和生长锚点。
- C 锁定城市边界、功能区、道路和可物化结构。
- C 阶段只能消费已登记的 CitySeed，不应按 chunk 首次加载顺序抢占有限城市名额。

## AI 与程序边界

AI 适合做：

- 国度主题、生活方式、文化偏好和叙事设定。
- 从带网格坐标的世界 / 大陆 / 地貌预览图中选择国度落脚坐标。
- 决定国度为什么在这里生长，未来会形成哪些类型的城市。
- 基于单国度城市候选图给城市名册命名，分配身份、规模、核心功能清单和候选编号选择。

程序适合做：

- 大陆 / 海洋 / 地貌粗扫和聚类。
- 候选图生成、点位合法性校验和落盘。
- 多国度统一扩张。
- 防止国度重叠、越界、落到无效地形。
- 生成城市候选池、二级区域、图距离约束和重叠校验。
- 生成可被 C 链读取的结构化 CitySeedRegistry。

AI 不应在 T 阶段逐格绘制城市边界，也不应直接决定 jigsaw / prefab 的执行参数。

## 设计风险

- T 做得太细，会提前侵入 C2-C4，导致城市规划无法根据真实地貌自适应。
- T 做得太粗，会让 C 阶段失去国度基调，只剩随机地貌匹配。
- 旧 T4 的城市 bootstrap 语义要避免复活；它容易把“城市种子”误当成“城市已经生成”。
- CitySeed 需要稳定 ID 和可追溯来源，否则后续玩家接近时无法判断是否重复生成同一城市。

## 后续实现建议

1. 先把旧 W / T 中仍有价值的“AI 看图、程序校验、统一扩张”抽成当前 T 方案，旧选簇 / 选方向流程不迁回主线。
2. 再定义最小 RealmProfile 与 CitySeedRegistry 契约。
3. 迁移旧 T1 / T2 / T3 代码前，先列出旧 bug 和字段不一致风险，不直接搬运旧接口。
4. 后续真正开始实现国度规划系统时，在 `docs/systems/realm_planning/` 下补齐 `20_contracts/`、`30_code_guide/` 和 `40_tests/`。
5. C2-C4 设计时，只读取 T 的 RealmProfile 与 CitySeed，不回头依赖旧 W/T 接口碎片。
