# 国度规划系统 v1.1 开发计划：W 粗 Patch 与 T 阶段重建

> 历史开发计划：其中 T2 直接生成 `CapitalCitySeed` 坐标的语义已被 `首都AI候选选址-v0.1` 取代。当前真值是 T2 输出无坐标 `CapitalCityIntent`，T4 在 owned territory 中选定首都。

## 定位

本文承接从 GIS v1.1 收窄范围后移出的 W / T 工作。GIS v1.1 只提供可传入 `cellStepBlocks` 的地貌事实主链；W 粗 Patch、国度落脚、国度扩张和城市种子名册属于国度规划系统及其上游消费编排。

本轮目标不是兼容 legacy 的旧接口形态，而是审计旧 W / T 资产后，把可复用的算法思想迁移到当前主线：

```text
W 粗扫与 Patch -> T1 国度设定与候选图 -> T2 坐标选择与种子落盘 -> T3 国度扩张 -> T4 CitySeedRegistry
```

## 本轮目标

- W 阶段沿用 legacy 中大陆 / 海洋聚类、地貌摘要和预览图思路，新增粗 `WorldPatchMap` 与带网格坐标的候选图。
- T1 / T2 改为新方案：不再让 AI 填低层参数、选簇或选 `center/north/south/east/west` 方向；AI 只从带网格坐标的候选图中返回坐标和理由。
- T3 复用 legacy 多国度统一扩张的核心思路，但重写全局状态、坐标换算、snap 和 artifact 边界。
- T4 新增 `CitySeedRegistry`，补齐首都以外城市的名册、规模、身份、生长锚点和生成条件。
- 迁移 legacy 代码前先做缺陷审计；确认有 bug 或边界不合理的地方直接重写，不做表面兼容。

## 本轮非目标

- 不回到 GIS 内实现 W / T 调度，也不新增 `world_coarse`、`city_fine` 等命名 profile。
- 不复活旧 T1 / T2 的候选簇选择、方向选择和 pending selection 文件流。
- 不在 T 阶段生成城市内部边界、功能区、道路、结构池、jigsaw 或 prefab 参数。
- 不把旧 T4 的首都 bootstrap 当作当前 T4 主线能力。
- 不在缺少设计结论时硬迁移 legacy 中设计不周的逻辑。

## 主流程

| 阶段 | 输入 | 处理 | 产物 |
| --- | --- | --- | --- |
| W | 世界 seed、维度、世界主题、GIS step 参数化能力、legacy W 扫描思路 | 粗尺度采样、海陆 / 大陆摘要、粗 patch 聚合、预览与网格坐标标注 | `WorldSurveyContext`、`WorldPatchMap`、候选图 manifest |
| T1 | W 产物、国度数量 / 大陆分配、世界主题 | 生成或整理 `RealmProfile`，为每个国度准备候选图包和可解释摘要 | `RealmProfile`、`RealmCandidateMapPackage` |
| T2 | `RealmProfile`、候选图、AI 返回的网格坐标 | 坐标转换、合法性校验、有限 snap、冲突检测、扩张参数派生 | `RealmCoordinateSelection`、`RealmSeed`、`CapitalCitySeed` |
| T3 | 所有 `RealmSeed`、`WorldPatchMap`、地貌 cost | 多源统一扩张、冲突解决、面积和邻接统计 | `RealmTerritoryMap` |
| T4 | `RealmProfile`、首都种子、国度范围、世界摘要 | 生成城市名册、理论规模、生长锚点、触发条件和稳定 ID | `CitySeedRegistry` |

## Legacy 审计结论

| 范围 | 可复用点 | 必须重写 / 讨论点 |
| --- | --- | --- |
| W3 / W4 | 大陆 / 海洋聚类、地貌摘要、调试预览和图集输出思路。 | 不继续依赖 `ScanResultHolder` 和旧 `regionCacheMap` 作为真值；W 输出要接当前 GIS step 产物和新的 `WorldPatchMap`。 |
| T1 / T2 | 分阶段产物、状态文件、点位冲突校验和程序落盘思路。 | 旧“AI 选簇 / 选方向 / 填参数”流程废弃；旧 MCP 工具和 pending selection 文件流不能作为兼容主线。 |
| T3 | 多源扩张、地形 cost、国度冲突解决和统计摘要。 | `TerritoryManager` 的全局静态状态要拆成 per-job 服务；坐标换算要用 floor 语义；远距离 snap 不能静默跨大陆或跨海。 |
| T4 | 全境地貌窗口和摘要可作为后续调试参考。 | 旧 T4 是首都 terrain scan / bootstrap 语义，不是城市名册；当前 T4 需要新建 `CitySeedRegistry`。 |
| Artifact / MCP | legacy 的落盘追踪意识可保留。 | 旧字段名表达的是候选簇和方向选择，迁移时要改契约，不用兼容字段假装新语义。 |

已识别的高风险点：

- 旧扩张管理器存在全局可变状态，容易在多次运行、不同维度或不同大陆之间串结果。
- 旧坐标到网格的换算存在负坐标边界风险，新实现必须显式使用 floor 语义并写测试。
- 旧 snap 逻辑可能把无效点悄悄吸附到远处合法点；新实现应优先拒绝并输出原因，只允许在明确半径内有限 snap。
- 旧 T1 / T2 的 AI 决策被拆成候选簇和方向两次选择，接口碎片化，且不适合当前带网格坐标候选图。

## 阶段计划

### P0 文档与契约切分

- 固定 W / T 从 GIS v1.1 中迁出的边界。
- 在国度规划系统下补 `WorldPatchMap`、`RealmProfile`、`RealmCoordinateSelection`、`RealmSeed`、`RealmTerritoryMap`、`CitySeedRegistry` 的最小契约草案。
- 列出 legacy 代码迁移清单，标注“复用思想 / 重写实现 / 需要讨论”。

### W1 粗扫接入

- W 默认 `cellStepBlocks = 128`，作为大世界粗规划尺度；GIS 内核默认 step 仍保持 v1 兼容，不直接改成 128。
- 以 `planningRadiusBlocks` 控制初始最大扫描范围，默认建议 `8192`，正式存档可按世界设定调大。
- W 调度层按 GIS Region / tile 分片扫描，逐 tile 写缓存；重跑时按 `resumePolicy` 复用缓存或强制重扫。
- `world_survey_manifest.json` 记录 tile 状态、缓存命中、失败 tile、扫描范围、grid 尺寸、用时和数据量。
- 只有 `WorldSurveyContext.sealed = true` 且 `failedTileCount = 0` 时，T1 / T2 / T3 才能消费该 W 结果。
- 迁移或重写 legacy W3 的海陆 / 大陆聚类和摘要，输出大陆 id、面积、中心、边界、主要地貌和海岸关系。
- 每次 W run 记录维度、seed、step、采样半径 / 范围、数据来源和时间戳。

### W2 粗 Patch 与候选图

- 新增 `WorldPatchMap`：按粗 cell 聚合地貌、patch、海岸、山地、平原、河谷、盆地、森林、沙漠等宏观事实。
- 输出带网格坐标的候选图和 manifest，manifest 必须说明：
  - 网格原点、cell 尺寸、`cellStepBlocks`。
  - grid 坐标到 world block 坐标的转换。
  - patch id、continent id、地貌类型和摘要。
- 旧 W4 的图集可以作为预览层参考，但数据源改为当前 W / GIS 产物。

### T1 国度设定与候选图包

- 为每个国度整理 `RealmProfile`：名称、主题、生活方式、材料、产业、文化、地貌偏好、规模比例计划和扩张倾向。
- AI 可以参与叙事和偏好整理，但不直接填写底层权重、扫描阈值或旧式 site preference 参数。
- 程序为每个国度生成 `RealmCandidateMapPackage`：候选图、patch 摘要、禁用区域、已占用点、坐标说明和选择约束。
- T1 的完成条件是“候选图包可供 T2 选坐标”，不是“AI 已选中某个候选簇”。

### T2 坐标选择与种子落盘

- AI 从候选图直接返回网格坐标，可附带 1 到 2 个备选坐标和自然语言理由。
- 程序把 grid 坐标转换为 world block 坐标，并校验：
  - 坐标属于目标维度、目标大陆 / 大区和允许 patch。
  - 不落入明显无效地形或禁用区。
  - 与已有国度种子保持最小间距。
  - 有限 snap 不越过大陆、海域或禁止 patch 边界。
- 通过校验后写出 `RealmCoordinateSelection`、`RealmSeed` 和 `CapitalCitySeed`。
- 校验失败时返回结构化原因和可重试候选图，不自动把失败点改写成另一个语义不同的点。

### T3 国度扩张

- 以 legacy T3 的多源扩张为算法参考，重写为无全局静态状态的 job / service。
- cost 输入改为 `WorldPatchMap` 和必要的 GIS 指标摘要，避免直接读取旧 scan cache。
- 扩张前校验所有国度种子齐备、坐标合法、目标大陆一致。
- 按目标大陆 / 大区内可分配 land cell 对 `scalePlan.targetAreaRatio` 做归一化，避免按 MC 理论世界边界计算比例。
- 输出国度面积、邻接关系、海岸占比、主要地貌、主要群系和异常区域统计。
- 需要讨论后再定的策略：是否允许跨海扩张、飞地保留 / 修补、山脉和水体 cost 默认值。

### T4 CitySeedRegistry

- 基于 `RealmProfile`、首都种子、国度范围和世界摘要生成城市名册。
- 每个 `CitySeed` 至少包含稳定 ID、所属国度、城市身份、理论规模、生长锚点、候选范围、核心功能、触发条件和来源说明。
- 首都由 `CapitalCitySeed` 转入 registry，其他城市由国度范围和地理 / 叙事条件生成。
- T4 不创建城市实例，不扫描城市内部 step=1 地貌，不生成边界或道路。

## 需要先讨论的设计点

- `WorldPatchMap` 的最小 cell / patch 字段：先服务 T 阶段，还是一次性兼顾 C1 后续读取。
- T2 有限 snap 的半径、失败语义和 AI 重试方式。
- T3 是否允许跨海扩张，以及飞地、空洞和细长领土的修补策略。
- `scalePlan` 的配额策略：按同大陆归一化、按手动分组归一化，还是允许保留 wild land。
- `CitySeedRegistry` 的城市规模模型：按国度面积、叙事权重、资源点，还是固定配额混合。
- legacy MCP 工具是否完全换名，或保留旧命令但明确标记为 archive/debug。

## 验收计划

- 文档验收：GIS v1.1 只保留 step 参数化；W / T 内容只在国度规划系统 v1.1 计划中维护。
- W 测试：固定 synthetic world / fixture 能输出 `WorldPatchMap`、候选图和 manifest，且 step、坐标转换、patch id 可追溯。
- T1 / T2 测试：AI 返回的 grid 坐标能稳定转换并通过校验；非法坐标、跨大陆坐标和冲突坐标会被拒绝并给出原因。
- T3 测试：同一输入多次扩张结果一致；不同 job / 维度之间不串状态；负坐标种子转换正确。
- T4 测试：`CitySeedRegistry` 稳定 ID 不重复，首都必定存在，非首都城市有明确生成条件且不生成城市实例。
- 回归测试：legacy 可复用算法迁移后，用小型 fixture 对照旧输出趋势，但不要求兼容旧 artifact 字段。

## 开发顺序建议

1. 先补最小契约文档和测试入口，锁住产物名称、坐标体系和失败语义。
2. 再做 W 粗 Patch 与候选图，因为 T1 / T2 的新方案依赖带网格坐标的图。
3. 接着实现 T1 / T2 新链路，废弃旧选簇 / 选方向主流程。
4. 再迁移 T3 扩张，优先解决全局状态、负坐标换算和 snap 策略。
5. 最后实现 T4 `CitySeedRegistry`，把首都和后续城市名册统一交给 C 链消费。
