## AI 需求总结

### 本案身份

**实现当前案。** 用户于 2026-09-24 明确授权开发，接管模块职责与统一连接入口。 本案描述主 Mod、可选 Harness、地图与附属业务之间的职责，以及 MCP 启动体验。世界设计规则继续以[总调度当前案](../AI场景策划与程序执行分工-v0.1/README.md)为实现依据，附属业务接入仍遵循[附属模组规划流程扩展](../附属模组规划流程扩展-v0.1/README.md)。

### 主 Mod 保留完整主流程

**主 Mod 保留城市生成核心、MCP 入口与 workflow，始终控制主流程。** 它负责准备设计任务、组织队列、校验设计结果、推进程序阶段、记录进度以及衔接附属任务。AI 执行端领取任务并完成设计决策，不各自维护一套世界推进顺序。

不安装 Harness 或地图时，主 Mod 仍能启动 MCP，外部 Agent 仍能完成正常规划与城市生成流程。主流程的运行、进度恢复和附属任务衔接不能依赖这些可选模块存在。

### Harness 是面向普通玩家的赠品附属 Mod

**Harness 作为配套赠品，以可选附属 Mod 的形式提供，负责模型连接和 AI 任务执行，不接管主流程。** 它面向不知道 Agent 是什么、也不准备使用外部 Agent 的普通玩家：安装后直接在游戏内配置模型服务并开始或继续规划，**不要求玩家理解 Agent、安装外部 Agent 软件或手动连接 MCP**。已有外部 Agent 的玩家可以只使用主 Mod，无需安装 Harness 附属。

Harness 与外部 Agent 使用主 Mod 提供的同一套任务、资料和进度规则，避免同时修改同一任务。停用 Harness 后保留已提交进度，外部 Agent 可以接续；未完成的必要 AI 任务等待可用执行端处理，不能被静默跳过。

主 Mod 的 MCP 启动所需能力必须独立于 Harness，不能出现移走 Harness 后连 MCP 也无法启动的情况。现有 Provider 的配置和密钥需求继续由[Provider 当前案](../../../../city/10_product/案子/跨模块/玩家多模态Provider服务-v0.1/README.md)保存，并由 Harness 附属承载面向普通玩家的使用入口。赠品指配套定位，不表示模型调用免费；模型服务仍按玩家配置使用。

### 地图成为独立展示模块

地图负责面向玩家展示区域开放、国度归属、城市与玩家位置，具体体验见[冒险地图与大陆解锁](../冒险地图与大陆解锁-v0.1/README.md)。地图读取主 Mod 提供的真实规划和开放状态，不承担主流程调度；不安装地图不影响规划和城市生成，也不取消实际区域进入限制。

### 附属业务继续由主流程衔接

居民等附属业务通过现有扩展能力登记自己的规划任务。**主 Mod 决定何时交给 AI 执行并何时继续主流程**；附属业务提供自己的需求和完成判断。此次拆分不撤销现有附属规划接口，也不把附属业务内容移入主 Mod。

### 进入游戏时选择 MCP 端口

玩家进入游戏时获得 MCP 启动设置入口，可以选择启动端口，并在启动成功后取得供 Agent 连接的地址。启动服务本身不自动代表玩家要求开始世界规划。

首次进入主菜单时提供外部 MCP 设置，之后记住设置并自动启动，可从 Mod 设置页修改。安装 Harness 的普通玩家无需配置外部连接；仍可主动打开主 Mod 设置。独立服务器由管理员通过配置设置端口。

### 统一连接入口

**玩家只配置主 Mod 的一个对外 MCP 端口。** 接入主 Mod 的附属任务与能力通过同一个连接入口提供，玩家不必按附属 Mod 数量逐个填写端口，Agent 也不必为了完成一座城市的附属设计而切换多个连接。

这里的统一入口由主 Mod 承载，各附属模块向其接入能力；不是多个独立服务同时占用相同端口，也不表示任意第三方 MCP 服务都会自动合并。未接入主 Mod 的独立服务不在此承诺范围内。

```text
玩家选择一个 MCP 端口 → 获得统一连接地址
                                ↓
外部 Agent / 可选 Harness → 主 Mod 的任务与主流程
                                ├─ 世界与城市规划、程序执行
                                └─ 已登记的附属设计任务

独立地图 ← 读取主 Mod 的规划结果与区域开放状态
```

端口不可用时，建议在同一设置面板说明原因并允许改填，不按附属数量弹出多个输入框。实现状态以开发记录及验证结果为准。
