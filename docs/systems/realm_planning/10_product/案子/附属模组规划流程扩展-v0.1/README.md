# 附属模组规划流程扩展

## 需求原话

> 目前这套能够正常玩吗，就是我那边启动世界城市设计的情况下，接上那边MCP的服务器会在设计完一个城市后主动调用这边的MCP来配置居民吗

> 我觉得可以给那边的主流程暴露接口，那种可以从外部新增流程的接口，这会涉及到重构吗

> 我们整合包作者，只需要在配完各种各样的mod后构思到底哪些mod面向哪些玩家，然后AI在设计城市的时候配进去就行了。

> 落到具体的商人的商品肯定是程序概率得到的，主要就是池子的问题，mod的“道具掉落概率”（在我们这里是NPC身上的物品刷新概率，因为我们不但有交易还有赠送吧）的配置本来就是整合包作者的工作，这里我刚才的构思就是教一下AI哪些玩家喜欢玩什么mod而已，之后他根据功能把具体的池子配进去就行了，并且是可以多选的我觉得

## AI 需求总结

**案子身份：设计中案。** 本案负责向主模组规划流程追加附属模组任务的扩展能力。2026-09-24 整理，尚未接管实现；世界自动规划总调度仍以[AI 场景策划与程序执行分工](../AI场景策划与程序执行分工-v0.1/README.md)为实现当前案。

### 外部可以接入额外规划步骤

主模组提供可供附属模组接入的流程扩展能力，使附属模组能够登记自己的规划任务，并由主流程在合适时机衔接。用户连接主模组的规划入口后，AI 可以继续领取附属任务，不必由用户逐座城市另行安排居民设计。

扩展能力面向“新增附属步骤”，不把居民设计写成主模组只能识别的一种固定特例。具体接口与挂接位置在实现设计时确定。

### 城市设计衔接居民与物品内容

本次首个应用是国度冒险附属模组：城市已有功能与设定后，AI 能继续配置城市的居民规则、少量关键人物、物品池组合及城市权重。

整合包作者提供 Mod 玩法与玩家兴趣说明、物品池和基础概率；AI 根据功能选择多个池并调整城市权重；普通 NPC 和具体物品继续由程序生成。城市风格不成为 Mod 内容的硬性限制。

完整业务需求由[城市物品池与多商品交易](E:/Mod/_Dev/国度冒险附属Mod/需求案/05_城市物品池与多商品交易.md)保存，本案只规定它如何获得主流程的接入机会。

### 沿用 AI 设计、程序执行的分工

主流程把需要设计的内容交给 AI，把按规则计算、生成具体居民及物品的工作交给程序。AI 使用已提供的能力提交配置，不在游戏运行中编写或执行未经测试的行为代码。

流程扩展的实现讨论与尚待确定的衔接细节见[设计草案](E:/Mod/_Dev/国度冒险附属Mod/docs/城市物品池与主流程接入设计草案.md)。
