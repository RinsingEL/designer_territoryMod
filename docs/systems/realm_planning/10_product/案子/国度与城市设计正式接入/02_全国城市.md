# 全国城市

在真实国土上安排城市分工与分布，明确每座城服务谁、有什么活动、采用什么表达。**设计中案**；[返回纵览](README.md)。

```mermaid
flowchart LR
  A[国度设定与实际领土] --> B[考虑全国服务与城市联系]
  B --> C[各城定位、规模、功能与风格]
  C --> D[候选比较与全国分布复核]
  D -->|调整| B
  D -->|成立| E[城市名册与简短设计说明]
```

## 先安排全国城市，再进入单城

<small>原话：“我觉得还有一步，就是把第一、第二题实现到我们的mod里”</small>

**AI 总结：** 第二题从国家整体考虑哪里需要全国中心、区域中心、地方城镇或专门据点，再结合候选地形调整位置与规模。每座城说明自己的服务对象、综合功能和存在理由；各城可以共享产业、玩法和风格，通过服务范围与侧重点形成差异。

每国城市总数在本局配置的上下限内选择，首都计入总数；具体选多少、怎样组合规模，由 AI 结合国土和设计需要判断。

保留聚落之间的荒野和联系，不以铺满国土为目标。日常居住、饮食、生产和交流可以共同构成城市，不把每城压成一种独占产业。这里只说明城市间的联系，不提前绘制城内道路与街区。

## 首都身份、规模与服务层级分别决定

<small>原话：“麻烦你核对一下呢，就是现有实现和实验的区别”</small>

**AI 总结：** 正式接入沿用第二题的独立判断：一座城市是不是首都、占多大规划范围、服务全国还是周边，是三个不同问题。首都规模在本次城市设计中决定，不由前面的国度优先级提前定死。

| 判断 | 示例（说明三个维度，不是固定配置） |
| --- | --- |
| 身份 | 首都 |
| 规模 | 镇级 |
| 服务层级 | 全国中心 |

这样的首都可以依靠议事、技艺交流等职能服务全国，并不必须是面积最大的城市。

## 每座城留下一份可继承的设计说明

<small>原话：“先根据地图思考这个城市需要用什么风格、功能，这些感觉只需要定下来tag就ok了”</small>

**AI 总结：** 用标签与短句保存城市决定，第二题的表格就是主要表达，不再逐城重复写长篇介绍。

| 内容 | 要让后续单城设计知道什么 |
| --- | --- |
| 名称、身份、规模与服务层级 | 这是什么地方，为谁服务 |
| 大致位置与选址依据 | 为什么安排在这里 |
| 综合功能与侧重点 | 日常需要什么，哪些活动值得突出 |
| 玩家活动、模组组合与物资需求 | 玩家来做什么，空间要支持什么；哪些仍待核验 |
| 风格方向 | 建筑、植被、桥路等准备怎样组合，哪里允许地方变化 |

这些内容随城市保存，不能只在答卷里存在、交接时只剩一个坐标或职能标签。分项风格在此确定方向，整体设置、具体换皮和选结构留给单城设计。
