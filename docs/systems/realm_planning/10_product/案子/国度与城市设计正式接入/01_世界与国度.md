# 世界与国度

AI 先理解真实世界和可用内容，再构思文化圈与国度，给后续城市设计提供共同背景。**实现当前案**；[返回纵览](README.md)。

```mermaid
flowchart LR
  A[世界与内容总览] --> B[按需看图、查功能与玩法]
  B --> C[文化圈与各国差异]
  C --> D[简短世界概述与国度表]
  D --> E[AI 决定本国各类地形的扩张消耗]
  E --> F[选择扩张起点，程序统一形成领土]
```

## 材料就在当前设计任务里

<small>原话：“我感觉这套展示风格和功能的数据的过程可以也应用到第二题里？”</small>

**AI 总结：** 第一、第二题共用世界地图、风格概览、功能分类和真实模组玩法资料。先给能开始判断的总览，再按兴趣查详情和图片；风格外观与功能含义采用作者提供的标注，玩法说明让 AI 知道玩家能做什么、需要什么。

AI 在任务内即可查看这些材料，不必读项目代码或工程规则来补题意。标签描述选择方向，不能保证已经有对应的可用结构。展示细节见[风格与功能选择](../城市风格与功能选择/README.md)。

## 文化与国度由组合形成

<small>原话：“我希望各个风格是通用的，其实核心思路就是为了解决各种文明游戏的文明都是预制好的”</small>

**AI 总结：** 文化圈概括共享的建筑传统、生活方式与简短命名习惯；国家在共同文化下结合环境形成地方差异。同一种风格或玩法可被多国采用，一国也可组合多种表达，不按风格数量分配文明，不要求一片大陆只放一个国家。

第一题沿用实验的简洁表格表达：

| 层次 | 保留的内容 |
| --- | --- |
| 世界 | 一小段共同背景与整体特色 |
| 文化圈 | 共享风格、生计、影响空间使用的习惯与命名规律 |
| 国度 | 名称、所属文化、大致分布、地方表达、生活与玩法需求，以及地形扩张倾向 |

历史和制度只写会影响后续设计的部分。地理事实、计划生产和待实现玩法分开表达，不能把故事当成已有矿藏、航道或游戏能力的证明。

## 扩张消耗来自国家设定

<small>原话：“我最初的设计是打算由AI根据国家的设定，比如矮人族遇到水扩张力消耗大，山地消耗比其他文明小这样”</small>

**AI 总结：** AI 在构思国度时，一并决定本国适应哪些地形、在哪里扩张更吃力，并给出相应的地形消耗选择。程序据此计算各国从起点向外的扩张与竞争，不能把所有国家处理成相同成本。

| 用户例子 | 对领土扩张的影响 |
| --- | --- |
| 善于山地生活的矮人国度 | 山地消耗比其他不擅长山地的国家低，更容易沿山地扩展 |
| 同一国度不擅长涉水 | 遇到水域消耗更大，跨越水域更吃力；消耗高不直接等于禁止通过 |

这是 AI 根据具体国家设定作出的选择，不是看见“矮人”名称就自动套用的文明模板。不同国家可拥有相似适应能力，同一种族的国家也可因设定不同而产生差异。

地形消耗说明“扩张到这里有多费力”；总扩张额度与面积边界说明“能扩张到多大”，两者分开。后者是否调整现有规则，本次未定。

## 国度构思接上真实领土

<small>原话：“把第一、第二题实现到我们的mod里”</small>

**AI 总结：** 第一题先说明各国为什么存在、偏向在哪里生活、需要什么空间；随后选择扩张起点，由程序统一形成各国实际领土。第二题据此设计城市，不另画一份想象中的国界。

此时的大致分布不是首都坐标，也不提前列逐城建筑。玩家初始区域按本局实际保护范围处理，不能把实验地图里的大陆编号写成固定规则。国家数按本局配置执行，见[数量配置](README.md#保留国家数与城市数量范围)。
