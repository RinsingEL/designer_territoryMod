# Patch 探索式选址 v0.1

## 目的

W / T / City 主链继续保留 patch 作为 AI 理解世界地理的主要单元，但不再让 AI 从整张预览图的数百个细小 patch 标签中直接辨认编号，也不让程序按一个综合评分自动决定唯一的“最佳选址”。T 与 City 使用不同的首要语义：T2/T4 以主导群系连续区表达文明环境，City D4 以 D3 精细地形 patch 表达建筑承载面。

选址交互改为探索式决策：AI 先根据国度设定、世界预览和已知地貌类型，选择它感兴趣的 patch 类型；程序只负责将该类型中面积最大的少量候选清晰地渲染出来，并计算候选之间的空间关系；AI 可以选择其中一个，也可以继续查看其他类型或后续排名，直到找到能启发文明设计的地理区域。

该能力同时服务三个尺度：

- T1 / T2 在大陆或 W 候选范围内探索国度扩张核心。
- T4 在 T3 已确定的单国 owned territory 内先探索首都最终落脚区域，再探索后续城市种子区域。
- City D4 在 D3 局部精细 patch 中探索关键建筑、新功能区和阵列的落脚区域。

这一设计保留“世界先存在，文明再因地生长”的顺序。AI 不需要预先把选址意图翻译成一组地形查询参数，城市角色也不必在看到地理之前完全确定；AI 可以因为某块平原与山地、水体或国境的真实关系，再决定那里应当生长出什么样的聚落。

## 方案

### 1. Patch 真值与跨尺度投影

- W 阶段 sealed `WorldPatchMap` 继续作为粗尺度自然地理真值，T 阶段不重新加载 chunk，不重新扫描同一片世界。
- T1 / T2 候选以大陆、W 指定范围或国度可用范围为 scope，按 `WorldPatchMap.cells[].biomeHist` 的主导 biome 将四邻 cell 连成群系 patch。
- `RealmPlanningService.prepareT1` 既有的整大陆候选图只表示目标大陆的可分配 scope，不按国度文化或地貌兴趣做差异化；多个国度共享大陆时图片可以相同。它是 Patch Explorer 的范围参考，不是正式叙事选址图。
- T1 完成后的主动作固定为 `patch_explorer_open(scopeType=realm_t2)`；AI 必须先浏览类型、候选与关系，再把选择凭证交给 T2。直接手填 grid 坐标只保留给旧调用方和人工调试，不进入无上下文 AI 的推荐主链。
- T4 候选将群系 patch 与 T3 owned territory 相交，面积、排名和关系均以国境内的实际部分为准。
- T4 会话创建后不继承 T2 坐标为首都；AI 必须先消费一个 `realm_t4` 选择凭证建立唯一首都，才能继续添加非首都城市。
- T 阶段可以为群系连续区、裁剪或派生候选生成稳定 ID，但每个区域必须保留覆盖到的来源 W patch IDs 和 territory scope；`landform`、`baseLandform` 与坡度事实作为候选组成返回，不再把 `cliff` 等局部形态当作 T 的互斥主目录。
- City D3 在最终城市粗锚点周围生成局部精细 patch；T 阶段候选只决定宏观落脚区域，不取代 D3 的局部地形复查。
- 对 T4 AI 候选选出的首都，D3 复查是强制闸门：必须显式接受当前选址才能进入 D4；若局部真实地形不承载目标城市，回到原 T4 探索尺度重选，不默认改造城市原型。
- City D4 只消费当前 `CityLandformReviewPackage` 中的 D3 patch 真值，并将已冻结 occupied、现有建筑群、功能区和阵列区作为当前 scope；D4 不回头直接使用 W 粗 patch 替代 D3。
- 各尺度共用“类型目录 -> 每类 Top 3 -> 关系事实 -> 继续浏览或选定”的交互语义，但不共用或混淆不同尺度的 patch ID。

### 2. Patch 类型目录

每轮探索开始时，程序不向 AI 展开全部 patch 编号，而是返回当前 scope 内的类型目录。T2/T4 目录类型是完整 biome ID，例如 `minecraft:plains`、`minecraft:forest`、`minecraft:badlands`；City D4 目录类型仍是 D3 landform。目录至少说明：

- patch 类型与可读名称；
- 该类型的 patch 数量；
- 总面积、最大面积和面积分布摘要；
- 当前 scope 内是否存在足以承载国度核心或城市粗锚点的区域；
- 类型事实来源与置信度摘要；T 尺度置信度为 cell 内主导 biome 样本占比。
- T 尺度每种群系及候选的 `terrainComposition`、`baseLandformComposition`，用于说明群系内部平地、坡地、悬崖、谷地等组成，而不替 AI 选城。

City D4 的类型目录另外返回每类 patch 在扣除已冻结 occupied 后的剩余可用面积，但不因容量较小就向 AI 隐藏该类地理；是否足以承载指定建筑或阵列，在 AI 选定兴趣类型后作为事实返回。

AI 只需选择它当前感兴趣的一个或多个类型，不需要提交“靠山、临河、大平原”等组合查询表达式，也不需要直接填 patch ID。

### 3. 每类 Top 3 候选图

- 程序对 AI 选择的每种 patch 类型按 scope 内面积降序排列，每种默认只展示前 3 个。T1 / T2 / T4 使用群系连续区在 scope 内的实际面积；D4 默认使用扣除硬 occupied 后的连续可用面积，并同时报告原始 patch 面积。
- 排序不使用隐式的“文明最优”综合分；程序只负责面积排序、稳定并列打破和硬合法性标记。
- 预览图隐藏未入选 patch 的密集文字，只对当前候选大面积染色，并使用稳定、醒目的大号编号，例如 `PLAIN-01`、`MOUNTAIN-02`、`SHORE-03`。
- 不同类型使用可区分的固定色，同类型的 1‑3 名使用同色系不同明度；图例只显示本轮候选。
- 每个候选同时返回结构化摘要，包含面积、包围盒、中心、成员粗格、地形指标、置信度和来源 patch；预览图用于观察，结构化事实用于决策。

### 4. 程序关系事实

程序只计算并返回本轮 AI 主动选择的 patch 类型、当前页已展示候选之间的空间关系。未选择类型、未展示候选和其他世界对象不进入探索关系表；AI 想了解某种地理关系时，应先把对应 patch 类型加入当前兴趣集合。

关系表保持稀疏，不枚举当前页所有候选的完整两两组合。对每个候选，默认只返回它与其他每种兴趣类型中最近候选的关系，以及所有直接相邻项。单条关系只包含可计算的几何事实：

- 是否相邻、相交、包含或被分隔；
- 边界间最短距离和中心距离，同时记录 cell 与 block 单位；
- 从主候选看另一候选的主方位；
- 共享边界长度、接触比例和最近接触点；

程序不生成“控制河谷入口”、“只有一个主要出口”或“适合要塞”等叙事性描述。关系事实只描述兴趣 patch 之间“实际怎样”，如何解释这些关系属于 AI 决策。

首都、国境、已有城市、D4 已落建筑、父建筑群、既有阵列区、功能区、occupied 和出入口等对象仍可参与候选硬合法性、剩余容量、防撞和最终提交校验，但不作为 Patch Explorer 关系表的默认输出。

### 5. 可反复探索的分页闭环

- AI 对当前候选不满意时，可以查看同类型第 4‑6 名、第 7‑9 名，不得因首页 Top 3 未选中而自动回退到程序最高分。
- AI 可随时添加新的 patch 类型、移除已经失去兴趣的类型，或只对某个候选请求局部放大图。
- 每轮返回稳定的 exploration session 和 page token，保证同一 sealed W、同一 territory 与同一 scope 下的候选排名可重现。
- 候选图与结构化关系表记录本轮已展示类型、排名范围和来源 scope，使 AI 能明确知道“还可以继续看”。

### 6. 选定与粗锚点交接

- AI 最终只选择已展示候选的稳定 ID，并可记录选择理由；不直接填写小字 patch ID 或仅凭图片猜测 block 坐标。
- 候选应附带一个可追溯的建议粗锚点，该点只根据候选内部连通性、可建设面积、硬禁用格和与边界的安全距离产生，不替代 AI 做文明叙事判断。
- AI 选中候选后，程序必须立即生成并返回选中确认预览图，不得只返回 JSON ID。确认图只强调已选 patch，其他本轮候选降为淡色轮廓或隐藏，并保留 scope 边界与必要图例，避免再次出现密集小字。
- T1 / T2 / T4 的选中确认图在染色 patch 上叠加建议粗锚点；City D4 的确认图对选中 patch 内扣除硬 occupied 后的剩余可用区域单独染色。
- 选中确认图是下一阶段之前的视觉回执，用于证明程序消费的候选与 AI 刚选择的区域一致；它不要求 AI 再做一次提交，但 AI 可以在发现染色范围不符预期时返回 exploration session 重选。
- 选定后仍走现有坐标合法性校验、国境校验、城市间距离校验和有限 snap；程序不得静默把 AI 选中的候选替换为另一个语义不同的区域。
- T1 / T2 将国度核心选定结果交给 `RealmCoordinateSelection`、`RealmSeed` 和无坐标 `CapitalCityIntent`；T4 将首都与其他城市的选定结果交给 `CitySeedRegistry`。
- City D2 只读取 CitySeed 粗锚点和候选来源，City D3 在局部精扫后证明该区域是否真正可用；若局部事实否定 W / T 粗尺度判断，必须返回原 exploration session 重选，不得在 City 阶段无声换块。
- City D4 选中 patch 候选后不直接写入 anchor 或 occupied：关键建筑交给现有顺序 anchor 候选器在选中区域内生成少量精确点；新功能区或阵列交给现有 D4 阵列候选器生成 3‑5 组完整方案，仍由 AI 选中后才原子写入状态。

### 7. City D4 接入边界

- Patch Explorer 作为 D4 的地理探索入口，用于关键建筑新落点、新功能区和地理驱动阵列；它不直接生成建筑坐标，也不取代 D4 的 envelope、旋转、防撞和完整计数校验。
- D4 v0.5 的常规连续外扩保持现有语义：已有父建筑或建筑群、方向和目标间距已经明确时，候选仍可从父结构 D2 body 边缘连续生长，D3 patch 后置过滤，不强制预选 patch。
- AI 希望先查看局部地理再决定向哪里生长时，可在常规连续外扩之前进入 Patch Explorer；选中区域后，程序再以父结构与该区域的方位关系生成连续候选。
- D4 的预览仍分两层：Patch Explorer 图只对比地理区域；anchor / array candidate 图只对比选中区域内的精确建筑或整组阵列方案。
- D4 的两层预览之间还必须返回一张 patch 选中确认图：先证明 AI 选中的地理区域与剩余可用面，再进入 anchor / array candidate 精确候选图。

### 8. T4 调整

- T4 不再把港口、矿业镇、边境堡等城市直接简化为程序 `bestCityCell` 的单点最优结果。
- T4 的 AI 兴趣输入以 biome 为主，例如先对平原、森林、恶地或海岸环境产生兴趣；候选返回的地形组成和最大连续面积再回答是否能承载目标规模城市。
- 程序不在选定前按预设城市角色过滤世界，也不在选定后自动追加 AI 未选择 patch 类型的关系解释。
- 城市角色可以在选中地理后由 AI 确定，也可以在已有国度名册约束下调整；无论哪种情况，程序都只负责返回事实、硬约束和稳定候选，不代替 AI 做最终文明决策。
- 单国规划 finalize 后必须以合并后的 `CitySeedRegistry` 重建 `t4_report.json`、城市预览、单国候选包和 `score_manifest.json`；不得让旧自动 T4 证据继续与正式名册并存。
- 已存在的全链 `acceptance_report.json` 不能局部冒充重新验收：finalize 必须将其标记为 `stale=true`、`status=stale`、`passed=false`，并提示重新运行验收。
