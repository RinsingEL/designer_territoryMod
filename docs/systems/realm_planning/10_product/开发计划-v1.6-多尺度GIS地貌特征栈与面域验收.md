# 国度规划系统 v1.6 开发计划：多尺度 GIS 地貌特征栈与面域验收

## Summary

v1.6 承接 v1.5 的高步长局部指标修正，但目标更进一步：把 W 粗扫从“固定尺度指标 + 硬阈值 + 点式验收”升级为“多尺度 GIS 特征栈 + 证据分层 + 面域验收”。

v1.5 的重点是让 `cellStepBlocks=128` 时的 `cliff` / `steep` / `water_edge` 不再被 coarse GIS 直接误传。v1.6 的重点是解决更深层的问题：

```text
W cell 是面域标签。
人工 TP 是点位观察。
relativeHeightRank 是扫描内排名。
ridge / plateau / lowland 是多尺度地貌语义。
```

因此 v1.6 不再继续围绕单个阈值调参，而是引入明确物理尺度上的 local / regional 指标、TPI / DEV / roughness / fitted slope / curvature / geomorphon 近似，并把开发期 Tag Audit 改成以 cell 为抽样单位的面域 reference。

## 研究参考

参考资料：

```text
C:\Users\Rinsing\Downloads\面向 Minecraft Mod 的 GIS 地貌识别与遗迹 PCG 深度研究.md
```

该研究对本系统的可用结论：

| 研究结论 | v1.6 落点 |
| --- | --- |
| 地貌识别高度依赖尺度 | `ridge` / `plateau` / `lowland` 不再只靠 scan-wide `relativeHeightRank`。 |
| 分类图验收要匹配空间支持面 | Tag Audit 以 W cell 为抽样单位，输出 cell reference，而不是只用角点 TP 判断对错。 |
| 局部几何不能只靠四向高度差 | 增加拟合坡度、曲率、roughness 和 breakline 证据。 |
| TPI / DEV / Geomorphon 是成熟地貌识别路径 | 作为 W 粗扫宏观地貌的第二特征栈，先进入 debug / evidence，再进入正式规则。 |
| 水边分类应看距离场和水体形态 | `seacoast` / `riverbank` / `lakeshore` 后续从水体连通域升级到水距、开放水体和流网语义。 |
| PCG 选址应走 suitability | 后续遗迹 / 城市选址消费地貌 evidence score，而不是硬绑定单个 landform。 |

本轮不会把 ArcGIS、GRASS、WhiteboxTools 或 TauDEM 直接嵌入运行时；它们只作为算法参考和离线标定对象。

## 背景问题

当前在 ReTerraForged / 巨型生物群系真实验收中观察到：

- `ridge`、`plateau`、`lowland` 的高度区间经常都落在 `80..110`，单看高度很难解释。
- 小型平顶土坡容易被旧规则误判成 `plateau`；真实高原应当有可解释的连续面域，并且明显高出周边背景。
- `ridge` 样本 TP 到一个点时可能像平原，但 cell 里或视野旁边有小山 / 坡面。
- `relativeHeightRank` 依赖本次扫描范围；扫描半径和世界地貌组合变化后，同一块地的 rank 可能漂移。
- 之前的人工抽样把 cell 角点当作代表点，容易把面状标签误判成点位错误。
- `shore` / `coastal` / `riverbank` 的水边语义已经拆开，但仍缺少成熟水文距离和开放水体证据。

这些问题说明：v1.5 的 micro 修正能压住 `cliff` 误报，但不能单独解决宏观地貌分类的尺度问题。v1.6 需要重建地貌证据层。

## Scope

本轮包含：

- 新增 W 粗扫多尺度 GIS 特征栈设计。
- 拆分 scan-wide rank、local rank、regional rank 的职责。
- 为 `ridge` / `plateau` / `lowland` / `valley` / `cliff` 定义证据组合，而不是单阈值规则。
- 把 `baseLandform` 从单一硬分类扩展为主类 + evidence + confidence。
- 重写开发期 Tag Audit 的抽样与 reference 口径，以 W cell 面域为基本验收单位。
- 为后续水文距离场、流网语义和 ruins / city suitability 预留字段与阶段边界。

本轮不包含：

- 不重写低 step GIS 主链的基础架构。
- 不把 W 粗扫提升到 C 阶段城市精扫精度。
- 不要求一次性实现完整 GRASS / Whitebox / TauDEM 等价能力。
- 不在本轮实现遗迹生成、Jigsaw 物化或 grammar 建筑生成。
- 不把 `prior` 大扫改成全量 `verifySurface`；高成本验证只打到样本、高价值点和低置信区域。

## 核心原则

```text
采样贵，计算便宜。
先复用已有 feature grid，再在内存中扩展指标。
先输出 evidence / debug reasons，再收紧正式规则。
先修验收几何，再根据结果调阈值。
```

## 特征栈设计

### 1. 高度相对位置

当前 `relativeHeightRank` 是本次扫描内的全局排序，只能作为辅助特征。v1.6 建议拆成：

| 字段 | 建议尺度 | 说明 |
| --- | ---: | --- |
| `scanHeightRank` | 当前扫描范围 | 保留现有语义，只用于全局概览和 debug。 |
| `localHeightRank` | 512 block 左右 | 当前 cell 相对邻近地貌背景的位置。 |
| `regionalHeightRank` | 2048 block 左右 | 当前 cell 相对更大区域背景的位置。 |
| `heightRankStability` | 多半径对比 | 判断 rank 是否对扫描半径敏感。 |

`plateau` / `lowland` / `upland` 不应只消费 `scanHeightRank`。正式判定至少应参考 local 或 regional 物理尺度。

### 2. TPI / DEV

建议新增：

| 字段 | 说明 |
| --- | --- |
| `tpiLocal` | 当前高度与 local 邻域均值的差。 |
| `tpiRegional` | 当前高度与 regional 邻域均值的差。 |
| `devLocal` | local TPI 按邻域标准差归一化后的局地 z-score。 |
| `devRegional` | regional TPI 按邻域标准差归一化后的局地 z-score。 |
| `devMaxMagnitude` | 多尺度 DEV 中绝对值最大的偏离强度。 |
| `devMaxScaleBlocks` | 当前地貌最显著的物理尺度。 |

TPI / DEV 用于减少不同世界高度分布导致的阈值漂移。它们应从已有 coarse / micro feature grid 派生，避免重复 generator 查询。

### 3. roughness / relief

建议新增：

| 字段 | 说明 |
| --- | --- |
| `roughnessLocal` | local 窗口高度起伏或邻域差分强度。 |
| `roughnessRegional` | regional 窗口的地形破碎度。 |
| `reliefLocalP90P10` | local 高度分位起伏。 |
| `reliefRegionalP90P10` | regional 高度分位起伏。 |

`ridge` 和 `mountain_front` 应要求 roughness / relief 支撑；`plateau` 则要求相对高位但 roughness 较低。

### 4. fitted slope / curvature

当前 micro slope 主要来自中心点到东 / 西 / 南 / 北半径点的高度差。它适合低成本检测陡坡，但对斜向山脊、台地边缘、窄谷和曲折断崖有方向偏置。

v1.6 建议在局部参考网格上增加拟合面指标：

| 字段 | 说明 |
| --- | --- |
| `fittedSlope` | 局部样本拟合平面后的坡度。 |
| `profileCurvature` | 沿最大坡降方向的曲率，用于 cliff / breakline。 |
| `planCurvature` | 等高线方向曲率，用于 ridge / valley 形态。 |
| `curvatureConfidence` | 样本数量和拟合残差决定的可信度。 |

第一阶段可以只在 Tag Audit reference 或低置信样本上计算；稳定后再进入 W 正式特征。

### 5. geomorphon 近似

v1.6 不强制完整实现 GRASS / ArcGIS Geomorphon，但建议先实现一版简化 8 方向形态：

```text
flat
peak
ridge
shoulder
spur
slope
hollow
footslope
valley
pit
unknown
```

简化实现可以先基于 8 方向采样线的相对高低模式，不必完全复刻 lookup table。它主要用于给 `ridge` / `valley` / `plateau edge` 提供第二意见。

### 6. 水体距离与水文语义

v1.5 已把 `coastal` 拆成 `seacoast` / `riverbank` / `lakeshore`。v1.6 建议继续补：

| 字段 | 说明 |
| --- | --- |
| `euclideanWaterDistance` | 到最近水体的直线距离，替代只看 4 邻接 BFS 的语义。 |
| `waterComponentId` | 最近水体连通域。 |
| `waterComponentType` | `open_water` / `river_like` / `lake_like` / `boundary_truncated`。 |
| `waterBoundaryConfidence` | 扫描边界是否截断水体导致不确定。 |
| `flowAccumulationHint` | 后续流网 / 谷地语义的预留字段。 |

扫描边界触水不应直接证明 `seacoast`；更稳妥的标签是 `boundary_truncated` 或 `open_water_unknown`，除非 halo 扫描、ocean biome 或更大范围组件证明它是开放海岸。

## 地貌判定语义

### baseLandform

`baseLandform` 继续表达面状主地貌，但 v1.6 后不再被视为唯一真相。建议输出：

```text
baseLandform
baseLandformConfidence
landformEvidence[]
overlayTags[]
debugReasons[]
```

### evidence 组合

| 地貌 | 必要证据 |
| --- | --- |
| `lowland` | local / regional 相对低位或中低位，局部平坦，roughness 低，不处于山脚 breakline。 |
| `plateau` | local / regional 相对高位，局部平坦，roughness 低，具备一定连续面域，并相对外圈背景有明确抬升。 |
| `upland` | 相对高位或中等起伏，但未满足 ridge / plateau 的强语义。 |
| `ridge` | 正的 local / regional 相对位置，geomorphon ridge / shoulder / spur 候选，roughness 或 fitted slope 支撑。 |
| `valley` | 负的 local / regional 相对位置，geomorphon valley / hollow 候选，水距或 flow hint 支撑。 |
| `cliff` | overlay / breakline 标签，要求高 slope、profile curvature 或两侧高度落差连续性，不作为 128 cell 主类。 |
| `shore` | 水陆混合或近水面域，需结合 water distance 和 component type。 |

### confidence

建议把置信度拆成：

| 字段 | 说明 |
| --- | --- |
| `metricConfidence` | 当前 cell 样本是否足够、是否来自缓存、是否边界截断。 |
| `semanticConfidence` | evidence 是否一致，例如 rank、slope、geomorphon 是否同向。 |
| `supportConfidence` | cell 面域内部是否一致，还是混合地貌。 |
| `surfaceConfidence` | `prior` 与 `verifySurface` / observed 之间是否可能有偏差。 |

低置信 cell 不应强行变成硬标签，应输出 `needs_review`、`mixed_cell`、`boundary_truncated` 或 `low_confidence` 诊断 tag。

### plateau prominence

`plateau` 不能只由“局部平坦 + 高度 rank 偏高”推出。v1.6 首版实现新增 plateau 专用上下文：

| 指标 | 首版尺度 / 阈值 | 用途 |
| --- | ---: | --- |
| `plateauCoreScaleBlocks` | 512 | 检查核心平顶面域是否连续。 |
| `plateauOuterScaleBlocks` | 1536 | 检查核心面域相对更大外圈是否明显抬升。 |
| `plateauCoreFlatSupport` | `>= 0.65` | 核心窗口内，平坦且接近当前高度的可分配陆地比例。 |
| `plateauProminence` | `>= 18 block` | 核心窗口平均高度减去外圈平均高度。 |
| `regionalHeightRank` | `>= 0.80` | 当前 cell 在区域背景中确实处于高位。 |

因此小村庄旁的土坡、局部雪坡、单个 128 cell 平顶，即使局部平坦，也应降级为 `lowland` / `upland`，而不是 `plateau`。真正的 `plateau` 需要同时满足“顶面连续”和“高出周边”。

## 面域 Tag Audit

### 目标

开发期验收从“抽一个点然后 TP 肉眼判断”升级为“以 W cell 为样本，构建更高精度 reference，再评估分类图”。

### 抽样单位

抽样单位改为 W coarse cell，而不是单个 block 点。

每个样本 cell 输出：

| 点位 | 用途 |
| --- | --- |
| `cellCenter` | 默认 TP 点，减少角点偏差。 |
| `highestMicroPoint` | 检查高地 / ridge / plateau 语义。 |
| `lowestMicroPoint` | 检查 valley / lowland / water_edge 语义。 |
| `maxSlopeMicroPoint` | 检查 cliff / steep / mountain_front 语义。 |
| `recommendedTpPoint` | 按待验收标签选择最有代表性的点。 |

人工传送时应明确自己看的是哪个代表点，不能把一个角点观察直接等价为整个 cell 错误。

### reference 扫描

对抽中的 cell 做局部精扫：

```text
referenceCellStrideBlocks = 8
referenceLocalRadiusBlocks = 128
referencePointRadiusBlocks = 32
referencePointStrideBlocks = 4
```

两类 reference：

| reference | 说明 |
| --- | --- |
| `cellReference` | 对整个 W cell 或 cell 内规则网格汇总，评估面状主地貌。 |
| `pointReference` | 对代表点周围局部范围精扫，评估玩家 TP 位置附近是否符合标签。 |

只有 `cellLabel` 与 `cellReference` 显著冲突时，才算 W 面域标签错误。`pointReference` 与 `cellLabel` 不一致时，应先标记为 `mixed_cell` 或 `bad_representative_point`，再决定是否修分类器。

### 报告指标

`tag_audit_report.json` 建议输出：

| 指标 | 说明 |
| --- | --- |
| `confusionMatrix` | 按 baseLandform 和 overlay tag 分开统计。 |
| `userAccuracy` | 用户看到某类标签时，实际为该类的概率。 |
| `producerAccuracy` | reference 中某类地貌被正确标出的概率。 |
| `overallAccuracy` | 总体分类正确率。 |
| `areaAdjustedAccuracy` | 按抽样分层面积权重修正后的准确率。 |
| `boundaryF1` | 对 shore / cliff 这类边界标签的边界 F1。 |
| `mixedCellRate` | cell 内多种 reference 并存的比例。 |
| `representativePointMismatchRate` | 推荐 TP 点与 cellReference 不一致的比例。 |
| `rankDriftRate` | 扫描半径变化导致 landform 漂移的比例。 |

### 抽样分层

| 分层 | 目标 |
| --- | --- |
| `confirmed_cliff` | 检查 cliff overlay precision。 |
| `steep` | 检查 steep tag 是否对应局部坡面。 |
| `ridge` | 检查 ridge 是否具有高位与山脊形态。 |
| `plateau` | 检查高且平、连续面域，以及是否满足相对外圈 prominence。 |
| `lowland` | 检查低且平，排除山脚边界误入。 |
| `valley` | 检查低位、凹形、水距或流网语义。 |
| `seacoast` / `riverbank` / `lakeshore` | 检查水体组件类型和水陆关系。 |
| `micro_contradiction` | 检查 v1.5 对 coarse cliff 的拒绝是否合理。 |
| `random_land_baseline` | 估算普通陆地误报率。 |

## 数据与契约影响

v1.6 进入实现前，需要同步检查 `20_contracts/数据契约/W-T阶段数据契约.md`。建议新增或预留：

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| `metricScales` | feature grid manifest | 记录 local / regional 指标半径，以及 plateau core / outer 半径和 prominence 阈值。 |
| `terrainEvidence` | `WorldPatchCell` | 多尺度证据列表或结构化对象。 |
| `landformConfidence` | `WorldPatchCell` | 主类置信度。 |
| `overlayTags` | `WorldPatchCell` | cliff / water_edge / mixed / low_confidence 等非互斥层。 |
| `validationSupport` | audit samples | 记录 cell / point reference 的空间支持面。 |
| `representativePoints` | audit samples | 输出中心、最高、最低、最大坡度和推荐 TP 点。 |

## 实施顺序

1. 固化 v1.5：确认 `cliff` / `steep` / 水边基础语义不再由 coarse GIS 直通。
2. 修正抽样输出：每个样本 cell 输出中心、最高点、最低点、最大坡度点和推荐 TP 点。
3. 实现面域 Tag Audit：区分 `cellReference` 与 `pointReference`，输出 confusion matrix。
4. 新增 local / regional height rank 与 rank drift 统计，先进入 debug reasons。
5. 新增 TPI / DEV / roughness 指标，先做产物输出和可视化，不立即强改正式分类。
6. 用 `4096` ReTerraForged run 对比旧规则、新 evidence 与人工抽样。
7. 将 `ridge` / `plateau` / `lowland` 改为 evidence 组合判定。
8. 追加 fitted slope / curvature 或简化 geomorphon，优先用于低置信和争议样本。
9. 升级水边分类：加入欧氏水距、水体边界不确定性和 `boundary_truncated`。
10. 跑 `16384` 标准档，检查性能、缓存、准确率和 rank drift。

## 测试计划

### Synthetic / JVM

| 用例 | 预期 |
| --- | --- |
| 平坦低地 | `lowland` 高置信，roughness 低，rank 稳定。 |
| 高且平的平台 | `plateau` 高置信，不因 scan-wide rank 漂移变成 upland。 |
| 山脊线 | `ridge` 需要高位 + 形态证据，不能只靠旁边一座小山。 |
| 山脚缓坡 | 可为 `upland` / `mountain_front`，不应误成 ridge / cliff。 |
| 谷地 | `valley` 需要低位 + 凹形或水文 hint。 |
| cell 内混合地貌 | 输出 `mixed_cell` 或低置信，而不是强行高置信主类。 |
| 扫描边界水体 | 输出 `boundary_truncated`，不直接等价 `seacoast`。 |

### 真实世界验收

至少跑：

```text
planningRadiusBlocks=4096
cellStepBlocks=128
microSampleStrideBlocks=32
runTagAudit=true
```

然后在 ReTerraForged / 巨型生物群系存档中抽样：

| 类型 | 数量 | 验收重点 |
| --- | ---: | --- |
| `ridge` | 10 | 是否位于山脊 / 肩部 / 高位连续形态，而不是平原旁边有山。 |
| `plateau` | 10 | 是否高且平，是否有连续面域。 |
| `lowland` | 10 | 是否低且平，是否不是山脚边界。 |
| `cliff` / `steep` | 10 | 是否有局部陡坎或坡面证据。 |
| 水边三类 | 15 | `seacoast` / `riverbank` / `lakeshore` 是否符合水体组件语义。 |
| mixed / low confidence | 10 | 是否确实属于 cell 内混合或边界不确定。 |

### 通过标准

| 类别 | 标准 |
| --- | --- |
| 验收几何 | Tag Audit 使用 cell 面域 reference，不再以角点 TP 直接判错。 |
| 产物 | audit samples 输出 representative points 和 `/tp` 命令。 |
| 指标 | local / regional rank、TPI / DEV / roughness 至少进入 debug 产物。 |
| 稳定性 | `ridge` / `plateau` / `lowland` 对 scan radius 的漂移率可统计。 |
| 语义 | `ridge` 不再只由 slope / relief 推出；`plateau` 不再只由高度 rank 推出。 |
| 水边 | 扫描边界触水不直接生成高置信 `seacoast`。 |
| 性能 | 4096 smoke 可接受；16384 标准档不显著劣化 v1.5。 |
| 回归 | `./gradlew.bat test` 和 realm planning / GIS 相关 JVM 测试通过。 |

## 风险

- 指标增加后容易过度复杂，需要先作为 evidence / debug 输出，避免一次性改坏正式分类。
- local / regional 半径选择会影响语义，需要用真实世界和 synthetic 双重校准。
- curvature / geomorphon 如果采样太稀会不稳定，第一阶段不应强依赖。
- `prior` surface 与玩家实际看到的 surface 可能仍有差异，需要保留 `verifySurface` / observed 抽样通道。
- 面域 Tag Audit 的报告会比旧点式验收复杂，需要明确哪些指标用于阻断，哪些只用于诊断。

## 非目标提醒

v1.6 的目标是让 W / T 阶段拥有更可信、可解释、可验收的地貌事实。它仍然不是城市内部落地系统，也不是遗迹物化系统。后续 ruins / city PCG 应消费本轮输出的 suitability / evidence，而不是把结构生成逻辑塞回 W 粗扫。
