## 包结构

| 包 / 路径 | 职责 |
| --- | --- |
| `systems.realm_planning` | W / T 主服务、数据对象、扩张算法、CitySeedRegistry 产物导出。 |
| `systems.realm_planning.testsupport` | Forge GameTest 真实 ServerLevel 验收入口。 |
| `platform.GisPlatformEvents` | Forge 命令入口，包含 `/geomantia realm status` 和 `/geomantia realm acceptance`。 |
| `platform.http.RealmPlanningHttpController` | 本地 HTTP 调试接口，承接 MCP 请求并在 server thread 上运行 GIS prior 采样。 |

| `country_designer_mcp/src/realm` | MCP tool schema 与 handler，透传到本地 HTTP 服务。 |
| `src/test/java/.../realm_planning` | JVM 合成样例、契约和 runner 测试。 |

## 当前实现入口

| 能力 | 主要入口 | 说明 |
| --- | --- | --- |
| W / T 主链 | `RealmPlanningService.runAcceptance` | 一次性运行 `W -> T1 -> T2 -> T3 -> T4`，写出 `acceptance_report.json`。 |
| W 粗扫产物 | `RealmPlanningService.runW` | 从 GIS `RefreshResult` 构建 `WorldSurveyContext`、`WorldPatchMap`、粗 patch 图和 grid overlay。 |
| T1 候选图包 | `RealmPlanningService.prepareT1` | 生成或接收 `RealmProfile`，输出候选图包和候选图。 |
| T2 坐标选择 | `RealmPlanningService.selectT2` | 校验 grid 坐标，有限 snap，生成 `RealmSeed` 与 `CapitalCitySeed`。 |
| T3 扩张 | `RealmPlanningService.expandT3` | 按同一大陆可分配 land cell 归一化比例并做多国度扩张。 |
| T4 城市名册 | `RealmPlanningService.buildT4` | 生成 `CitySeedRegistry`，不创建城市实例。 |
| HTTP 调试接口 | `RealmPlanningHttpController` | 暴露 `/realm/status`、`/realm/w/refresh`、`/realm/t1/prepare`、`/realm/t2/select_coordinate`、`/realm/t3/expand`、`/realm/t4/build_registry`、`/realm/acceptance/run`。 |
| MCP 工具 | `realm/tools.ts`、`realm/handlers.ts` | 暴露 `realm_status`、`realm_w_refresh`、`realm_t1_prepare`、`realm_t2_select_coordinate`、`realm_t3_expand`、`realm_t4_build_registry`、`realm_run_acceptance`。 |
| Forge 命令 | `GisPlatformEvents` | 玩家 / 开发者可用 `/geomantia realm acceptance [radiusChunks] [cellStepBlocks]` 跑真实世界验收。 |
| 自动客户端 smoke | `DevAutoLoadClient`、`build.gradle` | `-PgeomantiaDevRealmSmoke=true` 时进入开发存档后自动执行 realm acceptance 命令。 |
| Forge GameTest | `RealmPlanningGameTests.realmPlanningPriorAcceptance` | 在真实 `ServerLevel` 上使用 `MinecraftPriorAtlasSampler` 跑 W / T 验收。 |

## 主调用链

```text
MCP realm_run_acceptance
  -> POST /realm/acceptance/run
  -> RealmPlanningHttpController.runGisRefresh
  -> GisRefreshService.refresh
  -> RealmPlanningService.runAcceptance
  -> runW -> prepareT1 -> selectT2 -> expandT3 -> buildT4
  -> acceptance_report.json + 预览图 + 各阶段 JSON
```

Forge 命令和 GameTest 复用同一条服务链，只是触发入口不同。

## 当前边界

- 当前只实现 W / T 最小闭环，不进入 C 阶段城市内部边界、道路、功能区、结构池或 jigsaw 物化。
- T1 / T2 不兼容旧“AI 选簇 / 选方向 / 填低层参数”接口。
- T3 复用 legacy 扩张思想，但实现为 per-run 服务，不使用旧全局静态状态。
- `CitySeedRegistry` 只生成城市种子名册，不创建城市实例。
- `DevAutoLoadClient` 是临时开发验收辅助，只在开发环境和显式 Gradle property 下启用。

## Review 快速入口

本系统改动时优先检查：

| 检查点 | 重点 |
| --- | --- |
| W 产物 | `cellStepBlocks`、`gridOriginBlock`、`surveyId`、patch / continent id 是否可追溯。 |
| T1 图包 | `gridLegend.originBlock`、`gridLegend.cellStepBlocks`、候选图路径、允许 patch 是否齐全。 |
| T2 校验 | 非法坐标是否结构化 rejected；有限 snap 是否不跨大陆、海域或禁用 patch。 |
| T3 扩张 | 比例是否按 `normalizationGroup` / 目标大陆归一化；不同 run 不共享可变状态。 |
| T4 名册 | 首都是否必定存在；城市种子 ID 是否稳定唯一；是否越界生成城市实例。 |
| 接口入口 | HTTP/MCP/Forge 命令是否只做参数解析和调用服务，不复制业务逻辑。 |
| 验收证据 | `./gradlew.bat test`、`./gradlew.bat runGameTestServer`、`npm run build` 是否覆盖本次改动。 |
