## 当前实现入口

| 能力 | 主要入口 | 说明 |
| --- | --- | --- |
| W / T 主链 | `RealmPlanningService.runAcceptance` | 一次性运行 `W -> T1 -> T2 -> T3 -> T4`，写出 `acceptance_report.json`。 |
| W 分片扫描 | `WorldSurveyRunner.run` | 按 `planningRadiusBlocks` 和 `cellStepBlocks=128` 默认值枚举 GIS Region tile，写 tile cache、配置 hash、`world_survey_manifest.json`、`world_feature_grid.json` 和开发期 `world_survey_progress.json`，支持恢复扫描；调用 `GisRefreshService.ArtifactMode.NONE` 禁止逐 tile GIS PNG/manifest，只保留最终世界级预览。进度按约 1 秒写文件和日志，并由 `WorldSurveyChatProgress` 每 5 秒向目标玩家聊天框报告。 |
| W 生成器快路径 | `RealmPlanningHttpController.runWorldSurvey`、`TerrainPreviewAtlasSampler` | `prior` 模式按请求开关选择 provider；RTF 原生二维样本适配到既有 W sampler，实际 provider provenance 进入 manifest、survey context 与 cache hash。非 prior 模式和显式关闭都使用 Minecraft sampler。 |
| W 粗扫产物 | `RealmPlanningService.runW` | 消费 sealed `WorldSurveyResult`，构建 `WorldSurveyContext`、`WorldPatchMap`、粗 patch 图和 grid overlay。 |
| W 多尺度地貌指标 | `RealmPlanningService.assignMultiScaleTerrainMetrics` | 从 W feature grid 派生 local / regional rank、TPI、DEV、roughness、geomorphon，并为 `plateau` 计算 core flat support 与 outer-ring prominence。 |
| T1 候选图包 | `RealmPlanningService.prepareT1` | 生成或接收 `RealmProfile`，输出目标大陆合法 scope 参考图；响应以 `patch_explorer_open` 为唯一推荐下一步，直接坐标入口单列为 compatibility。 |
| T2 坐标选择 | `RealmPlanningService.selectT2` | 校验国度核心 grid 坐标，生成 `RealmSeed` 与无坐标 `CapitalCityIntent`。 |
| 跨尺度 Patch 探索 | `PatchExplorerService`、`TerrainScalePatchService` | T2/T4 以 sealed W / T3 owned cells 为范围，在不大于 32 格的 T 尺度重新采样、分类并跨 GIS region 合并 Patch；City D4 通过 `CityTestRunLayout` 读取同一测试运行包内跨 region 合并后的 D3 和 occupied artifact；提供地貌类型 Top N、候选高程高亮主图、稀疏关系、选择凭证与 stale 校验。 |
| T4 粗地形证据 | `RealmT4CoarseTerrainPreviewService`、`TerrainPreviewProviderSelector` | 每个 owned W cell 中心采样一次，生成 JSON/PNG 和邻格起伏指标；provider provenance 与 territory/W context 一起构成缓存身份。 |
| Patch 候选高程预览 | `PatchCandidateTerrainPreviewService`、`PatchExplorerService` | T2、T4、City D4 的当页候选按边界加上下文自适应取景，生成随高程变色、带水体/轻量山影并直接高亮候选的单张主图；选中后按 16 格在 1024 格城市尺度重绘，证据 identity 进入选择凭证。 |
| RTF 粗览快路径 | `MinecraftTerrainPreviewProviderFactory`、`RtfTerrainPreviewProvider`、`RtfTerrainPreviewReflectionBridge` | 从当前 `RandomState` 探测 RTF `GeneratorContext`，直接调用二维 Heightmap 并用 `Levels.scale` 还原高度；未激活或 API 不兼容时由 selector 回退现有 prior sampler。 |
| T3 扩张 | `RealmPlanningService.expandT3` | `strict` 默认使用 `action_budget` 行动力扩张模型；`quota_frontier` 保留为 smoke / 对照模型。 |
| T3 quota 兼容重平衡 | `RealmPlanningService.rebalanceAreaQuotas` | 对跨国边界建立确定性优先队列，常驻维护 realm count；每次转移只更新当前 cell 与四邻候选，并要求 donor 超 quota、receiver 低于 quota，保证总配额误差单调下降。连通性门禁仍由 `canReleaseCellWithoutDisconnecting` 执行。 |
| T4 兼容验收名册 | `RealmPlanningService.buildT4` | 以 `rule_fixture` 模式生成 `CitySeedRegistry`，不代表正式 AI 选址。 |
| T4 AI 城市规划会话 | `RealmT4PatchPlanningService`、`RealmPlanningService.synchronizeT4RegistryArtifacts` | create 载入无坐标首都意图；`selectCapital` 消费 `realm_t4` 选择凭证建立唯一首都；首都完成后才能 add city，finalize 按 realm 合并并重建 T4 派生产物。 |
| Tag Audit | `RealmPlanningService.runTagAudit` | 对 W tag 抽样局部精扫；即使 W 使用生成器原生快路径，审计仍持有 Minecraft sampler 作为独立真实复核层。run 不在内存时可从 sealed `world_survey_manifest.json`、tile snapshots 和 `world_feature_grid.json` 恢复 W 结果。 |
| 运行状态作用域 | `RealmPlanningServices`、`RealmPlanningService` | 每个 Minecraft server 复用一个 service；service 内部 `runs` 为实例状态，HTTP / Forge 共用且关服释放。 |
| HTTP 调试接口 | `RealmPlanningHttpController` | 除原 W/T path 外，暴露 `/realm/patch_explorer/*` 与 `/realm/t4/patch_planning/*`；T2 和 D4 在进入既有 planner 前解析选择凭证。 |
| MCP 工具 | `realm/tools.ts`、`realm/handlers.ts` | 除原 W/T 工具外，暴露 `patch_explorer_open/show_candidates/select_candidate` 与 `realm_t4_patch_planning_create/add_city/finalize`。 |
| Forge 命令 | `GisPlatformEvents` | 玩家 / 开发者可用 `/geomantia realm acceptance [planningRadiusBlocks] [cellStepBlocks]` 跑真实世界验收。 |
| 冒险者地图物品与粗略地图 | `AdventurerMapItem`、`AdventurerMapStarterGrant`、`GeomantiaItems`、`AdventurerMapScreen`、`AdventurerMapStatusReader` | 每名玩家在当前存档首次登录时获得一张 `geomantia:adventurer_map`，持久化领取标记并跨死亡继承；物品打开地图，不注册热键。从 W feature grid 与国境产物生成最多 `96×96` 的缓存底图，5 秒低频检查 artifact 更新，玩家位置每帧独立覆盖。 |
| Forge GameTest | `RealmPlanningGameTests.realmPlanningPriorAcceptance` | 在真实 `ServerLevel` 上使用 `MinecraftPriorAtlasSampler` 跑 W / T 验收。 |

## 主调用链

```text
MCP realm_run_acceptance
  -> POST /realm/acceptance/run
  -> RealmPlanningHttpController.runWorldSurvey
  -> WorldSurveyRunner.run
  -> tile cache + world_survey_progress.json + world_survey_manifest.json
  -> RealmPlanningService.runAcceptance
  -> runW -> prepareT1 -> selectT2 -> expandT3 -> buildT4
  -> acceptance_report.json + 预览图 + 各阶段 JSON
```

已有 sealed W run 可单独复核 tag：

```text
MCP realm_tag_audit
  -> POST /realm/tag_audit
  -> RealmPlanningService.runTagAudit
  -> 若内存无 RealmRun，则统一 requireRun -> restorePersistedRun
  -> WorldSurveyRunner.loadSealedResult 恢复 sealed W，并只读恢复完整 T1/T2/T3/T4 checkpoint
  -> tag_audit_samples.json + tag_audit_report.json
```

Forge 命令和 GameTest 复用同一条服务链，只是触发入口不同。

真实验收辅助命令：

```text
MCP realm_debug_command
  -> POST /realm/debug/command
  -> RealmPlanningHttpController.handleDebugCommand
  -> MinecraftServer.getCommands().performPrefixedCommand
```

`realm_debug_command` 只作为调试辅助，不进入 W/T 或 City 主链业务状态；执行前必须传 `confirmCommandExecution=true`。

Patch 探索交接链：

```text
patch_explorer_open
  -> PatchExplorerService.open
  -> T2/T4: range + provider identity -> shared patch_explorer_refinements/t_scale_<sha256>.json
  -> lightweight scope_snapshot.json + patch_explorer_session.json
patch_explorer_show_candidates
  -> shared refinement reference / compact snapshot + streaming source hash
  -> candidate page + sparse relations
  -> all scopes: displayed candidates x 32-block aligned contour/hillshade/patch views
patch_explorer_select_candidate
  -> all scopes: selected candidate x 16-block aligned city-scale views
  -> patch_selection.v0.1 + selected views + terrain evidence identity
  -> T2 selectT2 / T4 planning session / City D4 existing planners
```

`realm_t4` 额外在 open 阶段冻结国境粗览；三个 scope 的 show/select 都生成候选高程高亮预览：

```text
POST /realm/patch_explorer/open (scopeType=realm_t4)
  -> server thread 解析 ServerLevel、RandomState 与 provider selection
  -> HTTP worker 扫描单国 owned cell
  -> RTF Heightmap fast path 或 MinecraftPriorAtlasSampler fallback
  -> realm_t4_terrain_preview/*.json + *.png
  -> PatchExplorerService.open 冻结 typed coarse terrain
  -> candidate/type/selection coarseTerrainEvidence
  -> show candidates 时按候选边界自适应生成单张高程高亮主图
  -> select candidate 时为选中候选生成 16 格、1024 格城市尺度确认图
  -> D3 city_d3_site_review
```

provider 初始化不可用时可整体回退；开始采样后的点级错误直接失败，不能生成混合来源证据。候选比较与选中确认必须保持同一 provider provenance；T4 还必须与国境粗览保持一致，否则要求重开会话。RTF 快路径不创建 chunk，D3 仍保留既有高精度 `getBaseHeight` / 地貌审查职责。

W 的 `world_patch_map.json` 可能很大；`open` 只解析一次，用 W cell union 形成 T 搜索 mask，再由 `TerrainScalePatchService` 写入内存中的 T 尺度 Patch 结果并冻结紧凑 scope 快照。后续 show/select 不得重复把整份 W JSON 读入内存，来源一致性改用 streaming hash 校验。T Patch 可跨多个来源 W Patch 连通，候选边界、面积和类型只认 T 重算结果。

## 当前边界

- 当前只实现 W / T 最小闭环，不进入 C 阶段城市内部边界、道路、功能区、结构池或 jigsaw 物化。
- T1 / T2 不兼容旧“AI 选簇 / 选方向 / 填低层参数”接口。
- T1 的 `RealmCandidateMapPackage` 是共享大陆 scope 参考，不承载文明兴趣差异；正式 T2 语义选址必须由 `PatchExplorerService` 在 T 尺度重算地貌 Patch 并生成选择凭证。直接 grid 只保留为兼容 / 调试入口。
- `RealmPlanningService` 的 run map 是实例状态；`RealmPlanningServices` 只在 platform 层按当前 `MinecraftServer` 复用实例并在关服释放，不使用跨世界全局 run 状态。新实例的 `status` 不主动扫盘，但 T / Tag Audit 按 `runId` 首次访问时由 `requireRun -> restorePersistedRun` 从 sealed W 和完整阶段 checkpoint 懒恢复，且不重写上游 artifact。当前 strict 默认 action budget，按预算、地形成本、竞争压力和 wild / contested / blocked / unreachable 状态生成国度范围。
- `CitySeedRegistry` 只生成城市种子名册，不创建城市实例。
- `RealmT4CoarseTerrainEvidence` 只用于 T4 国境粗览；`PatchCandidateTerrainPreview` 用于三个 scope 的候选观察。不得让 RTF provider 类型泄漏到通用 Patch Explorer 契约，也不得绕过 D3 最终审查。

## Review 快速入口

如果本轮改动涉及以下内容，必须读取 `review/国度规划主链Review清单.md`：

- `WorldSurveyRunner` 分片扫描、缓存和 sealed 语义。
- `RealmPlanningService` 的 `runW`、`prepareT1`、`selectT2`、`expandT3`、`buildT4` 主流程。
- `RealmRun` 内存状态、阶段产物和 artifact 输出。
- T2 坐标校验、snap、accepted/rejected 语义。
- T3 frontier、repair、rebalance 或 score hard block。
- T4 `CitySeedRegistry`、城市候选包和 spacing 约束。
- HTTP/MCP/Forge/GameTest 入口字段。
- preview、manifest、score、acceptance report 输出。

快速检查点：

| 检查点 | 重点 |
| --- | --- |
| W 产物 | `cellStepBlocks`、`gridOriginBlock`、`surveyId`、patch / continent id 是否可追溯。 |
| W 完整性 | `WorldSurveyContext.sealed` 是否为 true；`world_survey_manifest.json` 中 `failedTileCount` 是否为 0；缓存恢复统计是否可解释。 |
| T1 图包 | `gridLegend.originBlock`、`gridLegend.cellStepBlocks`、候选图路径、允许 patch 是否齐全。 |
| T2 校验 | 非法坐标是否结构化 rejected；有限 snap 是否不跨大陆、海域或禁用 patch。 |
| T3 扩张 | 不同 run 不共享可变状态；strict 默认 action budget，quota 模型只作为对照验证。 |
| 服务生命周期 | 两个 `RealmPlanningService` 实例不共享可变内存 run；新实例 `status` 初始为空，但按明确 `runId` 可从同一 debugRoot 的 sealed checkpoint 懒恢复。同一 `MinecraftServer` 的 HTTP / Forge 入口必须复用实例，并在关服后释放。 |
| T4 名册 | 首都是否必定存在；城市种子 ID 是否稳定唯一；是否越界生成城市实例。 |
| 接口入口 | HTTP/MCP/Forge 命令是否只做参数解析和调用服务，不复制业务逻辑。 |
| 验收证据 | `./gradlew.bat test`、`./gradlew.bat runGameTestServer`、`npm run build` 是否覆盖本次改动。 |
