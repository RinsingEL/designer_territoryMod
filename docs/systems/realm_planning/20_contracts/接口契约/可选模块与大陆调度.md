# 可选模块与大陆调度契约

需求依据：[模块拆分](../../10_product/案子/主模组与可选模块拆分-v0.1/README.md)、[冒险地图与大陆解锁](../../10_product/案子/冒险地图与大陆解锁-v0.1/README.md)。

## 模块及生命周期

- 主包 `geomantia`：公共规划服务、HTTP/MCP、区域进入及区块生成保护；拥有独立 Node 运行资源，不引用可选附属类。
- 可选 `geomantia_harness`：模型配置、凭证、模型客户端与执行循环。依赖主包，使用 `com.rinsing.geomantia.harness` 包前缀。
- 可选 `geomantia_map`：物品、配方、网络与界面。依赖主包，使用 `com.rinsing.geomantia.map` 包前缀；物品 ID 保持 `geomantia:adventurer_map`。
- `PlanningHost` 随世界服务启动、关闭 `PlanningSessionService`，并发布 `Started` / `Stopping` 生命周期事件；Harness 只借用该实例，不拥有其关闭权。任务准备、工具作用域、完成判断和占用规则由主包提供。
- 附属不得重复携带主包的 MixinConfigs；Java 包名不得跨三个 Mod 重叠。

## MCP 启动设置

对外 URL 为 `http://127.0.0.1:<port>/mcp`。`mcp_server.json` 的 `port` 为高级角色端口（默认 5001），`flashPort` 为 Flash 角色端口（默认 5002），二者与内部 HTTP（默认 5000）不得冲突；设置页分别输入、复制 URL。旧单端口配置自动兼容第二端口默认值。附属规划任务沿用 Java 扩展接口，由 Flash 角色领取，无每附属单独端口。

MCP 设置中 `embeddedAdvanced` / `embeddedFlash` 分别控制哪个角色由 Mod-Harness 接管，可同时开启，也可全部关闭交给外部端。仅切换接管不重启 MCP，不中断当前任务；后续轮次读取新设置。两类内置消费者使用不同租约身份，共享同一世界锁，逐项执行，不能同时写入。`planning_next` 对已经分配给内置消费者的空闲任务等待内置接管；旧任务持有者可以完成当前项再交接。每侧的 API 配置页自动规划开关与该接管标志保持一致。

Flash 沿用 `provider.json` / `provider-secret.txt`，高级侧使用独立的 `provider-advanced.json` / `provider-advanced-secret.txt`，环境 Key 可用 `GEOMANTIA_ADVANCED_API_KEY`。高级侧不继承 Flash 的端点、模型或 Key，首次须显式配置；Harness 会话分别保存于 `.harness` 和 `.harness-advanced`。旧配置没有接管字段时，仅把旧 `provider.enabled` 迁移成 Flash 接管，高级默认关闭。没有装 Harness 时这两项设置不可操作。单机主菜单也可配置对应 API；联网配置包携带角色并过滤过期的其他角色响应，协议版本为 6。

两个监听器共享同一世界 `PlanningSessionService` 和占用租约。T1/T2/EXTENSION 默认 Flash，T4/CITY 默认高级；确定性程序步骤不调用模型。旧 `planning_resume` 中错误角色返回 `waiting_for_role` 且不占锁；同角色第二 Agent 返回 `PLANNING_BUSY`。角色来自监听器，不接受模型工具参数指定角色。双角色监听只暴露规划会话工具，业务工具通过当前任务 `planning_action` 调用。

高级外部 Harness 与 Mod-Harness Flash 持续接力时，使用 `planning_next(timeoutSeconds=20)` 作为总调度入口：在有权限的阶段推进程序，等待另一角色/执行端，准备好后直接返回当前任务和图片。`dispatch` 为 `task`、`waiting_for_role`、`waiting_for_executor`、`waiting_for_program`、`needs_input`、`blocked`、`complete` 或 `paused`；以 `nextCall` 和 `continuePlanning` 指示继续。任务完成的 `taskFinished` 不代表全流程结束，必须再次调用 `planning_next`。换 session 从存档恢复；旧执行端占用未释放或过期前，新端只等待，不抢锁。`planning_release` 同时取消本连接正在等待的调度请求。

大厅和调度结果包含 `embeddedFlashStatus` / `embeddedFlashMessage` 以及高级侧 `embeddedAdvancedStatus` / `embeddedAdvancedMessage`。内置 Flash 关闭、缺 Key 或失败停机且没有另一执行端处理时，返回 `needs_input` 提示具体条件；已有 `design_saved` 仍要求明确施工授权，不因持续调度自动施工。选择由外部执行的高级 session 必须保持调用循环；Mod 不提供唤醒已结束聊天的通用协议，不能把端口等待描述成后台自动启动高级 Agent。

`planning_escalate(taskId, reason)` 仅允许当前 Flash 执行者在无运行中请求时交接；保存语义任务身份、原因和最近提交参数/错误，释放旧租约。高级模型的任务 state 含 handoff；旧 token 不再可写。升级绑定原语义任务，完成后后续任务恢复默认角色。游戏内置 Harness 按高级/Flash 接管开关领取对应角色任务，不领取未启用角色的任务；独立 Harness MCP 客户端见实现仓 `geomantia_harness/README.md`。

客户端缺少 `config/geomantia/mcp_server.json` 时等待用户设置；未装 Harness 时首次到主菜单打开设置面板，保存后启动。装了 Harness 时不主动弹出外部 MCP 设置，玩家可从主 Mod 设置页主动配置。已保存配置下次自动应用。独立服务器由管理员配置，缺配置时沿用默认启动。

## 出生国度与地理队列

- 世界服务启动时，主 Mod 独立执行首次 W 准备，不依赖 HTTP、Harness、地图附属或 Provider 凭证。采样与 W 导出在后台 worker 完成；服务端进度条显示当前阶段和实际阶段百分比。准备期间首次进入玩家停留在安全等待点；HTTP 规划写操作返回 `WORLD_PREPARING`，避免和首次扫描竞争。
- 当前存档 `geomantia_world_entry.json`（schema `geomantia_world_entry.v1`）冻结 worldSeed/runId/planningRadiusBlocks；status 从 preparing 到 ready，AI 发现准备状态时等待程序完成，不另启 W。已有当前世界 sealed W 优先复用；中断沿同 runId 和缓存恢复；已完成存档重进不调用采样。后续配置默认范围变化不自动替换该存档的 W。地图、区域保护和规划发现使用该入口。
- 特殊国度 ID `geomantia_starter`，名称“新手村国度”。出生初始化先保留安全等待点；W 完成后以该点所在的完整大陆及近海作为初始国度，不计入普通国度数量，不进入普通 T1/T4 城市名册。
- `geomantia_starter_realm.json` / W 的 `starter_realm.json` 使用 `geomantia_starter_realm.v2`，保存 `shape=continent_and_near_sea`、cellStepBlocks、cells（gridX/gridZ）、geographicRegionId、sourceRunId/sourceConfigHash、centerBlockX/Z、spawnX/Y/Z、realmId/name/unlocked/generateCities。`selection=continent_v2` 表示安全落点已确认；候选中断使用 `continent_candidate` 恢复。准备期的旧圆形只用于保障安全等待点加载，不作为正式大陆边界展示。
- 正式开放、地图揭示和 T 阶段新选址排除共用持久化大陆 mask，加载保护外扩 256 格；保留已有待建城市保护范围。初始大陆开放不自动开放独立远海或其他大陆。
- 每位玩家首次准备完成后传送到已保存的安全点，随后发布 `StarterRealmReadyEvent`。可选地图附属监听后打开轮廓地图；主包不引用附属。玩家持久化 `geomantiaStarterContinentArrived`，重进及死亡复制后不重复首次传送或自动弹图。
- 存在有效 W 格网时，队列采用 `continent_grouped`；地理区域按距原点最近的格心距离排序，区内按城市距原点排序，再按城市 ID 稳定打破平局。国度跨大陆时按城市位置归队。
- 当前区域的相关国度先完成 T4 名册；当前区域城市尚未完成时，不优先为下一片大陆启动设计。附属城市任务继续在该城规划后执行。
- 地理区域开放仍检查相关国度名册封存、区域内城市方案激活、附属预留就绪与待建保护范围。不存在“提交蓝图即可开放”的新捷径。

## 玩家视距与区块加载需求

主包在原版 `DistanceManager.PlayerTicketTracker.onLevelChange` 进入票据限流队列之前裁剪玩家视距需求。保留原版汇总的视距意图，按实际已放行的状态生成添加/撤销转换；使用原版队列取得和释放限流槽，不在 `addTicket` 后直接丢弃票据。权限快照更新时重新核对仍在视距内的意图，支持玩家不移动时解锁恢复与权限撤销；离开视距的意图移除，多玩家共享需求仍由原版汇总。

玩家票据中心及其周边 14 区块必须全部符合 `permitsChunk`，否则不申请玩家票据。14 来自 1.20.1 的最大生成状态距离 12 加 ENTITY_TICKING 到 FULL 的 2 区块差。结果随权限快照缓存，单维度票据缓存超过 16384 项、区块权限缓存超过 65536 项时清空重建。区块阶段调度入口继续拒绝非法读盘与生成请求；其他来源的票据仍走该兜底保护。

普通开放区域与待建城市的通行安全缓冲由“服务端视距加 12 区块”改为固定 256 格（16 区块），不再因提高视距而扩大。初始大陆生成 halo 缩为 256 格，保留 14 区块的票据生成依赖；沿直线边界，完整玩家票据边缘通常比通行线外伸约 32 格。硬禁止加载线仍外伸 256 格，不代表缓冲区没有生成。允许生成邻区不代表允许玩家通行；世界内雾幕依然绘制实际通行线。尚未承诺支持改变原版区块依赖图的第三方加载模组。

## 地图网络

### 世界内禁行预警

主包独立维护 `geomantia:access_boundary` 通道（协议 1，仅服务端向客户端发送）。服务端基于当前 `PlanningAreaAccessPolicy.evaluate` 的实际通行结果，在玩家附近 96 格内按 8 格采样、二分交点构建局部轮廓；包含城市保护与生成缓冲，轮廓为近似显示，不取代服务端精确拦截。未改变通行距离或开放规则，不读取禁区地形，不请求区块。

最多每秒检查一次，按玩家错开；玩家进入另一 16 格网格或权限快照变化才重算，静止时每 5 秒续发缓存。消息包含维度与最多 1152 条 X/Z 线段。客户端仅在同维度且收到数据后 10 秒内显示，断线清空。80 格内渐显深蓝黑色流动雾幕（中部最大 alpha 约 0.95，约 38 格处约 0.44–0.55），并提示到最近轮廓的近似距离；使用世界空间透明面片，受地形深度遮挡，无新增实体、光影包或全屏黑暗滤镜。边界预警不依赖地图附属。

地图网络协议为 11，请求与响应携带同一 requestId，客户端忽略已关闭界面或其他请求的过期响应；主包与地图附属须配套更新。打开地图消息支持初始视图中心及缩放；首次弹图适配完整出生大陆及近海的边界，留出视图边距。手动物品打开在收到范围后适配完整 W 总览，首次出生弹图继续使用初始大陆视图；提供总览按钮。最小缩放 1/128，最大视口半径 524288 格，发送栅格仍限制为 96×96。快照携带初始中心 X/Z；CoarseMap 保留与 realmIds 同序的 realmNames；请求含 debug 布尔值，仅服务器权限等级至少 2 的玩家可实际读取 Debug 快照。尚无 W 数据或初始大陆尚未准备好时显示准备进度，不绘制圆形占位大陆。普通玩家保留 W 状态、阶段及百分比；不因此获得未开放地域数据。

普通快照在服务端移除未揭示格子的地形及国度编码，重新构造可见国度调色表，过滤隐藏城市并清除 T/City 调试阶段、当前任务和未公开计数。客户端仅将可见数据画成陆地/海面、边界和名称，不渲染具体地形。Debug 查看不改变实际开放权限。


### 地图缓存与读取状态

服务端按当前存档绝对路径与采样/领土/上下文文件指纹复用紧凑采样数据，视口变化只重建显示栅格；区域开放快照独立按权限来源、世界入口文件与开放配置失效，不随缩放重建。底图仍受 96×96 上限约束，不为地图读取或生成新区块。

客户端在同一连接、同一 ClientLevel 内仅复用最近 5 秒的普通快照，重开后立即请求更新；断开连接清空，Debug 快照不进入普通缓存。地图栅格及调色表未变化时复用纹理。切换回普通模式立即过滤隐藏数据，并丢弃视图模式不匹配的待收响应。

首次响应到达前显示地图读取状态，不伪造世界扫描 0%。扫描中显示实际阶段百分比；读取失败与准备失败分别提示。图例说明黑色代表未开放或暂无数据、黄色箭头代表玩家、城市标记可悬停查看状态；Debug 图层明确说明查看权限不改变通行权限。


### 地图范围与城市生成就绪修正

快照新增 SurveyBounds（minX/minZ/maxX/maxZ，最大值不包含），由当前 W context.scanBounds 的包含式最大值加一得到。普通快照保留矩形扫描范围，不透露隐藏国度、地形或城市。客户端按范围中心及最大边长适配总览；最小缩放按半边长的 1.1 倍加 256 格边距确定，拖动中心限制在扫描范围内。扫描外为灰绿底，扫描内未开放或暂无数据仍为黑色，并显示扫描范围格数。底图与节点的权限过滤不变。

大陆生成就绪检查对户外 PRESERVE 与 GENERATE 区别处理：当前 run 的非空建筑激活注册仍为共同前提；明确 PRESERVE 的已保存 CityBlueprint 不要求额外 LandUse 激活，其他模式仍沿用有效 LandUse 准备检查。缺失 Blueprint 不推断为 PRESERVE。现有队列状态、国度名册封存、未准备城市保护和附属区域就绪继续生效。外海在 W sealed 后默认开放，不再依赖邻近大陆或名册，但保留海域内未完成城市及附属预留保护。Blueprint 文件变化进入权限来源指纹，使地图、移动与区块许可一并重新评估。
