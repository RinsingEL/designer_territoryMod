# 冒险内容分布附属配置与接口 v1

需求依据：[冒险内容分布附属模组](../../10_product/案子/冒险内容分布附属模组-v0.1/README.md)。独立包 `geomantia_adventure` 依赖主模组；不依赖地图或 Harness。

## 配置入口

实例目录 `config/geomantia_adventure/` 下五份 JSON，每份 `version: 1`。首次启动补齐缺失文件，完整校验后一起启用；不接受未知字段、缺失字段、非整数计数、无效资源 ID、未定义的池引用。实体、结构注册 ID 在服务端启动时核验，错误中止附属初始化。配置修改后重启生效。

默认配置位于实现仓 `src/adventure/resources/adventure_defaults/`，仅引用原版怪物与结构；三档相同内容仅供作者起步，不冒充已完成难度平衡。

### distribution.json

- `tiers`：从第一档起连续排列。每项包含 `land` 和 `nearSea`，二者各有 `mobs`、`structures` 字符串数组，分别引用对应池 ID。
- `ocean`：同样包含 `mobs`、`structures`，与大陆档位独立。
- 空数组表示不追加对应内容。多档可复用同池；超过 tiers 长度后封顶。档位不修改怪物属性。

### mob_pools.json

`pools` 数组，每池包含：

| 字段 | 含义 |
| --- | --- |
| id | 唯一池名称 |
| chance | 每次符合规则的生成初始化被接受的概率，0～1 |
| cooldownTicks | 自然刷怪在同维度、同池、64 格网格内的冷却；0 为关闭 |
| nearbyLimit / nearbyRadius | 自然刷怪附近同实体类型数量上限与查询半径；半径最多 128 格 |
| entries | entity、weight、minCount、maxCount、conditions；组大小 1～64 |

`conditions` 必填 `biomes`（群系注册 ID 集合，空为不追加限制）、`minY`、`maxY`。保留怪物原有生成条件。原版总体类别上限仍有效，权重只表达相对选择比例。

自然刷新与区块生成产生的生物均参与内容准入和 chance；冷却、附近实体计数只用于服务端自然刷新，不在生成线程访问实体列表。刷怪笼、命令、召唤、繁殖不接管。居民区规则额外阻止自然生成的 MONSTER 类敌人，不要求其出现在池中；不会禁止已有怪物移动。

### structure_pools.json

`pools` 数组：id、spacingChunks、separationChunks、chance、entries。spacingChunks 为候选格尺寸（1～4096 区块），separationChunks 小于 spacingChunks，chance 为该格是否安排候选的概率。entries 包含 structure、weight、conditions（与怪物条件同形）。

世界种子、池 ID、格坐标决定稳定候选位置和抽样；跨池间距取双方 separationChunks 的较小值，使每次只检查各池的邻近候选格；不同池按固定优先级消除过近候选，不依赖区块加载次序来决定最小间距。地形、群系、保护区和占地冲突仍可使候选失败，因此配置密度不保证成功结构数。

标准结构按原有 biome/terrain 规则构造完整 StructureStart，再做城市保护、居民区和共享预留检查。超出标准相邻八区块引用范围的结构不追加。不会晚贴到已有区块，不支持第三方绕开标准结构入口的自定义粘贴器。

### settlement_rules.json

`rules` 按 city、suburb、village、road 定义。每项包含 bufferBlocks（0～4096）、blockMobs、blockStructures、allowedMobs、allowedStructures。允许名单只放宽附属外围限制，不能取消主模组实际施工范围的结构保护。

`zones` 可显式登记 dimension、kind、minX、minZ、maxX、maxZ，边界包含端点。城市名册提供 city/village 保护范围；郊区、道路与未来程序村庄使用 zones 或共享预留 API 提供实际范围。国度政治边界不自动等于居民区。

### generation_control.json

`mobs`、`structures` 均为注册 ID 到布尔值的对象；池内每个 ID 必须显式登记。false 表示在受管地理范围内替代其原有自然生成；true 表示保留原有生成，同时允许作者池追加。未登记内容不参与内容池替换。

结构保护仍优先于保留原生成；被登记的探索结构也受居民区规则限制。特殊生成器不因填写名单而自动获得兼容。

## 地理快照与持久化

主模组 `WorldRegionApi.load(server)` 在服务端准备只读地理快照，不在刷怪或结构生成中读文件。使用已封存 W 和初始大陆状态，陆地格平均中心附近的本大陆陆地格作为代表中心，避免环状大陆和内岛中心重合。附属计算 Voronoi 共边邻居及最少跨越层数，初始档一、近海同档、外海独立。

档位保存到当前世界 `geomantia_adventure/tiers.json`，核验地理身份；同身份与档数恢复时直接复用。变更地理身份拒绝静默复用。普通坐标查询通过地理格索引完成，不加载区块。

## 双向占地预留

主模组公开 `SettlementReservationApi`：

- `Reservation(id, dimension, kind, RegionBounds)`：kind 为 city/suburb/village/road/adventure，bounds 必须包含调用方所需安全范围。
- `reserve(server, reservation)`：同步原子检查并登记；相同 ID 与内容幂等，冲突返回 false。村庄生成器必须先获准登记，再落地；地牢同样遵循此入口。
- `intersects` / `snapshot`：只读查询；`settlements` 返回排除冒险地点的居民范围视图。
- `releaseFailed`：仅供未落地的失败尝试释放预留，不能借此移除既有地点。

存档数据为 `geomantia_spatial_reservations`。服务器启动时加载，预留检查可在生成线程调用，不从该线程写文件。接口不会替调用方生成村庄，也不自动发现任意第三方村庄。

## 生成与委托接口

主模组 `StructureDistributionEvent.Attempt` 在原生结构构造之前提供低成本准入拦截；`StructureDistributionEvent.Candidate` 在原生完整外部结构起点登记前触发，可取消；`Prepare` 在原有城市结构起点安排后触发。上述事件在生成线程同步执行，监听器不得加载区块或进行磁盘 IO。Candidate 的 afterDecision 回调在全部监听器投票及起点登记之后执行；最终否决时撤回本次新预留，避免留下虚假委托地点。

附属 `AdventureMod.sites(server)` 返回地点只读快照，包含稳定身份、维度、结构 ID、区域、档位、位置、范围、complete。存档名 `geomantia_adventure_sites`。complete=false 表示起点登记；相关区块全部完成并被观测后为 true。保存和恢复保留已完成区块集合，绝不为委托主动加载未生成区块。完成观测按区块索引匹配地点，定期补查每轮最多 256 个已加载区块，避免地点数量增加后产生全量平方扫描。该状态不代表玩家已清剿，也未实现 NPC 委托发布。

## 验证入口

`adventureTest`：分档、负坐标、共点非邻居、配置引用与类型、候选间距、存档恢复、地点完整性、居民与地牢并发争用。

`verifyAdventurePackaging`：主包无附属类/默认配置、附属独立资源、无重复 Mixin。

`runGameTestServer -PgeomantiaDevAdventure=true -PgeomantiaGameTestNamespaces=geomantia_adventure -PgeomantiaGameTestDir=build/adventure-gametest`：隔离 Forge 事件验收；实际执行结果见任务记录。
