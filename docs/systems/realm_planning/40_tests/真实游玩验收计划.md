# 国度规划系统真实游玩验收计划

## 定位

本文定义国度规划系统 v1.1 的真实游玩验收闭环。它补足单元测试无法覆盖的部分：agent / 人类能否在真实 MC 世界中通过 MCP 控制 W / T 主链，看到候选图、选择坐标、扩张国度并生成城市种子名册。

当前状态：实现仓库已提供国度规划 MCP / HTTP / Forge 命令入口；本文作为真实游玩验收目标和执行口径。

## 验收目标

| 目标 | 标准 |
| --- | --- |
| MCP 可控 | agent 可以通过 MCP 从 W 跑到 T4。 |
| 可视可审 | 每个关键阶段都有预览图或 manifest 支撑人工判断。 |
| 坐标可选 | AI / 人类能根据带 grid 坐标候选图提交 T2 坐标。 |
| 结果可玩 | T3 输出国度范围，T4 输出城市种子名册，但不提前生成城市实例。 |
| 质量可阻断 | W / T3 / T4 的坏结果必须进入 `score_manifest.json` 并阻断 strict 验收。 |
| 可复现 | 固定 seed、固定中心、固定 step、固定国度配置下结果稳定。 |
| 进度可见 | W 长扫描期间，目标玩家聊天框持续看到当前阶段、百分比和 ETA。 |

## 前置条件

| 条件 | 要求 |
| --- | --- |
| MC 调试服务 | `/realm/status` 可访问。 |
| MCP 工具 | `realm_status`、`realm_w_refresh`、`realm_t1_prepare`、`realm_t2_select_coordinate`、`realm_t3_expand`、`realm_t4_build_registry` 可列出。 |
| GIS 能力 | GIS v1.1 step 参数化可用。 |
| 固定测试世界 | 至少一个固定 seed / 中心点可重复启动。 |
| debug 目录 | W / T 产物写入统一 run 目录。 |

当前实现补充入口：

| 入口 | 用途 |
| --- | --- |
| `realm_run_acceptance` | MCP 端到端 W -> T4 主验收入口。 |
| `POST /realm/acceptance/run` | HTTP 端到端验收入口。 |
| `/geomantia realm acceptance [planningRadiusBlocks] [cellStepBlocks]` | 已进服或开发客户端中的手动命令验收入口。 |
| `./gradlew.bat runGameTestServer` | 自动启动 Forge GameTest，用真实 `ServerLevel` 跑 prior acceptance。 |

## 推荐验收用例

| 用例 | 目的 | 建议配置 |
| --- | --- | --- |
| `realm_v1_1_smoke` | 跑通 W -> T4 最小闭环。 | `planningRadiusBlocks=1024..8192`、2 到 3 个国度、step 128。 |
| `realm_full_world_survey` | 验证配置范围内完整 W 扫描、缓存和 sealed 后规划。 | `planningRadiusBlocks` 按当前世界设定配置，step 128，`resumePolicy=use_cache`。 |
| `realm_negative_coords` | 检查负坐标 grid / block 换算。 | 中心点在负坐标区域。 |
| `realm_coastal_choice` | 检查亲水 / 沿海国度选点和港口城市名册。 | 至少 1 个海岸 patch。 |
| `realm_ratio_balance` | 检查 `scalePlan` 面积比例归一化。 | 同一大陆 3 到 4 个国度。 |

## 标准验收流程

| 步骤 | MCP 工具 | 人工 / agent 检查 |
| --- | --- | --- |
| 1 | `realm_status` | 服务在线，debugRoot 可写，GIS ready。 |
| 2 | `realm_w_refresh` | 产出 `WorldSurveyContext`、`WorldPatchMap`、粗 patch 图、grid overlay。 |
| 3 | `realm_t1_prepare` | 每个国度有 `RealmProfile` 和候选图包；候选图能读 grid 坐标。 |
| 4 | `realm_t2_select_coordinate` | 按候选图提交坐标；合法点 accepted，非法点 rejected。 |
| 5 | `realm_t3_expand` | 输出国度范围图；面积比例和邻接摘要合理。 |
| 6 | `realm_t4_build_registry` | 输出 `CitySeedRegistry`；首都存在，非首都城市有条件。 |
| 7 | 人工入服查看 | 国度范围和城市种子锚点与预览图大体一致。 |

## 通过标准

| 类别 | 标准 |
| --- | --- |
| 结构 | 所有 JSON 产物符合 `W-T阶段数据契约.md`。 |
| W 完整性 | `WorldSurveyContext.sealed = true`，`world_survey_manifest.json.stats.failedTileCount = 0`，并记录 tile 数、缓存命中、耗时和数据量。 |
| W 微采样 | 分片 W survey strict 验收必须 `microSamplingImplemented=true`，`microSampleCount>0`，并输出 `world_feature_grid.json`。 |
| 坐标 | grid 到 block 的转换可追溯，负坐标 fixture 通过。 |
| T2 | 合法坐标可 accepted；跨大陆、跨海、禁用 patch、冲突坐标会 rejected。 |
| 比例 | `scalePlan.targetAreaRatio` 按目标大陆 / 大区可分配 land cell 归一化。 |
| 面积弹性 | `quota_frontier` 下 `actualAreaRatio` 必须落入 `scalePlan.minAreaRatio/maxAreaRatio`；`action_budget` 下面积为软目标，偏离进入预算与过扩张评分。 |
| T3 | strict 默认 `expansionModel=action_budget`，扩张结果稳定，不串 run / 维度 / 大陆状态。 |
| T3 状态 | `t3_report.json` 必须记录 `owned/wild/contested/blocked/unreachable` 比例、预算使用率、地形成本分布和停止原因。 |
| T4 | `CitySeedRegistry` 中 `citySeedId` 唯一，首都必定存在，不创建城市实例。 |
| 可视 | 关键预览图存在，人工能看出候选图、国境图和城市种子锚点。 |
| 评分 | v1.2 strict 模式下，`score_manifest.json.passed = true` 且无硬阻断。 |

## v1.2 质量阻断

| 情况 | 阻断口径 |
| --- | --- |
| `cliff` 或 `steep` 明显过量且不满足坡度 / 起伏 / 边缘形态证据。 | W 地貌分类阻断。 |
| 单格 patch 比例过高或主大陆模式下小 continent 过多。 | W patch / continent 阻断。 |
| 任一非海权国最大连通块比例低于 `0.90`。 | T3 连通性阻断。 |
| `detachedAreaRatio > 0.05` 或 `holeAreaRatio > 0.03`。 | T3 拓扑阻断。 |
| `quota_frontier` 下任一国度 `actualAreaRatio` 超出 `scalePlan.minAreaRatio/maxAreaRatio`。 | T3 面积弹性阻断。 |
| `action_budget` 下预算使用、地形身份、荒野或争议区评分明显异常。 | T3 行动力模型阻断或 warning。 |
| 城市种子同格重叠，且未标记为复合城市或卫星节点。 | T4 城市分布阻断。 |
| 人工 review 五问通过不足 3 项。 | 可视 review 阻断。 |

## 当前实现状态

- `microSampleStrideBlocks`、`localSlopeRadiusBlocks` 已进入 MCP 参数、W manifest 和 `score_manifest.json`。
- 分片 W survey 已输出真实 `WorldFeatureGrid`，`WorldPatchMap.cells[]` 内嵌 `heightStats`、`slopeStats`、`waterFrac`、`biomeHist` 和 `microSampleCount`。
- strict T3 默认使用 `action_budget`；`quota_frontier` 保留用于 smoke / 对照。
- Forge GameTest 可使用 `qualityMode=smoke` 覆盖真实 ServerLevel 链路；正式真实游玩验收必须使用 `qualityMode=strict`。
- 2026-06-12 已完成 Dregora 标准档真实验收：`realm_v13_v14_real_16384_20260612`，`planningRadiusBlocks=16384`、`cellStepBlocks=128`、`microSampleStrideBlocks=32`、`expansionModel=action_budget`，最终 `passed=true`、`totalScore=82.95`、`hardBlocks=[]`。

## 失败即阻断

| 情况 | 说明 |
| --- | --- |
| MCP 无法列出 W / T 工具 | 不能做真实游玩验收。 |
| W 不输出 grid 坐标 manifest | T2 无法可信选点。 |
| v1.2 strict 模式缺少 `score_manifest.json` | 无法证明结果质量可阻断。 |
| T2 对非法坐标静默 snap 到远处 | 违反新方案。 |
| T3 使用全局静态状态导致串结果 | 违反 legacy 重写要求。 |
| T4 创建城市实例或城市内部规划 | 越过 T 阶段边界。 |

## 验收报告字段

`acceptance_report.json` 至少包含：

| 字段 | 说明 |
| --- | --- |
| `caseId` | 验收用例。 |
| `runId` | 本次 run。 |
| `passed` | 是否通过。 |
| `durationMs` | 总耗时。 |
| `surveyStats` | W 扫描 tile 数、缓存命中、失败数、扫描范围和数据量。 |
| `stageResults` | W / T1 / T2 / T3 / T4 分阶段结果。 |
| `artifacts` | 关键产物路径。 |
| `coordinateChecks` | 坐标转换和 T2 校验摘要。 |
| `ratioChecks` | 面积比例归一化摘要。 |
| `visualChecks` | 预览图存在性和人工待看清单。 |
| `failures[]` | 失败断言。 |

## 开发门槛

进入真实游玩验收前必须完成：

1. 实现 `W-T阶段MCP接口.md` 中的 P0-P3 工具。
2. `./gradlew.bat test` 覆盖契约、坐标、比例、T2 校验、T3 稳定性和 T4 名册。
3. `country_designer_mcp` 的 `npm run build` 通过。
4. 固定验收用例能通过 `realm_run_acceptance` 输出完整 `acceptance_report.json`。

当前 v1.3 / v1.4 实现已满足上述门槛，并完成 `planningRadiusBlocks=16384` 标准档真实游玩验收；后续真实人工入服验收仍可继续对预览图和现场地形做主观合理性确认。
