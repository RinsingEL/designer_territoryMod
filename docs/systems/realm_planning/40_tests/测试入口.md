# 国度规划系统测试入口

## 定位

本文记录国度规划系统 v1.1 的测试与结构校验口径。当前最小实现已落地，本文同时作为实现仓库回归入口。

| 层级 | 目标 | 推荐入口 |

## 最小 fixture

| fixture | 用途 |
| --- | --- |
| `two_continents` | 校验 T2 不允许跨大陆选点，T3 不串大陆。 |
| `coastal_realm` | 校验亲水国度能选择海岸 patch，T4 能生成港口类候选城市。 |
| `negative_coords` | 校验负坐标下 grid / block 换算使用 floor 语义。 |
| `conflicting_seeds` | 校验两个国度种子过近时，后选坐标被拒绝或要求重试。 |
| `area_ratio_normalization` | 校验国度比例以目标大陆可分配 land cell 为分母，不使用 MC 理论世界边界。 |
| `noisy_cliff_map` | v1.2 校验 `cliff` 过量和单格 patch 过多会触发评分阻断。 |
| `fragmented_territory` | v1.2 校验非海权国最大连通块过低会触发 T3 阻断。 |
| `city_overlap` | v1.2 校验同格或半径重叠城市会触发 T4 阻断。 |

| 断言 | 阶段 |
| --- | --- |

| v1.2 中 `microSampleStrideBlocks`、`baseLandform`、`landformTags`、clean continent / patch id 可追溯。 | W |

| W 长任务观察：`world_survey_progress.json` 最终为 `status=completed` / `phase=complete`，tile 与 micro-sampling 计数分别能和 `world_survey_manifest.json` 的统计对齐；运行期间文件和 debug 日志按约 1 秒更新，目标玩家聊天框按 5 秒节流显示阶段、百分比和 ETA。 | W |
| v1.3 固定 stride micro-sampling 必须在 `world_survey_manifest.json` / `world_survey_context.json` / `acceptance_report.json` 中记录 `microSampleBudget`、`microSampleBudgetPerCell` 和 `adaptiveSampling=false`，不得把固定采样伪装成自适应加密。 | W |

| v1.6 水边分类中，扫描边界截断水体应允许 `boundary_truncated` / `open_water_unknown`，不得只因触边就给高置信 `seacoast/coastal`。 | W |
| `RealmCandidateMapPackage` 必须包含候选图路径、grid 图例、允许 patch、`mapRole=continent_scope_reference`、`profileDifferentiated=false` 和 Patch Explorer 主选择流；T1 响应的 `nextActions` 只推荐 `patch_explorer_open`。 | T1 |
| `RealmCoordinateSelection.validation.status = rejected` 时必须有 `errors[]`。 | T2 |

真实产物最低验收：

1. 使用真实 sealed W 打开 `realm_t2` 会话，确认大型 `world_patch_map.json` 只在 open 阶段解析一次；show/select 在默认 JVM 内存下完成，T 候选按 `patchId + landform` 生成，同一群系内的不同 W patch 不得被合并。
2. 每种兴趣类型默认只显示 Top 3；每个候选返回一张非空的高程高亮主图，候选直接高亮在保留周边地形的原图上，不再返回密集多候选总图；关系表不出现首都、国境、已有城市或叙事句。
3. select 后必须按 16 格、1024 格城市尺度返回单张确认图；修改来源 W、T3 territory、D3 package、hard occupied 或预览 evidence 后，旧凭证消费失败。
4. T2 最终仍通过原 `selectT2` 合法性校验；T4 城市仍在 owned territory 且满足连续面积/间距；D4 选择后仍由原 anchor/array 候选器产生精确方案。
5. T4 Patch finalize 后，注册表、`t4_report.citySeedCount`、`score_manifest.subScores.T4.citySeedCount` 和城市预览必须来自同一最终名册；旧 acceptance 必须失效，直到完整重跑。
6. 在真实 RTF 世界打开 `realm_t4` 会话，确认 `terrainPreviewProvider.sourceKind=generator_native`、`sampleCount=ownedCellCount`，预览非空且没有因粗览创建 chunk；随后仍需用 D3 step=16 审查候选误差和最终可建性。
7. 分别展示 T2、T4、D4 候选，确认每个当页候选都有按候选边界自适应取景的高程高亮主图；选中后确认另有 16 格、1024 格直径的城市尺度单图。T4 provider provenance 与粗览一致，且仍声明下一门禁为 D3。
8. 运行半径 `32768`、step `256`、micro stride `64` 的真实 RTF W，确认 `terrainProvider.sourceKind=generator_native`、`failedTileCount=0`、产物 sealed；再进入 T3/T4 并分别验证 T4 开关开启与关闭时的 provider provenance。
9. 同一真实 W 确认 tile 文件数从每 tile 13 个降为每 tile 2 个 snapshot/meta 文件，且最终 W/T 预览图仍存在。

## 验收命令口径

当前已接入：

```text
./gradlew.bat test
./gradlew.bat runGameTestServer
cd country_designer_mcp
npm run build
```


真实游玩辅助命令示例：

```text
realm_debug_command {
  command: "/tp Rinsing 775 200 -6552",
  confirmCommandExecution: true,
  sourceMode: "player",
  playerName: "Rinsing"
}
```
