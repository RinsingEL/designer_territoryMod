# 验收流程

## 定位

验收执行是只读运行角色：复用已有有效产物，通过既有入口运行目标阶段，展示正式结果并核对验收口径。验收不是第二轮开发，也不是自动故障修复。

## 允许与禁止

| 允许 | 禁止 |
| --- | --- |
| 启动或连接既有运行环境 | 修改代码、契约、配置、测试或工作流 |
| 调用正式命令、MCP、HTTP 或测试入口 | 因结果不理想而临时补算法 |
| 读取日志、报告、截图和结构化产物 | 有可复用上游时重跑完整主链 |
| 用现有工具生成正式 preview | 将诊断或修复混入验收 |
| 修正一次明显的调用参数或命令拼写 | 为证明通过而切换 fallback |

## 执行前必须锁定

```text
验收目标：
最高有效上游阶段及产物：
本次只执行的阶段：
唯一命令与参数：
停止点：
正式产物路径：
时间预算：
```

系统 `40_tests/测试入口.md` 有专门预算时以系统规则为准。对于已有有效上游产物的交互式复验，默认目标 3 分钟、硬停止 5 分钟。

## 执行规则

1. 先确认上游产物真实存在且版本可用，不从头重建作为保险。
2. 执行一次目标命令，并在约定停止点停下。
3. 明显的命令拼写或调用参数错误最多修正一次，仍复用同一上游产物。
4. 先展示该阶段要求的正式结构化产物和 preview，再询问用户是否继续下游。
5. 达到时间上限、首次有效失败或缺少必要预览时立即停止报告。

## 失败后的处理

验收失败只做分类，不进入修复：

| 分类 | 处理 |
| --- | --- |
| 环境未就绪 | 报告缺失条件和已完成检查 |
| 调用参数错误 | 在一次修正额度内重试，否则停止 |
| 上游产物无效 | 报告无效证据，不擅自重建 |
| 实现或契约异常 | 给出失败位置，等待切换到故障诊断 |
| 结果可运行但观感不符 | 展示对比，交由用户判断方案方向 |

只有用户明确要求诊断或修复后，才能开始新的角色流程。

## 阶段复用示例

已有冻结 D3、目标查看 D4 时：

```text
D3 frozen artifact
-> D4 attempt
-> D4 / LandUse 正式 preview
-> 停止等待用户判断
```

D4 参数需要调整时创建同一 D3 下的新 attempt，不重跑 W、T、D1-D3。未产出 D4 正式 preview 时不得推进 D5-D7，也不得以传送进游戏替代 D4 验收。

## 验收输出

- 实际复用的上游和执行命令。
- 用时、重试次数和停止点。
- 正式产物与 preview 路径。
- 通过项、失败项和需要用户判断的事项。
- 如失败，建议进入的下一角色，但不自行切换。
