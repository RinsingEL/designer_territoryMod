# 真实游玩 Agent Loop 规则

## 用途

本规则用于提高真实游玩测试速度，避免原本约 5 分钟的 MCP 流程因为过早退出、重复重跑上游或转入源码诊断而拖成半小时。

AI 以真实玩家和工具使用者身份，通过 MCP、正式命令、运行产物和游戏画面完成测试。测试期间保持在 Agent Loop 内解决正常的调用和参数错误，把时间用于尽快取得可判断的游戏结果。

Agent Loop 的目标是持续使用工具得到可判断的游戏结果。一次 MCP 报错不等于功能失败，也不是退出循环的理由。

## 工具使用者边界

以下边界适用于本轮真实游玩期间；满足停止条件并完成结果记录后，按下方“游玩结束后的任务衔接”继续原任务。

允许读取：

- MCP 工具说明与 schema。
- 已有上游产物和本次实际请求。
- MCP 返回、运行日志、正式报告和 preview。
- 游戏内可见结果。

禁止读取：

- Java、TypeScript 或测试源码。
- 代码导览、Git 历史和开发诊断记录。
- 为解释错误而临时进入实现层或修改代码、配置、契约和测试。

## 循环规则

1. 明确本次要看到的结果、可复用的最高有效上游和目标 MCP 工具。
2. 按正式说明或 schema 发起调用，并保存实际请求与返回。
3. 返回错误时，先检查工具名、字段名、参数类型、路径、阶段状态和上游产物是否传错。
4. 错误返回或 schema 仍提供新的可执行信息时，根据该信息修正调用并继续重试，不设固定的一次重试额度。
5. 每次重试必须有明确修正理由，不得无变化地重复同一请求。
6. 返回状态、reasonCode 或异常文本只代表当前调用结果，不自动等于产品根因。
7. 调用有效后，继续取得正式产物、preview 或游戏画面，再判断功能结果。

## 结果分类

| 情况 | 处理 |
| --- | --- |
| 命令、字段或参数传错 | 修正并继续 Agent Loop，不记为功能失败。 |
| 上游路径或阶段引用错误 | 根据现有产物修正并继续，不从头重跑作保险。 |
| 环境尚未就绪 | 在工具使用者权限内完成连接或启动检查；无法继续时报告测试受阻。 |
| 返回信息不足或互相冲突 | 展示实际请求与返回；有合法修正方向就继续，否则报告测试受阻。 |
| 有效调用得到错误结果 | 展示结果并记录功能失败，结束本轮游玩；后续按原任务授权进入任务衔接。 |
| 结果可运行但观感不符 | 展示正式画面或 preview；已有明确验收标准时据此判断，涉及尚未确定的审美或需求选择时交给用户判断，后续按原任务授权衔接。 |

## 停止条件

只有以下情况停止 Agent Loop：

- 已得到用户可以判断的正式结果。
- 同一错误已尝试所有明确修正，返回不再提供新信息。
- 缺少必须由用户提供的选择或外部环境条件。
- 用户要求停止。

停止时必须说明实际请求、已做修正、最后返回和产物位置。不得把“测试受阻”写成“验收不通过”。

## 游玩结束后的任务衔接

停止本轮 Agent Loop 不等于结束整个任务。先保存实际请求、已做修正、最后返回、正式产物或受阻证据，再说明后续动作：

- 原任务已包含开发、修复或“修好并验证”时，发现未达成的明确要求，或工具层修正已经耗尽且需要源码定位时，自动进入已授权范围内的诊断和必要修复，无需再次询问是否继续。进入诊断后可以按任务路由读取源码、相关契约和诊断记录；仅凭返回状态不得预设产品根因。
- 修复后完成相关验证，再回到 Agent Loop 取得可判断的游戏结果。仅复用未被修改影响的有效上游；受影响产物需重新生成。
- 原任务仅要求游玩、预览或验收时，交付结果或受阻证据；仅要求诊断时可以继续定位并说明原因，不由此推定获得修复授权。
- 缺少必要的用户选择或外部环境条件时，说明所缺内容，只暂停依赖它的工作；用户要求停止时立即停止。规则审查或一次 MCP 报错本身不触发诊断与修复阶段。

## 调用记录

真实游玩测试必须保存每次 MCP 调用的工具名、关键参数、返回摘要、修正理由、最终结果和产物路径。调用记录属于运行或开发留档，不属于需求真值。
