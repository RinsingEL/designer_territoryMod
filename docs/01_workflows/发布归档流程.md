# 发布归档流程

## 定位

用于功能和验收已完成后的最终检查、归档和提交。发布归档员不修改功能行为；发现问题时停止并退回对应角色。

## 执行顺序

1. 分别检查相关仓库 `git status --short`，识别任务内外改动。
2. 查看目标仓库近期 `git log --oneline -n 10`，确定标题和版本风格。
3. 核对方案、契约、代码导览、测试入口和影响面是否因本轮失真。
4. 按影响面执行最终回归，记录命令、结果和未覆盖风险。
5. 如有 active 任务记录，显式读取并按规则归档。
6. 只暂存和提交本轮文件；双仓库分别提交并分别说明职责。

提交格式和归档细则见：

- `../02_standards/Git提交规则.md`
- `../02_standards/dev_docs组织规则.md`

## 停止条件

- diff 中存在无法区分归属的改动。
- 验收尚未通过或关键验证缺失。
- 当前文档真值与实现存在未决冲突。
- 发布检查需要改变功能行为。
