# 故障修复流程

## 前置条件

用户已明确要求修复，并且现象、预期和修改范围足够清楚。若尚未定位，先执行 `故障诊断流程.md`。

## 修复顺序

1. 检查相关仓库状态，保护已有改动。
2. 读取故障证据、目标系统真值和聚焦测试入口。
3. 修复最小必要范围，不顺手改变目标函数或阶段职责。
4. 先执行能覆盖根因的聚焦测试。
5. 根据代码影响面决定补充回归，不默认重跑完整业务链。
6. 必要时同步契约、代码导览、测试入口、影响面和故障索引。
7. 结束修复角色，把固定输入、命令和预期产物交给验收。

## 收敛限制

同一根因最多连续修复两轮。第三轮前必须停止并输出：

```text
问题现象：
已尝试修复：
仍未收敛的证据：
怀疑的设计偏差：
需要用户决定：
```

不得为了让测试通过而绕开正式输入、阶段真值或主链，也不得把 fallback 改成默认实现。
