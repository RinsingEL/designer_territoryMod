# 需求案规则

## 用途

本规则用于解决策划案过长、技术内容过多，导致人类难以 review、难以确认方案是否符合原始需求的问题。

需求案只保存用户真正提出的需求，让用户能够快速看懂、修改并确认最终要做出的行为。它不是技术方案、开发计划、契约或测试报告；是否合格首先取决于人类能否轻松完成方案确认，而不是文档是否覆盖所有工程细节。

最新一次经用户确认的原话和示意图优先于既有需求案。两者冲突时先指出冲突，再按最新确认结果更新需求案。

## 当前案身份与定位

仓库可以同时保存和推进多个案子，唯一性只在同一职责链内判断，不对整个仓库设置唯一案子。用户当轮明确指定的需求案路径和最新确认原话是本次任务最高真值。用户未指定路径时，先从目标 system / tool README 与案子索引定位本次任务所属职责链。

每条职责链使用以下身份区分并行状态：

- `实现当前案`：该职责链当前代码开发和验收的唯一需求依据，每条职责链必须且只能有一份。
- `设计中案`：尚在讨论或尚未接管实现，可以有多份，不得自动参与当前代码解释和验收。
- `能力参考`：跨案复用的稳定能力说明，不决定所属职责链的整体流程顺序。

不同职责链可以同时开发或设计；同一职责链也可以一边维护实现当前案、一边设计下一案。只有用户明确要求下一案接管实现时，才将其提升为 `实现当前案`，同步当前入口，并按下方“真值状态联动”标记清理到期；旧案迁移和删除在获准启动清理后执行，不在当前任务中自动展开。不得根据文件修改时间、文件名中的“最新”、目录顺序或案子数量自动认定当前案。

一旦锁定当前案，普通开发不得再通过全目录关键词搜索读取其他产品案。只有用户要求追溯、发现明确冲突、进行下述必要的只读核对，或正在执行清理工作流时，才读取与当前案职责直接重叠的相关案。不得用旧案、Git 历史、开发记录、现有代码或测试覆盖当前案和用户最新原话。

如果索引无法唯一定位当前案，先在本次任务所属职责链内只读核对用户最新确认、目标 README、案子索引及直接相关案的原话和身份。能据此确定本次需求依据时继续当前任务，不因索引缺失或陈旧自动启动清理；仍存在影响本次行为的语义冲突时，只暂停依赖该冲突的实现，列明冲突并询问用户，其他不依赖该选择的工作继续。核对本身不迁移或删除案子；确认竞争案等状态变化时按下方规则标记到期，是否执行清理仍按 Session 检查和用户同意条件判断。

## 真值状态联动

正在开发的 `实现当前案` 根据用户反馈继续修订，即使修订推翻了案内旧表述，也属于当前需求收敛，**不触发**需求案清理。只有新建替代案、修改案子职责链、把设计中案提升为实现当前案，或发现相反要求来自同一职责链中的另一份竞争案时，才运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\Mod_Dev\StructureBinder\scripts\mark_requirement_cleanup_due.ps1 -Reason <简短原因>
```

该命令只把下一次 session 的轻量检查标记为到期，不在当前需求编辑任务中自动展开清理。当前案身份按本文“当前案身份与定位”确定，无需为此读取清理工作流。

## 固定结构

```markdown
# 功能名称

## 需求原话

完整保留用户原话，不润色、不技术化。

## 示意图

保留原图、草图、路径或必要标注。

## AI 需求总结

### 子功能名称

用一小段信息密度较高的文字，完整说明这个子功能的效果、运行过程、可能分支、必要例子和明确禁止的结果。

### 另一个子功能

继续使用一小段完整说明。
```

AI 总结通常保持 3-8 个三级标题，每个标题对应一个人类可以独立 review 的子功能。标题下优先使用一段信息密度较高的完整说明，把互相依赖的效果、流程、分支和例子放在一起；不要为了形式整齐，把一个完整子功能拆成多个彼此孤立的抽象点。只有真正离散的选项、严格顺序或需要逐项核对的内容才使用列表。

对影响理解和确认的核心对象、状态、关系与禁令使用 Markdown `**加粗**`，例如 **不规则**、**已有景观**、**旧起点**、**禁止固定图形 fallback**。加粗用于帮助人类快速锁定语义，不用于装饰；不要加粗整段、完整长句或每个普通名词。

AI 总结只做用户需求的清晰重组。用户没有提出的内容不得自行补成产品要求。

## 不进入需求案的内容

- 类名、方法名、算法步骤和代码组织。
- schema、字段、错误码和 MCP 参数。
- 开发拆分、测试计划和提交安排。
- 用户未提出的通用化、未来扩展、兼容方案和 fallback。
- 为填满模板而添加的“本轮不做”或风险清单。

确实改变外部接口、配置、存档或阶段间结构化数据时，另行维护对应契约；不得把这些内容回填到需求案。
