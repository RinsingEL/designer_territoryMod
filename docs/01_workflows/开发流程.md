# 开发流程

## 适用范围

用于方案和契约已经足够明确的实现、新功能扩展及工程修补。新系统、大重构或阶段职责变化先走 `从0到1设计开发流程.md`；已知故障修复走 `故障修复流程.md`。

## 开发前检查

```text
本轮要解的问题：
输入与真值来源：
输出：
不做事项：
成功标准：
实现路径：
聚焦验证：
需要用户判断的点：
```

涉及目标函数、阶段职责、契约或 fallback 变化时，停止开发并切回方案契约阶段，不自行扩大实现范围。

## 执行顺序

1. 检查相关仓库状态，识别并保护已有改动。
2. 读取目标领域 README，以及本轮涉及的方案、契约、代码导览和测试入口。
3. 实现最小完整切片，不顺手重构无关模块。
4. 先运行聚焦测试，再按影响面决定是否扩大回归。
5. 同步因实现而失真的契约、代码导览、测试入口或影响面。
6. 输出实现摘要和验证证据，结束开发角色。

## 开发中的自行闭环

开发执行员可以自行处理编译失败、测试失败、字段拼写、坐标偏移、空值和同一实现切片内的小范围工程问题。同类问题最多自行修复两轮；第三轮前必须停止并报告当前证据和设计疑点。

此权限只属于开发阶段，不能带入后续验收阶段。

## 交给验收的内容

- 已冻结的输入或最高有效上游阶段。
- 唯一推荐的执行入口和参数。
- 预期停止点及正式产物路径。
- 已完成的聚焦测试。
- 仍需用户判断的视觉或体验问题。
