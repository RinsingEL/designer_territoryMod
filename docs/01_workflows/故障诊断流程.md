# 故障诊断流程

## 定位

用于解释异常、测试失败、行为不符或性能停滞。诊断角色只负责建立证据链和修改建议，不修改实现。

## 诊断顺序

1. 明确用户看到的现象、预期结果和首次偏离点。
2. 读取目标系统的测试入口、代码导览和故障索引。
3. 复用现有日志与产物；证据不足时只运行最小只读复现。
4. 区分环境、调用参数、上游数据、契约、实现、执行产物和视觉判断层。
5. 找到最早出现错误的层，而不是只解释最终症状。
6. 输出根因可信度、影响范围和最小建议修改面。

## 输出格式

```text
现象：
预期：
首次偏离层：
关键证据：
根因或当前最强假设：
受影响范围：
建议修改面：
仍缺少的证据：
```

无法证明根因时必须标为假设，不把相关性写成结论。诊断完成后停下；只有用户明确要求修复，才进入 `故障修复流程.md`。

## 记录规则

有长期复用价值的结论写入实现仓库对应 `故障索引.md`。需要多轮交接或保留复杂证据时，才按 `../02_standards/dev_docs组织规则.md` 创建任务记录。
