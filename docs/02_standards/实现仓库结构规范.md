# 实现仓库结构规范

## 定位

本文档定义实现仓库 `E:\Mod_Dev\StructureBinder` 的代码目录组织规则。它用于约束 Java / MCP / 运行时实现如何按系统内聚，而不是按 Minecraft 原版资源分类或临时占位目录扩张。

本文档不替代具体系统或工具的方案、契约、代码导览和测试入口。系统真值仍位于：

- `docs/systems/<系统>/`
- `docs/tools/<工具>/`

## 核心原则

1. 已开发系统才进入当前系统结构和导航。
2. 未开发系统不预建实现仓库 package，也不在文档仓库创建完整四层目录。
3. Java 代码优先按系统 / 能力边界内聚，Minecraft / Forge / HTTP / MCP 只作为适配边界。
4. `workflow` 代表执行流程和用例编排，应优先落在所属系统内部，不作为全局杂物目录。
5. Minecraft 强制要求的资源目录继续遵守原版结构，不能为了系统内聚破坏 datapack / resource pack 约定。

## 已开发系统规则

一个系统进入当前结构前，至少应满足：

- 有明确的系统名称和职责边界。
- 有可执行代码或即将落地的真实入口。
- 有对应文档入口：`docs/systems/<系统>/README.md`。
- 本轮涉及的方案、契约、代码导览或测试入口已经同步到对应分层。

只写未来可能存在的系统名称，不等于系统已经进入当前结构。

## 未开发系统规则

未开发系统只保留在明确的规划说明中，不预建以下内容：

- 空 Java package。
- 只有 `package-info.java` 的占位目录。
- 空的 `systems/<系统>/10_product`、`20_contracts`、`30_code_guide`、`40_tests`。
- 没有当前使用入口的 API / runtime / debug 抽象层。

当系统真正开始重建时，再按从 0 到 1 流程补齐文档入口和实现包。

## 推荐 Java 结构

实现仓库 Java 代码推荐按以下意图组织：

```text
com.rinsing.geomantia
  GeomantiaMod.java
  systems/
    <system>/
      domain/
      algorithm/
      application/
      adapter/
      preview/
      testsupport/
  platform/
    forge/
    http/
    mcp/
  client/
  shared/
```

当前仓库不要求一次性迁移到该形态。已有稳定实现可以在专门结构重整任务中逐步迁移，并通过测试证明行为不变。

## 系统内部职责

| 目录 | 职责 |
| --- | --- |
| `domain/` | 系统核心对象、状态、枚举和领域规则。 |
| `algorithm/` | 可独立测试的算法、分类、合并、求解、计算逻辑。 |
| `application/` | 系统内部执行流程、用例编排和状态推进。 |
| `adapter/` | Minecraft、Forge、HTTP、MCP、文件 IO 等边界适配。 |
| `preview/` | 调试图、报告、review 产物导出。 |
| `testsupport/` | 合成样例、测试 runner、测试夹具；可放在 `src/test` 时优先放测试源码。 |

小系统可以减少层级，但不应把所有代码都塞进按技术名词划分的大目录。

## Workflow 规则

`workflow` 是“流程语义”，不是必须存在的顶层代码目录。

推荐口径：

- 系统内部流程代码放在该系统的 `application/`，必要时可命名为 `workflow/`。
- 跨系统流程可以有独立 orchestrator，但只能做调度和状态串联。
- 跨系统 workflow 不沉淀领域规则，不直接改写其他系统内部对象。
- 方法调用流程、review 流程图和执行说明优先写入 `30_code_guide/flows` 与 `30_code_guide/diagrams`。
- 实现仓库 `dev_docs/workflows` 只记录过程、联调和归档，不作为当前功能真值。

## 平台与适配层规则

`platform/`、`client/` 和后续 MCP / HTTP 适配层负责把外部运行时输入转换为系统 application 的调用。

适配层允许：

- 读取 Minecraft / Forge 运行时对象。
- 解析命令、HTTP body、MCP 参数。
- 组装系统服务需要的输入。
- 返回响应、日志、调试产物路径。

适配层不应：

- 重复实现系统算法。
- 持有系统主状态机。
- 私自定义与契约冲突的数据字段。
- 把 debug fallback 写成生产主链。

## Minecraft 资源目录规则

`src/main/resources` 中受 Minecraft / Forge 约束的目录继续按原版规则组织，例如：

- `data/<modid>/worldgen/`
- `data/<modid>/structures/`
- `assets/<modid>/`
- `META-INF/`

这些目录是资源加载契约，不参与 Java package 的系统化重整。若资源属于某个系统，应通过文档和生成脚本说明归属，而不是破坏资源目录格式。

## 清理规则

可以删除的占位目录：

- 目录下只有 `package-info.java`。
- 没有任何生产代码、测试代码或资源引用。
- 文档仓库没有把它登记为当前已开发系统入口。

删除前应使用 `rg` 或 `git ls-files` 确认可删范围。删除后至少执行编译或测试入口，证明没有引用残留。

## 更新触发

出现以下情况时，应检查并更新本文档或相关导航：

- 新系统开始重建并进入实现。
- 顶层 package 或系统边界发生迁移。
- 新增跨系统 workflow / orchestrator。
- 新增 MCP / HTTP / Forge 入口并改变适配层边界。
- 用户要求进行项目结构健康检查。
