# Git提交规则

## 定位

本文档定义实现仓库和文档仓库的提交信息规则。它适用于 agent 准备执行 `git add`、`git commit`、归档 `dev_docs` 或双仓库分别提交时。

## 提交前检查

提交前必须执行：

```powershell
git status --short
git log --oneline -n 10
```

如果是文档仓库：

```powershell
git -C E:\Mod_Dev\designer_territoryMod status --short
git -C E:\Mod_Dev\designer_territoryMod log --oneline -n 10
```

检查目标：

- 确认只提交当前任务相关文件。
- 确认没有混入用户或其他 agent 的无关改动。
- 确认提交标题沿用目标仓库近期日志风格。
- 双仓库联动时，分别检查两个仓库，不把两边职责混在一个提交说明里。

## 标题规则

2026-10-14 起统一为两个仓库近期实际使用的格式：

```text
类型(范围): 主题
```

- **类型**：`feat` 新功能、`fix` 修复、`refactor` 重构、`docs` 文档、`test` 测试、`chore` 杂项。
- **范围**：系统、附属或工具名，例如 `city`、`realm`、`realmfolk`、`adventure`、`workbench`、`product`；跨多处时可省略。
- **主题**：中文或英文均可，说清本次改了什么；不带版本号（版本见[版本规则](版本规则.md)）。

禁止只有 `fix`、`update`、`change`、`misc` 等没有具体主题的标题。

## 正文规则

提交正文中文或英文均可，必须足够详细。除非用户明确要求单行提交，否则不得只有标题。

实现仓库正文至少说明：

- 改了哪些模块、类、流程或工具。
- 新增或调整了哪些能力。
- 影响哪些阶段、接口、数据结构或使用方式。
- 是否创建、更新或归档了 `dev_docs`。
- 做了哪些验证，命令或结果是什么。
- 是否存在剩余风险。

文档仓库正文至少说明：

- 更新了哪些方案、契约、代码导览、测试入口或影响面。
- 是否新增规则性文档或工作流文档。
- 和实现仓库的对应关系是什么。
- 是否调整历史归档或导航入口。
- 做了哪些验证，例如链接检查、索引检查、diff 范围检查。
- 是否存在剩余风险。

## 分支与 PR

每项工作在功能分支上提交，完成后提 PR 合入主线分支（当前为 `codex/offline-structure-studio`）；流程见[开发流程](../00_nav/开发流程.md)。

## 双仓库提交

双仓库联动时，必须分别提交：

- 实现仓库提交说明实现改造、接口影响、验证、`dev_docs` 记录或归档。
- 文档仓库提交说明方案更新、契约变化、导览或测试入口调整、影响面和导航变化。

不得把文档仓库未确认的 GIS 文档改动混入纯规则提交；不得把实现仓库代码改动混入纯文档提交。

## dev_docs 归档

如果本轮创建了 `dev_docs/.../active/.../任务记录.md`，提交成功后按 `../01_workflows/开发与Bug留档规则.md` 归档到同领域 `archive/`。

归档目录名应包含：

```text
<短提交号>_vX.Y.Z_中文标题
```

标题取自本次提交标题的核心中文主题，不转拼音，不混放多个提交版本。
