# 仓库地图

## 仓库职责

| 仓库 | 路径 | 承载内容 |
| --- | --- | --- |
| 实现仓库 | `E:\Mod_Dev\StructureBinder` | Java、MCP、运行时实现、测试、调试产物和 `dev_docs/`。 |
| 文档仓库 | `E:\Mod_Dev\designer_territoryMod` | 当前方案、契约、代码导览、测试入口、影响面和全局工作流。 |

## 写入边界

- 功能方案、字段契约、阶段职责和验收口径以文档仓库为真值。
- 代码、运行时配置、测试实现和调试记录以实现仓库为真值。
- `dev_docs/` 只记录过程、联调和故障经验，不替代当前方案或契约。
- 双仓库联动时分别检查状态、分别验证、分别提交。
- 历史方案不保留在当前文档目录；需要追溯时使用 Git 历史或实现仓库既有过程记录。

## 从文档找实现

1. 从 `domain_map.md` 进入目标 system / tool 的 `README.md`。
2. 先用 `10_product/` 和 `20_contracts/` 确认目标与输入输出。
3. 再通过 `30_code_guide/代码导览.md` 定位实现类和测试锚点。

## 从实现找文档

1. 按包名、能力和术语在 `domain_map.md` 判断领域。
2. 回到目标领域 README，再进入对应文档层。
3. 无法命中时使用 `rg`，不得只凭记忆猜测归属。

实现仓库结构细则见 `../02_standards/实现仓库结构规范.md`，过程记录细则见 `../02_standards/dev_docs组织规则.md`。
