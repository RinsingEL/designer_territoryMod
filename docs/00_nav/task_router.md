# 任务路由

## 路由顺序

1. 判断本轮属于方案设计、实现开发、验收执行、故障诊断、故障修复还是发布归档。
2. 声明一个活动角色；未经用户明确授权，不在同一轮自动切换角色。
3. 用 `domain_map.md` 定位领域，读取该 system / tool 的 `README.md`。
4. 读取活动角色对应的唯一流程入口和必要的领域真值。

## 角色入口

| 活动角色 | 适用任务 | 流程入口 |
| --- | --- | --- |
| 任务路由员 | 仅判断归属、范围和下一入口 | 本文档 |
| 方案契约员 | 新方案、阶段职责、字段、接口、验收口径 | `../01_workflows/从0到1设计开发流程.md` |
| 开发执行员 | 已有方案下的实现、新功能和工程自测 | `../01_workflows/开发流程.md` |
| 验收执行员 | 启动环境、执行既有命令、展示并核对产物 | `../01_workflows/验收流程.md` |
| 故障诊断员 | 解释异常、定位根因、评估修改面 | `../01_workflows/故障诊断流程.md` |
| 故障修复员 | 用户已明确要求修复的已定位问题 | `../01_workflows/故障修复流程.md` |
| 发布归档员 | 最终回归、diff 检查、归档和提交 | `../01_workflows/发布归档流程.md` |

完整权限矩阵见 `../02_standards/AI角色与权限.md`。

## 领域真值选择

| 任务语义 | 读取位置 |
| --- | --- |
| 目标、功能、主流程、边界、方案取舍 | `10_product/` |
| 字段、schema、输入输出、配置、MCP 参数 | `20_contracts/` |

## 检索兜底

`domain_map.md` 无法命中时，用 `rg` 搜索文档仓库核心名词，再回到命中文件所属 system / tool 的 `README.md`。不得直接把随机命中片段或 Git 历史当作当前真值。
