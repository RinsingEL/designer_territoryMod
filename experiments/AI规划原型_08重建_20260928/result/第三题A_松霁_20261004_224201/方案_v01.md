# 第三题 A · 松霁城市功能与风格方案

版本：v01；阶段：A，供讨论。依据当前城市卡和假结构池规则，不进入 B，不编译布局。

## 1. 定位与依据

松霁是榆岑西北的地方聚落（village），服务附近居民、工匠及跨区旅人。本方案将其组织为日常木作与修补、基本旅居和日用品服务相互支持的聚落；树苗培育、木料交换、箱具及家用木器作为计划发展的方向。以下“核心”表示与定位直接相关，“配套”表示支撑这些服务，并不对应建筑等级或固定数量。

已知消费为小麦、蔬菜、原版羊毛；原版木作／种植与 Farmer’s Delight 只作背景，不配置生产配方、NPC、产能或运输机制。居民体型、人口、客流、场地和本地树种未知。材料选色不证明原料产地，松霁之名也不证明当地有松林。

## 2. 功能需求与合用关系

每行是需求单元，不是一栋建筑。合用表示可共享部分空间，B 仍须检查所选结构是否支持；不表示一个实例可同时启用多个用途配置。

| 功能需求 | 依据／待确认 | 合用或分开及原因 | 核心／配套关系 |
| --- | --- | --- | --- |
| 日常木器制作；计划增加箱具与家用木器 | 城市卡明确木器制作及计划产品；尺度、工序与订单量未知 | 箱具、家用木器归入同一木作需求，避免重复设厂；接单、成品交付可共享，原料、粉尘作业与成品保护须分区。不推定大锯木或工业加工 | 现有核心；计划产品扩展 |
| 工具修理 | 城市卡明确；是否需要热加工待确认 | 可与木作共享接单、工具及后勤支持，但保留维修工作面；本轮只按普通手修讨论。若涉及锻造、熔炼，另提专业设施，不让普通作坊承担 | 现有核心，与木作互补 |
| 织物修补 | 城市卡明确，消费原版羊毛；羊毛如何进入修补供应尚未说明 | 可共享服务接单信息，但必须有独立隔尘的洁净工作空间和干燥存放处；不与木作共用开放工作面。不据羊毛消费推定纺纱、织布或染整生产线 | 现有核心，与工具修理并列 |
| 旅人住宿与接待休息 | 城市卡要求住宿，服务跨区旅人；停留时长、客流未知 | 倾向与餐食形成合用服务，住宿保持安静、私密，后勤与客人使用空间分开；若 B 选基础住宿结构，不能直接改名当作含厨房的餐宿组合 | 现有核心 |

| 日用品供应、木器展示交付与修补取送 | 城市卡明确日用品与就近修补；商品品类和销售强度待确认 | 日用品零售与成品展示可形成相互支持的服务；修补取送可与接单合用，但零售空间不自动具有制作维修能力。B 再判定共用前台还是分开 | 现有核心；支持木作与修补 |
| 树苗培育、养护与交付 | 城市卡计划培育树苗；树种、水源、土壤、光照和育苗规模未知 | 与木料交换可共享信息接待，育苗区与重物搬运、堆料分开；需要种植／育苗基面、浇灌取水条件、养护通行与工具暂存。假池未列苗圃专业设施，记 B 待补素材 | 计划核心，不宣称已建成 |
| 木料交换、验收整理与暂存 | 城市卡计划交换木料；来源、规格、流量未知 | 可为木作共享材料接收、整理和短时暂存支持，交易交付与作业面需有边界；不将其升级为大型交易市场或大锯木场 | 计划核心，支撑木作 |

| 居民及常住工匠的起居 | 地方聚落与居民服务对象支持此需求；人数及居住安排未知 | 可讨论店宅合用，但保留私人起居、睡眠和私入口；作业噪声、粉尘及旅客活动需与居住隔开。住宿不能默认替代居民住宅 | 基础配套 |
| 入口识别、等候会面与日常通行 | 根据居民、工匠、旅客共用服务提出的空间建议 | 门廊可承担遮蔽、识别及短时等候，不能挤占入口与搬运通道；小型会面可共享，不据此增加独立行政大厅或公共建筑 | 配套，空间需求，非已选模型 |
| 卫生清洁、取水及废弃物暂存 | 餐宿、维修、木作和育苗派生的空间需求；供排水条件未知 | 预留卫生、清洗与维护条件；木屑、维修杂物和厨余分开管理，取水与排污关系由 B 结合场地确认。卫生专用空间及设施支持尚未核实 | 必要配套，B 核查／待补素材 |

优先落实已明确的日常服务，并为计划功能保留需求记录；这只是功能优先关系，不给出施工分期、容量或用地承诺。无需为每类服务单独设一栋建筑，也不强行将所有服务塞入一座综合建筑。

## 3. 风格方向

**主风格：中式木构。** 以柱梁开间、可识别的门廊、出檐和木梁组织建筑表达，浅墙与深屋面形成清楚层次。保持地方聚落日常使用的尺度感，不把住宅、作坊、食肆全部宫殿化；具体开间、台基、院落、屋顶组合由 B 根据功能和场地选择。

**辅助表达：精灵式枝叶细节。** 从精灵风格的轻盈、舒展和通透感取意，重点留在门廊、梁端、入口识别等部位的枝叶纹样或细部表达，不将全城改为独立的精灵体量体系。叶绿可作为后续局部强调的候选，不能代替真正的枝叶造型。分叉柱架、弯折屋脊等涉及几何的变化不通过换皮生成；若 B 需要此类形体或连接构件，须另核对素材支持。

两者的分工是“中式木构组织主体，枝叶细节提供识别”。风格名称不代表居民种族、职业、体型或科技等级；不因精灵风格假设树屋、高塔或当地森林。通行净空、门窗尺寸及装饰密度仍待居民体型与模型确定。

## 4. 整体材料与换皮默认值

提出温和木色、浅墙、深色屋面的统一方向。以下使用假池选项名，不对应已验证的真实方块映射，也不表示运行时替换已经实现。

本轮只设一份**全城方案**，包含采用中式主体及精灵细节的建筑；不另设相互竞争的风格覆盖。只有结构明确声明的兼容槽才继承下表。表中“槽名／组”必须一起匹配，不能按模型内的方块材质全局搜索替换。

| 声明槽名／选项组 | 本轮默认值 | 适用范围与未定边界 |
| --- | --- | --- |
| 构架／木构 | 云杉 | 仅声明木构构架槽且允许云杉的结构；不推定本地种植云杉 |
| 墙面／墙面 | 浅色填充 | 仅兼容墙面槽；不将木梁、门窗或家具改为浅墙 |
| 屋面／阶梯屋面 | 深色橡木阶梯 | 仅兼容阶梯屋面槽；保留台阶形状、朝向和连接关系 |
| 饰面／饰面 | 本色 | 仅兼容饰面槽；叶绿仅作为 B 的局部候选，本轮不对全城饰面施加叶绿 |

石构、框架、板状覆面、织物、透光围护等组本轮均不设置整体默认值；遇到相应结构，保留结构默认，B 再决定是否需要覆盖。不将“框架”组的木架与“木构”组的云杉视为同一槽；板状屋面也不能强行继承阶梯屋面值。

执行继承时遵循：结构默认 → 全城方案 → 所属风格方案 → 单个实例覆盖。本轮无风格级方案；B 若新增，混合风格实例必须明确归属。未标注部位保持原样；不兼容选值进入待处理记录，不声称成功替换。换皮不修改形体、不添加厨房或枝叶构件、不替换用途与内装。

## 5. B 待核查与待补素材

- 苗圃是明确专业设施缺项：按树苗培育所需空间补素材，不能将普通店铺改名替代。
- 若工具修理需要炉火／锻造，须补专业设施；当前普通手修方向不要求高温设备。
- 枝叶细部、连接构件、卫生清洗等需求的具体素材支持尚未确认，B 再查证；不声称现有假模型自带这些内容。
- 餐宿合用须核对实际包含餐厅、后厨、食材储存及后勤；住宅与店铺合用须保留住宅空间。织物修补的隔尘条件不能被共享接待省略。
- 木料交换可参考整理与暂存类空间，实际交换服务是否完整仍需 B 核对；假结构条目不等于真实模型或玩法支持。

## 6. 待讨论项

1. 是否接受“中式主体＋克制枝叶细节”，以及云杉构架、浅色填充、深色橡木阶梯屋面、本色饰面的整体方向？
2. 餐宿服务优先考虑合用还是分开？本方案倾向合用服务，但不预选具体形体。
3. 树苗培育与木料交换在后续设计中的优先程度如何，是否与日常木作同等展开？
4. 工具修理是否止于普通手修，织物修补的供应是否已有成品布料／线材？居民体型、人口、客流与场地信息若仍未知，B 应继续保留数量、尺寸和落位未定。
